# 新账号监控 · 高保真原型《UI 元素与文案字典规格》

> 产品经理：许清楚（Xu）｜执行人：前端工程师裴像素
> 本文是「账号监控 v2」高保真原型的**唯一验收口径稿**：§2 信息架构与组件白名单、§3 逐字文案字典、§4 演示数据脚本、§5 验收 Checklist。
> **铁律**：页面上一切可见文本必须逐字出自 §3 字典；一切可见元素必须列在 §2 白名单内。未授权元素（私加 Badge、副标题、装饰图标、解释性括号）一律视为缺陷，PM_SIGN_OFF 直接 REJECT。

---

## 1. 产品概况与口径声明

### 1.1 本次原型范围

在 `docs/prototypes/account-monitor-lightweight-demo.html` 基底上演进为高保真演示页，覆盖：
标题条 → 三 Tab 导航 → 「账号监控」页内：监控池状态条、单行筛选行、Feed 内容网格、三档空态、导入弹窗、详情弹窗、额度/冷却置灰与原因说明。

### 1.2 Non-Goals（明确不做）

| # | 不做事项 | 说明 |
|---|---|---|
| N1 | 左侧 280px 账号抽屉列表 | 旧 IA 的账号导航容器，已由「监控池状态条 + 账号筛选下拉」取代 |
| N2 | 「为你推荐 / 关注监控」双 Tab | v2 原型简化为单一聚合 Feed + 排序下拉，不再做二级 Tab |
| N3 | 卡片九宫格式账号卡片 | 信息单位是内容，不是账号 |
| N4 | 任何营销副标题、装饰图标、Emoji、彩色渐变装饰 | Anti-Overdesign 铁律 |
| N5 | 「一键互动」评论候选面板 | v2 操作栏四项为「原帖直达 / AI 拆解 / 立即复刻 / 已处理标记」，互动链路不在本原型 |
| N6 | 真实接口对接 | 全部数据来自 §4 演示脚本 |

### 1.3 术语与口径对齐

- 旧文案真源 `locales.js` 中 `rivalFeed.*` / `rivalAccounts.*` 可复用的逐字保留；与本文冲突处以本文为准并回填字典。
- 增速口径严格遵循 PRD §5.1 三级可信度：**实测增速 → 发布均速 → 账号内相对爆发度**。**严禁把相对爆发度（该号 Nx）包装成实时增速**——不得使用 `爆款/飙升` 前缀、不得使用 `k/h` 单位、不得使用橙红/琥珀色。
- 几何与设计令牌遵循 `design.md` v2.0：DSH 原生 `--dsw-*` token、32px 控件高、8px 控件圆角（卡片 12px / 弹窗 16px）、单行工具栏 `nowrap`、无 Emoji 无字符图标（一律 SVG）。

#### R3 · 监控池状态条（仅账号监控 Tab 内）

| 元素 ID | 类型 | 文案/内容 | 状态规则 | 严禁附加项 |
|---|---|---|---|---|
| `pool.summary` | 单行状态文本 | `监控池 {total} 个账号 · 正常 {ok} · 冷却 {cooling} · 待重导入 {reimport} · 已停止 {stopped}` | 常驻，独占状态条第一行；计数为零的分段仍显示（如 `已停止 0`）；四段计数互斥且 `正常 + 冷却 + 待重导入 + 已停止 = {total}` | 禁拆成多行、禁加彩色圆点图标、禁省略零值分段 |
| `pool.quota` | 单行状态文本 | `今日剩余刷新额度 {left}/{total}` | 常驻，状态条第二行左侧；`left` 数字等宽 | 禁加「额度告急」等情绪化文案 |
| `pool.freshness` | 单行状态文本 | `数据更新于 {n} 分钟前` | 常驻，状态条第二行右侧；11px 三级文字；容器宽度不足时**优先隐藏本段**（`pool.summary` 与 `pool.quota` 不隐藏、不换行） | 禁写「实时」「刚刚同步过」 |

#### R4 · 筛选行（单行 `nowrap`，空间不足时从左向右依次隐藏为溢出菜单，禁止折行）

| 元素 ID | 类型 | 文案/内容 | 状态规则 | 严禁附加项 |
|---|---|---|---|---|
| `filter.perf.group` | 单选胶囊组 ×4 | `全部` `超强爆款` `急速飙升` `最新发布` | 单选，默认 `全部`；28px 高 999px 圆角 | 禁加第 5 项、禁加括号阈值解释（不写 `(>20k/h)`） |
| `filter.platform` | 下拉触发器 | 默认 `平台: 全部`；筛选态 `平台: TikTok` | 菜单项：`全部` / `TikTok` / `Instagram` / `YouTube` / `X`，多选至少保 1 项 | 首项严禁写 `全部平台`；菜单项禁加副标题 |
| `filter.account` | 下拉触发器 | 默认 `账号: 全部 (8)`；部分选 `已选 {n} 个账号`；全不选 `未选择账号` | 见 D1 Popover 白名单 | 严禁写 `全部账号` |
| `filter.sort` | 下拉触发器 | `综合推荐` | 菜单项：`综合推荐` `增速最快` `最新发布` `播放量最高`；表现档选 `最新发布` 时自动跟随为 `最新发布` | 禁加第 5 个排序项 |
| `filter.search` | 搜索框 | 占位符 `搜索内容或账号` | 32px 高，左侧 SVG 放大镜，300ms 防抖 | 禁加搜索建议下拉之外的任何元素 |
| `filter.refresh` | 主按钮 + 额度角标 | `刷新`，角标 `{left}/{total}` 即 `6/8` | T0 缓存新鲜时按钮文案 `刚刚更新` 且弱化；额度耗尽置灰**但可点**（见 D4） | 禁加转圈动画以外的刷新图标语义 |

#### D4 · 刷新置灰原因 Popover（点击置灰 `filter.refresh` 触发）

### 8.1 账号健康态「已停止」（2026-10-05 拍板：方案①）

> 来源：§8 待拍板项，用户拍板走方案①——给账号加「已停止」健康态，让 `refresh.stopped` 的指向成立。
> 口径真源：Host `refresh_state` 取值 `idle | queued | running | backoff | error | paused`（`plugins/omnimux-inspiration/src/rival/constants.js`）。

**定义**：`已停止` = `refresh_state === 'error'` 且失败原因为**非身份类**（当前实现为退避序列用尽）。语义是「自动刷新已停止，只能由用户手动处理」。

**与「需要重新导入」的关系：并列，不是包含**。二者同属 `refresh_state=error` 的两个互斥子类，`error` 的全部取值必落到其中之一：

| `refresh_state` | 失败原因 | 账号行健康态 | 用户动作 |
|---|---|---|---|
| `error` | 身份类（`identity-unverified`，云端明确拒绝账号身份） | `需要重新导入` | 改用 channel/UC… 链接重新导入（走 `导入账号` / `导入灵感` 打开 D2，不新增行内按钮） |
| `error` | 非身份类（退避序列用尽） | `已停止` | 行内 `重试` |
| `paused` | — | 不显示（见 N12） | 无需处理，日界自动释放 |
| `backoff` / `queued` / `running` / `idle` | — | `正常` | — |

判定顺序：先判身份类，再判其余；同一账号任何时刻只显示一个健康态。**并列而非包含**的理由：两态的用户动作不同（换链接 vs 重试），合并会让一个状态挂两种修法；且 `需要重新导入` 已是既有字典条目与既有验收项。

**显示**：标记 `已停止`（错误色文字）+ 常驻原因行 `连续 {n} 次刷新失败`（11px 三级文字）+ 行内 `重试`。与 `需要重新导入` 同构（标记 + 常驻原因行），原因行必须常驻、不得做成悬浮提示。
**原因行的存在判据**：原因行只在原因会改变用户动作时出现——`需要重新导入` 的原因行告诉用户改用哪种链接，故必备；`已停止` 的原因行只提供客观事实，动作由行内 `重试` 承担，不做重复表述。

**状态优先级（账号行）**：`需要重新导入` > `已停止` > `冷却中 · {n} 分钟后恢复` > `正常`。
与 D4 同一套判据（不可自动恢复的终态优先于会自恢复的限流），但账号行不含「额度」项：额度是池级共享事实，由 `pool.quota` 常驻表达（见 N12）。

**恢复路径**：`重试` 触发该账号单账号刷新（`refresh_state` → `queued`），消耗 1 次刷新额度，连续失败计数清零，健康态立即回 `正常`、原因行消失；再次失败时按退避序列重新计次并再次进入 `已停止`。额度为 0 时 `重试` 置灰但可点，弹出 D4 的 `refresh.quota`。
**`已停止` 账号不参与主 `刷新`**：筛选集内存在 `已停止` 账号时，主 `刷新` 按钮按 D4 置灰并显示 `refresh.stopped`（逐字不变）。`refresh.confirm.skip` 不改：T3 未实现，且已停止账号在置灰阶段就被拦下，不进入跳过计数。

**N12（不做）**：账号行不新增额度态。理由：额度是池级共享事实，`pool.quota` 已常驻表达；账号级 `paused` 与全局同步、日界自动释放，不需要用户在账号行处理。若后续出现真正的账号级额度差异，另行开票。

**依赖**：原因行 `{n}` 取 Host 上报的连续失败次数（`refresh_state=error` 时必带，字段名以实现侧契约为准）。未上报时原因行整行不渲染，标记仍显示 `已停止`。

**验收（并入 §5.1）**：
- 账号筛选 Popover 四态齐全；两个终态（`需要重新导入` / `已停止`）的原因行常驻可见，不依赖悬停
- `已停止` 行有行内 `重试`；点击后该行回 `正常`、原因行消失、`pool.summary` 计数同步变化
- 计数闭合：`正常 + 冷却 + 待重导入 + 已停止 = 监控池账号数`
- 同一账号不同时显示两个健康态；多个条件同时成立时按上表优先级取一个
- 全页无字典外文字；`已停止` 相关可见文本只有 `已停止` / `连续 {n} 次刷新失败` / `重试` 三条

| 操作栏 `card.actions` | **仅悬停显示**（维持 B2 的两行排布） | 有了决定才需要操作 |

**状态裁决（覆盖 PRD US-13 的实现方式，不改它的目标）**：
- US-13 的目标是「扫榜时避开已处理内容」。已处理样式在扫视时比一个小号虚线标签更容易看到，而且不占任何元素位，所以同时满足 US-13 和用户的极简要求。
- 三种状态（`已互动` / `已复刻` / `已处理`）一律用同一套已处理样式，不再在默认态区分。区分只在悬停时看文字。
- **已处理样式**（默认态，三处同时生效，**禁止**再用整卡 `opacity`）：
  1. **胶囊中性化**（主信号）：胶囊文字不变（如仍是 `爆款 42k/h`），样式改用所在表面的 `观察` 档中性样式：叠在媒体上的胶囊用 §3.3 观察档的 `--dsw-specific-media-*` 中性样式；文本卡顶部行的胶囊用 §9.1 的 alias 中性样式。`爆款` 卡的橙红描边与外发光（B5）同时撤掉，描边回到 `--dsw-alias-border-l1`。
  2. **媒体去色淡出**：只作用在媒体元素本身（封面图 / 图片 / 内嵌视频的 `img` / `video`），`filter: grayscale(1)` 加 `opacity: 0.45`，不使用 `brightness`。媒体向所在卡底淡出：暗色主题融进深色卡底，亮色主题融进浅色卡底，两套主题下都读作「褪色」，不会被当成加载失败。胶囊是媒体之上的独立图层，不受滤镜和不透明度影响；整卡 `opacity` 仍为 1。这是 §9.1 暗底原则的唯一例外。
  3. **文字降一级**：标题 / 正文颜色从 `--dsw-alias-label-primary` 改为 `--dsw-alias-label-secondary`，字号与字重不变。
- 纯文本卡（`text`）没有媒体，只靠第 1 条和第 3 条后退；无胶囊的纯文本卡只靠第 3 条。
- 悬停时三处一起恢复常规样式（彩色胶囊、媒体无滤镜、文字 `label-primary`）。
- 只改颜色和滤镜，不改尺寸，所以标记状态不改变卡片高度，瀑布流不会重新排位。
- 第四个操作位：卡片有状态时显示该状态的静态文字（`已互动 · 09:12` / `已复刻` / `已处理`），不再提供 `标为已处理` 按钮；卡片无状态时显示 `标为已处理` 按钮，点击后变成静态文字 `已处理`，鼠标移出后进入已处理样式，并弹出 Toast `已标记为已处理`。
- 第四个操作位的状态文字：12px、单行不换行；该行三个位置按内容宽度分配，不等分，保证 `已互动 · 09:12` 在 220px 列宽下不截断。
- **对比度结论（按 design.md §3 参考值计算，满足 §2.6 正文 ≥ 4.5:1）**：标题 / 正文用 `label-secondary`，亮色主题 `#4b5563` 在卡底 layer-1 `#f7f7f8` 上约 **7.1:1**；暗色主题 `rgba(255,255,255,0.72)` 在 layer-1（`rgba(255,255,255,0.04)` 叠在 bg-base `#111113` 上）约 **9.4:1**。两套主题都达标，不设任何豁免。媒体上的已处理胶囊沿用 §3.3 观察档媒体样式，自带半透明深色底；媒体淡出后亮度不超过卡底，等同于观察档胶囊叠在浅色封面上的情形，对比度沿用 `观察` 档本身的结论，本条不另作豁免。演示数据下两套主题实测 ≥ 4.5:1（见 V14）。

**悬停层结构**（所有类型结构统一，从卡片底部向上贴底排布；底色见结构图下方）：

```
│ [平台 SVG 12px] 昵称 · 12 分钟前          高契合 │ ← 作者行（匹配度可无）
│ 播放 12.8万 · 点赞 8,640 · 评论 214 · 分享 96     │ ← 指标行（模板见 §9.5）
│ [原帖直达] [AI 拆解] [标为已处理 | 状态文字]      │ ← 28px 描边次级
│ [            立即复刻            ]                │ ← 32px 满宽主按钮
```

悬停层总高约 135px，所以所有卡片最小高度定为 144px（见 §9.3）。

悬停层底色分两种：
- 媒体类（`short-video` / `long-video` / `image`）：沿用 `--dsw-specific-media-overlay` 渐变，文字与按钮用 `--dsw-specific-media-*`。
- 文本类（`text` / `text-media`）：悬停层用不透明的 `--dsw-alias-bg-elevated` 底色，文字与按钮用 alias token（主按钮沿用 design.md 的墨水色主按钮），避免正文和悬停层文字叠在一起，也保证亮色主题下可读。悬停层上沿外侧加 20px 渐隐带（等于正文一行行高，`linear-gradient` 从透明到 `--dsw-alias-bg-elevated`），被遮住的正文在渐隐带内淡出，不出现被硬边切开的半行字。渐隐带不占布局、不改变悬停层与卡片高度、不拦截鼠标。悬停层不画顶边描边，顶部不做圆角。胶囊在悬停时始终可见；悬停时正文只作背景，全文在 D3 查看。

### 9.3 瀑布流规则

**列数与列宽**（按 Feed 容器内容宽度 `W` 计算，不是按视口宽度）：
- 最小列宽 220px，列间距 16px，列宽等分：`列数 n = max(2, min(6, floor((W + 16) / 236)))`，`列宽 = (W − 16 × (n − 1)) / n`。
- 对应断点：

| 容器宽度 W | 列数 | 列宽范围 |
|---|---|---|
| < 692px | 2 | 等分 |
| 692–927px | 3 | 220–298px |
| 928–1163px | 4 | 220–279px |
| 1164–1399px | 5 | 220–267px |
| ≥ 1400px | 6 | ≥ 220px |

**排列顺序（排序语义必须保持）**：
- 禁止用 CSS `columns`（按列从上往下填，排名会错乱），也禁止用 `grid-auto-flow: dense`（会把后面的卡挪到前面）。
- 按当前排序结果逐张放置：每张卡放进**放置前底边最高的那一列**（即最短列）；几列一样短时放最左边那列。这样阅读顺序仍然是从左到右、从上到下。
- DOM 顺序必须等于排序顺序，保证 Tab 键顺序和读屏顺序与排名一致。
- 切换排序、筛选、搜索或容器宽度变化后，全量重新排列。
- 悬停、标为已处理、已处理样式都不改变卡片高度，因此不触发重新排列，卡片位置不能跳动。
- 媒体区高度在图片加载前就按数据里的比例占位，加载后不能出现布局跳动。

**间距**：横向和纵向都是 16px，与 v2 网格一致。

**高度上下限**：

| 类型 | 最小高度 | 最大高度（由截断规则保证） | 列宽 220px 时的参考高度 |
|---|---|---|---|
| 所有卡片 | 144px（能放下悬停层） | — | — |
| `text` | 144px | 胶囊行 28 + 8 行正文 160 + 内边距 ≈ 220px | 短推文按最小高度 144px；长推文约 220px |
| `text-media` | 144px | 胶囊行 + 3 行正文 + 16:9 媒体 + 内边距 ≈ 240px | ≈ 238px |
| `long-video` | 144px | 16:9 媒体 + 2 行标题 | ≈ 184px |
| `image` | 144px | 4:5 媒体 + 1 行配文 | 4:5 约 317px；1:1 约 262px |
| `short-video` | — | 9:16 媒体 + 1 行标题，是最高的卡 | ≈ 433px |

结论：文本卡最高不超过约 240px，远低于短视频卡，超长推文不会把一列拉长。
