# 账号监控（原「对标账号」）内容 Feed 重构 PRD

> 产品经理：许清楚（Xu）｜子系统：`omnimux-inspiration`（对标账号模块）
> 语言：中文｜本文只写「要什么、为什么」，不写架构与代码实现。
> 现有实现按「账号列表 + 帖子列表」两栏组织，本文把它重构为「内容优先的聚合 Feed」。

---

## 0. 决策摘要（先看这 6 条）

| # | 决策 | 依据/收益 |
|---|---|---|
| D1 | 废弃「账号卡片/九宫格」为主视图，默认进入**全账号聚合内容 Feed**；账号列表降级为「筛选入口 + 单账号聚焦视图」 | 创作者目标是「发现爆款内容」，不是「浏览账号」 |
| D2 | 每条内容右上角常驻**爆款增速胶囊**（`23k/h`），三级分类：爆款 >20k/h、飙升 >1k/h、观察 200–1k/h | 一眼看出实时爆发力，是抢时效的唯一决策依据 |
| D3 | 增速由**同一帖两次播放量采样**计算（`Δ播放 ÷ Δ小时`）；采样间隔 <1.5h 或样本不足时降级为「发布至今均速」，并在胶囊上以弱化样式标注可信度 | 增速必须可解释，不能是估算出来的假数字 |
| D4 | 双 Tab：**为你推荐**（综合排序，含跨账号探索配额 15%）/ **关注监控**（时间倒序） | 对齐用户熟悉的 Feed 直觉（X 的 For you / Following） |
| D5 | 数据获取坚持**只读 + 配额硬上限**：沿用现有 2 次/账号·周期、4 次/账号·日、50 次/全局·日 账本；新增「2 小时内本地缓存命中不计费」与三级阶梯刷新成本面额 | 外部接口有真实调用成本，必须让用户在「花钱刷新」前看到价格 |
| D6 | 「一键互动」= **打开原帖 + 生成评论草稿并复制**，不做自动代发、不做自动点赞 | 互动在平台侧完成，避免账号风控与平台规则风险 |

### 1.1 现状与缺口（基于代码侦察的事实）

| 现状 | 结论 |
|---|---|
| 当前视图 = 左「账号列表（280px）」+ 右「该账号帖子列表」，账号是导航单位 | 用户必须逐个账号点开 → 就是本次要消灭的痛点 |
| 已有帖子指标：播放/点赞/评论/转发/收藏，且每帖带 `views_history`（最多 30 个「时间 + 播放量」采样点） | **增速数据原料已经存在**，只需新增计算与展示层 |
| 已有 R1–R4「潜力」相对规则（对比该账号自身播放中位数 3 倍等） | 与「爆款增速」是两套正交信号，可叠加使用，不重复建设 |
| 已有账号级和帖子级字段（昵称、头像、粉丝、播放中位数、发布频率、赛道推断） | 卡片账号身份行可直接复用，无需新增采集 |
| 平台：TikTok / Instagram / YouTube / X 四平台 | 与「四大平台多选」需求天然对齐 |
| 已有成本账本：2 次/账号·周期、4 次/账号·日、50 次/全局·日；失败退避 5/15/60 分钟；手动冷却 10/30 分钟 | 本 PRD 的配额设计**在这套账本上扩展，不另起一套** |
| **缺口 1**：无内容 Feed（无聚合、无排序、无推荐） | 本次重构主体 |
| **缺口 2**：无增速指标（只有累计值与静态相对规则） | 本次新增「爆款增速」计算与标签体系 |
| **缺口 3**：无产品库匹配度 | 本次新增匹配度标签；产品库已有 `名称 / 分类 / 卖点 / 目标人群 / 品牌` 字段可作为匹配输入 |
| **缺口 4**：无「每日免费额度」的用户可感知口径（只有服务端硬上限） | 本次新增配额可视化与阶梯成本确认 |

## 2. 产品定义

### 2.1 核心洞察

创作者打开账号监控，**不是在找账号，是在找「此刻正在爆的内容」**。账号只是内容的来源属性。因此：

- 信息组织的单位从「账号」换成「内容」；
- 排序的第一权重从「账号权重」换成「内容的实时增速」；
- 决策路径从「点开账号 → 看列表 → 挑内容 → 判断」压缩为「扫一眼胶囊 → 点操作」。

### 2.2 Product Goals（3 个正交目标）

1. **时效优先**：把「全网爆款进入视野」的延迟从天级压到小时级——用户打开即看到按实时增速排序的内容，胶囊数字直接回答「这条现在有多猛」。
2. **决策闭环**：每条内容在卡片上就地完成「判断 → 互动 → 复刻」，把「看到」到「行动」的跳转次数压到 ≤1 次。
3. **成本可控**：在不突破外部接口调用预算的前提下，做到「看起来是实时的」——靠两级缓存、阶梯刷新、配额可视化，而不是靠无节制轮询。

### 2.3 成功指标

| 指标 | 口径 | 目标 |
|---|---|---|
| 爆款发现时效 | 内容爆发起点 → 进入用户 Feed 首屏的中位延迟 | ≤ 2 小时（自动刷新档） |
| 卡片→行动转化率 | 卡片的「拆解/复刻/互动」点击数 ÷ 卡片曝光数 | ≥ 8% |
| 扫榜效率 | 用户从打开到完成一次「发现 + 操作」的时长 | ≤ 60 秒 |
| 配额健康度 | 全局日预算耗尽（触发暂停）的天数占比 | ≤ 5% |
| 缓存命中率 | 读取命中本地或云端缓存（不产生新调用）的比例 | ≥ 70% |
| 匹配度可用性 | 有产品库的用户中，Feed 首屏出现「高契合」标签的比例 | ≥ 25% |

## 3. 用户角色与场景全景

### 3.1 用户角色画像

| 角色 | 代号 | 特征 | 核心诉求 | 使用频次 |
|---|---|---|---|---|
| **抢时效截流操盘手** | P1 · 快手 | 运营 3–20 个账号，主战场评论区；对新内容极度敏感，看到就回 | 3 分钟内判断「这条值不值得跟」并立刻评论/引流 | 每天 3–5 次，早中晚各一轮 |
| **爆款复刻创作者** | P2 · 复刻者 | 有明确产品与定位（用产品库管理），靠同行验证过的选题与结构降低试错成本 | 找到「高增速 + 与我产品契合」的内容，一键拆解脚本分镜后二创 | 每天 1–2 次，单次 20–40 分钟 |
| **矩阵负责人** | P3 · 负责人 | 管理 10+ 监控账号，关注整体趋势与投入产出 | 一眼看到全局哪些赛道在起量，决定资源投向 | 每天 1 次，5–10 分钟 |
| **轻度试用者** | P4 · 新手 | 刚导入 1–3 个对标账号，尚未建立产品库 | 先看懂「这个功能能干嘛」 | 首次使用后 3 天内流失风险高 |

> 设计含义：P4 决定首次体验的成败——**空状态必须给出「导入 1 个账号就能看到内容」的即时正反馈**，不能要求先建产品库。

### 3.2 核心用户故事

| # | 用户故事 | 主要角色 | 优先级 |
|---|---|---|---|
| US-1 | As a 抢时效操盘手，I want 打开账号监控时直接看到「全部监控账号里此刻增速最快的内容」按增速排序，so that 我不用逐个点账号就能第一时间发现正在爆的帖子。 | P1/P3 | **P0** |
| US-2 | As a 抢时效操盘手，I want 每条内容右上角有一个醒目的 `爆款 23k/h` 胶囊，so that 我 0.5 秒内判断这条是不是值得现在去回帖。 | P1 | **P0** |
| US-3 | As a 抢时效操盘手，I want 点「一键互动」直接打开原帖并把写好的评论候选复制到剪贴板，so that 我用 3 步完成截流而不被平台判定为机器行为。 | P1 | **P0** |
| US-4 | As a 复刻者，I want 每条内容上标出它与我产品库的匹配度（高契合/可参考/无关），so that 我优先看真正能用的爆款，不被无关赛道干扰。 | P2 | **P0** |
| US-5 | As a 复刻者，I want 点「AI 拆解脚本」就地看到钩子、结构、节奏与分镜并可直接送到会话二创，so that 我复用已被验证的结构而不是从零想。 | P2 | **P0** |
| US-6 | As a 复刻者，I want 点「一键复刻」生成我自己的版本（换成我的产品与话术），so that 选题到成片的路径最短。 | P2 | **P0** |
| US-7 | As a 矩阵负责人，I want 在同一个 Feed 里同时看四个平台的内容，按平台多选筛选，so that 我不用在四个平台之间来回切换。 | P3 | **P0** |
| US-8 | As a 矩阵负责人，I want 切换「表现」筛选（全部/超强爆款/急速飙升/最新发布），so that 我能只看最猛的或只看最新的。 | P3 | **P0** |
| US-9 | As a 矩阵负责人，I want 点某个账号即切到「只看这个账号」的聚焦视图，再一键切回全部，so that 我可以从宏观下钻到单账号而不丢上下文。 | P3 | **P1** |
| US-10 | As a 轻度试用者，I want 在空状态里被明确告知「导入 1 个账号后 1 分钟就能看到内容」，so that 我不会因为看不到数据而退出。 | P4 | **P0** |
| US-11 | As a 任何用户，I want 在点「实时刷新」前看到这次刷新会消耗多少额度、当前还剩多少，so that 我不会有「用着用着突然不能用了」的意外。 | 全部 | **P0** |
| US-12 | As a 任何用户，I want 内容在 2 小时内已被读过时不再重复计费，so that 我上下滚动 Feed 不担心额度被偷跑。 | 全部 | **P1** |
| US-13 | As a 复刻者，I want 已拆解/已复刻的内容有明确的「已处理」标记，so that 我不会重复看同一条。 | P2 | **P1** |
| US-14 | As a 矩阵负责人，I want 一个账号刚被导入时它的历史帖子也能立刻按「账号内相对爆发度」排序，so that 我不必等 24 小时才有内容可看。 | P3/P4 | **P1** |

### 3.3 高频场景全景

#### 场景 A · 早间扫榜与快速抢评/截流

| 步骤 | 用户动作 | 系统响应 | 设计要点 |
|---|---|---|---|
| A1 | 09:00 打开「账号监控」 | 默认进入**为你推荐** Tab；展示缓存内最新数据，顶部显示数据新鲜度（如「3 分钟前更新」） | 首屏必须是可决策内容，不是空态、加载骨架不超过 400ms |
| A2 | 视线扫过前 5 条，只读**右上角胶囊** | 胶囊按增速降序排列，`超强爆款` 置顶 | 胶囊是视觉第一重心：位置固定、色相反差最大、数字等宽 |
| A3 | 看到 `爆款 23k/h · 12 分钟前` | 该卡片带轻微高亮描边，标注「正在爆发」 | 时间新鲜度是第二重心，紧贴胶囊 |
| A4 | 点击「一键互动」 | 打开原帖新窗口 + 弹出评论候选（3 条：含产品植入版与纯互动版），一键复制 | 3 步内完成；不自动代发 |
| A5 | 原帖评论完成，返回 | 卡片标记「已互动 · 09:12」，并从推荐流中降低同帖权重 | 防止重复劳动 |
| A6 | 继续下扫，遇低增长内容 | 增速胶囊降级为中性灰、数字变小 | 视觉噪音随价值下降而下降 |

**场景 A 的验收口径**：从打开到完成首次互动 ≤ 60 秒；前 5 条内容全部具备可读增速标签。

#### 场景 B · 选题挖掘与基于产品库的爆款复刻

| 步骤 | 用户动作 | 系统响应 | 设计要点 |
|---|---|---|---|
| B1 | 10:30 打开账号监控，筛选「急速飙升 + 最新发布（<24h）」 | Feed 立即收敛为对应子集 | 筛选是多选胶囊，不弹二级面板 |
| B2 | 用平台多选只看 TikTok + YouTube | 平台角标与筛选态一致 | 结果为空时给出「放宽某个条件」的一键入口 |
| B3 | 锁定 2 条「高契合」内容 | 匹配度标签悬停可展开：命中的品类词/卖点词 | 匹配必须可解释，不能是黑盒分数 |
| B4 | 点击「AI 拆解脚本」 | 卡片内联展开：钩子（前 3 秒）、叙事结构、节奏节点、分镜要点、可替换变量（产品/人群/场景） | 就地展开，不跳页、不丢滚动位置 |
| B5 | 点击「一键复刻」 | 生成改写脚本（保留结构、替换为我的产品话术），进入会话继续二创；卡片标记「已复刻 · 进行中」 | 复用现有「添加到会话 / 拆解」通路 |
| B6 | 复刻完成，卡片标记「已复刻」 | 该账号权重上调（常复刻信号） | 让 Feed 越用越准 |

## 4. 内容 Feed 浏览体系与信息架构（重构重点）

### 4.1 从「账号优先」到「内容优先」的信息架构

| 维度 | 旧结构（对齐账号） | 新结构（内容优先） |
|---|---|---|
| 首屏单位 | 账号卡片（头像 + 昵称 + 粉丝 + 平均播放） | **内容卡片**（账号身份降为卡片内一行元信息） |
| 排序依据 | 账号列表按添加时间/粉丝量 | 内容按**综合推荐分**（增速为第一权重） |
| 账号的作用 | 导航容器（点进去才看到内容） | **筛选维度 + 权重因子**（不再需要点进去） |
| 「爆款」的表达 | 账号级平均播放数字 | **内容级实时增速胶囊** |
| 空状态 | 「还没有监控账号」 | 「导入 1 个账号，1 分钟后这里会出现按爆发力排序的内容」 |

> 账号列表不删除，降级为左侧「聚焦筛选器」+ 单账号视图入口（US-9）。真正被删掉的是「必须点开账号才能看内容」这条强制路径。

### 4.2 页面骨架（三层）

| 层 | 名称 | 内容 | 是否常驻 |
|---|---|---|---|
| L1 | 顶部筛选区 | 搜索框 · 双 Tab（为你推荐/关注监控）· 平台多选 · 表现分档 · 排序 · 刷新按钮 + 额度提示 | 常驻吸顶（滚动时收为紧凑条，仅保留 Tab 与刷新） |
| L2 | Feed 流 | 内容卡片纵向流（宽屏 2 列，窄屏 1 列） | 主体 |
| L3 | 左抽屉（可收） | 账号聚焦列表 + 监控开关 + 账号状态（正常/冷却/待重导入） | 宽屏常驻，窄屏收为抽屉 |

### 4.3 单条内容卡片的核心要素（P0 定义）

| # | 要素 | 内容 | 优先级 |
|---|---|---|---|
| 1 | **爆款增速胶囊** | `爆款 23k/h` / `飙升 1.2k/h` / `观察 320/h` | **P0** |
| 2 | **账号身份行** | 头像（24px）+ 昵称 + 平台角标（四平台图形）+ 发布时间（相对时间） | **P0** |
| 3 | **内容主体** | 视频封面/播放器（16:9 或 9:16 自适应）+ 标题/正文（最多 3 行截断）+ 时长角标 | **P0** |
| 4 | **关键指标行** | 播放 · 点赞 · 评论 · 转发（紧凑化：`1.2万` / `23.4k`）；播放量带「较上次采样 +x%」 | **P0** |
| 5 | **产品库匹配度标签** | `高契合 · 品类命中` / `可参考`；未建产品库时不显示 | **P0** |
| 6 | **账号相对爆发度徽标** | `该号爆款 · 高于账号中位 4.2x`（复用 R1–R4） | **P1** |
| 7 | **快捷操作栏** | 一键互动 · AI 拆解脚本 · 一键复刻 · 原帖直达 | **P0** |
| 8 | 状态标记 | 已互动 / 已拆解 / 已复刻 / 已入库 | **P1** |
| 9 | 来源可信度 | 数据采样时间点（如「12:05 采样」），悬停显示 | **P2** |

## 5. 智能推荐与排序算法机制

### 5.1 「爆款增速」（k/h）的定义与计算

**定义**：单位小时内的**播放量净增量**，即 `Δ播放量 ÷ Δ小时`，按千位缩写显示为 `23k/h`。

计算优先级（保证任何内容都能给出可解释的标签）：

| 档位 | 条件 | 计算 | 展示 |
|---|---|---|---|
| **A · 实测增速**（首选） | 同一帖存在 ≥2 个采样点，且时间间隔 ≥ 1.5 小时 | 取最近两次采样 `(v2 − v1) ÷ 小时差`，再做指数平滑（近一次权重 0.7） | `爆款 23k/h`，胶囊实心 |
| **B · 发布均速**（降级） | 只有 1 个采样点，或采样间隔 < 1.5 小时 | `累计播放 ÷ 发布至今小时数` | `均速 8.6k/h`，胶囊描边（提示是均值不是瞬时） |
| **C · 账号内相对爆发度**（兜底） | 数据不足以判断绝对量级（新账号、冷门内容） | 对比该账号历史播放中位数：`≥3x` 记为爆发 | `该号 4.2x`，中性色胶囊 |

**分级阈值（播放量/小时）**：

| 等级 | 阈值 | 胶囊文案 | 语义 |
|---|---|---|---|
| 超强爆款 | > 20,000 | `爆款 23k/h` | 全网红，立刻跟 |
| 急速飙升 | 1,000 – 20,000 | `飙升 1.2k/h` | 正在起，值得跟 |
| 观察中 | 200 – 1,000 | `观察 320/h` | 有苗头，备用 |
| 平稳 | < 200 | 只显示累计播放 | 不占视觉资源 |

> **与现有 R1–R4 潜力规则的关系（正交，不重复）**：R1–R4 衡量「这条在该账号内是否异常」（相对）；爆款增速衡量「这条在全网尺度上有多猛」（绝对）。卡片上两套信号并列：增速胶囊在内容右上（第一重心），账号内相对爆发度徽标在指标行（第二重心）。一条帖可能「账号内不异常但全网爆款」（大号日常发挥），也可能「账号内异常但绝对量级不大」（小号黑马），两者都要能被看见。

### 5.2 综合推荐评分公式

```
Score = 0.30 × 增速分 V
      + 0.16 × 时效衰减分 T
      + 0.12 × 账号权重分 A
      + 0.14 × 用户行为分 U
      + 0.22 × 产品库匹配分 M
      + 0.06 × 内容质量分 Q
```

| 分量 | 定义 | 归一化 |
|---|---|---|
| **V 增速分** | §5.1 的每小时增速 | `min(1, log10(1 + k/h) ÷ log10(1 + 30000))`，对数平滑防止超大值垄断 |
| **T 时效衰减分** | 发布时间衰减 | 发布 <48h：半衰期 12 小时的指数衰减；发布 ≥48h：改用「发布后 24h 内平均增速」参与 V，T 固定 0.2（避免老帖因累计值高长期霸榜） |
| **A 账号权重分** | 账号维度：粉丝量级（对数）、该账号近期平均播放、用户是否常看该账号 | `0.4×量级 + 0.3×近期表现 + 0.3×常看权重` |
| **U 用户行为分** | 该用户对该账号的历史行为：查看、复制、拆解、复刻、互动 | 复刻/拆解权重最高（强意愿），其次互动，再次查看 |
| **M 产品库匹配分** | 内容与用户产品库的语义 + 属性匹配 | 见 §5.3 |
| **Q 内容质量分** | 加权互动率（复用现有 CES：点赞 1.0 / 评论 2.0 / 收藏 3.5 / 分享 4.0） | 复用现有引擎，互动率 6% 视为满分 |

**冷启动与兜底**：新导入账号的帖子在 24 小时内享有曝光保护（A 分量以同类目账号中位数代入，不因缺数据被埋）；无产品库用户 M 分量置零，其余五分量按比例放大（保持总分可比）。

**反信息茧房**：为你推荐 Tab 固定预留 **15% 位置**给「跨账号探索配额」——即当前排序结果之外、来自用户最不常看的账号，但增速达「爆款/飙升」档的内容。目的：避免用户只看到自己已有账号池里那几条。

### 5.3 产品库匹配度（M 分量）

| 层级 | 方法 | 触发时机 | 成本 |
|---|---|---|---|
| 基础匹配（默认） | 内容标题/正文/标签 与 产品库的 `名称 / 分类 / 卖点 / 目标人群 / 品牌` 做词表命中与重合度计算 | 每次 Feed 渲染（本地计算） | 零外部成本 |
| 深度匹配（可选） | 判定契合度、可替换点、风险点 | 用户点「AI 拆解脚本」或「一键复刻」时 | 复用拆解通路，不额外增加调用 |

**展示口径**：

| 匹配度 | 标签 | 判定 |
|---|---|---|
| ≥ 85 | `高契合` | 品类 + 至少一项卖点/人群命中 |
| 50 – 84 | `可参考` | 品类或人群部分重合 |
| < 50 | 不显示标签 | 避免负向噪音 |
| 无产品库 | 不显示 | 空状态引导创建产品库，但不阻塞使用 |

**可解释性**：标签悬停展开命中证据（如「命中：宠物饮水机 / 养猫人群」），用户能判断标签是否可信。

### 5.4 双 Tab 排序逻辑

| Tab | 排序 | 适用 |
|---|---|---|
| **为你推荐** | 按 §5.2 综合分降序；同分按增速降序 | 默认；发现新爆款 |
| **关注监控** | 严格按发布时间倒序（同账号内容不折叠、不聚合） | 「我要按时间轴看监控池，不掺杂算法」 |

并集规则：Feed 只包含「已监控账号」的内容，不做全平台内容召回（这是「监控」功能的边界，也是成本可控的前提）。

## 7. 数据更新成本控制与缓存配额机制

### 7.1 为什么必须做

外部平台数据通过云端接口获取，**每次调用都有真实成本**（额度或计费）。不加控制会产生三个后果：① 成本不可预测；② 高频轮询触发平台侧限制；③ 用户「用着突然不能用了」的体验断崖。因此本模块的原则是：**默认自动、成本可预期、花钱前先看到价格**。

### 7.2 两级缓存体系（冷热分离）

| 层级 | 位置 | 时效窗口 | 命中时是否计费 | 说明 |
|---|---|---|---|---|
| **L0 热缓存** | 客户端内存 | 会话内 | 不计费 | 滚动、切 Tab、切筛选不产生任何调用 |
| **L1 温缓存** | 本地（本机） | **2 小时** | **不计费** | 2 小时内再次读取直接返回本地快照 |
| **L2 冷缓存** | 云端共享 | 2–6 小时 | 不计费（跨用户共享，命中即复用） | 多用户看同一账号时天然共享 |
| **L3 实时拉取** | 云端接口 | 6 小时以上或强制刷新 | **计费**（占用调用额度） | 唯一真正花钱的档位 |

**关键规则**：**同一账号在 2 小时内被任何视图读取，一律不产生新调用**——这是「用户不怕滑动 Feed」的保证。

### 7.3 每日免费额度与账号分级

| 档位 | 监控账号数上限 | 每账号每日自动更新 | 全局每日调用上限 | 手动深度探针/日 |
|---|---|---|---|---|
| 免费 | 2 | 1 次 | 4 | 1 次 |
| 标准 | 3 | 3 次 | 8 | 3 次 |
| 专业 | 10 | 2 次 | 20 | 5 次 |

> 口径说明：全局上限是**硬天花板**，优先级为 手动深度探针 > 自动增量 > 批量刷新。任何一档都不能突破全局上限；额度耗尽时进入「暂停刷新」状态，并在 UI 明确说明**恢复时间**，而不是静默失效。
> 现有服务端的更保守硬界限（2 次/账号·周期、4 次/账号·日、50 次/全局·日）继续作为不可逾越的技术底线：上表是**面向用户的口径**，必须 ≤ 技术底线。

### 7.4 阶梯式主动刷新与深度解锁（花钱前先看到价格）

用户点击刷新时，系统先判定当前缓存层级，再给出**明确成本面额**：

| 阶梯 | 名称 | 触发条件 | 成本 | 交互 |
|---|---|---|---|---|
| T0 | 无需刷新 | 缓存 <2 小时 | **0** | 按钮显示「刚刚更新 · 3 分钟前」，点击直接滚动到最新 |
| T1 | 轻量刷新 | 缓存 2–6 小时 | **1 次额度** | 一次点击即执行，无弹窗（低成本动作不打断） |
| T2 | 深度探针 | 缓存 >6 小时，或用户主动要「完整评论/最新数据」 | **3 次额度** | 弹窗确认，显示「本次消耗 3 次 · 今日剩余 6 次」 |
| T3 | 全量刷新 | 批量刷新全部账号 | **按账号数计** | 弹窗列出将刷新 N 个账号、合计消耗 M 次、跳过哪些（冷却中/额度不足） |

**确认弹窗的必要内容（缺一不可）**：本次消耗 · 今日剩余 · 预计耗时 · 「取消」按钮默认聚焦。
**额度耗尽时**：按钮置灰但**可点击查看原因**，弹窗说明「今日额度已用完，X 小时后（或明日 00:00）自动恢复」，并给出「只读浏览已有数据」的出路。

### 7.5 成本优化的实现约束（给工程）

| 约束 | 说明 |
|---|---|
| 请求合并 | 同一账号的「账号信息 + 帖子列表」在一次刷新周期内完成，不重复拉取 |
| 单账号单飞 | 同一账号的并发刷新请求必须合并为一次（用户连点不产生多次调用） |
| 失败退避不浪费额度 | 失败按 5/15/60 分钟退避，退避期间不消耗额度；连续失败达到终态则停止自动刷新并提示用户处理（如换用平台可识别的账号标识形式） |
| 抓取时窗错峰 | 自动刷新避开整点高峰，按账号把刷新时间分散到清晨/午间/晚间三个窗口，削峰填谷 |
| 额度可见 | 顶部常驻「今日剩余额度」轻量指示，悬停展开明细（按账号/按类型） |

| 卡片内 | 要素之间 8px，分组之间 12px，卡片内边距 16px |

| 色彩语义 | 用途 | 约束 |
|---|---|---|
| 橙红（强调） | 超强爆款胶囊、正在爆发描边 | 全页仅用于「爆款」语义，不做装饰 |
| 琥珀 | 急速飙升胶囊 | 同上 |
| 主色（蓝） | 选中态、焦点、链接 | 不新增语义 |
| 中性灰阶 | 其余全部 | 数字默认中性，只有「爆款/飙升」才有色 |

> 极简原则：**一屏之内，彩色只出现在真正在爆的内容上**。用户视线不需要做筛选，颜色自己把重点递过来。

### 8.7 微交互清单

| 动作 | 反馈 | 时长 |
|---|---|---|
| 悬停卡片 | 描边高亮；操作栏从 40% 不透明渐显到 100% | 120ms |
| 点击「一键互动」 | 打开原帖新窗口 + 评论候选面板滑入；卡片出现「已互动」标记 | 200ms |
| 点击「AI 拆解脚本」 | 卡片就地展开拆解区（钩子/结构/节奏/分镜/可替换变量），高度动画展开；再次点击收起 | 240ms |
| 点击「一键复刻」 | 按钮进入加载态（≤2s 显示进度文案），成功则标记「已复刻 · 进行中」并提示可去会话继续 | 即时反馈 |
| 刷新成功 | 顶部新鲜度文案更新；新增爆款卡片以极轻背景淡入出现（不移动已读位置，防止滚动跳动） | 200ms |
| 额度不足 | 刷新按钮轻微抖动一次（不循环）+ 弹出说明 | 180ms |
| 滚动 | 吸顶筛选区收缩为紧凑条（保留 Tab + 刷新 + 额度），滚回顶部还原 | 150ms |
| 键盘（P2） | `J/K` 上下移动焦点，`Enter` 打开原帖，`I` 互动，`D` 拆解，`R` 复刻 | 即时 |

**禁止项**：卡片入场不用位移 + 缩放的「弹跳」动画；不用视差；不用大面积彩色渐变装饰；同一屏不出现两个发光元素。

### 8.8 空状态与边界状态

| 状态 | 展示 | 出路 |
|---|---|---|
| 未导入任何账号 | 中部极简线性插画 + 「导入第一个对标账号，1 分钟后这里会出现按爆发力排序的内容」 | 主按钮「导入账号」（支持粘贴主页链接） |
| 有账号但无内容 | 「正在为你抓取内容…」（带进度）+ 预计时间 | 完成后自动进入 Feed |
| 筛选过窄无结果 | 「当前条件下没有内容」 | 三个一键放宽：取消表现档位 / 全选平台 / 切换 Tab |
| 额度耗尽 | 顶部提示条「今日额度已用完，明日 00:00 恢复」 | Feed 保持只读可用 |
| 账号需重新导入 | 左侧账号项带「待重导入」标记 | 点击进入导入对话框，带原因说明 |
| 增速数据不可用 | 胶囊显示 `该号 4.2x`（相对档），悬停解释「该内容数据样本不足」 | 提供「深度探针」按钮，明示成本 |

## 10. 开放问题（需确认）

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| Q1 | 增速采样间隔的物理下限：现有自动刷新最密为 12 小时，若维持该节奏，`23k/h` 对多数账号只能是「均速」而非瞬时增速 | 直接影响本功能的核心承诺（时效） | 建议自动刷新支持「高频档」（如 3 小时一次）作为高等级权益，并同步上调额度上限；否则文案必须统一为「均速」，避免过度承诺 |
| Q2 | 用户档位（免费/标准/专业）的判定口径：按账号套餐、按本机配置，还是按产品版本 | 影响额度文案与后端开关 | 需产品侧确认后接线；未确认前统一按「标准」档展示 |
| Q3 | 云端共享缓存（L2）是否已具备 | 若不具备，2–6 小时窗口无法免计费，成本模型需重算 | 需架构侧确认；不具备时降级为「本地 2 小时不计费 + 超出即计费」 |
| Q4 | 「一键复刻」产出物落点：进入会话继续二创（现状通路），还是直接生成成片任务 | 影响操作栏语义与预期管理 | 建议 P0 沿用会话通路，文案明确为「生成改写脚本」 |
| Q5 | 产品库匹配的基础匹配词表从何而来：现有字段（名称/分类/卖点/目标人群/品牌）是否足够 | 匹配质量直接决定「高契合」标签可信度 | 建议先以上述字段做基线，观察命中率后再决定是否引入品类词库 |
| Q6 | 是否需要「跨账号去重」：同一内容被多个监控账号转发时如何展示 | 影响聚合视图的重复感 | 建议按内容指纹去重，保留最早发布的账号为主，其余折叠为「另有 2 个账号发布」 |
