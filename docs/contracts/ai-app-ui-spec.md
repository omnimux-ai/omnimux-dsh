# OmniMux AI 应用 UI 布局与表单交互标准规范

## 1. 规范目标、现状与证据限制

本文规定产品与 UI 验收目标，不是代码实现或 CI 接入证明。2026-09-09 修订收敛产品要求、交付状态及技术边界；技术目标与源码缺口见 [Canvas / Apps 协作契约](workflow-app-boundary.md)，不修改实现。

审计固定基线 `e416238631cc78ef8caeab7b5313d9571947ef5a`，目标 `a1ecf7bddc110992d870efd3b4e56511dfe43c9e`，原型代码位于旧任务树 `omnimux-dsh-wt-contracts`，不能等同于 main、Dev 或生产环境。本文源码路径与行号均指该固定目标 SHA 的历史证据，不保证在 main 存在；本次仅将文档融合到 main 基线，不合入原型代码。

**撤回此前不实交付宣称**：Production Ready、零缺陷、端到端闭环、Apps 持久化、CI 已接入、11 组对抗测试、完整团队 TDD 均不成立。上一轮审计证据仅为 **4 个 Apps 单测 + 1 个 mock seam 单测通过**、弱静态扫描通过；`git diff --check e4162386 a1ecf7bd` 因行尾空白失败。单测与文本扫描不证明 UI 挂载、真实执行、数据持久化或可播放产物。本轮没有重跑这些行为测试，也不把文档修订当作代码修复。

固定目标 SHA 的代码现状：发布向导未挂载；Apps Registry 为内存 Map；表单业务字段硬编码；消费端使用 4 秒 mock 成功；没有真实媒体播放器与上传选择器。历史为空时以 sampleTasks 代填，违反下文真实历史要求。具体对应表见第 5 节。

## 2. 入口、分类与工作台布局（规范目标）

- 宿主只有一个一级「AI 应用」入口。二级分类栏只分 **视频 / 图片 / 音频**；「全部」可作聚合过滤，不是第四类。应用和字段来自 schema 配置，禁止按 appId 写死业务页面。
- 二级栏选择应用后收起，保留可重新展开的入口；重开后保留当前应用选择。切换应用不得串用表单草稿或历史。
- 工作台顶紧 compact tabs，tabs 后是**一个左右分区的大卡片**：左表单、右历史/示例；不额外叠加大 Banner、重复标题或入口块。448px 是左表单分区宽度，不是整个工作台宽度。
- tabs 保持单行，溢出水平滚动；应用/工具选项由配置生成。
- 右侧仅「历史」「示例」两种内容视图。历史为空时默认打开示例，但历史仍为零；示例不足或加载失败必须显示真实空态/错误，不能构造成功或运行中任务。
- 发布者自主上传或选择多张图片、多条视频及封面，配置对比、轮播或网格；音频应用以可播放音频及相应封面呈现。Demo 保存对应输入快照，示例内容与真实任务记录分离。
- 不纳入本轮产品范围：agent 第四类、计费/退款/算力展示、评分、VS SYNC、wipe 卷帘、冗余回填按钮、工作流源链接及底层节点调试信息。复用 Demo 快照至多保留一个清晰动作，不把复用与微调做成重复按钮；复用不自动提交。

## 3. 控件几何与视觉目标

以下是 AI 应用表单及 compact tabs 的**特定例外**：相对于 [design.md](../../design.md) 的 32px 控件高 / 8px 圆角基准，保留输入 40px、内嵌按钮 36px、textarea 80px、CTA 44px、tab 28px/圆角 6px。例外仅作用于本文指定部件，其他宿主与发布向导控件仍遵循总规范；不修改 design 总规范，也不扩展为全站例外。

| 控件 | 几何与排布 | 视觉/交互要求 |
| --- | --- | --- |
| 左表单分区 | 外宽 448px；`box-sizing: border-box`；左右边框各 1px，padding 各 24px | 内可用宽为 **448 - 2 - 48 = 398px**；外大卡片圆角 12px |
| compact tabs 容器 | 高 32px，gap 4px；单行不换行 | 顶紧工作台，水平溢出可滚动 |
| tab 按钮 | 高 28px，圆角 6px，水平 padding 10px | 内容自适应，选中态明确 |
| 单行输入 / 全宽下拉 | 高 40px，宽 398px，圆角 8px | 使用统一定制 Dropdown/Popover，禁止裸原生 select |
| 双列下拉 | 每列 195px，gap 8px，总宽 398px | 两字段分别绑定 schema 键，不硬编码语言/国家 |
| 复合输入 | 外框 40px 或 44px，内嵌按钮 36px、圆角 6px | 解析与上传按 schema 提供；无能力时不得假成功 |
| textarea | 宽 398px，高 80px，圆角 10px | `resize: none`；长文本内部滚动，字数统计不遮挡输入 |
| 主 CTA | 高 44px，宽 398px，圆角 8px | 唯一主提交；校验失败/提交中状态明确，不能重复提交 |

色彩必须消费宿主 `--dsw-alias-*` / `--dsw-specific-*` 语义 Token，禁止在配置、CSS 或示例中硬编码 Hex/RGBA，也不私造平行主题。CTA 遵循 Ink：深色主题浅底深字、浅色主题深底浅字，不能把两种主题都锁为白底黑字。背景、边框、成功/失败、选中态与处理动画均用相应语义 Token；文本对比度遵循总规范。

图标使用 SVG（优先官方 primitives，其次 lucide），不用 Emoji/字符代替图标。所有按钮有可访问名称，下拉支持键盘和焦点反馈。处理中视觉应复用已认可的画布视觉能力，不能导入画布私有实现或复制一套硬编码渐变；复用既有公开共享展示组件；无公开出口时按协作契约记录后续最小共享边界，不以出现某个 CSS 类名判定功能完成。

## 4. 历史、示例与媒体呈现目标

- 历史只展示当前用户、当前应用的真实任务，状态与产物由执行权威返回；成功必须关联可用产物，mock 或固定延迟不能被当作真实成功。
- 右侧顶栏呈现历史切换、示例切换与准确的可操作数量；Demo 不计入真实历史数量，不显示伪造任务时间或运行状态。
- 多视频/多图由发布配置驱动，支持轮播、网格及并排对比。视频必须真实可播放，图片可检视，音频有真实播放控件；加载失败可见。
- 比例按媒体元数据和发布配置适配。**9:16 只适用于相应竖屏视频，不是全媒体强制比例**；横屏、方图保留内容，音频不套竖屏视频卡。
- 时间、状态、时长与删除操作仅在真实数据及能力存在时展示；删除需确认并反馈实际结果，不只移除前端卡片。
- Demo 输入快照应用前需校验与当前应用版本兼容；覆盖已编辑内容需提示，不自动提交，不新增冗余回填/微调按钮。

| ID / 优先级 | 规范目标 | 可观察验收条件 | 目标 SHA 的实现状态 / 证据限制 |
| --- | --- | --- | --- |
| APP-01 / P0 | 唯一入口、三类二级栏、收起可重开 | 实际宿主从入口选应用、收起、重开、切换均成功，只有三种 category | 待验证：组件源码不等于宿主挂载与导航证据 |
| APP-02 / P0 | schema 通用表单 | 视频、图片、音频各一份配置，无新增业务条件分支，正确渲染并校验输入 | 待实现：`plugins/omnimux-apps/src/client/index.tsx` 的 AppFormPanel 忽略 manifest 并写死字段 |
| APP-03 / P0 | compact tabs + 单个左右大卡片 | 实际 DOM 测量第 3 节尺寸、计算宽度及紧贴布局；明暗主题检查 | 待验证：静态扫描不能证明尺寸、布局与主题 |
| APP-04 / P0 | 三步发布与自主素材配置 | 从画布打开向导，配置画像/字段/多图多视频与封面，发布后读回 Demo 快照 | 待实现：`PublishWizardModal.tsx` 未挂载，上传选择器缺失 |
| APP-05 / P0 | 历史与示例分离 | 零历史默认示例，切到历史显示空态；失败不得伪装成功 | 待实现：client 的 sampleTasks 回退伪填历史 |
| APP-06 / P0 | 真媒体展示 | 真实视频/音频播放、图片检视、多素材切换及加载失败可见 | 待实现：client 没有真实播放器，mock URL 不构成媒体证据 |
| APP-07 / P0 | Canvas 执行、Hub 接入、Apps 域存储 | 表单提交可追踪到真实任务、真实产物，重启后可读回记录 | 待实现：4 秒 mock 成功；host Registry 为内存 Map；mock seam 单测不证明闭环 |
| APP-08 / P0 | 输入校验与快照复用 | 必填/类型/枚举错误阻止提交；复用只填表且无重复动作 | 待实现/待验证：4 个 Apps 单测不能覆盖通用控件与交互 |
| APP-09 / P1 | 草稿隔离、重连与取消 | 切应用/刷新后草稿不串用；真实状态可恢复；取消反馈与执行一致 | 待验证：需架构契约及独立运行验收 |
| APP-10 / P2 | 展示加载性能优化 | 在明确样本与设备上记录媒体切换/加载指标 | 待验证：不承诺无证据的 0 秒、60fps 或帧级同步 |

本次纯文档修订按用户授权跳过 L2，不做 App 物化；不据此放宽后续实现验收。后续实现按 [plugin QA](plugin-qa.md) 完成合入前自动化/静态检查和独立评审，合入后按需在 Dev 使用 ego-browser 与 shared verify:live，绑定实际构建 SHA 及同次证据。CI 接入必须提供 workflow 调用链和实际 run；测试数量、TDD 流程只能按可追溯证据报告。本文不能直接建立 CI 硬门禁。
