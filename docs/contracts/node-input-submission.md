# 节点有效输入与提交合同

本合同规定生成节点如何消费上游输入，以及创建、连接、提交和输入变化的产品行为。生成按钮必须判断本次任务的有效输入，不能仅判断本地输入框或连线数量。

## 1. 权威与适用范围

| 真源 | 负责 | 不负责 |
| --- | --- | --- |
| 本合同 | 输入来源与用途、内容组合、依赖状态、提交一致性 | 渠道模型能力、具体 API 字段及额度权限 |
| [模型能力合同](model-capabilities-matrix.md)与中枢 catalog | 模型、operation、输入槽、参数及可用资格 | 要求用户必须在某个本地输入框提供内容 |
| [模型 API 准据](model-api-authority.md) | 指定渠道官方文档、已知限制与未知项 | 用真实调用探测边界 |
| [本次 PRD 与验收矩阵](../specs/2026-09-06-node-input-submission-prd.md) | 本次缺口、交付范围、场景与完成证据 | 另一套长期业务规则或运行通过声明 |

适用于文本、图片、视频和音频生成节点中已经授权的能力。任务示例不表示模型已经接入或可上线，也不授权新增模型、自动执行整条流程、生产发布或真实模型探测。既有 MVP、账号、凭据、支付与发布边界保持不变。

本合同补充旧模型 I/O PRD/design 的 prompt 来源和提交语义；相关叙述冲突时以本合同为准。模型能力、权限和环境政策仍由各自合同负责。

## 2. 有效输入

有效输入是本次任务实际要消费的内容及其用途：本地内容、上游当前选定的输出、任务本身明确提供的指令，以及模型所需配置。每项输入必须能追溯来源、选定结果、顺序、用途和可用状态。

- 消费上游选定的输出，不继承生成该输出时的 prompt、模型、参数或全部历史结果。没有多结果选择器的节点使用其明确的当前输出。
- 无输出、空字符串和纯空白不能满足必需文本。非空但简短或表达不佳，只能给非阻断建议，不能按主观内容质量拒绝提交。
- 图片、音频和视频必须有可解析的素材身份及可用内容；只有节点类型、缩略图、连线或本地预览 URL，不能证明执行侧能消费素材。
- 必须区分渠道限制未知、素材元信息尚未读取和素材不可用。未知不能伪造为零或任意上限；缺少执行必需的信息时显示读取中或具体失败，按 [模型 API 准据](model-api-authority.md)处理文档未知项。
- `source: node_field` 描述现有合同的节点请求字段映射，不等于只准用户在本地手填。上游内容可以经过输入解析形成该字段；不能据此放宽该字段的渠道约束。

## 3. 创建、连接与提交

| 阶段 | 条件 | 用户可见结果 |
| --- | --- | --- |
| 独立创建 | 目标节点具有产品允许的能力；内容可以未填写 | 允许创建并逐步配置；暂无能力时解释不可用，不展示可执行承诺 |
| 从上游创建并连接 | 至少存在接受预期输出类型和当前已知约束的可用任务方案 | 只提供兼容目标；未生成的上游可作为待补齐依赖，不计为有效素材 |
| 新增连线 | 当前输入组合能由至少一个可用模型/operation 接受，且不违反已知类型、角色、容量等约束 | 接受中间态；缺少其他必需素材或文本不等于不能连线 |
| 提交当前节点 | 所有纳入本次任务的输入已就绪；必需槽、文本、角色和配置满足所选任务 | 启用生成；否则显示具体缺项或不兼容来源 |
| 运行依赖流程 | 由已有流程执行合同决定调度范围与依赖 | 流程可调度不等于当前节点已具备可直接提交的输入 |

每个已连接且纳入本次任务的来源都必须被消费或明确说明未纳入的原因。已连接输入尚未就绪时，不得静默跳过它而仅使用本地内容提交；用户可以移除引用后独立生成。本合同不要求另建一套“忽略输入”控件。

本合同中的可提交性是输入与配置就绪条件。既有鉴权、额度、并发、执行中及权限校验仍然有效；必须区分这些原因与缺少内容。

## 4. 文本来源与组合

### 4.1 普通文本生成、改写和描述型生成

以下组合均以任务可用、其他必需素材和参数已满足为前提。

| 上游文本 | 本地输入 | 行为 |
| --- | --- | --- |
| 无 | 空 | 无有效文本；任务要求文本时阻止提交 |
| 非空且已就绪 | 空 | 使用上游文本；不得因本地空值禁用生成 |
| 无 | 非空 | 使用本地输入 |
| 非空且已就绪 | 非空 | 上游作为任务内容，本地作为补充要求，共同参与请求；不得按优先级只取其中一个 |
| 多段已就绪文本 | 空或非空 | 按界面可见顺序组合全部已选文本，并保留来源边界；超限时说明，不静默截断或只取第一段 |

默认引用而非复制：上游内容不自动写入本地编辑框。已有有效上游文本时，显示来源摘要及“补充要求（可选）”；只有任务确实缺少必需内容时才提示填写。

上游剧本加本地“缩短到 30 秒”，请求必须同时包含原剧本和修改要求。仅有上游 `1dog` 的文本生成请求仍是有效输入，内容是否足够具体不由提交闸主观决定。

### 4.2 语义不同的文本不能盲目拼接

- 配音：朗读正文与音色、语气、语速要求分别处理。“温柔一点”作为表达要求时不得进入朗读正文。若模型没有独立表达控制能力，不得假装已经应用；提示该要求不可用，并允许用户调整。
- 音乐：歌词与风格描述由当前任务明确区分；不能将任意文本同时当作歌词和风格。
- 翻译、描述图片、转写等明确任务可使用产品公开的固定任务指令；开放问答不能偷偷补入任意任务来掩盖缺少问题。未定义固定任务的能力仍需用户提供必要要求。
- 用户已经明确指定用途时必须保留。用途不唯一、且选择会改变结果时，要求一次可理解的选择；不得根据文字内容猜测后静默赋予角色。

上述用途是产品语义，不是新增 operation 或 DTO 枚举。具体字段映射仍须服从中枢合同；无法表达时记录实现缺口，不能静默丢弃。

## 5. 媒体与任务适配

| 任务示例 | 输入用途 | 提交条件 |
| --- | --- | --- |
| 文本生成/改写 | 上游文本是任务内容；本地是内容或补充要求 | 有有效文本即可满足文本要求 |
| 图片/视频理解 | 媒体是待理解素材 | 素材有效，且有明确任务或有效问题；模型确实支持该媒体 |
| 语音转文字 | 音频是转写源 | 有效音频及必需配置齐全；任务不要求 prompt 时不得额外强制文字 |
| 文生图/文生视频 | 文本是画面或视频描述 | 上游、本地或两者形成有效描述 |
| 图生图/多图参考 | 图片分别是原图或参考图 | 必需素材齐全；prompt 是否必需由当前 operation 决定，上游文本可满足 |
| 局部重绘 | 原图、蒙版、修改要求分别绑定 | 满足各必需槽；文字不能代替蒙版或原图 |
| 首帧/首尾帧视频 | 图片分别绑定首帧、尾帧 | 所需帧齐全；prompt 可选时允许仅凭素材提交 |
| 视频编辑 | 视频是源素材，文字是编辑要求 | 满足所选任务的素材与要求，不能仅因有视频就视为齐全 |
| 配音 | 文本是朗读正文 | 正文、音色等必需配置齐全；本地正文可空而由上游提供 |
| 音乐生成 | 文本是歌词或音乐描述，音频可为参考 | 依据所选任务的用途与必需输入判断 |
| 参考声音配音/数字人 | 音频可能是声音样本或驱动音轨 | 声音样本不能替代朗读正文；人物素材和驱动输入按任务分别判断 |

矩阵不是模型支持清单，不得据此新增或启用尚未实现的能力。不得把“图生视频都必须有 prompt”或“有上游就可提交”写成全局规则。

### 5.1 顺序、角色与模型选择

- 当前模型和任务仍兼容时保持不变。必须适配时按现有模型选择策略切换当前生效模型，并显示原因；不得改写已保存的手动偏好或修改其他节点。偏好的持久化和恢复沿用现有策略。
- 两张图片不能仅按数量被静默解释为首尾帧。已选首尾帧任务可按明确显示的顺序绑定；已选参考图任务则保留参考用途。
- 同一素材占据不同合法角色时分别保留，例如同图作为首帧和尾帧。相同来源、结果和角色的重复绑定不得静默重复发送；复用已有绑定并明确反馈，不能按文件内容去重而丢掉不同角色。
- 顺序以显式输入顺序为准；旧数据没有顺序字段时使用已有稳定的连线顺序并显示。不能用节点屏幕位置、请求完成先后或对象遍历的偶然顺序改变语义。
- 超量或已知不兼容的新连接应拒绝并指出来源；不得连上后偷偷裁剪素材或借用其他渠道的限制。

## 6. 输入变化与状态反馈

| 变化 | 下游行为 |
| --- | --- |
| 修改上游正文、切换结果、重排、连接或断开 | 立即重新解析有效输入并更新模型候选、角色及提交状态；不得等待本地编辑才刷新 |
| 已连接上游为空、上传中或生成中且无可用选定输出 | 保留连线，显示来源与“等待上游内容/结果”；当前节点不可直接提交 |
| 上游重新生成，但仍有明确选中的已完成结果 | 明示使用该结果；不得自动改用半成品。用户选择的新结果未完成时，进入等待态 |
| 素材失效、读取失败 | 显示具体来源与重试/替换/移除引用路径；不将旧缓存伪装成最新结果 |
| 上游编辑使既有连接失去兼容性 | 保留用户编辑和连线，重新适配；没有兼容方案时显示配置问题，禁止提交，不静默删边 |
| 本次请求已经提交后，上游或本地变化 | 在途任务使用提交时的内容与配置快照；新输入用于下一次生成 |

必需信息尚在读取时显示等待，不提前显示“没有输入”。所有阻断原因都应指出受影响的来源/字段及修复动作；多个原因先显示最直接的必要动作，其余可展开查看。内部 `operation`、`prompt_required` 等术语不直接充当用户错误说明。

选中节点、连接有效、输入已就绪和生成中是不同状态；连线亮点或来源绿点不得被用作生成成功或提交就绪的唯一证明。

## 7. Agent 实现与验收义务

- 修改节点输入、连线、生成配置、提交或执行映射时必须先读取本合同，并在变更说明中列出受影响规则及对应验收用例。
- 复用现有共享解析/校验边界，使界面状态、点击提交时的校验和执行载荷基于相同的有效输入规则。不得为某个按钮增加 `localPrompt || hasEdge` 一类独立放行补丁。
- 点击提交时必须重新核对选定输出及配置；不能把此前渲染的可用按钮当作当前请求有效的证据。提交后固定输入快照，不能在同次请求中混用两个版本的内容或角色。
- 页面、快捷入口和 Agent 执行入口必须遵循同一输入语义。单节点提交与完整流程调度应分别验证；不能以放宽输入条件代替依赖调度。
- 验收必须同时证明应放行的请求携带全部正确内容，以及应拒绝的请求没有进入生成执行。测试应核对合成素材的文本、选择结果、角色和顺序；不得仅断言按钮可点。
- 按 [验收矩阵](../specs/2026-09-06-node-input-submission-prd.md#acceptance)和 [plugin QA](plugin-qa.md)选择实际适用检查。离线请求捕获证明输入组装，真实 ego-browser 共享探针证明产品交互；两者均不冒充真实模型生成成功。
- 未支持的任务、未实现的用例及未通过的验证必须明确记录。文档接受、代码完成、合并、Dev 物化和运行验收分别报告。

本合同不新增自动门禁、实现状态或执行权限；后续变更应将上述语义落入现有实现和有意义的回归检查，不能宣称写入文档即已受 CI 强制执行。
