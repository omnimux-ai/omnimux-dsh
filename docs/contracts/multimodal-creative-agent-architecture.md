# 多模态创意内容生产 Agent 架构与工程实践规范

> **定位**：面向全域社媒（以竖屏短视频与图文轮播为核心切入点，支持多平台平滑扩展）的现代多模态内容生产 Agent 顶层架构设计与工程方法论研究报告。  
> **核心目标**：实现“高专业度认知 + 全链路工程交付”的统一，彻底解决 Agent 凭空瞎编、长上下文漂移、多模态资产断层与跨平台扩展困难的痼疾。

---

## 1. 架构总览与设计原则

现代多模态内容创作具有**高算力成本、强依赖性、多工序协同、多模态异构**的特征。传统的“单体长 Prompt + 聊天框线性对话”在长链条生成中必然面临上下文爆炸与严重幻觉。

本架构确立以下四大顶层设计原则：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│ 1. 认知角色拓扑 (Cognitive-Role Topology)：按项目认知链条分工，非按模态切割    │
│ 2. 四层渐进知识库 (Progressive Knowledge Pyramid)：微内核+按需外挂，杜绝膨胀  │
│ 3. 画布即物理状态机 (Canvas-First State Machine)：无限画布作为唯一生产载体    │
│ 4. 创意与模型编译解耦 (Decoupled Model Compilation)：高维剧本与低维参数分层   │
└─────────────────────────────────────────────────────────────────────────────┘
```

---

## 2. 认知角色拓扑（Cognitive-Role Topology）

不同于将 Agent 简单按技术模态粗暴拆解（如“文本Agent、图片Agent、视频Agent”），工业级内容生产架构按**项目推进的认知角色**组织多 Agent 网络：

```text
                                 ┌──────────────────────┐
                                 │   Orchestrator 主理人 │ (面向用户的唯一总控)
                                 └──────────┬───────────┘
                                            │
                        ┌───────────────────┴───────────────────┐
                        ▼                                       ▼
              ┌──────────────────┐                    ┌──────────────────┐
              │  Router 路由器    │                    │  Planner 规划器  │
              │ (无状态分类裁决)  │                    │ (画布物化与计划) │
              └──────────────────┘                    └─────────┬────────┘
                                                                │ 派发单阶段
                                                                ▼
                                                      ┌──────────────────┐
                                                      │ Executor 执行器  │
                                                      │ (无状态并发生产) │
                                                      └─────────┬────────┘
                                                                │ 协同工艺
                                            ┌───────────────────┼───────────────────┐
                                            ▼                   ▼                   ▼
                                      【文案专员】          【视觉生图】         【剪辑合成】
```

### 2.1 角色职责与边界契约

| 角色 | 状态属性 | 输入 Payload | 核心职责 | 输出产物与边界 |
| :--- | :--- | :--- | :--- | :--- |
| **Orchestrator<br>(主理人/总控)** | 有状态 (会话级) | 用户原始 Prompt、上下文、参考文件指针 | • 用户意图分流 (Direct vs Canvas Workflow)；<br>• 驱动阶段状态机推进与门禁拦截；<br>• 向用户交付最终汇总成效。 | 终验报告与可点击画布资产；**严禁直接撰写大段模型参数与长提示词**。 |
| **Router<br>(场景/工作流路由器)** | **无状态 (Stateless)** | `user_intent` + `source_documents` 指针 + 工作流索引 | • 极轻量路由判定：单步直出 (`direct`)、匹配工作流模板 (`workflow`)、或信息严重缺失问询 (`ask`)。 | 极简 `routing_capsule: { route_kind, workflow_match }`；**不进行任何发散式创作与生成**。 |
| **Planner<br>(工作流拆解与规划器)** | 任务状态 (Task-bound) | 确认的意图契约、输入源、画布当前状态、工作流模板 | • 在画布上物化文档节点（制作简案、分镜数据表）；<br>• 生成 Stage Execution Plan（阶段执行计划）；<br>• 执行 **单阶段推进（One Stage at a time）** 纪律。 | `plan_id`、阶段大纲与当前阶段详情；**只规划当前阶段，绝不预先虚构后续阶段资产**。 |
| **Executor<br>(阶段执行器)** | **无状态 (Stateless)** | 单个 `stage` 载荷 (含本阶段 `work_items`) | • 单次执行单一阶段，读取当前阶段的最终 Prompt 与输入 Slot；<br>• 调取底层模型中枢 (Hub) 并发生产；<br>• 将产物挂载为画布 `media node` 并返回 `node_id`。 | 结构化 `results[]` / `failed[]`；**不跨阶段执行，不修改计划拓扑**。 |
| **Execution Guild<br>(模态工艺专家团)** | 无状态专家 | 结构化设计 Brief 与具体上下文 | • 文案、配音、视觉、视频、音乐、剪辑各司其职，提供最极致的单项工艺水准。 | 纯净的文本、音频、分镜或时间轴；**听从主理人下达的平台级约束 Brief**。 |

## 3. 四层渐进式知识金字塔（The Progressive Knowledge Pyramid）

彻底放弃将所有平台知识、工具清单、模型参数塞进单一 System Prompt 的粗放做法，采用**分层物理隔离与按需渐进式加载**：

```text
┌────────────────────────────────────────────────────────────────────────┐
│ Layer 1: Core Persona (角色微内核, ≤ 80 行)                            │
│ 纯粹的身份定义、主权定位、双轨分流准则、权限与安全防线。                   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 启动期 / 部署时静态缝合
┌───────────────────────────────────▼────────────────────────────────────┐
│ Layer 2: Living Contracts (常驻行为契约, 单个 ≤ 100 行)                 │
│ 跨 Agent 共享的硬性行为守则：                                           │
│ • content-discipline.md: 界面安全区、时长规范、合规防线                 │
│ • canvas-discipline.md: 画布物理节点唯一性、不造假、原子回写            │
│ • semantic-judgment.md: 参考素材输入角色与 take/adapt/ignore 决策律    │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 运行时能力字典驱动 (On-Demand)
┌───────────────────────────────────▼────────────────────────────────────┐
│ Layer 3: Micro Knowledge Cards (微型专业知识卡片, 单个 ≤ 50 行)         │
│ • 平台业务卡 (Playbooks): 各平台 (TikTok / Instagram / Shorts) 算法与节拍 │
│ • 模型编译卡 (Vendors): 各多模态模型专用 Prompt 语法与运镜规范            │
│ • 失败规避卡 (Failures): ≤ 25 行，针对常见多模态生成的决策避坑测试       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 业务模板选择
┌───────────────────────────────────▼────────────────────────────────────┐
│ Layer 4: Workflow DAG Topologies (项目拓扑模板库)                       │
│ 预定义的工业级生产流水线 (爆款短视频复刻模板、图文轮播模板、TVC 广告模板)│
└────────────────────────────────────────────────────────────────────────┘
```

### 3.1 核心调用机制：能力清单指针驱动（Capability Manifest Drive）
Agent 不预先记忆全网模型的使用说明，而是在运行时通过中枢 API 动态获取：
1. Agent 请求生成能力清单：`caps = await list_capabilities({ modality: "video" })`；
2. 返回的数据中包含该模型专属的知识卡片相对路径：`knowledge_card: "knowledge/vendors/model-a.md"`；
3. **知识门禁（Knowledge Gate）**：仅在真正选定该模型时，Agent 才会临时单次读取这篇 50 行的卡片，将其中的编译规则（如景别要求、运镜指令）编译进 Prompt，**执行完毕立即丢弃，绝不污染全局对话上下文**。

## 4. 画布即物理状态机（Canvas-First State Machine）

在长链条多模态创作中，**聊天框仅作为用户沟通通知与输入界面，无限工作流画布（DAG Canvas）才是唯一的物理生产载体与协同白板**。

### 4.1 画布三大物理纪律（Canvas Discipline）
1. **原子生成即节点（Auto-Node Invariant）**：底层模型生成的一切图像、视频、音频文件，落盘后自动注册为画布上的 Material Node，拥有唯一的 `node_id`，杜绝重复创建与假节点。
2. **文本与分镜局部增量编辑（Hunk Edit）**：剧本、分镜等表格数据（`.htable`）在微调时，采用局部 patch 机制，禁止频繁全量重建覆盖，避免破坏版本哈希与人工标注信息。
3. **当前轮次自动栅格化成组（Auto-Grouping & Layout）**：当同一阶段产出多个并生成果（如 4 个候选分镜图、6 张轮播卡片）时，系统自动调用栅格化布局工具将其打包进同一个 Group 容器中，保证画布整洁度。

## 5. 爆款参考复刻：多模态摄取与语义判断契约（Semantic Judgment）

用户提供参考视频/图文时，Agent 严禁直接根据文件路径“凭空脑补”。必须经过**语义角色映射**与**决策矩阵处理**：

### 5.1 输入角色映射（Input Roles）
任何传入系统的素材，必须首先赋予明确的贡献角色：
- `source/edit`：提供时间线节奏、镜头切点、前后动作承接；
- `layout`：提供画面主体数量、空间几何关系、前后景排布；
- `style/design`：提供色调氛围、光影质感、运镜动势；
- `character/scene`：提供实体身份与场景连续性；
- `mood`：提供情绪张力与音乐节奏。

### 5.2 决策矩阵（Decision Matrix）
面对参考素材，必须执行严格的五维决策，严禁眉毛胡子一把抓：
- **`take`（保留/继承）**：原片中最核心的**爆款骨架**——前 3 秒 Hook 结构、核心冲突推进节奏、关键转折点、转场卡点；
- **`adapt`（迁移/适配）**：将原片中的通用卖点演示与场景，精准替换为用户当前目标商品/主题的真实参数；
- **`ignore`（忽略/剥离）**：坚决剔除原作者个人标签、背景噪音、原有品牌水印及无关道具；
- **`block`（阻断）**：拦截侵权、违规诱导、夸大虚假宣传元素；
- **`ask`（问询）**：仅在核心诉求产生不可推断的歧义（如“目标人群定位不明确”）时发起最小化确认。

## 6. 分镜创意与底层模型编译器解耦（Decoupled Model Compilation）

严禁让业务创意层（如文案专家）直接手写生涩的底层模型代码与生图/生视参数。采用**两层编译解耦**：

```text
【业务创意层 (人类可读分镜)】
镜头 1: 【0-3s】特写，主播拿起产品猛烈摇晃后拧开，冒出大量冷雾，台词：“别再买放两小时就变温的杯子了！”
                       │
                       ▼ 自动经由 Model Prompt Compiler (模型编译器)
【底层执行层 (符合物理模型规律)】
全局基准: [8K, Photorealistic, Cinematic Lighting, 9:16 Vertical Safe Area]
【镜头1】: [Extreme Close-up][Push in] 主播快速摇晃保温杯(初始) ➔ 拧开杯盖冷雾喷涌(刺激) ➔ 眼神坚毅吐出台词(反应与动作收束)
参数绑定: @图片1(产品主图) 映射至 slot:reference_images; aspect_ratio: "9:16"; resolution: "2K"
```

### 6.1 编译器的核心工业法则
1. **景别跨越法则（The Contrast Law）**：同一主体连续出现在相邻镜头时，相邻镜头必须至少跨越一个景别（如全景切近景）；视角观察角度变化必须保持在 **30° 至 90° 之间**，防止 AI 视频产生画面抽搐与空间断裂。
2. **微叙事四段式（Micro-Narrative）**：动作提示词不写单纯结果，统一编译为 `初始状态 ➔ 环境/事件刺激 ➔ 可见反应与情绪变化 ➔ 动作完成与收束`。
3. **界面安全区避让（Safe Area Invariant）**：针对社媒平台（TikTok/Reels/Shorts），画面核心主体与动态字幕必须编译在居中偏上安全视窗内，杜绝被平台右侧互动条与底部文案遮挡。

## 7. 跨平台扩展性设计（Multi-Platform Extension）

本架构虽然首发切入 **短视频** 与 **图文轮播** 两种主力形态，但整个脚手架具备向全社媒平台的平滑扩展能力：

```text
                       多模态创意内容生产架构
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
【短视频矩阵平台】         【图文轮播与图文笔记】     【中长视频与横屏影视】
• TikTok 短视频            • TikTok Photo Carousel  • YouTube 长视频/专题片
• Instagram Reels        • Instagram 轮播帖       • 商业 TVC / 品牌大片
• YouTube Shorts         • 小红书 图文笔记        • 微短剧 / 漫剧系列
• 微信视频号 / 抖音      • 电商 6-Funnel 详情页   • 播客可视化视频
```

### 7.1 扩展新平台只需新增两张卡片（零脚手架改动）：
1. **平台规则卡（`knowledge/platforms/<platform-name>.md`）**：定义该平台的安全区边距、推荐时长、算法留存偏好（如 TikTok 强调完播率与 3s Hook，小红书强调封面点击率与收藏深度）；
2. **发布契约卡（`contracts/publish-<platform-name>.md`）**：对接该平台的发布 API 字段与账号鉴权规则。  
底层的多模态拆解、DAG 画布编排、模型编译和剪辑工坊**完全复用，零代码重构**。

## 8. 实施落地四阶段计划（Four-Phase Roadmap）

```text
P0: 架构脚手架与契约抽象 (规范化)
 └── P1: 画布模板引擎与自动分组 (可视化生产)
      └── P2: 多模态事实输入与拆解表直通 (根治瞎编)
           └── P3: 模型编译中间件与全自动门禁 (工业级闭环)
```

### 阶段一：P0 架构脚手架与契约规范沉淀（第 1~2 周）
- **目标**：完成四层知识金字塔解耦，瘦身主 Agent Persona，建立独立的常驻契约。
- **交付物**：
  1. `contracts/content-discipline.md`：界面安全区、时长规范与合规防线；
  2. `contracts/semantic-judgment.md`：爆款参考 take/adapt/ignore 决策规范；
  3. `knowledge/platforms/tiktok-playbook.md`：短视频 3s Hook 与图文轮播规范卡；
  4. `knowledge/vendors/model-rules.md`：主流生成模型的提示词编译规则卡。

### 阶段二：P1 画布标准模板引擎与自动分组（第 3~4 周）
- **目标**：在 `omnimux-workflow` 中内置标准业务 DAG 模板，实现一键建工程与画布自动规整。
- **交付物**：
  1. 内置两套官方 DAG 模板：`TikTok 爆款短视频复刻工作流`、`TikTok 高转化图文轮播工作流`；
  2. 接入 `hub_canvas_group_recent_outputs` 自动网格排列，产物自动成组入框；
  3. 支持 Agent 一键根据模板参数完成节点拓扑实例化。

### 阶段三：P2 多模态事实输入与表格节点直通（第 5~6 周）
- **目标**：切断未分析直接生成的旁路，打通“多模态视频拆解 ➔ 数据表节点 ➔ 卖点改写”的硬闭环。
- **交付物**：
  1. 视频素材拖入后，自动调用 `video_analyze` 提取逐镜头关键帧与时间戳；
  2. 自动生成标准 `HTableDocument` 节点（`.htable`）放置在画布中；
  3. 文案专家强制消费数据表，执行结构化改写并产出分镜表节点。

### 阶段四：P3 模型编译中间件与阶段门禁闭环（第 7~8 周）
- **目标**：完成“创意分镜 ➔ 底层模型编译”解耦，建立人机协同门禁。
- **交付物**：
  1. 模型指令编译器（Model Prompt Compiler）：自动注入景别跨度、视角防抽搐及安全区约束；
  2. 画布阶段门禁（Review Gate）：分镜就绪后自动挂起等待确认，确认后触发 `workflow_run` 批量并发；
  3. 最终产物自动调用 `clip_export` 渲染合成，并直通 `publish_create_draft`。

## 9. 验收标准与健康度指标

1. **解耦度指标**：主 Agent Persona 保持在 80 行以内，修改单一平台策略无需变更底层模型或画布代码。
2. **保真度指标**：用户提供爆款视频时，复刻产物的前 3 秒 Hook 结构、转折节奏与原片特征重合度 ≥ 85%，商品卖点替换准确率 100%。
3. **工程合规性**：全量多模态资产 100% 具备确定性物理路径与画布 `node_id`，杜绝孤立文本应付与虚假生成。
