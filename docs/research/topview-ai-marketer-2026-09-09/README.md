# Topview AI Marketer：业务入口、预填提示词与 OmniMux 新会话方案

研究日期：2026-09-09。对象：[Topview AI Marketer](https://www.topview.ai/ai-marketer)。用途：产品决策与后续实现输入。研究结论已进入 [Issue #844](https://github.com/omnimux-ai/omnimux-dsh/issues/844) 的实施：3 组 6 张卡片、可编辑草稿和可见 URL 同步。以下竞品观察保留研究时点；实现交付与运行验收另行记录。

## 1. 决策结论

值得借鉴的是「业务结果卡片 → 可编辑任务草稿 → 按任务补充材料 → 用户发送」这条路径。它让用户先认出自己要完成的业务，再学会如何描述任务。卡片的价值不止是少打字，还在于把输入条件、分析维度和交付标准一起展示出来。

Topview 实际采用两套入口：顶部 4 组 10 个小按钮负责预填；下方大卡片承担更具体的配置流程。两者不能视为同一种交互。尤其 Marketing Insight 大卡片在本次操作中触发了任务执行，随后被免费套餐 MCP 权限拦截。

OmniMux 建议先做围绕 TikTok 视频复刻的 3 组 6 张卡片，保留现有输入框和发送路径。优先解决「我不知道该问什么」，再用紧邻草稿的资料输入解决「我不知道要提供什么」。不建议照搬泛电商选品、Listing 优化和广告账户分析的完整目录。

## 3. 首页信息架构

从上到下是品牌承诺、通用任务输入框、业务分类快捷入口、Popular Ways to Get Started、可复刻热门视频、Creative Gallery，以及产品说明。侧栏另有 New Task、Assets、Experts Market、Skills 和 Codex Plugin。

用户截图中的「分类」是并列分组标题，并非必须先点击的分类页。每组直接展示动作按钮，用户一次点击就到草稿状态。

| 分类 | 按钮 | 提示词要求的上下文 | 预期业务输出 | 点击后新增组件 |
| --- | --- | --- | --- | --- |
| Market Insights / 市场洞察 | Category Opportunity / 品类机会 | 品类、平台、市场 | 需求、竞争、定价、门槛和入场建议 | 无 |
| 同上 | Trending Products / 热门产品 | 品类、平台、市场、经营约束 | 推荐产品及需求、季节性、风险依据 | 无 |
| 同上 | Competitor Scan / 竞品扫描 | 关键词或品类、平台、市场 | 排名靠前的商品定位、价格、评论、转化策略比较 | 无 |
| Listing & Reviews / 商品页与评论 | Title Optimization / 标题优化 | 现有标题、平台、商品信息或关键词 | 建议标题与理由 | 无 |
| 同上 | Review Insights / 评论洞察 | 商品、市场、评论来源或导出数据 | 投诉、未满足需求、购买动机、措辞和机会 | Product URL |
| Content & Creators / 内容与创作者 | UGC Brief / UGC 创作简报 | 商品、平台、市场、人群、目标、约束 | 信息要点、拍摄指引、必拍镜头、交付标准 | 无 |
| 同上 | Video Scripts / 视频脚本 | 商品、平台、人群、优惠、语气 | 10 条包含钩子、场景、演示、证明、CTA 的脚本 | 无 |
| 同上 | Recreate Viral Ads / 爆款广告复刻 | 视频与参考材料；文案提到 clone mode | 按选定模式复刻 | Video URL |
| Ad Analytics / 广告分析 | Search Terms / 搜索词分析 | 报表、平台、日期、归因、目标指标 | 高效查询、浪费支出、否词、竞价与预算建议 | 无专属组件 |

这里的「无」指没有新增的专属输入；通用附件和专家入口仍存在。商品标题优化没有自动出现 Product URL，不应按业务直觉替它补齐。

## 4. 预填交互与组件机制

### 4.1 顶部按钮

逐项点击后 URL 保持首页，textarea 的实际 value 发生变化，文本可编辑；再次选择其他按钮会替换前一模板。页面同时保留发送按钮。采集期间这 10 个按钮未产生聊天消息。

方括号内容是普通文本占位符，例如 `[target market]`。现场没有看到这些文字变成独立下拉菜单或表单字段。因此它属于「提供写法的草稿」，不能直接称作自动填参表单。

通用结构可以归纳为：任务动词 + 业务对象 + 场景条件 + 工作维度 + 交付要求 + 信息不足时追问。其中品类、评论、广告分析还主动要求区分事实、推断和假设。这是提示词承担教育功能的主要方式。

### 4.2 URL 行

评论洞察在正文上方增加 Product URL，placeholder 为 `Enter or paste a product page URL...`；顶部广告复刻增加 Video URL，placeholder 为 `Enter or paste a video URL...`。两者与正文是独立控件，旁边有 Clear URL 按钮。

实际 DOM 均为 `type=text` 且没有 HTML required 属性。这只能说明没有原生 required 标记，不能推断提交时 URL 可省略。URL 如何被序列化、抓取、校验、失败后恢复，本次没有提交验证。

正文还有 Clear message。清空与草稿替换的完整边界、用户编辑后是否有覆盖提示，仍需专门回归；不把图标存在等同于所有清空语义已验证。

### 4.3 附件与报表

通用附件按钮的可访问名称为 Attach image，但 file input 的 accept 声明覆盖图片、视频、音频、PDF、TXT、MD、CSV、JSON、YAML、DOCX、PPTX、XLSX。说明通用附件入口比名称更宽，命名存在误导可能。

Search Terms 没有自动弹出报表上传框。ROAS 草稿第一行提醒上传 CSV/XLSX，也没有自动打开文件选择器。应区分「提示词索要资料」和「前端真的创建专属组件」。本次未上传文件，不评价报表解析能力。

### 4.4 专家与模型

输入工具栏一直保留 Activate expert 和模型选择器。顶部卡片切换过程中工具栏仍显示相同模型，也没有显式弹出专家选择。因此没有证据说每张卡片都绑定独立专家、Skill 或模型。后端路由是否基于内容自动选择，属于未验证项。

## 5. 下方大卡片：从提示词教育到生产配置

| 大卡片 | 实际观察 | 提交边界 |
| --- | --- | --- |
| Marketing Insight | 操作后进入 Marketing Expert 会话，提交内容为品类机会模板 | 已触发一次任务，随后 MCP 权限拦截；没有完成研究 |
| URL to Video | 打开示例 + 参数表单 | Start creating 未点击 |
| Recreate Viral Ads | 打开双模式复刻表单 | Start creating 未点击 |
| Bulk Create Ads | 打开批量创意表单 | Generate creative plans 未点击 |

### URL to Video

弹窗展示 3 个示例、前后切换，再依次收集商品 URL、目标受众、核心卖点、视觉风格、时长、画幅。风格包括 Clean studio、Cinematic luxury、Minimalist premium、Natural lifestyle、Bold & colorful、Futuristic tech、UGC style、Unboxing、Street style。时长支持 Auto，显示范围 4–180 秒；画幅提供 21:9、16:9、4:3、1:1、3:4、9:16。另有浏览器扩展链接，用于采集商品页面资料。

此处已经是专用工作流配置，而不是把长 prompt 简单放进输入框。表单最终如何转成提示词或工具参数未验证。证据：[表单文字](url-to-video.txt)。

### Recreate Viral Ads

两种模式分别为 Recreate structure（保留镜头、节奏、结构，创作新内容）与 Replace elements（替换人物或商品，其余保持）。表单要求上传目标视频，标明 MP4、最大 50 MB、2–60 秒；另有「新视频展示什么」文字输入和最多 6 个可选参考文件。

切换 Replace elements 后，没有观察到额外独立人物/商品槽位，基本字段保持不变。顶部同名小按钮只显示 Video URL 和一句简短草稿，未显示模式选择。这是同名入口的真实差异，不应将大卡片能力直接归给顶部按钮。证据：[初始表单](recreate-viral-ads.txt)、[切换模式](recreate-replace-elements.txt)。

### Bulk Create Ads

创意简报要求描述商品、钩子、利益点和 CTA；支持最多 6 个可选参考文件；画幅为 16:9、4:3、1:1、3:4、9:16；时长显示默认 15 秒，范围 4–30 秒；数量默认 4，范围 1–10。按钮写的是 Generate creative plans，不能直接宣称点击即交付批量视频。证据：[表单文字](bulk-create-ads.txt)。

## 6. 为什么它能教育用户

| 设计选择 | 用户学到什么 | 我们应如何吸收 |
| --- | --- | --- |
| 用业务动作命名 | 可以让 Agent 完成哪些工作 | 写「拆解爆款」「改成我的商品」，避免暴露工具名 |
| 点击即可看完整草稿 | 好需求应包含哪些条件 | 正文写清目标、关键输入和具体交付物 |
| 缺什么资料就展示什么入口 | 要交给 Agent 什么材料 | 视频任务展示视频资料，商品替换展示商品素材 |
| 默认允许编辑 | 模板是起点，可以表达自己的改写意图 | 保留自由输入和用户原有文字 |
| 示例与配置并列 | 产出大致长什么样、哪些参数可控制 | 后续在复杂复刻表单中再加入示例 |
| 要求证据和追问 | Agent 不应凭空补业务背景 | 未知条件明示，缺关键材料先问 |

目前只能论证设计机制，不能声称提高了转化率。需要真实新用户任务测试，验证他们是否理解输入要求、能否独立发出有效任务，以及是否拿到可用产物。

需要规避的缺点：方括号太多容易让草稿像作业；顶部复刻文案提及未显示的模式；附件命名与支持格式不一致；大、小卡片的执行语义不统一；免费权限限制在任务触发后才暴露。

## 7. OmniMux 当前新会话流程

源码可以确认以下链路，Dev 现场尚受认证阻断：

1. 侧栏新会话由官方生命周期创建或复用空白会话，OmniMux 负责在进入会话时退出产品页、恢复隐藏的对话栏。参见 [conversation-box.js](../../../plugins/omnimux/src/client/conversation-box.js)。
2. 空白会话 Hero 使用官方品牌槽位；当前布局将 Logo/标语放在剩余空间中部、输入框靠下。参见 [hero-brand.js](../../../plugins/omnimux/src/client/hero-brand.js) 和 [composer-compact.js](../../../plugins/omnimux/src/client/composer-compact.js)。Topview 输入框与分类相邻的布局不能直接套进当前底部输入框而不重新处理空间。
3. 灵感库已有「复刻到新会话」：发起一次官方新会话操作 → 取得目标 sessionId → 展开对话 → 关联素材 → 填入草稿。参见 [replicate-to-chat.js](../../../plugins/omnimux-inspiration/src/client/replicate-to-chat.js)。
4. 预填消费者挂在 `conversation.input.dock`，读取该会话的 draft，使用 `inputActions.setDraft` 写入。只有目标 sessionId 匹配才消费，并保护非空草稿；附件失败时不写入模板。参见 [index.js](../../../plugins/omnimux-inspiration/src/client/index.js)、[session-prefill.js](../../../plugins/omnimux-inspiration/src/client/session-prefill.js)。
5. 该预填模块的注释明确说明，Hero 分支没有 `conversation.composer.dock`，应使用首条消息之前也存在的 `conversation.input.dock`。实际运行时槽位及传入属性仍须在 L2 核验。
6. Skill 工坊还有基于新会话和 DOM 的预填实现，参见 [session-create.js](../../../plugins/omnimux-market/src/client/session-create.js)。新入口应优先使用官方输入动作，而不是复制通用 DOM 搜索编辑器的实现。

现有灵感预填是领域私有实现，Hub 不能直接 import 它。新会话卡片由 Hub 持有 UI，在当前官方槽位直接使用 inputActions；只有确有跨入口复用需求时，才建立最小的公开 Hub seam。不为此创建第二输入框、第二会话系统或跨域私有依赖。

浏览器访问 `http://localhost:45120` 返回 `dsh web authentication required`。没有借助其他浏览器或绕过认证；也没有把源码判断当成 Dev 验收。后续现场核验需要当前 Desktop 提供的正式浏览器访问入口，按 [plugin QA](../../contracts/plugin-qa.md) 恢复认证。

## 8. 建议落地：3 组 6 卡片

下面是建议模板，不是 Topview 原文，也不是已上线能力。所有任务围绕已选参考视频的发现、拆解、复刻与交付；没有依据时不声称素材是真实爆款。

| 分组 | 卡片 | 用户获得什么 | 按需输入 |
| --- | --- | --- | --- |
| 找参考 | 挑选适合我的参考 | 给定候选中的适配排序 | 候选视频、商品资料、目标市场 |
| 拆解思路 | 拆解参考视频 | 结构、钩子、节奏、镜头表 | 视频 URL / 素材库视频 / 上传视频 |
| 拆解思路 | 改写成我的卖点 | 3 种开头及镜头脚本 | 参考视频、商品资料、受众 |
| 制作视频 | 复刻视频结构 | 围绕自己商品的新视频 | 参考视频、商品素材、改写意图 |
| 制作视频 | 替换人物或商品 | 保留指定内容的替换版本 | 原视频、替换素材、保留与替换要求 |
| 制作视频 | 做 3 个开头版本 | 同一视频的钩子变体 | 已有视频、卖点、目标受众 |

「挑选参考」先使用用户给定候选或现有素材来源，不承诺新的全平台实时爬取。后三项只有现有生产链路验证可执行后才以可用状态展示；未就绪时不靠模板掩盖缺失能力。

### 可直接评审的中文草稿

**挑选适合我的参考**

> 请从我提供的候选视频中，挑选适合【商品】面向【目标市场与人群】在 TikTok 使用的参考。比较开头吸引力、商品演示、制作难度和可迁移的表达，给出排序及理由。把实际观察与效果猜测分开；没有播放或成交证据时，不把它认定为爆款。缺少商品信息时先问我。

**拆解参考视频**

> 请拆解这条参考视频，按时间段说明开头钩子、用户痛点、商品演示、信任建立和行动引导，输出镜头、画面、台词和节奏表。指出哪些表达适合迁移到我的商品，哪些依赖原人物或场景。无法读取视频时请明确告诉我需要补什么材料。

**改写成我的卖点**

> 请参考这条视频的结构，为【商品】面向【目标人群】改写一份 TikTok 视频脚本。重点突出【卖点】，给出 3 个不同开头和一份完整镜头脚本，标明画面、口播、字幕及所需素材。不要编造功效、评价或使用经历；缺少关键资料先问我。

**复刻视频结构**

> 请参考这条视频的镜头顺序和节奏，用我提供的商品素材制作新视频。我的改写要求是【改写意图】。保留有效的表达结构，调整不适合我的商品的部分；默认输出 TikTok 竖屏版本。缺少必需素材先问我，完成后提供可播放、可导出的成片。

**替换人物或商品**

> 请将参考视频中的【需要替换的对象】替换为我提供的素材，保留【需要保留的内容】。先说明当前工具能实现的替换范围，再按我的要求制作；无法保持一致的地方明确标注。完成后提供可播放、可导出的版本。

**做 3 个开头版本**

> 请基于这条已有视频，为【目标人群】制作 3 个不同开头，分别突出痛点、商品演示和使用场景。其余主体内容尽量保持一致，并说明每个版本要验证的创意假设。仅使用有依据的卖点，输出可播放、可导出的版本。

### 交互细则

空白会话显示分组和卡片，卡片与现有输入框保持视觉邻近；窄对话栏改为两列或纵向分组，不横向挤压成十个小图标。点击后立即出现可编辑草稿、聚焦输入，并在旁边显示当前任务需要的资料入口。发送后隐藏首次引导，保留正常会话体验。

第一版让「视频资料」接受 URL 或现有素材选择；「商品素材」复用现有附件能力。明确选一个主参考视频。URL 和附件必须按 sessionId 保存；切换任务时保留相容素材，不静默清除用户上传文件。

没有用户编辑过的模板可以直接换卡替换；已有用户修改时提供行内「替换草稿 / 保留当前」选择。取消不得丢失内容。首次 Hero 尚无有效 sessionId 时，必须先走官方生命周期，不能将请求写进 default 或另一个保留的编辑器。

资料字段必须真实进入最终请求或现有附件协议。不要只在 UI 上画一个 URL 标签；也不要仅通过不可见状态给模型添加用户未见过的目标。卡片点击本身不调用生成、不自动发送、不切换模型或专家。

## 9. 实现与验收次序

第一步先完成现有空白会话的现场核验，确认 Hero、输入 dock、draft、会话切换和附件协议。第二步实现 3 组卡片、官方 setDraft、草稿保护与视频/商品资料输入。复杂生产参数弹窗放在后续确有必要的任务里。

| 验收案例 | 必须看到的结果 |
| --- | --- |
| 新建或复用空白会话 | 卡片正常出现，不重复创建会话 |
| 点卡片 | 草稿准确预填，没有发送请求 |
| 编辑后再点另一卡 | 用户修改不被静默覆盖 |
| A 会话点卡后切 B | 草稿和附件不串会话 |
| 有 URL 或附件再发送 | 请求中真实包含正确资料，且无重复注入 |
| 无资料、附件失败、URL 不可读 | 可理解的补充或重试路径，草稿不丢失 |
| 360 / 460 / 560 像素宽度 | 卡片可读、发送按钮可用，无遮挡 |
| 首条消息发送后 | 引导退出，官方会话功能正常 |
| 业务闭环 | 选参考 → 拆解 → 按用户意图复刻 → 可播放可导出 |

实现时先在隔离 worktree 执行相关自动化/静态检查与独立评审，经 required CI/MQ 合入后才物化 Dev，在 45120 使用 ego-browser 与共享 verify:live 验收；不建立合入前独立运行环境。本次是研究，未运行产品测试，不产生 UI 已验收声明。产品代码、PR、Dev 物化、业务产出四个状态仍分别核对。

教育效果可通过一组首次使用者的小任务观察：是否能不用额外解释选对卡片、补齐材料、描述改写意图并发出有效任务。记录失败原因和完成时间，用于改文案；不把点击量当作业务完成，也不为此扩建独立运营分析系统。
