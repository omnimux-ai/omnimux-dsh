## 1. 业务背景与产品定位

### 1.1 现状与痛点
1. **分散鉴权体验割裂**：目前 OmniMux 各垂直插件（如 `omnimux-accounts`、`omnimux-workflow` 等）对登录状态的检查缺乏统一的拦截视效与交互规范，部分场景出现未登录点击白屏、控制台抛错或弱提示。
2. **意图丢失（Context Drop）**：用户在未登录状态下点击某个具体业务插件（例如想打开「剪辑工坊」处理视频），跳往个人中心登录后，无法自动恢复并打开刚才被拦截的目标功能。
3. **品牌认知与转化不足**：缺乏高辨识度、有商业价值感的登录引导弹窗，难以向用户有效传达 OmniMux「商业出海与出片」的全链路价值（灵感 → 资产 → 画布 → 剪辑 → 多账号矩阵分发）。

### 1.2 产品定位与核心价值
- **统一中枢门禁（Hub-owned Gate）**：登录状态与授权弹窗作为 OmniMux 执行中枢（`plugins/omnimux`）的核心基础设施，由中枢统一提供 `window.__omnimuxAuth.ensureLogin()` Seam，垂直插件无需重复开发登录 UI。
- **免除冷启动门禁（No Cold-Start Block）**：保留用户「未登录可进 App、可逛货架与基础浏览」的低门槛体验；但在**点击/进入任意具体 OmniMux 插件功能**时，触发统一弹窗拦截。
- **意图无缝恢复（Resume-After-Login）**：登录成功后，系统自动清空阻断、拉起并打开用户最初点击的插件页面或重试中断动作。
- **商业出海与出片（Locked Positioning）**：弹窗不是「通用 AI 工具登录页」，而是把 OmniMux 定位为**商业内容出海的多模态 Agent 矩阵**——理解拆解多平台生产任务、用工作流画布与 Skill 十倍出片、从一条灵感陪用户全链路落地。

## 3. 用户故事与典型场景

### 场景 1：未登录点击侧边栏一级 Stage 插件（主路径）
- **As a** 首次打开或未登录 OmniMux 桌面端的创作者 / 出海运营；
- **When** 在左侧侧边栏点击「工作流画布」或「剪辑工坊」；
- **Then** 系统不直接进入空白或报错页，而是立即平滑弹出「OmniMux 全面接入商业 Agent 矩阵」高保真弹窗，背景高斯模糊；
- **And** 用户点击「立即登录」完成设备码授权后，弹窗自动关闭，并自动切换并打开刚才点击的插件页面。

### 场景 2：浏览过程中登录态过期 / Token 失效
- **As a** 正在使用灵感库或产品库的用户；
- **When** 后端接口返回 401 `needs-omnimux` 认证失效时；
- **Then** 前端 API 封装层自动捕获，静默挂起当前重试请求，唤起通用授权弹窗；
- **And** 用户重新授权成功后，自动重发该请求，无需用户手动刷新页面。

### 场景 3：用户主动取消 / 关闭弹窗
- **As a** 仅想随意看看界面的游客用户；
- **When** 弹窗弹出后点击右上角「✕」或遮罩空白处或按 `ESC` 键；
- **Then** 弹窗顺滑收起，用户停留在当前主界面，系统清空挂起的待恢复意图队列，并给出轻量 Toast 提示。

## 5. 核心交互流程与状态机

### 5.1 交互时序图
```
[ 用户点击任意插件 ]
        │
        ▼
[ 触发 window.__omnimuxAuth.ensureLogin({ reason, onSuccess }) ]
        │
   [ 是否已登录? ]
     ├── 是 ──> 直接执行 onSuccess() (无弹窗，零感知进入)
     └── 否 ──> 挂起 intent，将弹窗状态置为 starting -> waiting
                  │
                  ▼
          [ 居中弹出 1:1 授权弹窗 (高斯模糊蒙层) ]
                  │
          [ 用户点击「立即登录」]
                  │
                  ▼
          [ 调用 Host 设备码登录流程 (获取 verification_url + user_code) ]
                  │
          [ 唤起系统默认浏览器打开授权页，弹窗切换为「轮询中态」]
                  │
         [ 轮询检测是否授权成功? ]
           ├── 成功 ──> 写入本地 Token -> 触发 resolveAll() -> 关闭弹窗 -> 自动恢复执行 onSuccess() (打开目标 Stage)
           └── 取消/超时 ──> 用户点击 ✕ 关闭 -> 触发 rejectAll() -> 关闭弹窗 -> 停留当前页
```

### 5.2 状态机定义
- `closed`：门禁关闭状态（默认）。
- `checking`：正在静默检查本地鉴权缓存。
- `starting`：用户点击登录，正在请求设备码与授权 URL。
- `waiting`：已获取设备码，正在前台展示并在后台轮询 Auth 状态。
- `authorized`：授权完成，分发 profile，执行意图恢复。
- `error` / `expired`：授权超时或网络异常，提供重试按钮。

## 6. Seam 跨插件接口契约

由 `plugins/omnimux` 执行中枢在客户端全局 `window` 下挂载单例对象。详细架构见 `docs/specs/2026-08-20-omnimux-login-gate.md`。本 PRD 只冻结产品面必须遵守的接口：

```typescript
interface OmnimuxAuthGate {
  /** 获取当前登录态（verify=false 时仅读内存/本地缓存） */
  getStatus(verify?: boolean): Promise<{ logged_in: boolean; profile?: any }>;

  /**
   * 核心登录守卫：未登录时弹窗并排队 intent，登录成功后自动执行 onSuccess
   */
  ensureLogin(options: {
    reason?: string;             // 触发来源，如 "sidebar:omnimux-workflow"
    onSuccess?: (profile: any) => void; // 登录成功后恢复执行的回调
    onCancel?: () => void;       // 用户主动关闭/放弃的回调
  }): void;

  /** 关闭弹窗并放弃所有挂起意图 */
  cancel(): void;

  /** 订阅门禁状态变更 (用于 React useSyncExternalStore 驱动 UI 渲染) */
  subscribe(listener: () => void): () => void;

  /** 获取门禁快照数据 */
  getSnapshot(): AuthGateState;
}
```

硬约束（与 AGENTS.md 对齐）：
- 登录/身份属 OmniMux 核心，全部改动落在 `plugins/omnimux`；垂直包只消费 seam，不实现登录 UI。
- 跨 bundle 不得 `import` hub client；垂直包通过 `window.__omnimuxAuth` 懒读取。
- 不做启动门禁；检测按需（点击时），不每次联网强制 verify。
- Agent 工具返回 `needs-omnimux` **不自动弹窗**，保持结构化错误（遵守 `docs/decisions/2026-08-14-execution-hub.md`）。

## 7. 异常边界与非功能性要求

1. **防抖与重复点击拦截（Debounce & Concurrency）**：
   - 当门禁已处于打开状态时，用户重复点击其它插件不会重复打开多个弹窗，而是将新的 `onSuccess` 追加到意图队列中（单门单例保证）。
2. **多端/多 Tab 状态同步**：
   - 授权成功后，通过 `window.postMessage` 或 Storage 事件广播登录态，刷新所有已挂载的 OmniMux Stage 组件。
3. **网络超时与断网降级**：
   - 设备码轮询默认最长持续 5 分钟，超时后展示「授权已过期，点击重新获取」，不发生前端崩溃。
4. **轻量与性能**：
   - 弹窗采用 `React Portal` 挂载至 `document.body`，未激活状态下 DOM 节点返回 `null`，零内存开销。
5. **视觉 Token**：
   - 生产组件 100% 消费 `--dsw-alias-*` / `--dsw-specific-*`；原型 hex 仅作视觉对照，不得直接进生产。
