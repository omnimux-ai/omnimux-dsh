# Composer 与文件选择能力的集成验收

状态：历史集成方案。当前原生菜单需求由 [#676 单击添加规格](2026-09-06-composer-single-click.md) 定义；本文保留 #554 当时的决策与证据，不作为当前入口实现要求。日期：2026-09-06。

## 目标与授权

用户确认先证明一次无需人工处理系统窗口的真实文件选择流程，再整合文件管理任务与 #554，统一验收后合并、物化 Dev。文件内容、目录结构、附件及资产引用必须保持原有语义。没有生产发布授权。

## 基线与职责

- #554 产品 PR #558：`b23d7ea62a283a1b446449b4ebd48b69185049f3`；桌面 PR #37：`da003bd1df28f7de42441953d2023d23edc3fd4c`。
- 文件管理任务：`agent/common-file-selection-reuse`，基线 `4092a8f195b145bd3f59ff7a79169788a24f020e`；改动尚未提交，不能将工作目录视为冻结交付。
- 文件管理任务准备选择、传输和领域接入能力；#554 负责最终集成、验收、PR 合并与 Dev 物化。各任务仅修改自己的工作树，不单独更新共享 Dev。

## 已确认的选择入口

`添加文件或文件夹` 通过 clientAction 直接打开页内本地路径面板，每行一个运行 OmniMux 的电脑上的绝对路径，支持文件和目录同时导入。复用现有 materialize 接口及领域校验，不启动系统窗口；部分失败保留失败路径供修正，成功项不重复提交。该入口替代此前要求的原生系统面板交互，保留其他 #554 行为约束。

## 执行顺序

1. 暂停会触发系统文件窗口的测试。先核对工具支持的操作和正常产品入口；不能绕过工具对 Codex 应用或 CDP 操作的拒绝。
2. 用任务自建文件和目录证明一次真实选择、读取及取消，无人工选取或关闭窗口，无残留系统面板。`setFiles` 返回成功、文件哈希一致和单测通过都不能单独证明此项。
3. 在选择流程通过后核对冻结的文件管理补丁及实际依赖，只集成目标必需的能力。已确认本机 composer 路径入口直接复用 materialize，不依赖浏览器上传或其他领域改动；116 文件保留为独立任务交付，不整包覆盖 #554。不能先合并未验收实现来解除验收门禁。
4. 在隔离 L2 验证完整附件与资产链路、会话切换、取消、错误及清理；运行适用共享探针并保存当前提交的 GIF。需要 Electron 的行为另行提供对应证据。
5. 独立最终验收与 required checks 通过后按授权合并，确认远端 merged 状态；通过官方入口从已合并源码物化 Dev，再验收 45120 及适用 App 行为。

## 集成约束

- 保留 `commandUi.clientAction`：鼠标与 Enter 使用相同执行路径，不恢复 `popupSelect` 二次菜单。
- 保留取消信号、注册卸载、会话身份、错误传播和焦点恢复，防止选择结束后的晚响应写入另一会话。
- `composer-add/install.js`、资产路由与被删除的原生 picker 存在重叠，必须按最终接口整合，不能整文件覆盖。
- 文件内容导入与本机路径引用分别按领域语义处理。目录保留分组、相对层级和空目录语义；不把浏览器 FileList 当作真实绝对路径。
- 如果需要新的页内路径入口，它必须是用户和 Agent 均可使用的正常产品功能，复用既有鉴权、路径及领域校验；不能靠测试专用注入冒充真实选择。
- 确认前取消不发送导入请求、不产生副本。确认后关闭会中止客户端等待并阻止晚响应写入托盘，但不能承诺撤销服务端已经执行的复制；已完成的副本仍属于原项目。
- 导入期间配额变化导致托盘暂时不能接收时，当前面板保留已经复制的结果，重试只添加附件，不重复复制。
