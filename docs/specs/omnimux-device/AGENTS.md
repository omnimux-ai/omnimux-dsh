# omnimux-device

> OmniMux 移动真机矩阵与设备智能体中枢（Mobile Device Farm & Agent Brain）
> 负责连接物理 iPhone 集群，将硬件能力转化为标准智能体工具，通过快慢双脑分层回路实现高并发短视频矩阵自动化分发。

## 核心使命与定位 (Mission)

1. **设备池化中枢**：纳管 USB 直连物理 iPhone，维持 WDA 进程常驻与端口自动转发，实现设备自动唤醒与密码解锁。
2. **双脑分层控制**：顶层通用大模型做意图解析与发片全局规划；底层 TypeSafe Jev 决策模型（100~200ms）负责单步微操与异常自愈。
3. **配额与并发解耦**：管理多苹果开发者证书池（突破单账号 100 台上限），基于时间片轮换排班调度器（Time-sharing Scheduling）以最低 Mac 硬件成本并发调度海量真机。

## 架构铁律与硬约束 (Hard Bounds)

- **严禁写死像素坐标**：界面交互严格依赖 AXe 无障碍元素树（标签/ID）或本地苹果 Vision OCR 识别，坚决杜绝依赖绝对屏幕坐标。
- **直连 WDA 协议，严禁引入 Appium**：保持极简单体与低延迟，通过轻量 Node.js 直连手机端 WDA 原生 REST API（端口 8100+），消除多层中间件。
- **置信度硬门禁**：所有微操动作必须经过 TypeSafe 概率校准。日常动作要求 `confidence >= 0.85`；发布与删除等不可逆动作要求 `confidence >= 0.95`。低于阈值坚决拒绝盲点并触发安全挂起。
- **防风控拟人化规范**：点击点位强制引入 ±8~15px 随机高斯扰动，手势滑动强制模拟非线性贝塞尔加速度阻尼曲线。
- **发片幂等锁**：所有向社媒平台投递的任务必须具备全局唯一任务指纹，严格杜绝同一视频重复上传。

## 多证书与排班纪律 (Fleet & Cert Quota)

- **授权配额与并发隔离**：明确区分静态授权配额（苹果绑定的 100 台/账号）与单 Mac 动态并发量（10~15 台/机）。任何批量任务必须走轮换排班流水线。
- **证书隐私保护**：Apple Team ID、P12 密钥与证书凭据必须通过系统安全凭据通道注入，严禁硬编码提交至代码库。

## 质量循环与验证门禁 (Quality Gates)

- **代码修改基线**：任何新增功能必须包含无障碍解析单测与模拟 WDA REST 通信单元测试。
- **UI 原型交付标准**：新交互界面必须遵循苹果极简设计哲学，必须通过单文件 HTML（`docs/prototype.html`）在侧边栏真实浏览器完成实机端到端交互闭环核验。
