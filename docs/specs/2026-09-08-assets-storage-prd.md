## 二、产品定义

### 1. 产品目标

1. **降低整合成本：**一次选择目录即可纳入已有文件与目录，无须逐个添加。
2. **降低重复占用：**目标目录已有文件默认原位使用；迁移中经内容校验可复用的文件不再新增持久副本。
3. **控制数据风险：**每次覆盖、整理、切换、清理均有明确范围、校验与恢复路径；失败不得伪报成功。

不承诺硬盘损坏、恶意外部修改等条件下“绝对零丢失”，而应承诺明确可测的保护措施和风险提示。

### 2. 用户故事

- 作为拥有现成素材目录的创作者，我希望直接将该目录设为资产库，以便继续维护原目录，而非再维护一份导入副本。
- 作为已有资产库的用户，我希望更换位置时自动合并原有资产，以便不丢失资产名称、分类、文件和引用。
- 作为需要解决重名文件的用户，我希望对比来源和目标并决定覆盖或跳过，以便避免误覆盖。
- 作为使用外置硬盘的用户，我希望掉盘或关闭应用后能恢复任务，以便不必重新搬运全部文件。
- 作为重视磁盘空间的用户，我希望知道安全副本占用及清理条件，以便在确认迁移有效后回收空间。

### 3. 非目标

- 不建设多库同时挂载、跨设备同步、云盘同步或通用文件管理器。
- 不自动识别角色/场景等语义，不自动重命名、分类全部客户素材。
- 不改项目资产物化、全局到项目实例化快照、项目生成物归属。
- 不迁移其他插件的数据、整个 DSH Home 或用户作品包。
- 不自动对用户目录内历史重复文件做删除式去重。
- 本轮需求调查及后续测试不得直接迁移 `/Users/x/Desktop/Project/OPC/资产库/素材库`；仅使用隔离样本。

## 三、关键产品规则与合同限定例外

### 1. 作用域与唯一生效根

- 每个 DSH Profile 的全局资产库同时只有一个**生效根**。
- 未配置时，完整保留当前默认路径和解析优先级。
- 用户选中的目录本身就是资产根，不能暗中再建立一个完整副本目录充当真正资产库。
- 自定义路径仅影响 `omnimux-assets`，不得通过修改 `DSH_HOME` 实现。
- 根配置及恢复任务入口必须在目标掉盘时仍可读取；绝对路径仅允许存于必要的根配置、受限迁移日志等控制信息中，不能写回项目内容账本。
- 全局资产内容引用仍使用相对当前资产根的 POSIX 路径，继续执行词法及真实路径 containment 检查。

### 2. 三类文件所有权

| 类型 | 定义 | 默认删除语义 |
|---|---|---|
| 外部原件 | 位于选定资产根之外的用户文件 | 继续只读；普通导入仍复制，禁止移动或删除 |
| 原位接管文件 | 选择目标根之前已经存在的文件 | 纳入索引不等于同意删除；移除资产记录默认只移除索引 |
| 应用受管文件 | 应用导入、生成或历史资产库管理的文件 | 按资产记录、共享引用及迁移清单进行受控回收 |

必须记录来源/所有权，不能仅凭“文件现在位于资产根内”就认定应用拥有删除权。重复文件被多条记录引用时，删除单条记录不得删除其他记录仍使用的文件。

### 3. 旧合同的限定例外

架构阶段须明确修订全局库相关条款，不能只改代码绕过合同：

1. **目录布局例外：**经用户选择的全局资产根内，已有文件可保持相对路径原位登记，无须强制复制到 `data/files/<id>/`。新导入文件继续采用应用规范目录。
2. **迁移回收例外：**变更根目录时，经校验、成功切换及清理授权，可回收清单内旧的应用受管文件，无须删除对应资产记录。
3. **覆盖/整理例外：**仅允许处理本次计划中明确列出、用户确认的目标文件；必须先建立可恢复版本，不允许授权无限扩展。
4. **不外溢：**上述例外不修改普通外部导入、项目 `assets/`、项目 `artifacts/`、instantiate/promote 的既有规则。

“选目录”只授权扫描和制定计划；“开始迁移”授权执行已展示计划；不等于授权整理、覆盖、删除该目录内所有内容。

## 四、功能范围与优先级

**P0＝必须，P1＝应有，P2＝后续可选。**本次优先级以用户明确需求及数据安全依赖确定，未虚构用户规模或收益数据。

| 优先级 | 要求 |
|---|---|
| P0 | 搜索框左侧设置入口，路径查看、选择、预检、确认 |
| P0 | 原位接管既有目标树；按记录合并原库，保留资产元数据和引用 |
| P0 | 内容去重、重名冲突、结构冲突及范围明确的批量动作 |
| P0 | 大文件/多文件分阶段进度，关闭弹窗后可重开 |
| P0 | 根切换一致性、持久化恢复、并发写保护、空间及掉盘处理 |
| P0 | 覆盖前恢复版本、旧源安全保留、受控清理和异常报告 |
| P0 | 相对路径与 containment、符号链接及特殊文件保护 |
| P1 | 剩余时间估计、报告导出、历史任务查询 |
| P2 | 用户主动发起的目标目录历史重复文件清理；不属于本次默认迁移 |

技术栈沿用现有 React、`dsh-ui-kit` 与插件 Host 能力，不引入新前端框架或独立配置系统。

## 五、交互流程

### 1. 设置入口与弹窗

搜索框紧邻左侧新增齿轮图标：

- Tooltip、无障碍名称均为“资产库设置”。
- 键盘可操作；弹窗关闭后焦点返回入口。
- 不新增一级 Settings 导航；沿用官方配置能力，不另建配置真源。

弹窗标题：**资产库保存位置**

内容包含：

- 当前生效位置、是否默认位置、可用/离线状态。
- “选择文件夹”、待选路径、恢复默认位置入口。
- 说明：“已有素材将优先原位使用；迁移与必要整理将在确认后开始。”
- 存在未完成任务时，优先展示恢复任务，不允许并行创建另一迁移。

操作：**取消 / 检查并继续**。选择或修改文本不立即切换资产根。

### 2. 预检

预检不移动、覆盖、删除用户文件。必须检查：

- 路径存在性、目录类型、读写权限、文件系统能力。
- 源与目标真实路径关系：同一根为无操作；互为父子目录必须阻止，避免递归迁移。
- 目标是否为另一个有效资产库，是否有不兼容/损坏的账本或保留名称冲突。
- 应用受管文件、已有目标文件、不可访问文件、特殊文件及符号链接。
- 实际需复制数据、可原位接管数据、内容重复、重名冲突、结构冲突。
- 各涉及卷的**峰值额外空间**，包括暂存、覆盖恢复版本、账本及余量；不得提前扣减尚未清理的旧源。
- 源账本版本、目标身份及扫描后变化。

摘要须显示：

> 原位接管数量 / 待迁移数量与字节 / 可复用数量 / 待决策冲突 / 排除项 / 预计额外空间

扫描总量尚未知时显示“已扫描 N 项”，不得显示虚假的确定百分比。

### 3. 计划确认

展示文件级或目录级变更预览：

- 哪些只登记、不移动；
- 哪些从旧库复制；
- 哪些复用目标已有内容；
- 哪些需要改名、覆盖或规范化；
- 哪些保留于旧路径、不会进入新库；
- 哪些暂时安全副本会占用空间。

默认方案为**保留现有结构**。必要整理必须单独列出原因、原路径、新路径及恢复方式；拒绝某项整理后，应能保留原结构，或明确告知该项暂不能纳入，不能强制整库重排。

主按钮：**确认并开始迁移**。不可处理的阻断项存在时禁用。

### 4. 迁移与切换

状态流程：

**检查 → 待确认 → 迁移/合并 → 校验 → 提交切换 → 已完成 / 已完成但有跳过项**

任一处理阶段可进入：**等待冲突处理 / 已暂停 / 等待磁盘恢复 / 失败待恢复**。

要求：

- 任务由 Host 执行；关闭弹窗或资产页不等于取消任务。
- 显示阶段、文件数、传输字节、当前文件、错误与跳过数。
- 批量或单文件超过 10 MB 必须显示进度；持续活动时每 1 秒内至少更新一次状态或心跳。
- “复制完成”不等于“迁移完成”；校验和切换必须分别可见。
- 提交前旧根仍为生效根；新索引和目标文件校验完成后，原子提交根配置与一致的索引版本。
- 提交后新导入、查询、预览、上传、删除统一使用新根，禁止新旧根混写。
- 短暂提交阶段不可中途取消，须明确提示。

### 5. 恢复与结果 UI

- **提交前暂停/取消：**继续使用旧根，保留可恢复任务；只清理任务自建且能证明未被引用的暂存文件。
- **应用重启：**展示“检测到未完成迁移”，提供继续、查看详情、放弃并处理暂存。
- **掉盘：**展示缺失的源/目标位置及受影响阶段；重连后复核目录身份，不能见到同路径就直接续传。
- **失败：**显示可操作原因、已完成数量、原库是否仍可用，以及“重试 / 查看保留文件”。
- **提交后回退：**不是简单改回旧路径。若新库已有新写入，必须另行预检和反向合并，不得丢弃新增资产。
- **完成页：**显示实际生效路径、合并结果、跳过/排除项、安全副本占用与清理入口。

## 六、合并、原位接管与冲突规则

### 1. 原位接管规则

- 普通目录的顶层文件可登记为独立资产，顶层文件夹保留为目录型资产；默认分类为“自定义”。
- 子目录按现有层级浏览，不拍平，不将同一目录下每个文件再重复生成顶层资产。
- 有效资产库必须解析并合并账本，不能把其 `library.json` 当作普通素材覆盖。
- 资产名称、分类、描述、标签、封面、文件引用应保留。旧资产 ID 尽量稳定；存在不同库 ID 冲突时必须建立并应用映射。
- 内容相同不代表资产语义相同：两条不同角色/描述的记录不能仅凭文件哈希合成一条。
- 目标既有未知格式文件保留原状，是否可预览沿用现有能力；排除项必须可查，不能静默删除。
- 应用控制文件必须可识别并从素材扫描中排除；名称被用户文件占用时不得覆盖。

### 2. 文件冲突矩阵

“同名”指**计划落点相同**，不是不同文件夹中恰好同名。

| 情形 | 必须行为 |
|---|---|
| 同内容、同名或异名 | 通过完整内容校验确认后，优先复用已有目标文件；不新建相同迁移副本。不能仅凭名称、大小或时间判重 |
| 不同目录同名 | 原路径可保留时不视为冲突 |
| 同落点、同名异内容 | 展示来源/目标路径、大小、时间及可用预览；等待用户选择 |
| 目录与目录同落点 | 合并子项，对子项分别判断；禁止将“覆盖目录”解释为递归删除 |
| 文件与目录同落点 | 单独列为结构冲突；不允许普通“全部覆盖”替换整棵目录，提供跳过或改名保留两者 |
| 大小写、Unicode、目标文件系统命名限制冲突 | 按目标文件系统实际规则预检，提供改名方案；不得静默改名 |
| 资产记录 ID、handle 冲突 | 与文件覆盖分开处理；保留双方记录并明确消歧、映射，禁止按同名直接删除记录 |

### 3. 冲突按钮语义

必须提供：

- **覆盖：**用来源内容替换目标内容，但先保留经校验的目标恢复版本。
- **跳过：**不迁入该来源项，目标不变；来源项保留并记录位置。
- **全部覆盖：**仅适用于本次已确认范围内的普通文件内容冲突，并展示数量及恢复空间。
- **全部跳过：**仅跳过本次迁入冲突项，不删除其源文件。

建议同时提供 **保留两者（改名）**，避免用户在两个都需要时被迫二选一。

批量决策不得用于保留名称、结构冲突、权限问题、符号链接或扫描后新发生的变化。发现新冲突必须暂停重新确认。

**跳过不等于成功合并：**不能把旧资产记录静默指向内容不同的目标文件。跳过造成的未迁入记录必须在结果中单列；经用户确认可完成部分切换，但旧源及恢复信息不得清理，也不得将任务标成“全部迁移成功”。

## 七、安全、异常与空间取舍

### 1. 迁移安全要求

- 跨盘使用“复制到暂存 → 完整内容校验 → 提交”，不能依赖跨盘 rename，更不能边复制边删除源文件。
- 同盘优化不能降低同等的可恢复性、授权和校验要求。
- 文件内容、索引和根配置应具备可恢复提交顺序；在任意阶段中断后不得只剩指向半成品的账本。
- 全程有持久化任务清单，记录来源、目标、状态、校验结果、冲突决定和恢复版本。
- 失败重试具有幂等性，不能反复新增副本或重复资产。
- 保留必要的文件时间及权限语义；不能因创建应用目录而递归 chmod 用户已有树。无法保留关键元数据时在预检中告知。
- 含敏感文件的清单和恢复信息仅限本机受控存储，不自动上传素材或详细路径。

### 2. 异常处理矩阵

| 风险 | 产品行为 |
|---|---|
| 空间不足 | 开始前阻止；运行中不足则安全暂停，不删除旧源腾空间，不擅自缩减恢复副本 |
| 目标掉盘/只读 | 暂停，保留任务；切换后掉盘显示资产库离线，不静默回落默认根新建空库 |
| 崩溃/强制退出 | 重启识别任务，复核已完成文件，继续或恢复，不重新无条件覆盖 |
| 应用并发写 | 执行前等待已有写入结束；迁移期间阻止新的全局库写入，所有 UI、API、工具入口一致返回可重试状态 |
| 外部程序写入 | 校验源和目标是否变化；变化项重检，不沿用旧冲突决定。无法证明稳定时暂停相关处理 |
| 符号链接 | P0 不跟随、不复制成普通文件；目标根若为链接则拒绝并提示选择真实目录。内部链接、循环和断链列为排除项 |
| 特殊文件/不可读项 | 不当作普通文件处理，不静默忽略；列出保留位置及原因 |
| 恢复时同路径换成另一块磁盘/目录 | 身份不一致则阻止续传，要求重新预检 |
| 外部程序在回滚后仍有新增修改 | 不用旧副本直接覆盖，转为冲突处理 |

对外部程序无法实施可靠锁定的场景，UI 必须提示迁移期间停止外部编辑。应用不得以自身写锁声称能够阻止所有外部修改。

### 3. 临时安全副本与清理规则

**决策：安全优先于迁移过程中的最低空间占用；尽量消除稳定双份，不以立即删除换取表面节省。**

- 原位接管且未修改的目标文件不额外备份整棵树。
- 旧库受管文件、被覆盖目标的旧版本、必要的整理恢复材料按任务清单保留；不得顺手备份或清理整个用户目录。
- 建议默认保留期为成功切换后 **7 天**，届满只进入“可清理”，不直接按时间删除。
- 清理须满足：目标在线、相关文件复验通过、无未解决异常、无其他引用，并取得针对该批文件的清理确认。
- 跳过项、唯一剩余副本、来源变化项、身份不明文件不具备清理资格。
- 对客户原位文件的恢复版本，在清理前必须明确告知将失去该版本的应用内恢复能力。
- 清理按清单逐项执行，绝不递归删除整个旧根或用户目录；已改变的文件保留并报告。
- 清理后保留轻量迁移结果与清理凭据，不保留不必要的完整媒体副本。

若用户长期不确认清理，安全副本可能持续占用空间，应持续展示占用和原因，不能承诺无条件自动消除所有双份。

## 八、架构交付约束

架构师需明确但不必机械采用特定实现：

1. 根配置发现、生效版本及目标离线时的控制信息存放位置。
2. 原位接管文件的所有权标识、相对路径模型及共享文件引用回收。
3. 迁移任务状态机、锁范围、幂等恢复、提交与回滚协议。
4. 普通目录与已存在资产库的识别、账本合并、ID/handle 映射。
5. 预检计划与执行时变化检测、空间预算和内容校验。
6. 所有读写入口切根的一致性，包括惰性迁移、预览、上传、删除与后台任务。
7. 对 `library.json`、`artifacts.json`、`data/files/`、`artifacts/`、遗留映射的完整性策略；可再生扫描缓存允许重建，不能误当唯一数据删除。
8. 与现行物化合同、设置入口合同和跨插件边界的精确增量修订。

不要为实现本功能修改官方 DSH 源码、扩展其他插件写权限或创建第二个路由中心。

## 九、可测验收标准

以下是**未来必须取得的验收证据**，不是本轮已通过的结果。

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A01 | 设置入口 | 搜索框左侧入口可见、键盘可达；弹窗显示真实生效路径；取消不切根 |
| A02 | 普通目录原位接管 | 中文及多层目录样本纳入资产页后，原文件路径、内容不变，未产生相同导入副本 |
| A03 | 空目标/已有资产库 | 两种情况均完成预检与合并；资产元数据、封面和文件引用可用；控制文件未作为素材覆盖 |
| A04 | 内容去重 | 同内容异名样本可复用目标文件；无新增重复迁移副本，不丢不同资产语义 |
| A05 | 四种冲突动作 | 覆盖、跳过、全部覆盖、全部跳过与界面说明一致；批量规则不越范围 |
| A06 | 文件目录冲突 | 不递归覆盖/删除目录；用户可跳过或改名；目标无未经确认的变化 |
| A07 | 规范化授权 | 默认保留用户结构；未勾选/确认的整理项不执行 |
| A08 | 迁移完整性 | 全部实际复制文件逐一内容校验；资产和产物引用有效；旧 ID 保留或有完整可验证映射 |
| A09 | 跨盘和空间不足 | 跨卷样本完成；开始前及传输中空间不足均安全阻止/暂停，无源文件提前删除 |
| A10 | 中断与掉盘 | 在复制、校验、覆盖、索引提交、根提交各阶段注入故障，重启后可恢复；没有指向半成品的成功状态 |
| A11 | 并发与外部修改 | 并发写被一致阻止；扫描后文件变化被发现并重检；不覆盖新变化 |
| A12 | containment | `..`、绝对引用、链接逃逸、循环链接均不越界读写；同根无操作，父子根迁移被阻止 |
| A13 | 进度与重开 | 1 万个小文件及至少一个大于 1 GB 的隔离样本下，进度可见、界面可操作；重开弹窗恢复当前任务 |
| A14 | 切换和回退 | 切换后各入口统一读写新根；新根离线不生成默认空库；已有新增数据时回退不会丢弃新增内容 |
| A15 | 删除与清理 | 原位接管资产移除不删客户文件；共享文件仍被引用时不删；未满足条件的安全副本不可清理 |
| A16 | 合同回归 | 普通外部导入仍 copy；项目物化、instantiate、promote、项目删除行为不变 |
| A17 | 平台/UI | macOS 系统目录选择、确认、进度和恢复取得真实 UI 证据；其他未支持平台明确返回不支持，不伪造成功 |

所有破坏性用例均用隔离 Profile、隔离目录和生成样本。UI 验收按仓库规定使用 ego-browser；系统目录选择另补 Electron/原生壳证据。

## 十、待决策项与交接结论

### 需用户决策

**目前没有阻塞 PRD 或架构设计的不可推断事项。**以下已有合理默认值：

- 保留已有目录结构；
- 顶层文件/目录纳入“自定义”；
- 仅单一生效根；
- 安全副本保留 7 天后，经校验与确认清理；
- P0 不跟随符号链接；
- 冲突按任务内明确范围处理。

真实目录的覆盖、整理和清理决定必须在未来运行时依据实际预检提出，不能现在用笼统授权代替。若后续要求 NAS、云盘占位文件或多进程共享写入，则需另行确认平台与一致性范围，当前不得假定支持。
