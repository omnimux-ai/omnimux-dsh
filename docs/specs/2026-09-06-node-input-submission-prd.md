# 节点上游输入与提交一致性需求补充

产品规则已由用户确认；本文接受的是需求和验收标准，不代表代码、自动化用例、CI 或运行验收已经完成。本阶段交付文档，后续实现须以 [节点有效输入与提交合同](../contracts/node-input-submission.md)为唯一产品依据。

## 1. 问题与目标

用户将含有 `1dog` 的文本节点连接到文本生成节点。界面显示已引用的来源，却因本地输入框为空显示“该 operation 需要非空 prompt”，生成按钮不可用。

目标：上游与本地都能提供任务所需内容；按钮状态、提交校验和实际请求对输入的理解一致。生成按钮不能要求用户把已有上游内容再抄一遍。

成功必须同时包含两面：满足输入条件时可提交且不丢内容；条件未满足时拒绝并明确缺项。仅能点击按钮不构成完成。

## 4. 用户可见结果

- 截图场景中保留上游引用，显示其内容摘要，本地框提示“补充要求（可选）”；其他条件满足时生成可用。
- 缺少内容时显示“输入内容，或连接一个有内容的文本节点”；等待来源时指出哪个上游尚未完成，不能统称 prompt 为空。
- 改变引用结果、文字、顺序、角色或连线后，界面即时反映下一次生成将使用的内容；本地输入和已经完成的结果不被无关自动适配覆盖。
- 多模态节点依据任务说明具体缺项，例如“还需要尾帧”或“声音样本已添加，请提供朗读正文”；不凭一个通用文本框推断所有用途。

## 5. 验收矩阵

用例默认使用合成内容和可用测试模型合同，其他必需参数已满足。表中结果是预期，不是执行记录；实现者逐项填写通过、失败或不适用及证据。不适用必须说明能力未接入或本次范围，不能省略后宣称全类型完成。

| ID | 场景 | 界面/提交预期 | 请求或执行断言 |
| --- | --- | --- | --- |
| IN-01 | 上游 `1dog`，本地空，文本生成 | 可提交，显示引用；本地为可选补充 | 请求含该文本，不含自动虚构的用户要求 |
| IN-02 | 无上游，本地有效文本 | 可提交 | 请求含本地文本 |
| IN-03 | 无上游，本地空或纯空白 | 不可提交且提示内容缺失 | 无生成请求 |
| IN-04 | 上游剧本，本地“缩短到 30 秒” | 可提交，两个来源可理解 | 原剧本与修改要求均存在，不互相覆盖 |
| IN-05 | 多段文本，调整引用顺序 | 全部引用可见且顺序更新 | 所有文本按该顺序进入请求；超限明确拒绝，不截断 |
| IN-06 | 原先可提交，清空/断开唯一上游 | 无需编辑本地即可变为待补齐 | 无过期文本请求；有其他完整输入且已移除空引用时可继续 |
| IN-07 | 上游有多个历史结果，选择结果 B | 引用摘要为 B | 只消费选定结果 B，不发送全部历史或生成 B 时的 prompt |
| IN-08 | 本地已有文本，但已纳入的上游仍上传/生成/为空 | 显示等待具体来源，当前节点不可直接提交 | 不静默跳过该引用；移除引用后按剩余输入判断 |
| IN-09 | 上游重生成，仍选中已完成结果 A | 明示使用 A；改选未完成 B 后等待 | 明确选择 A 时允许用 A，不混入 B 的中间内容 |
| IN-10 | 上游文本分别连接文生图、文生视频 | 本地空不造成额外阻断 | 通用校验与视频参数校验均使用有效描述 |
| IN-11 | 首帧/参考模式的合同允许无 prompt，素材齐全 | 可提交 | 合法媒体与角色进入请求，不自动填充假 prompt |
| IN-12 | 同类模式合同要求 prompt，只有图片 | 待补充；再接有效文本后可提交 | 缺失时无请求，补齐后图文均保留 |
| IN-13 | 首尾帧只连首帧，再补尾帧 | 允许逐步连接，先待尾帧，补齐后就绪 | 首尾角色准确；交换角色会改变对应载荷 |
| IN-14 | 局部重绘缺蒙版，或两图任务用途不明确 | 指明缺项或要求明确用途 | 不把普通参考图自动当蒙版，不猜首尾帧 |
| IN-15 | 已有明确“描述图片/视频”任务及有效媒体 | 不强制用户再手写同一指令 | 发送可见任务指令与媒体；开放问答缺问题时不能套用此放行 |
| IN-16 | 有效音频转文字任务，无 prompt | 若能力已接入则可提交 | 音频作为源，产出类型为文本 |
| IN-17 | 上游是朗读正文，另有“温柔一点”表达要求 | 正文与表达要求用途清楚 | 正文不混入表达要求；不支持表达控制时明确说明 |
| IN-18 | 仅声音样本，任务还要求朗读正文 | 不可提交，定位正文缺失 | 不以样本或“温柔一点”代替正文 |
| IN-19 | 音乐歌词/风格、数字人素材/驱动音轨 | 分任务判断用途和必需项 | 不套用全局文本拼接；未接入能力不得伪装可提交 |
| IN-20 | 结构合法，但当前模式不消费该类型、数量超限或角色冲突 | 不掐线，供给进入备选池；Slot 装填至 max，角色冲突不猜测，允许点坑指定 | 不删边；API 只消费已入坑且就绪的素材，未入坑供给不得混入；缺必需槽仍拦提交；自连、成环及节点种类类型矩阵等结构非法仍拒边 |
| IN-21 | 已入坑素材因上游编辑不再兼容 | 保留编辑与供给边，自动占位可退回 Feed；显式绑定显示冲突 | 必需槽缺失或显式绑定冲突时无请求；不自动换模型、任务或删除供给边 |
| IN-22 | 文件元信息读取中、读取失败、素材失效 | 等待与失败分开，定位来源 | 不把未知当零；已知限制校验与素材可用性校验不混淆 |
| IN-23 | 同素材同角色重复连接，或同图分别作首尾帧 | 重复绑定反馈明确；不同合法角色分别显示 | 不静默重复同绑定，也不去掉不同角色 |
| IN-24 | 新增供给、超载，或用户显式切换任务 | 供给变化保留已选模型和 operation；显式切换后按新布局重算装填；未选模型的新节点按既有策略初始化 | 供给变化不切任务、不改手动偏好、不影响其他节点；手选未知模型仍拒绝 patch |
| IN-25 | 页面显示就绪后、点击前输入变化 | 提交时重新校验最新输入 | 不发过期版本请求；失效时明确反馈 |
| IN-26 | 请求发出后切换上游/修改本地 | 在途执行不变，下一次生成使用新内容 | 单次请求的结果身份、正文、角色和参数来自同一快照 |
| IN-27 | 页面、快捷入口和 Agent 入口提交同一节点 | 一致的输入解释与拒绝原因 | 合法请求载荷一致；非法请求不会经另一入口漏过 |
| IN-28 | 先创建空节点、连接未生成上游、运行当前节点/整条流程 | 创建与连线允许；单节点等待；流程由既有调度负责 | 不通过忽略依赖使单节点放行，不把依赖可调度误当素材已就绪 |
