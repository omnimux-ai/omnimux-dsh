## 1. Problem · 用户问题

用户在浏览器扩展中选中图片，希望下一次能在宿主资产库找到并使用图片，而不是只在灵感库看到网页记录。两个现有入口目前第一动作均为加入灵感库：TikTok 作品卡片角标展开工具栏，以及其他已支持社交页面的媒体悬浮胶囊。

真实基线存在两项阻止纯改文案的事实：

1. 保存链路会并行尝试宿主灵感库与扩展本地灵感库，其中任一成功即可反馈成功。这不满足图片真实加入宿主资产库的要求。
2. TikTok 作品卡片以 `img` 展示视频封面很常见，角标实现目前优先读取 `img`、再根据 DOM 元素类型决定图片或视频。若原样改路由，会把视频封面存入资产库。

事实来源见 [PM_PREFLIGHT：证据](<PM_PREFLIGHT.md#2-证据>)。没有用户访谈或覆盖率数据，本设计不虚构用户规模、转化或性能收益。

## 2. Solution · 最小产品改变

仅改变两个入口中“确定为图片作品”的第一动作：

- 图片：`加入资产库`，点击后把当前选中的真实图片保存到当前目标宿主的本地资产库；不是只存 URL、不是扩展本地缓存、不是灵感库、不是仅上报生成记录。
- 视频作品：继续 `加入灵感库`，保留现有视频灯泡与保存链路，包括现有本地灵感记录行为。本任务不承诺重构视频保存协议。
- 固定三个动作及顺序：第一动作 → 复制 → 加入对话。后两项的原文、图标、目标地址与会话投递行为不变。

“真实保存成功”同时满足：目标宿主完成图片文件保存；宿主本地资产记录能关联该文件；用户打开宿主资产库能看到并预览该图片。HTTP 成功、消息已发出、正在下载、仅收到 URL 或仅写到扩展 storage 均不是成功。

## 3. 用户故事与操作旅程

### US-1 · 图片入库

作为浏览素材的创作者，希望点击第一动作后在宿主资产库获得可再次使用的图片，以便后续选材，而不用再找网页链接。

旅程：进入既有支持页面 → 悬停作品/媒体 → 悬停品牌角标/胶囊 → 第一项提示加入资产库 → 点击 → 保持诚实处理中 → 收到宿主真实保存结果 → 提示已加入资产库 → 用户自行打开宿主资产库预览。

不自动跳转宿主、不弹分类表单、不打开新会话、不替用户执行后续创作。

### US-2 · 视频不误入图片库

作为浏览 TikTok 作品的创作者，希望 `/video/` 作品即使以图片封面呈现，第一动作仍是加入灵感库，以便保留视频作品而不是误保存封面图片。

作品链接/明确作品类型是业务语义，DOM `img` 只是显示载体。角标可保留封面预览，但第一动作不得把封面作为图片资产保存。类型不明确时拒绝图片资产写入，不能猜测成功或静默改存灵感库。

### US-3 · 新用户失败可理解

作为尚未连接宿主或图片下载受阻的新用户，希望知道图片没有保存成功及下一步，以免误以为资产已经可用。

缺少当前目标宿主/连接时在原操作处提示：`宿主未连接，请打开 OmniMux 后重试`。宿主返回明确图片下载失败时提示：`图片下载失败，请重试`。未收到最终保存回执时提示：`未确认保存结果，请稍后查看资产库`，不得把未知结果断言成失败未写入，更不得显示成功。

## 4. 范围

### 纳入

- 角标工具栏和悬浮胶囊两处图片第一动作的名称、无障碍标签、提示、完成反馈、图标和真实目的地。
- 影响第一动作路由的图片/视频作品语义核定，尤其 TikTok `/video/` 图片封面。
- 点击时重新核定当前作品，避免 SPA 卡片复用/懒加载后旧标签与新目标不符。
- 同一操作处理中的重复点击防护；失败恢复可重试；保存状态不串到其他图片。
- 与成功语义直接相关的宿主保存结果及资产库可见、可预览验收。
- 新用户宿主缺失、下载失败、拒绝、未知结果的原位短反馈。

### Out of Scope · 不做

- 不增加第四动作、操作菜单、徽章、标题、副标题、营销文案、分类弹窗或连接向导。
- 不改两个入口的显隐、定位、四角配置、尺寸、材质、开合动效、键盘开合与站点覆盖。
- 不在 TikTok 开启被现有规则禁止的悬浮胶囊；不改推荐流/详情页的场景固定菜单。
- 不重设计复制与加入对话，也不改变它们既有地址选择/页内视频引用逻辑。
- 不做视频下载入资产库、视频封面单独入资产库、图集批量抓取、页面截屏、绕过平台鉴权/反爬或后台补偿写库。
- 不迁移、清空或重写历史灵感记录；不改变既有资产库分类体系。
- 不把浏览器图片伪称为 AI 生成文件；不写入商品库、公共云目录或另一运行环境的库。

## 5. 产品决策

### 5.1 目标库与默认分类

目标是用户当前连接/选定宿主的本地创作资产库。单次点击保存一个当前图片，不自动抓取图集其他图片。没有用户选择的语义分类时，建议使用既有 `自定义` 分类；不得根据图像内容猜成角色/场景/道具。此建议及重复保存策略列为 [PM_PREFLIGHT：待确认](<PM_PREFLIGHT.md#3-待确认歧义与执行边界>)，不新增用户可见分类 UI。

图片名称优先使用真实图片描述/页面标题，遵守宿主既有合法名称约束；缺失时默认中文 `网页图片`、英文 `Web image`。来源保留真实页面 URL，不编造来源平台或生成者。

### 5.2 图标

图片第一动作优先原样复用宿主资产库侧栏现有矢量图形；已核实是内联 SVG，可以复用图形路径而无需把宿主 React/UI 运行时带进 content script。两个入口使用同一图形，按各自现有图标槽等比例绘制，不增加文件夹加号/下载箭头复合图形。

视频灯泡不变；视频胶囊既有已收藏星形反馈不改。图片只有真实保存成功才能使用既有勾形状态，不借视频星形暗示收藏。

### 5.3 文案一致性边界

图片第一动作在两入口中同语言、同状态逐字一致，包含 title、aria-label、tooltip 与 done。闲置名称与完成名称是不同状态，不要求将 `加入资产库` 与 `已加入资产库` 写成同一句。

复制与对话按基线逐渠道保留：复制无障碍/按钮名称是 `复制`，胶囊提示是 `复制素材链接`。不能借“一致性”顺便改成 `复制链接`。视频英文仍用基线 `Add to library` / `Added to library`，不借本任务改名。

## 6. 可测成功标准

| ID | 验收标准 | 必须证据 |
|---|---|---|
| AC-01 | 两入口均恰好三个动作，顺序不变；图片第一动作显示正确，后两项逐字保持原文 | 两入口 DOM 文案/ARIA 检查与功能截图 |
| AC-02 | 图片第一动作 title、aria、提示、完成反馈中英文与 UI-Spec 对应状态一致 | 中文/英文，两入口状态矩阵 |
| AC-03 | 图片成功后当前宿主本地资产库可见、文件真实存在并能预览 | 同次真实点击、宿主记录/文件/预览证据 |
| AC-04 | 图片任何失败/未知结果都不进入灵感库，不显示保存成功 | 故障注入结果、宿主/扩展灵感库写入监测 |
| AC-05 | TikTok `/video/` + `img`、视频 poster、`img` + `video` 混合卡片仍走视频第一动作，资产新增为零 | 类型断言与真实结构浏览器操作证据 |
| AC-06 | TikTok 明确 `/photo/` 图片及已支持非 TikTok 独立图片能入资产库；不批量保存整图集 | 当前图片与入库文件对应 |
| AC-07 | 无法判定类型、空地址、不可保存来源时不猜测写资产库 | 拒绝反馈与零错误写入 |
| AC-08 | 新用户无宿主、下载拒绝/失效、响应丢失均有最小诚实反馈 | 原位反馈截图与未误报成功证据 |
| AC-09 | 视频灯泡及原保存路径保留；复制与对话的原文、图标、地址与投递行为不回归 | 相关回归测试与实际操作 |
| AC-10 | SPA 卡片复用、延迟响应、连续点击不会把 A 图片结果标到 B 图片，处理后可恢复 | 状态交叉用例与截图 |
| AC-11 | 不新增常驻元素、不改几何与站点覆盖，不破坏即时显示/卡片内不闪烁/离开隐藏 | 专项浏览器截图与既有用例 |
