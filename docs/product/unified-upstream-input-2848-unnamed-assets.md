# 统一上游输入：Issue #2848 V1 无名称素材裁定

签发人：产品经理许清楚（Xu），本票 UI 与逐字文案唯一 Owner。
适用范围：Issue #2848 V1 返工的素材名称显示与对应无障碍名称，不新增设计。

**PM_PREFLIGHT: approved for scoped V1 unnamed-asset naming implementation**

**PM_SIGN_OFF: NOT_PERFORMED**

## 一、唯一裁定

采用既有批准的单一类型名称作为无真实名称素材的显示名。正常 ready 的图片、视频、音频不因未命名而被丢弃；有真实缩略图但无真实名称时，名称位置显示 `图片`、`视频` 或 `音频`。不采用“名称区留空、仅缩略图”的方案。文本沿用真实名称或既有真实正文摘录，无两者时使用 `文本`；空正文是否可用仍由原输入契约决定。

这是名称显示的兜底，不是给源节点命名，不是新增类型标签。网格和列表使用同一显示名规则，不得在另一行、Badge、缩略图角标或 aria 中重复追加类型。前端无需再向用户询问内部取舍。

本文是这一窄语义的产品真源，补充而不整体取代[产品四件套](unified-upstream-input-2848.md#L142-L185)、[英文逐字表](unified-upstream-input-2848-copy-en.md#L28-L38)及[UI 决策](unified-upstream-input-2848-ui-decisions.md#L90-L105)。真实名称优先、原角色和状态白名单、原输入支持与格式准入均不变。无名称场景依本文实施，不再把旧表中的“真实名称”解释成候选存在的必要条件。

## 二、显示名的确定顺序

对当前实际选定输出或当前资产，只取与其对应的真实业务数据，按以下顺序选择第一个非空名称：

1. 来源节点的真实 `label`。
2. 当前输出或当前资产的真实 `title`。
3. 对应源文件的真实 `originalName`。
4. 当前资产元数据中的真实 `name`。
5. 仅文本：沿用本票已批准的真实正文短摘录。
6. 对四类素材使用第三节锁定的单一类型名称。

空字符串、纯空白与内部标识不算真实名称。只允许在显示投影中移除首尾空白，不改业务字段、不翻译真实名称、不重写文件名。字段实际承载位置由工程沿现有数据源映射，不新增字段、接口或查询链；不得为找名字读取其他输出、历史未选结果或无关资产。已有文本摘录长度与呈现规则保持不变，不新增摘要、自动改写或标题生成。

`nodeId`、`outputId`、`assetId`、任务 ID、URL、路径片段、文件扩展名和模型名不得充当兜底名称。不得自行添加 `未命名`、`Untitled`、`素材 1`、`Image 1`、`生成图片` 等其他值或编号。真实用户名称本身含数字或与类型名称相同，按真实数据原样显示，不据词面认定为兜底。

真实名称缺失与真实缩略图缺失是独立事实。缩略图只展示当前真实媒体，不制造假封面；命名规则不负责改变既有缩略图、SVG、文本摘录或预览行为。不得新增“有缩略图才保留候选”的资格条件。

## 三、UI 元素与逐字文案白名单

本表锁定本票现有名称位置与相应可访问名称，前端不得扩写。类型取当前素材真实类型，不取目标生成节点的输出类型、用途、角色或文件扩展名猜测。

| 组件/语义 ID | 元素 | 中文唯一 literal | 英文唯一 literal | 规则与红线 |
|---|---|---|---|---|
| `picker.item.name.image` | 无名称图片的现有名称位置 | `图片` | `Image` | 仅第二节未取得真实名称时；不追加类型副行、Badge、序号或营销修饰 |
| `picker.item.name.video` | 无名称视频的现有名称位置 | `视频` | `Video` | 同上；英文只用单数，不用 `Videos` |
| `picker.item.name.audio` | 无名称音频的现有名称位置 | `音频` | `Audio` | 同上；不从声音用途生成新名称 |
| `picker.item.name.text` | 无名称且无可用真实摘录文本的现有名称位置 | `文本` | `Text` | 不把类型文字当正文，不为满足名称而伪造内容 |
| `picker.item.name.real` | 真实名称或已批准真实摘录 | 第二节得到的显示数据 | 同一真实数据，不翻译 | 真实名称优先；不加类型前缀/后缀、内部 ID 或新副标题 |
| `picker.item.a11y` | 现有候选交互目标的可访问名称 | 与该候选完整显示名完全一致 | 与该候选完整显示名完全一致 | 使用 `aria-labelledby` 指向名称文本或等义 `aria-label`，不同时拼接两份名称；选中态用既有原生/ARIA 状态表达 |
| `picker.item.thumbnail` | 交互目标内的重复媒体缩略图语义 | `alt=""` | `alt=""` | 候选交互目标已有名称，缩略图不再朗读第二个名称；保留真实图像，不新增图像说明 |
| `inputs.item.name`、`inputs.preview.name` | 已有名称位置及对应交互目标 | 同一显示名 | 同一显示名 | 只在 V1 已存在这些消费位置时复用同一规则，不新增名称行、控件或预览标题 |

以上组件 ID 是产品语义标识，不要求创建同名源码 key。固定类型名称复用[已批准中英文类型集合](unified-upstream-input-2848-copy-en.md#L73-L77)的四项 literal，不修改其他调用点的品牌、模型、角色或显示名称。`文档` / `Document` 的既有条件许可保持原样；本文不新增 document 无名称兜底或准入路径。

## 四、无障碍语义与现有状态

候选的可访问名称必须非空。中文无名称图片候选的名称恰为 `图片`，英文恰为 `Image`，其他三类依表对应；有真实名称时使用完整真实名称，视觉省略不截断其可访问名称。不得使用 `选择图片`、`Select image`、`图片素材`、`Image asset`、内部 ID 或隐藏编号代替这套规则。

同类型多个无名称候选可以拥有相同显示名和可访问名称。仍依现有源、选定输出、边、角色等身份独立选择，不按显示名去重。DOM 关联标识可沿用内部稳定身份，但该标识只用于关联和定位，不进入可见文字、`title`、aria 名称或描述。候选选中态及 `已使用` / `In use` 沿用已批准状态，不拼入名称，不新增计数或状态播报文案；必要状态描述复用原有单处语义，不重复渲染。

现有可访问性支持及名称应覆盖网格和列表同一候选。已有素材卡交互目标如消费该名称，亦使用同一完整显示名；预览容器仍沿用 `素材预览` / `Asset preview` 的已批准容器名称，不改成新的用途标题。必要角色显示和 aria 描述沿用原角色规则，不把 `首帧`、`正文` 等角色值拿来替代素材名称，也不因名称兜底删除真实角色数据。

## 五、明确不变的能力与数据边界

名字是否存在，不决定是否支持某种上游输入，不改变类型、MIME、大小、时长、角色、数量、组合、方式、渠道、listed 或 ready 的判断。R6 只解除“名称为空即丢候选”的错误条件；原公共资格判断和整组添加/替换/使用校验继续生效。名称非空不把不兼容、等待中、来源失效或格式未知的素材变成 ready。名称兜底也不豁免 R5 的已知不兼容候选过滤。

全部现有来源、正文、当前真实资产身份、角色、边、绑定、稳定顺序和显式使用状态原样保留。显示名只存在于显示投影，不回写原节点 `label`/name，不持久化为资产元数据，不复制成正文，不进入 TTS 朗读、请求输入、消费身份或兼容判定。搜索如沿现有名称位置消费该投影，不因此新增搜索维度或类型筛选规则。

不新增 UI 元素、布局、Badge、重复类型副行、命名编辑器、默认节点名称、自动标题、SVG 或营销说明。不扩写共享组件，不触碰并发前端 R1/R3 等修复；本轮不复审修改中的源码，不占用或启动浏览器运行环境。

## 六、实施接收与签发边界

可直接实施的接收标准：

- 同一合法 ready 图片、视频、音频无名称时，仍出现在现有网格与列表；名称和 aria 分别严格使用 `图片` / `Image`、`视频` / `Video`、`音频` / `Audio`。
- 第二节每个真实字段有值时按固定优先级显示；无名称文本有真实正文摘录时保留该摘录，不被 `文本` / `Text` 覆盖。
- 中英文候选名称非空，视觉与可访问名称一致；缩略图不重复朗读。原选择/选中态仍可用，同名候选不丢失、不合并。
- 类型兜底只占原名称位置，无重复类型行、Badge、内部 ID、隐藏编号或新教程；必要真实角色与既有状态不被删除。
- 显示前后原节点/资产数据、正文、消费身份和资格判定不变；真实名称、未知格式或不兼容反例仍由原公共契约判断，不通过命名改变输入支持。

这些是后续实施与验证要求，不是本轮测试或运行结果。本文不改源码、测试、原产品/英文/UI 文档、工程规格、设计文件或索引；文档影响仅新增本裁定。没有执行 UI、浏览器、生成、提交捕获或实现终验。是否通过后续 QA、独立复审与 PM 实现终验须另有同版本证据，不由本文 `accepted` 或 `PM_PREFLIGHT` 推导。
