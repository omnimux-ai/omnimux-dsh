## 一、PRD：问题、目标与范围

### 1.1 Problem

创作者需要在文本、图片、视频、音频生成节点复用已有内容。当前入口以媒体槽为中心：文本不进入同一绑定遍历，选择器固定媒体类型，TTS 特判排除输入，跨方式发现只借首个媒体方式，模式/渠道切换可能裁剪消费集合。用户无法从空节点直接判断哪些上游内容可用，也无法确信停用的文字已经停止进入请求。

目标用户是使用创作画布复用文案、参考画面、视频、声音和本地文本文件的创作者，以及通过同一画布状态执行任务的 Agent。没有新增用户调研或使用量数据，本文不编造商业指标。

### 1.2 Solution 与核心价值

素材卡槽统一作为上游输入入口。四类生成输出复用已有选择弹窗、卡槽和预览；可选类型、格式、角色及限制来自一个完整有效输入方案。文本具有与媒体相同的绑定、替换、停用、切换复核和提交身份；手写文字保留在现有编辑器，不伪造成上游卡。

有效方案包含模型、已准入生成方式、一条实际可用渠道及参数、组合和文本角色规则。发现可以覆盖多个方式，确认与提交必须有一个方式和一个渠道同时承接整组使用意图。用户不会在真正提交时才被暗切方式，也不会遇到“添加成功但请求只取第一项”。

### 1.3 已确认决策，无待用户确认项

| 决策 | 正式口径 |
|---|---|
| 统一入口 | 文本、图片、视频、音频输出，只要有效能力允许任意上游输入，包括文本，空态默认显示素材卡槽；不按输出类型推断输入能力 |
| 跨方式确认 | 同一素材弹窗显示目标方式，点击 `添加` 同时确认选材与方式变化；多个完整方案在弹窗内选择，不另开确认弹窗、不延迟到生成时暗切 |
| 单正文 TTS | 已绑定且使用中的上游文本按素材可见顺序合并，后接本地编辑文字，全部作为正文朗读；不读名称、来源标记或引用 token，不做正文二选一阻断 |
| 独立表达字段 | 只有模型、方式、渠道及 mapper 契约明确支持独立字段时，正文与表达要求分角色、分字段；表达要求不得进入朗读正文 |
| 首版文本来源 | 画布文本与本地 TXT、Markdown 同时纳入；本地文件经真实解析形成文本上游节点与绑定，不建附件旁路 |
| PDF/Office | 不默认提取为纯文本；只有当前有效 document 契约、导入和执行链真实支持时可选，否则登记缺口，不展示假支持 |
| 保留与停用 | 切换保留全部来源、连线、显式消费意图和顺序；不兼容项持续可见并阻断，替换或停用后重新验证；显式停用实际停止消费 |
| 验收 | 契约无损、全组绑定/停用、实际请求捕获、四类新建空节点真实功能交互与专属截图；模拟不冒充真实生成 |
| 发布边界 | 实现已授权；先演示后合入，不重启、不装未合并代码到共享 Dev、不付费生成 |

### 1.4 用户故事

1. 作为创作者，希望独立新建四类空节点后看到同一种添加入口，以便直接选择有效上游而不用先连线。
2. 作为文案使用者，希望画布文本和本地 TXT/Markdown 都成为可预览、可追踪、可替换、可停用的上游，以便内容不会被隐式复制或继续消费。
3. 作为视频创作者，希望首帧、尾帧角色明确且与通用入口共用选择机制，以便参考素材不会被自动误认成帧角色。
4. 作为配音创作者，希望多份上游正文后接本地正文按确定顺序朗读，以便每段文字只出现一次，文件名和来源名不会被念出。
5. 作为模型切换用户，希望保留所有原素材并看到冲突，以便替换、停用或回切，不丢失创作意图。

### 1.5 Non-Goals

不新建选择器、文本附件系统、第二套文本/媒体兼容内核、独立能力接口或资源库。不中途自动转码、OCR、解析 PDF/Office 正文，不自动猜测文本用途。不改变结果区、计费、音色/参数设计、账号或渠道设置。不把 draft 能力上架，不伪造 execution.live，不为了入口放宽模型准入。不新增营销副标题、装饰图标、冗余能力 Badge、教程横条或工程 ID 展示。

### 1.6 新用户基线

新用户可独立创建空节点，不需要已有连线或开发机专用数据。真实 catalog、产品资格、可用渠道和已实现输入 mapper 是能力前提；画布源为空时显示 `暂无可用素材`，本地 TXT/Markdown 导入是首版必做路径。目录不可用显示 `模型目录不可用`，渠道不可用显示 `当前渠道不可用`，禁用生成，不用静态型号或假输入兜底。空态入口不是输入就绪；必需正文、角色、组合或配置未齐全时不得提交。

## 二、Prototype：信息架构与文字原型

### 2.1 组件树

```text
现有节点配置面板
  素材行
    使用中/保留的素材卡，按稳定顺序
    首帧槽、对调、尾帧槽，仅当前方案含对应角色时
    通用添加槽，同一上游发现入口
  现有文字编辑器
  现有模型、方式、渠道、参数与生成底栏

现有 ResourcePickerModal
  素材标题、关闭按钮
  画布 / 本地
  画布：搜索、条件类型/格式筛选、既有网格/列表切换、候选
  本地：既有导入/拖拽区、解析后的待选条目
  条件方式确认、条件角色选择、一处必要校验原因
  取消、添加；替换会话为取消、替换

现有 SlotHoverPreview
  真实文本或媒体内容、必要角色
  替换、停用；已停用为使用
```

不增加“素材输入”“上游文本”重复区标题。使用和停用文字卡与媒体卡同列，不建立独立文本来源面板。本地编辑器始终是本地来源。

### 2.2 空态与选材旅程

新建节点 → 获取当前模型完整候选能力 → 有上游路径即显示虚线 Plus 卡槽 → 打开同一弹窗 → 选择画布内容或导入本地文件 → 每次选择按已有使用集合和全部待添加项重算 → 有完整方案时 `添加` → 原子创建必要上游、连线、绑定及已确认方式 → 已填卡可预览。关闭、取消不改变目标图的模型、方式、绑定或连线；未确认导入草稿不进入有效消费。

只支持上游文本的方案也显示入口；不因没有媒体槽而隐藏。只支持音频的转写任务不伪造文本入口。纯本地字段且无上游消费契约的方案不伪造上游能力，登记缺口。

发现其他方式时，唯一可行且不同于当前方式的方案显示 `方式：{方式名称}`；多个完整方式显示 `方式` 下拉。目标渠道需要显式变化时，同弹窗显示 `渠道：{渠道名称}` 或 `渠道` 选择，沿用既有渠道意图和可用范围，不开通新渠道。选材、方式及必要渠道意图一次确认，不因发现候选而提前改节点。

### 2.3 首尾帧

当前方式确有首尾帧角色时显示两个角色槽与对调按钮；通用添加槽可继续发现文本或其他完整可行路径。首帧入口固定首帧角色，尾帧入口固定尾帧角色，都打开同一 Picker。通用入口的图片只有一个可行角色时可直接映射，存在首帧/尾帧/参考歧义时用 `角色` 确认，不按两张图片数量自动赋义。

对调保留源节点、输出和边，只交换两个角色绑定；交换后整组约束同时满足才启用。相同来源、输出、角色的重复选择复用已有绑定；同一输出在不同角色重复使用仅在契约明确允许时成立。

### 2.4 已填、替换、停用与冲突

卡片展示真实名称与文本摘录或媒体缩略图，聚焦、悬停及点击复用现有预览。点击卡片不自动插引用 token。替换只改当前稳定绑定、角色和位置，新源经同一整组校验；旧源节点/供给边保留为未消费供给，下一次请求只含新源。取消替换不改变消费。

`停用` 保留卡片、来源、边、角色和顺序，卡片显示 `未使用`；请求、fingerprint、就绪与执行不能通过遍历所有文本边补回该内容。回切或刷新不自动恢复显式停用。`使用` 经整组复核才恢复。

切换仍可用的模型/方式/渠道时，输入不兼容不等于模型本身不可用。所有显式使用意图保留在原位置；格式、容量或角色冲突显示 `不兼容`，必要元信息未定显示 `格式未知` 或 `等待中`，失效来源显示 `不可用`。未解决的使用意图阻断生成，不能以必需槽已齐全为由静默忽略。仅有供给边、未选入或已停用的内容不计入本次消费，也不抢容量。

### 2.5 单正文 TTS 的可观察例子

素材顺序为卡 A 的正文 `第一段。`、卡 B 的正文 `第二段。`，本地输入 `最后一段。`，最终正文按 A → B → 本地顺序组成；合成采用正文段落边界，不注入名称、`来源 1`、`补充要求` 或 token。素材卡叫 `台词.txt` 也不会被读出。停用 B 后为 A → 本地；替换 A 为 C 后 C 保留 A 原位置。每份合法消费身份只出现一次，不按节点屏幕位置、请求完成时间或对象遍历偶然顺序排序。

有独立表达字段时，本地要求进入表达字段，上游正文按顺序进入正文；本地已有明确正文角色不得在切换时静默改成要求。角色无法映射时保留内容并阻断，允许用户在同一机制中显式选择或停用。不根据“温柔一点”等文字内容猜角色。单正文方式中的本地文字既然已被定义为正文，就不再显示 `补充要求…` 或伪称应用了风格控制。

## 三、Spec：UI 元素与逐字文案白名单

### 3.1 锁定范围与设计约束

下表是本功能中文 UI 的唯一新增/替换文案白名单。未列入的元素、Badge、副标题、分割线、提示条、装饰图标和说明文案不得添加。既有面板壳、模型品牌名称、参数和结果区只保留，不授权重写。变量限真实业务数据，不得拼工程 ID 或营销形容词。首版不另创多语言词条；既有英文等入口涉及变更时，由 PM 同步签发等义逐字表，前端不得自行扩写，缺失翻译不能冒充全语言终验。

### 3.3 角色与方式逐字集合

本功能弹窗方式名允许复用已登记逐字名称：`文本对话`、`图文对话`、`多模态对话`、`文生图`、`垫图参考`、`多图垫图`、`文生视频`、`首帧`、`尾帧`、`首尾帧`、`全能参考`、`参考图`、`视频编辑`、`视频延长`、`数字人/对口型`、`文本转语音`、`声音克隆`、`AI 音乐生成`、`语音转文字`、`语音识别`、`文档参考`、`网页参考`。这是显示字符串许可，不是能力上架许可；仅真实 listed、profile/mapping/route 可用的方案才能出现。遇未映射角色/方式不回退工程 ID，先登记工程/文案缺口并补签，不由前端命名。

### 3.5 行为规格

**统一消费身份。** 上游至少保留 source node、选定 output、edge、type、role、slot、稳定 ordinal、可用/元信息状态、正文或资产身份和显式使用状态。供给边仅说明可供给；文本与媒体均由显式消费绑定进入请求。本地编辑是独立 local 来源，不制造假边。`source: node_field` 是请求映射事实，不能据此禁止所有上游，也不能把所有 URL/参数 node_field 自动开放为文本槽。最终字段 max=1 不等于只准一个文本来源。

**整组方案。** 候选可来自当前模型全部真实允许方式，但每项携方式、角色、格式及渠道约束。设 U 为当前仍使用的所有绑定，L 为本地字段和参数语义，A 为全部待添加项，确认必须存在一个 operation 和一条允许渠道同时吸收 U+L+A。必需槽尚缺可继续装填，已知冲突不可通过部分绑定或退回供给池伪造确认成功。元信息未知可保留为待验绑定，不能算 ready。自动路由/回退的每条候选渠道都须独立承接全请求，空交集 fail closed，不删必需槽或组使其假就绪。

**文本组合。** 普通描述/改写：已使用上游正文按素材顺序作为来源内容，本地作为补充要求；只用上游也可满足允许的文本必需字段。单正文 TTS：上游正文按素材顺序，后接本地正文，使用正文段落边界，不加来源或要求标签，不能为空/纯空白，不丢文字、不截断。独立表达字段：按已批准 role 和 mapper 分字段；歌词、风格同理，不按 output=audio 一刀切。上游更新/选择结果变更后重验最新选定输出；提交前冻结同一内容/配置/目录/渠道快照，在途不混版本。

**本地 TXT/Markdown。** 首版支持 TXT（.txt）和 Markdown（.md、.markdown）的真实文本读取，形成统一文本上游。Markdown 默认保留源文本，不做隐式摘要、渲染后提取或去标记，不发文件名作为正文；编码/读取失败明确报错，不能返回空字符串当成功，不把未知文件大小填 0 当验证。解析编码、大小安全限制和资产归属由工程在 importer 合同中明确，不能因此把首版范围降为仅画布文本。取消不留下目标消费绑定或连线；同次多文件导入失败不静默部分成功。

**文档条件支持。** document 的类型声明不证明 Picker/importer/vendor mapper 完整。前置审计已观察 document 槽与选择/导入链差异，本轮未证明真实文档链可用。因此不承诺现有 PDF/Office 可选；实施者若取得同模式同渠道、真实导入和请求映射证据，则通过同一入口开放具体格式，否则保持缺口并明确报告，不以 TXT 扩展名或自动提取绕过。

**切换与恢复。** 模型下架或无资格不得执行；模型可用但对已有输入不合仍可手选切换。保留所有显式消费意图、边、顺序、正文，不 slice 首项、不自动改角色。所有未解决使用项必须阻断；用户停用是明确排除授权。回切可恢复普通冲突的原意图，但显式停用持续生效。未选纯供给不被补入文本，也不因删除编辑器 token 而被误认为已停用。

**旧图。** 不丢来源、顺序、正文、角色和历史结果；将旧的确实已消费文本显式水合为绑定必须有版本化迁移证据，不把所有新供给永久自动消费。具体存储/水合字段由工程规格决定；迁移不能重新启用已停用项或改变历史结果。未知旧消费身份保留并列迁移缺口，不猜测。
