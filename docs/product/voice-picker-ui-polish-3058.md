## 1. PRD：目标、故事与边界

### Problem

用户只找到一个音色时，界面仍像等待一整页内容；已经选中的生成音色在底栏不可辨。试听按钮与整行选中同时带强调色，容易把「正在听」误认成「已经选用」。搜索和筛选应是稳定的操作区，而不是随结果数量移动的目标。

### Solution

保留标题、独立搜索、四维筛选、单层列表及当前音色底栏。列表按真实内容收缩，长列表只在结果区滚动；弹窗顶部锚定，同次打开中搜索框不因过滤而上下跳。当前名称成为底栏主信息；选中反馈属于整行与 Check，试听反馈只属于播放按钮。视觉方向为现有原生中性表面、紧凑控件、清晰文字层级，不换字体、不引入装饰。

### 用户故事与关键旅程

1. 作为配置配音的创作者，希望搜索到一条结果后只看到紧凑结果区，以便快速核对名称，不被大片空白干扰。
2. 作为比较音色的创作者，希望试听另一条时仍能辨认当前已选音色，以免误改生成配置。
3. 作为键盘用户，希望持续输入、筛选与滚动时焦点不被重置，以便不重新寻找输入位置。

核心旅程：打开音色弹窗 → 浏览并滚动完整名录 → 搜索一条 → 试听且不改变当前值 → 清除到全列表 → 搜索空态并清除 → 点击名称区域选择并沿既有行为关闭。

### Non-goals / 新用户基线

不增加确认按钮、结果计数、热门/官方/已验证徽章、营销副标题、插画、波形、播放器、新图标、分组、收藏或可试听筛选。不调整排序、数据源、模型兼容、播放解析、声音候选、计费、参数写入、资产库、全局 Modal/Select 或 design.md；不付费生图，不迁移主题体系，不改门禁或绕 runner policy deny。

新用户仍依赖随包/既有接口提供的音色目录和已验证试听映射，不依赖开发机文件。无试听资格仍能选择；网络试听失败沿原提示。无匹配结果不是加载状态，不用最终空态掩盖仍在加载的数据。

## 2. Prototype：文本结构

以下为待实施结构，不是渲染演示：

```text
固定顶部锚点的既有 CustomModal
  页头：选择音色                       内建关闭
  内容：搜索音色...（独立完整一行）
        语言    口音    性别    场景（独立一行）
        结果区（内容自适应，仅此区纵向滚动）
          试听按钮 | 原始名称 / 真实场景 | 已选 Check
        或：未找到匹配音色 / 条件出现清除筛选
  底栏：既有 AudioLines | 当前音色 | 当前名称
```

全部结果：达到高度上限后列表滚动，搜索/筛选/底栏不随列表滚走。单条：一行结束后以正常内容内边距衔接底栏，无 160px 空槽。空态：短反馈区而非扩张空白。四筛选不塞进搜索同行；窄视口仍不折行，允许筛选区横向滚动，不裁掉任何维度。

### 3.1 尺寸与排版锁定表

下列名称仅是规格引用名，数值作用于本弹窗现有局部规则，**不建立第二套 CSS token 系统**。

| 规格引用名 | 精确值 / 约束 | 适用范围 |

| dialog.width | `min(480px, calc(100vw - 48px))` | 本弹窗，由暂留 540px 回归既有 design |

| dialog.topAnchor | 视口顶部 `15vh`；水平居中 | 同次打开不随结果重新垂直居中；只移动底边，不做高度动画 |

### 3.2 颜色、状态与焦点

沿 T.3 的单一链：表面 `var(--dsw-alias-bg-elevated, var(--dsw-alias-bg-layer-1, var(--dsw-alias-bg-base)))`；外框 `var(--dsw-alias-border, var(--dsw-alias-border-l2))`。名称/输入值/当前名称为 `--dsw-alias-label-primary`；场景/当前音色标签为 `--dsw-alias-label-secondary`，只有占位符可 tertiary。hover 为 interactive-bg-hover；选中行为 interactive-bg-active + 现有品牌描边及 Check；播放中的强调仅保留按钮原有品牌色反馈。light/dark 共用一组语义链，不硬编码颜色，不写 JS 主题分支。

选中与试听同时存在时，Check 仍只跟随原 value，当前音色底栏不跟 playingVoice。播放按钮 Enter/Space 不触发行选择；行本体 Enter/Space 沿原选择并关闭。Tab/Shift+Tab 可达关闭、搜索、全部筛选、可选行、合法试听按钮与空态清除；Escape 先关闭活动菜单，随后沿模态关闭与焦点恢复，不留后台声音。

搜索输入节点不重建；从全部 → 一条 → 空态 → 全部，同一 viewport 的输入框 top/left 偏移各不超过 1 CSS px，焦点/连续输入/中文组合输入不丢。菜单触发器也不随列表数量移动；过滤后只允许结果区与底栏底边改变。不用输入节流、强制 blur、重置查询或冻结整弹窗高度来掩盖跳动。

## 4. Plan：下一轮实施与真实浏览器验收

### 实施边界

1. 前端先读本文、原 §3.3 与 design，确认局部改动落在现有 VoicePickerDialog 与音色样式；只为顶部锚定/内容高度/原控件排布做必要局部结构调整，不改变公共 Modal/Select 的全局语义或 API。
2. 仅按批准值实施几何和层级；继承既有主题纠偏。保持试听资格、播放生命周期、选择事件隔离及动态名字数据来源。若需要业务状态或 runner 修改才能达成，不自行扩大，报告具体原因。
3. 工程负责人按现有 QA 契约选择最小测试集和隔离浏览器路径。测试证明尺寸/事件/参数不变量，不能代替截图与真实媒体事件。遇 policy deny 记录阻断并上报，不更改 runner 或绕行。
4. 同源码指纹下留存下表新证据，PM 对源码白名单与 display_file 人眼复检终验，再向用户展示真实改后界面。不得复用 round6 原图冒充改后结果。

### Real-browser acceptance

桌面 `1280×800` 与 `1920×929` 各检查；紧凑 `390×844` 检查无横向外溢及筛选可达。light/dark 使用真实官方主题。截图与测量记录包含源码指纹、时间、实际 viewport 与主题；每一场景不得用主页冒烟替代。

| 场景 | 必须执行的真实操作 | 验收条件与证据 |
|---|---|---|
| 全列表 | 从真实画布节点打开弹窗，清空条件，滚动首/末条 | 全目录可达；只结果区滚动；控件/底栏固定可用；列表上限 320px/剩余预算；保存首末专属截图 |

| keyboard / 窄态 | Tab/Shift+Tab、行及试听 Enter/Space、Escape；中文组合输入；窄态横向访问四筛选 | 焦点可见且不陷落；试听键不改选中；行本体可选；关闭后恢复触发器焦点且停止；四维都可达、不折行、不把搜索滚走 |
