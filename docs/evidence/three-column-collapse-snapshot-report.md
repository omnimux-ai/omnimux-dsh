# 收起左侧栏时按点击瞬间快照分栏比例（工单 #2074 续 2）

## 结论

前两版修复（PR #2076、#2087）后，开发版真机 CDP 实测仍暴露第三个缺口：收起左栏时会话栏被压到
420px 回退值，右侧工作台反而吃到 1500px。

根因：基准只在几何同步循环里取样，而该循环**只由已观察到的 DOM 变更触发**。应用启动时右侧工作台
尚未挂载（基准保持回退值），此后右栏挂载不触发循环，基准一直陈旧到用户点击——而那次点击正是收起动作。

修复：把快照挪到**点击收起的那一刻**，在触发官方折叠之前、帧仍处于三分栏形态时取样。

| 实测状态（1920 视口） | 修复前 | 修复后（预期） |
| --- | --- | --- |
| 展开 | 280 / 776 / 864，基准 **420px** | 280 / 776 / 864，基准 **776px** |
| 收起 | 0 / **420** / **1500** | 0 / **776** / **1144** |

## 修复内容

| 文件 | 改动 |
| --- | --- |
| `plugins/omnimux/src/client/sidebar-toggle-topbar.js` | 把基准取样抽成导出的 `rememberConversationWidth(doc)`（右栏 ≥ 200px 且会话栏 ≥ 420px 才接受）；同步循环继续调用它，**点击处理器在 `triggerClick(official)` 之前额外调用一次** |
| `plugins/omnimux/src/client/sidebar-toggle-topbar.test.js` | 新增 4 项用例：按需取样写入、无右栏拒收、低于地板拒收、快照必须早于触发折叠 |
| `specs/three-column-collapse-snapshot.spec.md` | AC-301 ~ AC-304 |

### 3. 前两版为何漏掉

隔离夹具每一帧都是三分栏且同步循环必然重跑，因此既复现不了「单栏读数污染」（#2087），
也复现不了「同步循环不触发导致基准陈旧」（本次）。二者都只在真实客户端启动时序下出现，
**开发版 CDP 实测因此固定为本任务的验收步骤**。
