# 规格：根治点击复刻后附件挂载提醒把页面拉回顶部的跳动 (Fix Attach-Reveal Scroll Spec)

## 一、需求背景与实机取证
- **用户反馈**（附实机截图）：在「软件应用与 SaaS」货架深处浏览时点击卡片「复刻」，页面先猛然跳回顶部、输入框随后才在底部显示。重启应用后问题依旧。
- **实机取证（CDP 全程滚动监听）**：点击当刻，宿主附件系统的提醒逻辑连续 3 次调用 `omx-attachment-dock.scrollIntoView()`（堆栈：`attachTemplateToConversation` → `handleReveal` / `revealAttachments` → `highlightLatestCard`）。此刻输入框仍在顶部文档流内，强制滚动定位把视口从浏览深处（如 1566px）拉回顶部；随后吸底状态才生效，形成「先跳上去、再降到底」的抽动。
- **根因**：`handleItemRecreate` 中 `attachTemplateToConversation`（触发宿主滚动定位）先于 `onApplyTemplate`（触发吸底）执行；上一版修复只锁住了聚焦环节，未防住更早触发的附件提醒通道。

## 二、根治方案
1. **吸底先手（同步落 DOM）**：`dock()` 被调用的同一帧内，立即以同步 DOM 操作写入停靠几何与 `data-omnimux-dock-open` 属性，把输入框物理转为视口底部 fixed 形态，不再等待组件渲染周期；同时记录当前真实滚动位置。
2. **顺序矫正**：`handleItemRecreate` 中先调用 `onApplyTemplate`（触发吸底先手），再执行 `attachTemplateToConversation`。附件提醒的强制滚动定位落在已 fixed 的输入框上，天然失效（固定元素已在视口内，无需滚动）。
3. **动画无损保留**：先手瞬间同步记录输入框原始视觉位置并做反向位移补偿，渲染周期到达后释放过渡，FLIP 平滑动画完整保留。
4. **兜底锁定不变**：吸底就位帧继续核验滚动读数，若有意外抖动原子恢复。

## 三、验收标准
1. 页面浏览至任意深处点击「复刻/使用」，视口位置 0 像素位移，输入框直接在底部平滑升起；
2. 附件缩略图正常挂载、提示词正常预填、光标正常聚焦；
3. 新增「附件强制滚动定位不再拉动页面」的回归断言，全量测试 100% 绿灯；
4. CDP 直连开发版客户端实机复测通过并留存截图证据。
