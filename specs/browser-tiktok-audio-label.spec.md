# TikTok 菜单第二项改名为「下载音频」（Issue #3590）

## 1. 业务目标

第二项的实际行为是把原声音轨下载到「下载」目录，但文案是「保存原声」，与相邻的「下载视频」措辞不一致。改为「下载音频」/「Download audio」，动作与行为不变。

## 2. 范围

1. `plugins/omnimux-browser/extension/src/content/tiktok-scene/copy.ts`：zh `menu.audio` = `下载音频`，en `menu.audio` = `Download audio`。
2. 不变：动作 id `audio`、菜单顺序、「提取音轨中」的进行中文案、失败文案、图标。
3. 历史规格（`platform-adaptation-anchor` AC-304、`tiktok-vertical-menu`）中列出的旧标签由本规格取代标签部分，不改历史文件。

## 3. 非目标

- 不改音频提取、下载落盘、入库链路。
- 不改另外两项文案或菜单布局。

## 4. 成功标准

- **S1** 默认菜单中文：下载视频 / **下载音频** / 收藏到灵感库；英文：Download video / **Download audio** / Save to library。
- **S2** 点击第二项仍触发 `audio` 动作，进行中显示 `提取音轨中`。
- **S3** 扩展单测全绿、`node scripts/build.mjs` 通过、真实浏览器截图（fixture + 构建产物）留存于 `.agent-reports/`。

## 假设

- 假设三个动作的语义不受标签影响：`audio` 仍是同一条宿主快捷动作，只是用户看到的措辞变化；菜单项点击、进行中、失败路径都不依赖标签文本。
- 假设「下载音频」与「下载视频」并列时语义清楚，且不会与「收藏到灵感库」的入库语义混淆。

## 证伪方式

- 用构建产物在真实 tiktok.com origin 的弹窗夹具上渲染菜单：若第二项仍显示「保存原声」，或点击后不再触发 `audio`/进行中不再显示「提取音轨中」，则本实现被证伪。
- 若单测里出现依赖字面量的断言失败（说明还有别处硬编码旧标签），也按证伪处理并回到源码修正。

## 文档影响

只新增本 spec；历史规格中的旧标签清单作为历史记录保留，本 spec 声明标签部分已被取代。
