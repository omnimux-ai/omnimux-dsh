# 规格：推特助手候选池评分、Jev 视角决策、去 AI 味规则与生成日志（#3100）

## 1. 背景
- 发帖框为空时只固定取信息流前 3 条，无评分、无关键词适配。
- 文案无鲜明视角，AI 腔重（大词套话、假升华、机械排比）。
- 生成过程无可追溯记录，无法复盘与调优。

## 2. 新用户基线
- 依赖：出厂浏览器扩展 + 出厂 `omnimux-browser` 插件 + 执行中枢（`textComplete`、`decisions` 席位）+ `$DSH_HOME`。
- 未登录 / 未配置 Jev：视角改由本地规则决定，日志标 `source:"rules"` 与原因；文案生成走原有补全通道，失败时提示「模型服务暂未响应」。
- 日志写入失败（服务未连通）：仅保留扩展本地缓存，条目标 `persisted:false`；不影响生成。

## 3. 行为规格

### 3.1 候选池与评分（发新帖、发帖框为空）
- 自上而下扫描页面已渲染的推文，最多 50 条；跳过广告/推广、正文 < 25 字、发帖框所在推文。
- 不自动滚动页面；可见不足 20 条时按实际数量处理，日志如实记录 `candidatesScanned`。
- 四维得分（0–100），总分 = 0.30×关键词 + 0.30×争议度 + 0.20×信息密度 + 0.20×爆发力：
  - 关键词：命中关键词数 / 关键词数；无关键词时 50（中性）。
  - 争议度：回复数相对转发数的比值（含平滑），封顶 100。
  - 信息密度：数字、英文专有名词、正文长度。
  - 爆发力：(回复+转发+点赞) / 存活小时数，对数映射。
- 总分 ≥ 75 的入选，按总分降序最多 3 条；无达标则走「纯原创」（`inputMode: PURE_ORIGINAL`），不硬塞灵感。

### 3.2 六大视角
| ID | 名称 | 写作指令要点 |
| --- | --- | --- |
| P1_CONTRARIAN | 反常识批判者 | 首句给出反直觉判断，挑战主流共识，结尾抛出站队式反问 |
| P2_PRACTITIONER | 一线实战老兵 | 只用素材里出现的场景与数字，写「原以为 A，实际是 B」的落差 |
| P3_SIMPLIFIER | 降维普及者 | 不用黑话，用一个生活类比讲清本质，说明和普通人的关系 |
| P4_ARBITRAGEUR | 商业套利猎手 | 从成本、时间、回报算账，点出确定收益或亏损陷阱 |
| P5_OBSERVER | 冷眼趋势观察家 | 跳出单品争论，讲二阶影响：谁受益、谁被替代 |
| P6_PEER | 真实同壕战友 | 平视同路人口吻，说出普遍的困境与真实感受，克制收尾 |

### 3.3 视角决策
- 首选 Jev：桥方法 `bridge.evaluateDecision`（服务端经 `ctx.get('decisions').evaluate`），3 秒预算。
- Jev 不可用、超时、返回不在候选内 → 本地规则：争议 → 工程数字 → 新名词 → 商业词 → 格局词 → 情绪词，均不命中默认 P2。
- 视角只作用于「发新帖」「引用转发」；回复类场景不注入视角。

### 3.4 去 AI 味规则
- 全部菜单项的系统提示词使用统一的「去 AI 味母语编辑」规则段（中/英两版），替换原严格规则段，保留零前言、单条、字数铁律（中文 45–85 字，英文 ≤ 220 字符）。
- 生成后扫描禁用表达（深入探讨、至关重要、赋能、闭环、底层逻辑、不仅是…更是、标志着…新篇章、让我们拭目以待、未来可期 等）；命中则带违规清单重试 1 次，仍命中照常回填并写入日志。

### 3.5 新菜单项
- 「多视角爆款创作」（`ai-perspective-post`），场景：发新帖、引用转发。

### 3.6 生成日志
- 文件：`$DSH_HOME/omnimux-browser/twitter-copilot.ndjson`（经 `dshHomePath`），每行一条。
- 扩展缓存：`chrome.storage.local['omnimux_twitter_copilot_log']`，环形保留 100 条。
- 字段白名单：`traceId, ts, scene, itemId, locale, inputMode, keywords, candidatesScanned, qualifiedCount, seeds[{author,textSnippet≤200,total,scores}], perspective{id,source,confidence?,latencyMs?,fallbackReason?}, generation{latencyMs,rawLength,finalLength,retried,humanizeViolations[]}, outcome{status,reason?}`。
- 不记录完整原推、草稿全文或任何凭据；单条 ≤ 16KB。
- 「用户最终是否发送」本期不采集。

### 3.7 设置
- 扩展设置页新增「推特赛道关键词」标签输入：输入后按回车或输入逗号即生成一个标签；标签可点 × 删除，输入框为空时按退格删除最后一个；去重、最多 12 个、每个 ≤ 24 字；每次增删即存本地；提取器读取后与草稿合并使用。

## 4. 验收标准
- AC-1 候选过滤与评分：单测覆盖广告/短文过滤、四维边界、阈值截断、无达标走纯原创。
- AC-2 视角规则：12 条标注样例（每视角 2 条）全部判对；Jev 参数截断正确。
- AC-3 去 AI 味：所有菜单项提示词含统一规则段；违规扫描单测正确；提示词无 `undefined`。
- AC-4 桥方法：成功 / 参数非法 / 未授权 / 依赖缺失 均有用例；日志追加到 `dshHomePath` 下。
- AC-5 产品基线、模块边界、反兜底门禁通过。
- AC-6 真机（ego-browser，任务工作树构建产物）：空发帖框多视角生成回填并点亮发帖按钮；引用弹窗生成；详情页回帖菜单不回归；日志文件出现对应 traceId；全程不点击发送。

## 4b. 真实环境验收后的修复（2026-10-05）
开发版真实模型验收：文案生成、填入、发帖按钮亮起、日志文件写入均正常，暴露两处问题并在此修复：
- Jev 素材永不为空：草稿、被引用原推、入选热帖都没有时，用赛道关键词组成写作背景；连关键词也没有，用「一线从业者的日常观察」。此前空素材被服务端以 bad-request 拒收，Jev 从未生效。
- 无达标热帖时的模型提示直接给写作任务，不出现「评分 / 门槛 / 信息流」等内部说法（此前模型把「没有热帖达到评分门槛」原样写进文案）；中英文一致。
- AC-7（单测）：空草稿、无热帖、无关键词时 Jev 素材非空且 ≤ 2001 字；无达标热帖的中英文提示不含「评分 / 门槛 / 信息流 / quality bar / feed」。
- AC-8（真机，开发版）：首页空发帖框生成一次，新日志条目的视角回落原因不再是 bad-request；全程不点击发送。
- 另记：开发版 Jev 服务本身返回「Invalid URL (POST /v1/decisions)」，属运行环境的服务地址配置，单独排查，不在本次代码修复内。

## 4c. 视角并入「爆款推文复刻」，移除「多视角爆款创作」（2026-10-05 用户决定）
- 移除菜单项「多视角爆款创作」（`ai-perspective-post`），不再新增菜单；§3.5 作废。
- 「爆款推文复刻」（`ai-hot-tweets`）改造为：先选视角（Jev 优先，失败回落本地规则），再按视角写：
  - 有草稿：以草稿为主题按视角改写；
  - 无草稿、有入选热帖：从热帖提炼钩子，按视角写全新原创，不复述原帖；
  - 无草稿、无入选热帖：围绕赛道关键词按视角原创（§4b 的提示不变）。
- 场景只保留「发新帖」；引用转发沿用现有引用类菜单，不注入视角。
- 其余发帖菜单（行业长推串、金句、热点借势、地道英文）保持现状，不注入视角。
- AC-9（单测）：菜单中不存在 `ai-perspective-post`；发帖菜单数回到 5；`ai-hot-tweets` 标记使用视角，系统提示含「写作视角：<名称>」，且三种素材分支各自成立；只有它使用视角。
- AC-10（真机，开发版）：推特首页点「爆款推文复刻」生成并填入发帖框；日志 `itemId=ai-hot-tweets` 且带视角字段；菜单里看不到「多视角爆款创作」；不点击发送。

## 4d. 双来源素材 + 优先带评论转发的爆款 + 复刻二创（2026-10-05 用户决定）
- 入选门槛由 75 调为 **65**（§3.1 中的 75 作废）。
- 素材来源扩大到首页「为你推荐」与「正在关注」两个标签：发帖框为空、在首页顶部发帖框点「爆款推文复刻」时，先采当前标签已渲染的推文，再自动切到另一个标签采集，采完切回原标签；每个标签最多 50 条，按「作者 + 正文」去重。不在首页或发帖框在弹窗内时只采当前页面。切换失败（标签不存在、5 秒内未加载）不影响生成，日志如实记录各来源条数。
- 识别「带评论转发」（帖子本身引用了另一条帖子）：拆出转发者的评论正文与被引用原帖的作者、正文；评论正文 ≥ 4 字且评论 + 原帖合计 ≥ 25 字即可入池。关键词与信息密度按评论 + 原帖合并计算。
- 入选排序：达到门槛的帖子里，带评论转发的排在前面，其次按总分；最多 3 条。
- 「爆款推文复刻」拿到入选帖时改为复刻二创：先拆它为什么火（对原帖用了什么角度、开头钩子、节奏），再按这个爆点结构写一条全新原创，换成自己的内容与赛道，不照搬原句、不提原帖或原作者。
- 日志新增：每条入选帖的 `isQuote`、`source`（for_you / following / page）；顶层 `sourcesScanned`（各来源条数）。
- AC-11（单测）：门槛为 65；带评论转发能拆出评论与原帖；同分时带评论转发优先；去重生效；复刻二创提示含原帖与评论且要求按爆点结构原创。
- AC-12（真机，开发版）：首页点「爆款推文复刻」，日志 `sourcesScanned` 同时含两个来源且条数 > 0，页面最终回到原标签，文案填入发帖框；不点击发送。

## 4e. 决策模型按语义挑爆款（2026-10-05 用户决定，取代 §4d 的字面关键词门槛）
- 目标：「爆款推文复刻」尽量每次都拿到一条**够热且贴合赛道**的真实帖子做复刻二创。
- 第一步「够不够热」（规则）：热度分只看互动规模、爆发力、争议度、信息密度（不含关键词）；取热度分 ≥ 40 的前 8 条作候选，带评论转发同分优先。
- 第二步「对不对路」（决策模型 Jev）：把 8 条候选作为选项、赛道关键词作为状态，问「哪条最值得按这个赛道做复刻二创」，另设「都不贴合」选项；选中即作为唯一复刻素材。
- 回落：决策模型不可用、超时或选「都不贴合」时，沿用 §4d 的规则打分（门槛 65）；仍无达标走纯原创。
- 只在「爆款推文复刻」发帖框为空时调用；其他菜单不变。
- 日志新增 `seedPick`：来源（jev/rules）、候选数、选中项、置信度、耗时、回落原因。
- AC-13（单测）：热度分不含关键词；候选最多 8 条且热度 ≥ 40；决策参数含候选正文、赛道和「都不贴合」；选中项成为唯一素材；「都不贴合」/失败时回落规则并记录原因。
- AC-14（真机，开发版）：首页点「爆款推文复刻」，日志 `seedPick.source=jev` 且选中一条真实帖子，生成走复刻二创分支（inputMode=AUTO_FEED_HOT）；不点击发送。

## 4f. 视频帖不再被当成广告（2026-10-05 真机缺陷）
- 现象：推特给每个视频播放器都套了 `placementTracking` 标记，原广告判断只看这个标记，导致所有视频帖被当广告丢弃；「为你推荐」以视频为主，实测每次只剩 1 条可用。
- 修复：广告只按帖子上的「Ad / Promoted / 广告 / 推广」标签判断；`placementTracking` 仅在不包含视频播放器时才算广告。
- AC-15（单测）：带视频播放器的普通帖进入候选池；带「广告」标签的帖仍被排除。
- AC-16（真机）：首页「为你推荐」采集条数明显多于修复前（修复前 1 条）。

## 4g. 挑爆款结果写进每一条日志（2026-10-05 真机缺陷）
- 现象：真机生成成功时日志里缺 `seedPick`，只有失败分支带上了，无法确认是决策模型选中还是规则回落。
- 修复：成功填入、生成为空、生成失败三种结局的日志都带 `seedPick`。
- AC-17（单测）：三处写日志调用都传入挑爆款结果。
