# 规格：会话输入框原生添加文件图标隐藏与指令菜单三项收敛

Issue: #2188
插件: omnimux
日期: 2026-09-17

## 1. 目标

1. 隐藏会话输入框底栏原生的独立「添加附件（回形针）」图标按钮，避免与「+」号菜单职责重叠，净化输入工具栏。
2. 将「添加文件」能力收纳整合至「+」号指令菜单中，点击后直接唤起系统原生文件选择对话框。
3. 指令菜单全量收敛净化，除「添加文件」「从资产库添加」「计划模式」3 项核心能力外，全面隐藏原生的其余 5 项底层指令（压缩历史、会话反馈、权限预设、fast、model 等）。

## 2. 成功标准

1. 会话输入框底栏的原生回形针附件图标（`button[aria-label="添加附件"]` / `button[aria-label="Add attachment"]`）不再占用工具栏空间，完全隐藏。
2. 点击「+」号按钮展开的指令菜单中，只呈现且严格呈现 3 个指令选项：
   - 「添加文件」（`add-file`）：图标为回形针，描述为从本地选择文件或图片。
   - 「从资产库添加」（`add-from-library`）：图标为统一资产库，描述为从统一资产库选择素材。
   - 「计划模式」（`plan`）：图标为灯泡，描述为开启或退出长任务计划模式。
3. 点击或键盘 Enter 选择「添加文件」时，无缝触发原生 `<input type="file">` 点击，直达系统文件选择器，零额外弹层。
4. 原生底层指令（`compact`、`feedback`、`permission`、`fast`、`model` 等）在候选列表与「+」菜单中完全不可见。
5. 相关单元测试 100% 通过，无回归破坏。

## 3. 边界

- 总是：精准隐藏原生回形针图标；保留 DOM 中的原生 file input 保证文件上传链路完整可用；「+」菜单仅允许 3 项白名单命令。
- 绝不：破坏既有的资产库选择链路；破坏原生文件上传和附件配额逻辑；修改底座不可碰代码。

## 4. 验证

1. 单元测试覆盖：
   - 候选白名单过滤契约（仅返回 add-file、add-from-library、plan）。
   - add-file 菜单项本地化名称、描述、回形针矢量图标与关键词匹配。
   - add-file 点击直达触发原生文件选择器。
   - placement CSS 样式表中包含隐藏原生添加附件按钮的样式规则。
