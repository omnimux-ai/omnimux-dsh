## T0 · 固定基线与证据命令

**类型**：验证 / 基础设施纵向票　**阻塞**：无　**建议变更风险**：R2（以实际改动复核）

**目标**：建立可重复的干净构建基线，为后续 20% 相对下降目标提供可比较的绝对 UTF-8 字节数，并核实发布包与证据产出入口。

**范围**
- 锁定基线源码 SHA、干净状态、Node/pnpm/esbuild 版本、lockfile 身份、构建选项及命令。
- 成功构建后记录原始和 ModuleLoader 包装后输出的 UTF-8 字节数；压缩值若可稳定取得则另列，不能替代原始口径。
- 核实模板 JSON 在客户端产物的贡献计算，避免与包含模板数据的上层模块重复计数。当前 `plugins/omnimux/scripts/build-client.mjs` 未开启 `metafile`，本票须以最小改动产出 metafile/依赖图证据，或给出等价的可复算静态证据，并说明对构建产物的零行为影响。
- 核实发布包打包、解包和资源可读的命令。已核实的候选：`plugins/omnimux` 下 `npm pack`（触发 `prepare` → `npm run build`，产物含 `files` 白名单内的 `src/`、`lib/client.js`、`cordis.patch.yml`）→ `tar -xzf <tgz> -C <临时目录>` → 断言 `package/src/client/session-guide/templates/creative-templates.json` 可读并计算 SHA-256。本票负责实际执行并记录；若该路径不满足，票面列明阻塞点而非写 PASS。
- 核实本功能可用的隔离浏览器验收入口。已核实：`pnpm test:worktree-web`（Stage 夹具运行器，伪造宿主，只覆盖其声明的局部证据）与 `pnpm verify:app`（即 `node scripts/worktree-app-qa.mjs`，完整应用 + 同源登录 + 真实浏览器 + PNG/结构化报告，证据落 `.workbuddy/evidence/app-qa/<runId>/` 与 `docs/evidence/worktree-app-qa-report.json`）。本票须把 T3/T4/T6 的任务专属场景入口落到可执行文件或命令参数上；通用运行器本身不构成业务验收。
- 已核实的测试发现边界：`plugins/omnimux/scripts/run-tests.mjs` 只收集 `plugins/omnimux` cwd 下 `src/**/*.test.{js,ts}`，`tests/e2e/*.e2e.test.mjs` 与其余目录不被收集且需在外层标注。各票新增的 seam 测试必须落在被收集的位置，或在票面显式声明独立命令。

**候选 seams / 验收**（逐票评审时确认命令及脚本是否值得落盘）
1. 从干净状态以记录的命令构建成功：`corepack pnpm --filter omnimux run build`，证据含源码 SHA、`pnpm-lock.yaml` 哈希、`node -v` / `pnpm -v` / esbuild 版本（`plugins/omnimux/package.json` `devDependencies.esbuild` 与 lock 解析版本）、构建选项、退出码。
2. UTF-8 字节统计可复算，明确区分未包装与包装产物；用固定样本证明使用 `Buffer.byteLength`/`statSync().size`（字节）而非 `wrapped.length`（字符数）。
3. 执行打包/解包命令并断言解包产物中模板数据可读、其 SHA-256 与源码内文件一致；记录 tarball 名称、临时目录清理方式。
4. 输出可供 T6 同口径复测的机器可读报告模板/字段，不引入不必要依赖。
5. 记录真实浏览器运行器的业务入口/身份绑定要求（worktree 根目录、动态端口、自清理、源码 SHA 绑定）；此票可确认入口，不能把后续业务行为测试标为通过。

**非目标**：修改生产客户端架构、改变产品预算、以一次性开发机产物代替固定基线。

**授权边界**：仅在该票单独发布并获实施授权后，才可做为可复现报告所必需的最小脚本/文档改动；不授权优化实现或业务代码改动。

## T1 · Host 本地模板数据与同步合同

**类型**：Host 数据能力　**阻塞**：T0　**建议变更风险**：R1（插件公开工具/HTTP 合同，按实际 diff 复核）

**目标**：将完整模板记录与纯选择逻辑从客户端展示模块移至 Host 包内数据模块，保持 Host 工具同步行为及既有消费者语义，并提供快照 HTTP 资源。

**范围**
- 将创意模板数据和纯选择逻辑放入不依赖 React、DOM 或浏览器服务的模块；Host 工具及 HTTP 适配器只依赖该模块。
- 保持工具 ID、参数、摘要字段、默认值、同步返回、搜索大小写归一与匹配、总数/limit、详情首次匹配等规格合同。
- 新增父规格 §3.3 定义的 `GET /omnimux/templates/creative` 版本化快照：原始有序记录、基于发布包 UTF-8 原始 JSON 字节计算的小写十六进制 SHA-256 `dataVersion`、no-store、JSON、错误码和访问边界；仅数据文件缺失/不可读返回 503 `templates-unavailable`，有效空数组返回 200 与 `items: []`；非 GET 405，不增加副作用或监听器。
- 路由随插件生命周期注册/注销；发布包包含数据，Host 不读开发机绝对路径或外部软链。

**候选 seams / 验收**
1. 同一 fixtures 在迁移前后比较搜索、详情、分类/货架输出；包含 id/appId、大小写、默认值、total、limit 边界、原始顺序、重复与首次匹配。
2. 纯数据模块单测证明不依赖 DOM/React，并保留完整数据记录。
3. HTTP 集成覆盖成功 envelope、对发布包 UTF-8 原始 JSON 字节计算的小写十六进制 SHA-256 稳定性/数据变化、有效空数组返回 200 且 `items: []`、缺失或不可读数据 503 `templates-unavailable`、意外内部错误 500 且不泄露路径/堆栈、非 GET 405。集成测试须启动真实 Host（或经审定的等价绑定方式，如直接调用已注册路由处理函数并说明等价理由）；仅断言纯函数不构成本项证据。
4. 验证跨站读取不绕过现有 Host 访问控制，不新增匿名/外部监听；验证卸载后路由注销。
5. 在隔离 Host 运行中验证路由确实响应；后续浏览器接线前仅作为 Host 合同证据，不宣称 UI 验收完成。
6. 安装包可读取资源的最终证据由 T6 汇总，T1 负责留下资源声明/构建输入证据。

**测试落点（已核实）**：新增测试文件须放在 `plugins/omnimux/src/**` 下以 `.test.js`/`.test.ts` 命名，方能被 `corepack pnpm --filter omnimux test`（`scripts/run-tests.mjs`）收集；若选择其他位置，票面必须显式声明独立执行命令并保证 CI 收集。本票可执行的命令集合（在票面最终确认）：`corepack pnpm --filter omnimux test`、`corepack pnpm --filter omnimux run build`。

**非目标**：改 Host 同步合同、远程获取模板、迁 Apps 数据/路由、删除旧客户端视图、改变模板内容或顺序。

**授权边界**：如需改变宿主访问控制、跨域策略或对外监听模型，必须暂停并另行取得明确确认。

## T2 · 客户端快照适配器与共享请求生命周期

**类型**：客户端数据适配　**阻塞**：T0、T1　**建议变更风险**：R2（按对外影响复核）

**目标**：实现单实例按需获取、校验、缓存与取消语义，为客户端迁移提供 Promise API，不改变 UI。

**范围**
- 实现 `loadCreativeTemplates({ signal } = {}) -> Promise<ReadonlyArray<Record>>`；请求 Host 快照并复用当前规范化与 featured 合并顺序。
- 按父规格实现一个成功缓存、一个共享 in-flight 请求；调用者取消隔离、全取消/卸载中止底层请求、代次保护、失败不缓存/不自动重试、显式再次调用可重试。
- 对 schemaVersion/dataVersion/items/基础记录结构进行校验；未知业务字段原样保留，未知协议版本显式失败。
- 插件卸载清空数据；不得允许过期响应写入缓存。分类派生缓存若保留，必须依赖快照版本并按合同失效。

**候选 seams / 验收**（建议通过注入 fetch、受控 deferred 与 AbortSignal 测试，不要求新增测试框架）
1. 首次请求、成功缓存命中、并发共享同一请求、显式请求失败后的重试。
2. 单调用者取消仅自身得到 AbortError；预取消不发 fetch；所有调用者取消时请求中止；新旧请求代次交错时旧 finally/响应不污染新状态。
3. 卸载中止并清空缓存，卸载后旧响应不写回；取消结果不变成业务失败状态。
4. 网络错误、非成功 HTTP、无效 JSON、schema 错误、未知 schemaVersion 都显式拒绝且不缓存。
5. featured 前置、模板后置、记录规范化、数组只读类型合同与重复/顺序不变。

**测试落点（已核实）**：适配器测试文件须放在 `plugins/omnimux/src/**` 下（`.test.js`/`.test.ts`），以被 `corepack pnpm --filter omnimux test` 收集；注入 fetch/deferred/AbortSignal 的受控测试不要求真实浏览器。本票无 UI 验收。

**非目标**：组件 UI 文案、自动重试、持久化/LRU、多版本并存、分页、预取。

**授权边界**：若技术实现要求改变快照合同或新增运行时依赖，停止该变更，先修订规格并单独确认。

## T3 · 探索页模板消费迁移

**类型**：客户端垂直迁移（数据接线 + 原界面行为）　**阻塞**：T2　**建议变更风险**：R2

**目标**：探索页在实际需要创意模板时异步读取适配器，不改既有页面布局、可见文案、筛选/详情语义或入口行为。

**范围**
- 迁移探索页分类、货架、详情所需的数据访问，显式 await 后再执行数组操作和纯选择器。
- 保持 featured-first 合并、原有分类缓存语义并绑定快照版本；只显示 featured apps 时不加载完整 JSON。
- 为组件卸载、上下文切换和快速重入提供取消/代次保护，避免旧结果覆盖。
- 首屏若本身走到创意模板消费路径，准确记录请求发生时机及传输字节数。

**前置 UI 门禁**：如加载、空、失败状态需改变任何可见内容，先补齐本票专属 PRD、原型、逐字文案白名单、Spec/Plan 并核验 `design.md`；没有获批文案不得自创。优先沿用当前状态组件。完成实现后取得 PM_SIGN_OFF。未经这套产品门禁授权时，本票可验收的非 UI 行为限定为：保持当前可见界面不变，完整成功加载路径按现有行为展示数据；在受控失败/取消场景断言无未授权界面变化、无陈旧数据覆盖，且记录拒绝/取消结果的程序化状态，不以新增 DOM、截图文案或无障碍标签作为可见状态反馈。无法在不改变可见界面的条件下区分加载、真实空与失败时，该部分标记为未验收并等待产品门禁，不得宣称通过。

**候选 seams / 验收**
1. 既有探索页真实浏览器路径覆盖分类、货架、详情及 featured-only 不发请求；数据路径和触发操作由本任务夹具/入口明确。
2. 慢响应下组件离开/切换上下文/快速连续触发，不显示过期结果；AbortError 不呈现为业务错误。
3. 产品门禁已完成时，加载/真实空/失败各有可观察且互不混淆的批准状态，并逐项匹配本票白名单、附 PM_SIGN_OFF。产品门禁未完成时，限定按本票“前置 UI 门禁”约定验收可见界面不变及程序化结果；不能满足区分性的部分标记未验收，不阻止其余非 UI 迁移验收。
4. 截图及结构化报告绑定实际运行 worktree 服务、动态端口、源码身份；保留当前文案和布局的对照。
5. 首屏/操作触发点与 HTTP 请求字节纳入报告，不将 JS 减少误报为总首屏性能改善。

**测试落点（已核实）**：Node 行为测试放入 `plugins/omnimux/src/**`（`.test.js`/`.test.ts`）由 `corepack pnpm --filter omnimux test` 收集。真实浏览器验收使用任务隔离 worktree 内 `pnpm verify:app`（完整应用，动态端口、自清理、PNG + 结构化报告落 `.workbuddy/evidence/app-qa/<runId>/`）；本票须在实施时声明该运行器中本任务专属的断言步骤（探索页分类/货架/详情路径），不得以运行器自身“应用就绪”检查代替业务断言。`pnpm test:worktree-web` 的 Stage 夹具不得充当本票验收。

**非目标**：新 UI 标签/图标/文案、视觉重做、过滤/排序语义更改、分页与首屏性能承诺。

**授权边界**：没有产品四件套与 PM 签收时，只能保持原可见界面或将该票停在门禁前；不得先行实施 UI。

## T4 · 素材库与资产中心模板消费迁移

**类型**：客户端垂直迁移（素材库 + 资产中心）　**阻塞**：T2　**建议变更风险**：R2

**目标**：将素材库与资产中心对完整模板的同步读取改为异步适配器，保留各自既有交互/顺序/空态合同。

**范围**
- 迁移素材库加载模型和资产中心加载逻辑，异步解析后再执行 slice/map/选择器。
- 并列消费可共享 T2 的同实例缓存，但不建立独立重复网络缓存；分别处理组件生命周期与上下文切换。
- 保持现有模板选择、顺序、重复、过滤、空结果与错误行为；若现状错误/空状态无法区分，先记录并按 UI 门禁处理，不擅自改变可见状态。

**前置 UI 门禁**：两个消费路径分别核验是否需出现新/改可见加载、错误或空状态。任何可见变更都须事先由产品经理核定各自 PRD、原型、逐字文案白名单、Spec/Plan 与 `design.md`，完成后 PM_SIGN_OFF。

**候选 seams / 验收**
1. 真实隔离浏览器分别打开素材库、资产中心路径，验证成功数据呈现、既有顺序/选择语义及请求共享/缓存。
2. 人为控制慢响应并切换/卸载组件，陈旧结果不覆盖当前上下文；取消不得显示为错误。
3. 产品门禁已完成时，网络/HTTP/schema 失败路径具有批准且可观察的区分，并附逐字文案核对及 PM_SIGN_OFF。产品门禁未完成时，按本票“前置 UI 门禁”约定只验收可见界面不变、程序化结果可观测、取消/失败不导致陈旧数据覆盖；无法在无可见差异条件下证明真实空与失败区分时标记该场景未验收，不阻止其余非 UI 迁移验收，也不得报告该场景通过。
4. 报告包含操作步骤、可观测数据行为、截图/结构化报告和运行源码身份。
5. 构建依赖图证明客户端消费者不再静态依赖完整模板数据模块。T0 需先提供 metafile 或等价依赖图证据产出方式；本票使用该产出物断言 `creative-templates.json` 不在客户端主包输入中（metafile `inputs` / `bytesInOutput` 为零），最终预算由 T6 统一验收。

**测试落点（已核实）**：Node 行为测试放入 `plugins/omnimux/src/**`（`.test.js`/`.test.ts`）由 `corepack pnpm --filter omnimux test` 收集。素材库与资产中心的真实浏览器验收使用任务隔离 worktree 内 `pnpm verify:app`；本票须声明这两条业务路径的专属断言步骤，运行器“应用就绪”检查不代替业务断言。`pnpm test:worktree-web` 的 Stage 夹具不得充当本票验收。

**非目标**：重新设计素材库或资产中心，新增筛选/文案/空态，改其他 UI 行为。

**授权边界**：产品门禁未满足时，暂停任何引入可见差异的实现；不能用测试夹具假状态代替产品批准。

## T5 · 本机请求安全原语与 Apps 职责分离

**类型**：安全/Host 纵向迁移　**阻塞**：T0　**建议变更风险**：R1（共享安全合同，按实际 diff 复核）

**目标**：将可共享的请求来源校验原语与 Apps 业务模块解耦，同时保持安全策略、活跃 Apps 服务及其生命周期不变。

**范围**
- 将纯校验原语及其测试迁移至合适的共享边界；旧导入位置保留兼容转导出，直至消费者/兼容要求另行确认。
- 保持缺失 Origin/Referer 处理、本机 hostname 白名单、cross-site 拒绝规则、Referer fallback、非法 URL、头部大小写与数组兼容；不加强也不放宽策略。
- 明确保留 Apps 配置、目录存储与刷新、标签读写、HTTP 路由、安装路径选择、卸载标签清理和 Cordis disposal 注册/注销。
- 避免依赖方向倒置；Apps 业务层可消费通用安全原语，但通用原语不能导入 Apps 实现。

**候选 seams / 验收**
1. 迁移前后针对固定 headers/URL fixtures 的输出逐例一致；覆盖 localhost、IPv4、IPv6、恶意/非法 Origin、缺失头、Referer fallback 与数组头。
2. 旧导入路径消费者测试仍通过，兼容转导出存在；未获单独授权不删除旧路径。
3. Host 集成验证 Apps 配置读取、目录刷新、标签增删查、bundled 安装选择、卸载只清理目标标签和 disposal 清理。
4. 无定时器/事件/路由泄漏；卸载后资源已注销，刷新服务行为未被停掉。
5. 只做适用 Node/Host 证据；无 UI 变化，无需伪造浏览器验收。

**测试落点（已核实）**：迁移后的安全原语测试须保持在 `plugins/omnimux/src/**/*.test.{js,ts}`（如 `src/apps/origin.test.js` 及其迁移目标路径），以继续被 `corepack pnpm --filter omnimux test` 收集；若迁至 `src` 之外的位置，票面必须声明独立执行命令。

**非目标**：删除或退役 Apps 服务/存储/路由，迁移数据格式，改变请求访问策略或工作流发布路由。

**授权边界**：发现必须改变安全策略、Apps 数据或公开行为方可实施时，立即暂停并请求修订范围；本票不授权删除活跃服务。

## T6 · 全链路回归、发布包与预算验收

**类型**：集成 / 发布产物验收　**阻塞**：T1、T2、T3、T4、T5；T0 提供比较基线　**建议变更风险**：继承最高关联风险（预计 R1）

**目标**：证明迁移完成后全部消费者和保留服务可用、发布产物可独立运行、固定口径客户端脚本达到至少 20% 相对下降，并形成可审计交付证据。

**范围**
- 运行锁定的包测试、插件构建、Host/客户端相关集成、端到端浏览器行为及安全/Apps 回归。
- 从真正打包并解包的安装产物启动/运行 Host，确认模板资源可读、快照版本和内容匹配，不依赖源码目录或开发机软链。已核实候选命令（T0 验证后锁定）：`plugins/omnimux` 下 `npm pack` → `tar -xzf omnimux-<version>.tgz -C <临时目录>` → 在解包产物内读 `package/src/client/session-guide/templates/creative-templates.json` 计算 SHA-256，与 HTTP `dataVersion` 对照；并断言解包产物内 `node src/index.js` 可加载 Host 入口。

- 汇总首次请求时机、响应字节、隔离 worktree 浏览器 screenshots 与结构化报告；严格区分 bundle 字节下降与首屏性能，不作未测的性能结论。

**候选 seams / 验收**

2. 完整行为矩阵逐项映射父规格 §5.2 seams：同步工具/HTTP/缓存取消/所有浏览器消费者/保留 Apps 与安全/发布包/邻接行为。
3. 完整应用隔离浏览器运行本任务的端到端路径；使用 `pnpm verify:app`（`scripts/worktree-app-qa.mjs`，动态端口、自清理），报告中包括截图和结构化输出；`pnpm test:worktree-web` Stage 夹具不能替代本任务业务行为。
4. 解包发布包后验证模板 JSON 存在且 Host 能读取；包内文件内容与返回 dataVersion 对应同一数据版本。
5. 客户端脚本包装后 UTF-8 字节较 T0 基线下降至少 20%；T0 提供的 metafile/依赖图产出证明完整 JSON 不在客户端主包和初始执行依赖图中（`inputs`/`bytesInOutput` 中 `creative-templates.json` 为零）。若失败，阻止后续发布，出具证据复审，不调整预算。

**非目标**：新增性能承诺、扩大到其他模板域、删除无关旧功能/测试、部署或生产发布。

**授权边界**：本票只授权已确认的隔离验证工作；不能仅凭票草案合并、发布或部署。达不到预算时停止交付推进并复审，不允许临时弱化标准。
