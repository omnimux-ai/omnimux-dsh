# 快捷方式链接胶囊：把纯文本令牌还原为真正的胶囊组件（Issue #2579）

## 问题

点「复刻爆款视频」后，输入框里出现的是**纯文本** `[视频] [商品]`，而不是设计稿里的链接胶囊（图标 + 名称 + 可粘贴链接的输入框 + 删除按钮）。

用户原话：「URL token 组件样式 没呈现出来」。

## 根因（已核实）

现有实现把链接写成了提示词槽位**文本令牌** `[视频]` / `[商品]`，依赖 `attachments/usePromptSlotEnhancer.ts` 的 CSS Custom Highlight（`::highlight(omx-prompt-slot)`）呈现——该机制只给文本加高亮，**不渲染任何胶囊组件**，所以界面里看到的就是普通文本。

更关键的事实：仓库里**已经存在**读取胶囊节点的通道，但**没有任何创建方**：

- `composer-add/AttachmentSubmitBridge.jsx` 会查找 `[data-omx-video-token="true"]` 节点，读其内部 `<input>` 的值，组装成 `[视频](url)` 追加进草稿，然后移除该节点；也支持 `window.__omnimuxVideoToken = { url }`。
- `attachments/dockStyles.ts` 已有 `[data-composer-chip="link"]` / `[data-composer-chip="video"]` 的完整样式，但全仓（含桌面外壳）**无渲染方**。

即：样式与提交读取两端都在，中间「创建节点」这一环缺失。

## 目标

点快捷方式、或点上方卡槽时，在输入框**光标位置**插入真正的链接胶囊组件；胶囊与设计稿一致，可粘贴链接、可删除；提交时链接仍能进入请求内容。

## 胶囊形态（设计稿）

| 种类 | 图标 | 名称 | 输入框占位 | 删除 |
| --- | --- | --- | --- | --- |
| 视频 | 链接图标 | 视频 | 粘贴 TikTok 视频链接 | × |
| 商品 | 包裹/商品图标 | 商品 | 粘贴商品链接或 ID | × |

两种胶囊颜色可区分（视频一种、商品一种），颜色取既有 design token，不新造色值。

## 成功标准

1. 点「复刻爆款视频」/「拆解爆款视频」/「反推视频提示词」后，输入框内出现的是**视频胶囊组件**，不是 `[视频]` 纯文本。
2. 点「一键创作带货视频」后，出现的是**商品胶囊组件**，不是 `[商品]` 纯文本。
3. 胶囊内可聚焦并粘贴/输入链接；胶囊带删除按钮，删除后上方对应卡槽**恢复可点**。
4. 链接已在输入框内时，对应卡槽**不可点**。
5. 切换快捷方式时整组替换，不残留上一个快捷方式插入的胶囊。
6. 提交时链接进入请求内容：视频胶囊 → `[视频](url)`；商品胶囊 → 对应标记。**不得因改渲染而丢失链接。**
7. 胶囊不得破坏输入框原有的打字、换行、光标行为与既有提示词槽位高亮。
8. **写入失败不得丢链接**：提交时把胶囊链接写进草稿失败（宿主 `setDraft` 抛错）时，胶囊**必须保留在输入框里**，用户的链接不丢、可重试；只有真的写进草稿（或草稿里已经有该链接）才消费掉胶囊。
9. **作用域收敛到当前会话**：宿主同时挂载两张输入框卡片（分屏 / 多标签保活）时，读胶囊、删胶囊、整组替换、提交读取都只作用于**当前会话的卡片**；文档里有多张卡片且定位不到本会话时，宁可不动作，也不动别的会话。
10. **撤回不吃用户手打的内容**：撤回只剥掉本快捷方式写入的提示语；草稿里用户手打的 `[视频]` / `[视频](url)` 令牌一律保留。
11. **商品形态认得出来**：草稿里已有 `[商品: <值>]`（本通道提交形态，也是既有商品槽位填充形态）时，商品卡槽判为「已填」、不可点，不再插出第二枚商品胶囊。

## 范围

只修链接令牌的呈现与插入通道，以及为商品补齐与视频对等的提交读取。不改四条快捷方式与技能的对应关系、不改技能货架数据、不改技能激活通道。

## 新用户基线

只依赖随插件分发的资源与既有输入框通道，不依赖本机私有配置或本机服务；拿不到输入框或写入失败时降级为不插入并给出提示，不报错。

## 已知行为与取舍

本节登记本特性的已知行为、明确取舍与仍在的口径缺口，避免它们只留在对话里。

1. **提交标记是语言无关的固定名**（名称固定为中文 `视频` / `商品`）。胶囊 → 请求内容的形态固定为
   视频 `[视频](url)`、商品 `[商品: <值>]`，**不随界面语言漂移**；规格 S6 的字面形态即为真源，
   下游（`composer-video-token.test.js` 钉死的形态、`attachments/promptSlotDetector.ts` 的「名称: 值」解析）
   因此只有一种写法要认。胶囊的**显示名**（卡槽文字、胶囊内名称与占位、删除按钮读屏名）仍然跟随界面语言。
   取舍：英文界面下，用户看到的胶囊名是 `Video` / `Product`，而提交文本与日志里仍是 `视频` / `商品`。

2. **撤回只剥提示语，绝不吃用户手打的令牌**。点同一条快捷方式两次撤回时，只把该条目的预填提示语
   从草稿开头剥掉；草稿里用户手打的 `[视频]`、`[视频](url)` 一律保留。此前会按「卡槽集数量」为上限
   剥离同名令牌，而本通道现在写入的文本令牌数为 0，那条上限会反过来吃掉用户手打的内容，已删除。
   取舍：用户改过提示语（提示语已不在草稿开头）时**整条保留**，不再顺手清理末尾令牌——宁可留下
   可见的文字，也不静默删掉可能是用户自己写的内容。胶囊的清理由胶囊删除通道承担
   （按当前会话的输入框卡片收敛）。

3. **胶囊游离于编辑器文档模型之外**。胶囊住在 `[data-composer-card]` 内、由本插件创建的
   `.omx-link-chip-row` 里，不是 Lexical 文档节点。受影响的具体行为：
   全选删除（Ctrl/Cmd+A 后 Backspace）只删可编辑区文本，**胶囊会留下**；撤销 / 重做**不含**胶囊的
   增删；复制草稿文本**不含**胶囊内容。根因是宿主硬事实：Lexical 每次渲染都会清掉自己根节点下的
   非受管子节点（浏览器实测：插进可编辑区的胶囊会被抹掉，`chipCount` 2 → 0）。
   恢复干净状态的路径：逐个点 × 删除，或再点一次该快捷方式撤回。

4. **卡槽两态只在胶囊变更事件里同步**。卡槽的「不可点」由 `omnimux:quick-link-chips:changed`
   驱动读一次节点（渲染期不读 DOM）。宿主重建输入框卡片（切换会话、卡片重挂）后事件不会补发，
   卡槽可能停在上一次的禁用态，表现为「胶囊已经删掉了，卡槽仍然不可点」。
   恢复路径：再点一次该快捷方式（整组替换会重新广播），或删除 / 重插胶囊（× 与插入都会广播）。

5. **商品标记的值语义需产品口径确认**。商品胶囊提交的值是链接或 ID（`[商品: <url 或 ID>]`），
   而仓库既有真源的商品填法是**商品名 + 真附件**（`ProductUrlPopover` → `onAddProductAttachment`
   会同时往附件库挂商品附件）。本轮不做「按 URL 反查商品并挂真附件」：那需要产品口径与接口口径，
   属未确认范围，不在本规格的改动面内。

6. **整组替换不是原子操作**。已按「先解析胶囊行 → 行拿得到才清旧插新 → 行拿不到就整条不动」实现，
   不会出现「先清掉旧的、新的又插不进去」的两不剩。仍未覆盖的残余情形：拿到行之后、插入过程中
   `createQuickLinkChipNode` 失败（种类非法或无 document）时，本批只插进一部分，已清掉的旧胶囊不回滚。
   该分支在现有调用面上不可达——`replaceQuickLinkChips` 先按 `quickLinkChipSpec` 过滤种类，
   无 `document` 时连行都拿不到（走「整条不动」）。

7. **端到端用例不构成自动防线**。`plugins/omnimux/tests/e2e/*.e2e.test.mjs` 不被任何收集器执行：
   `plugins/omnimux/scripts/run-tests.mjs` 的 glob 只有 `src/**/*.test.js` 与 `src/**/*.test.ts`，
   CI 的 quality-gate 也没有 `tests/e2e` 收集步骤。本规格的端到端预期只能手动跑，
   行为改动仍需浏览器证据（见上一节）。

8. **未收到正文的低问题条目**。审查报告的低-2 / 低-3 / 低-5 / 低-6 / 低-7 未附条目正文，
   本轮无法逐条登记具体内容与取舍（低-1、低-4 已修）。待审查员补录正文后在此登记。

## 边界

只改本任务工作区。先演示、后合入；用户确认前不合入。不改官方宿主，不发布生产。
