# 快捷方式链接胶囊：把纯文本令牌还原为真正的胶囊组件（Issue #2579）

## 问题

点「复刻爆款视频」后，输入框里出现的是**纯文本** `[视频] [商品]`，而不是设计稿里的链接胶囊（图标 + 名称 + 可粘贴链接的输入框 + 删除按钮）。

用户原话：「URL token 组件样式 没呈现出来」。

## 根因（已核实）

现有实现把链接写成了提示词槽位**文本令牌** `[视频]` / `[商品]`，依赖 `attachments/usePromptSlotEnhancer.ts` 的 CSS Custom Highlight（`::highlight(omx-prompt-slot)`）呈现——该机制只给文本加高亮，**不渲染任何胶囊组件**，所以界面里看到的就是普通文本。

更关键的事实：仓库里**已经存在**读取胶囊节点的通道，但**没有任何创建方**：

- `composer-add/AttachmentSubmitBridge.jsx` 会查找 `[data-omx-video-token="true"]` 节点，读其内部 `<input>` 的值，组装成 `[视频](url)` 追加进草稿，然后移除该节点；也支持 `window.__omnimuxVideoToken = { url }`。
- `attachments/dockStyles.ts` 已有 `[data-composer-chip="link"]` / `[data-composer-chip="video"]` 的完整样式，但全仓（含桌面外壳）**无渲染方**。

即：样式与提交读取两端都在，中间「创建节点」这一环缺失。

## 目标

点快捷方式、或点上方卡槽时，在输入框**光标位置**插入真正的链接胶囊组件；胶囊与设计稿一致，可粘贴链接、可删除；提交时链接仍能进入请求内容。

## 胶囊形态（设计稿）

| 种类 | 图标 | 名称 | 输入框占位 | 删除 |
| --- | --- | --- | --- | --- |
| 视频 | 链接图标 | 视频 | 粘贴 TikTok 视频链接 | × |
| 商品 | 包裹/商品图标 | 商品 | 粘贴商品链接或 ID | × |

两种胶囊颜色可区分（视频一种、商品一种），颜色取既有 design token，不新造色值。

## 成功标准

1. 点「复刻爆款视频」/「拆解爆款视频」/「反推视频提示词」后，输入框内出现的是**视频胶囊组件**，不是 `[视频]` 纯文本。
2. 点「一键创作带货视频」后，出现的是**商品胶囊组件**，不是 `[商品]` 纯文本。
3. 胶囊内可聚焦并粘贴/输入链接；胶囊带删除按钮，删除后上方对应卡槽**恢复可点**。
4. 链接已在输入框内时，对应卡槽**不可点**。
5. 切换快捷方式时整组替换，不残留上一个快捷方式插入的胶囊。
6. 提交时链接进入请求内容：视频胶囊 → `[视频](url)`；商品胶囊 → 对应标记。**不得因改渲染而丢失链接。**
7. 胶囊不得破坏输入框原有的打字、换行、光标行为与既有提示词槽位高亮。

## 范围

只修链接令牌的呈现与插入通道，以及为商品补齐与视频对等的提交读取。不改四条快捷方式与技能的对应关系、不改技能货架数据、不改技能激活通道。

## 新用户基线

只依赖随插件分发的资源与既有输入框通道，不依赖本机私有配置或本机服务；拿不到输入框或写入失败时降级为不插入并给出提示，不报错。
