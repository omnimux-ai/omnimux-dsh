# #1934 模块边界测试归属规格

## 1. 问题与目标

主分支的模块边界检查报告十条既有违规：五个媒体反馈测试辅助文件位于产品浏览器源码目录，其中两个引用 Node 模块；Hub 测试还直接导入市场、产品、素材和分析插件的私有实现。目标是把纯测试内容移回测试目录和各自插件的测试套件，让边界检查通过，同时完整保留原有覆盖。

## 2. 实施范围

1. 将 `plugins/omnimux/src/client/media-viewer/test-support/` 下五个测试专用文件整体迁移到 `plugins/omnimux/test-support/` 的专属子目录，并更新唯一使用方的路径。
2. Hub 的智能体预设浏览器测试只保留头像切换和文案检查；技能货架绑定断言由市场插件已有测试承接，缺失时只在该归属测试内补齐。
3. 把四个业务页的样式断言分别放回产品、素材、市场和分析插件的测试；确认等价覆盖后移除 Hub 的跨插件聚合测试。
4. 不改被测产品样式、页面行为、共享运行时接口或模块边界规则。

## 3. 验收标准

| 编号 | 可观察结果 | 判定方式 |
| --- | --- | --- |
| B-1 | 产品浏览器源码目录不再包含测试专用 Node 辅助文件 | 文件清单与模块边界检查 |
| B-2 | Hub 源码测试不再私有导入其他插件 | 模块边界检查无违规 |
| B-3 | 媒体反馈浏览器回归测试迁移后仍能启动、交互和自清理，原有用例数不减少 | 定向测试与真实浏览器证据 |
| B-4 | 智能体头像、文案及技能货架绑定的原有业务断言均由归属测试覆盖 | Hub 与市场插件测试 |
| B-5 | 产品分割线、素材双层标签间距、市场胶囊标签、分析页重复分割线四项样式断言均由所属插件测试覆盖 | 四个归属插件测试 |
| B-6 | 没有新增边界豁免、跨插件公开入口或产品源码行为变化 | 实际差异与独立复核 |

## 4. 验证策略

- 先运行模块边界检查和受影响的 Hub、市场、产品、素材、分析插件测试。
- 媒体反馈迁移后运行其原生浏览器回归，确认页面挂载、关键交互、正尺寸和测试进程清理。
- 集成阶段运行包文件检查、门禁脚本测试和完整仓库门禁。
- 若归属插件已有等价断言，优先复用并删除重复断言；只为实际覆盖缺口新增最小测试。

## 5. 约束

- 所有文件改动限定在当前仓库及 #1934 工作树。
- 测试辅助文件只能从产品源码移到测试支持目录，不进入发布包。
- 不能把跨插件私有实现包装成公共接口来绕过检查。
- 不能删除业务覆盖或改松断言阈值来取得绿色结果。
