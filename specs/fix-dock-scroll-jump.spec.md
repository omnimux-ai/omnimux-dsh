# 规格：彻底消除点击复刻与使用技能时页面向上跳动问题 (Fix Dock Scroll Jump Spec)

## 一、需求背景与业务痛点
- **用户反馈**：在页面任意位置点击卡片上的「复刻」或「使用」按钮后，页面应该完全保持不动，输入框平稳显示在底部。当前会出现明显的页面先向上跳动到顶部原位、随后才在底部显示的闪烁跳跃感。
- **根因分析**：
  1. **草稿写入与聚焦抢跑**：在卡片被点击的当刻，输入框吸底状态尚未完成 DOM 渲染，输入框物理上依然位于页面最顶部的 Hero 文档流内。此时如果立刻调用 `setDraft` 和 `focus()`，浏览器的原生聚焦机制会立即将视口强制滚动到顶部以迎合输入框；随后下一帧输入框才完成 CSS fixed 停靠，形成了“页面猛然跳上、再吸附到底部”的双重抖动；
  2. **缺乏滚动位置锚定**：输入框由流内定位转为 `position: fixed` 脱离文档流的微秒级瞬间，若滚动容器缺乏对用户当前真实浏览位点（`scrollTop`）的精确锁定，极易发生视口抖动；
  3. **模板挂载函数抢先 focus**：`attachTemplateToConversation` 内部直接调用了 `inputEl?.focus()`，在吸底之前抢跑了聚焦动作。

## 二、架构与逻辑重构方案
1. **意图延迟派发契约 (Deferred Prompt & Focus Pipeline)**：
   - 用户点击卡片（技能「使用」、模板「复刻」、热门「复刻」）时，吸底控制器先暂存本次意图 `pendingPromptRef.current = { prompt, item, ... }`，并立即激活吸底状态；
   - **吸底前绝不执行任何 `setDraft` 或 `focus()`**；
   - 在吸底专用的 `useLayoutEffect` 中，确认宿主打上 `data-omnimux-dock-open`、几何计算完成且输入框已被 `position: fixed; bottom: 20px;` 牢牢钉在底部之后，才将暂存的草稿交回输入框所有权方并执行聚焦；
   - 输入框物理位置已固定在视口底部，聚焦光标无论如何都不会拉动视口向上位移。
2. **滚动条位点原子锁定 (Scroll Position Lock & Restore)**：
   - 点击当帧立即记录当前真实滚动读数：`savedScrollTop = readPageScrollTop(scroller)`；
   - 在吸底完成的这一帧，强制核验滚动容器位点，若检测到抖动立刻原子重置为 `savedScrollTop`，实现绝对的零像素位移。
3. **清理提前抢跑的 focus**：
   - 优化 `attachTemplateToConversation`，移除未吸底前的同步聚焦与抢先填词，统一由吸底管线管理。

## 三、验收标准
1. 页面滚动至任意偏下位置（例如 scrollTop = 300px~800px）时点击任意卡片的使用/复刻按钮，页面完全静止不动（scrollTop 变化为 0）；
2. 底部输入框平滑浮现并正确填入对应的技能指令或模板提示词，光标自动聚焦；
3. 单元测试与 E2E 自动化测试 100% 绿灯通过。
