# 图像与视频生成页面输入面板直连优化规格说明书 (Issue #2416)

## 1. 业务目标与背景
当前图像生成页面（`MediaViewerTab`）底部借用了主对话框的底层逻辑，敲击回车默认作为普通聊天消息发给大语言模型助手，导致出图必须经历助手的漫长思考、容易意图漂移或漏调工具，且白白消耗大语言模型对话算力。
本规格将图像生成页面底部的输入面板彻底重构为独立内聚的专用生成输入组件（`MediaViewerComposer`）：
1. 彻底绕过大语言模型助手对话轮次，输入提示词并提交后，0 毫秒立即直连执行中枢模型生成引擎；
2. 底部工具栏严格按照三大胶囊按钮排布：`生成方式` ｜ `模型` ｜ `参数展示`；
3. 【模型】按钮 100% 复刻画布节点的三级级联模型面板（`ModelCascadeMenu`：品牌 ➔ 型号 ➔ 渠道版本）；
4. 【参数展示】按钮 100% 复刻画布节点的模型参数配置面板（`ImageParamPopover`：比例网格、清晰度分段、张数/时长分段、CFG 滑块等）；
5. 提交后，画布中央升起复刻自画布节点的有机炫彩流体波纹扫光任务卡片（`Organic Shimmer`），具备秒级实时秒表、模型标签与随时取消机制，完成后平滑淡入高清生成产物；
6. 100% 复用 DSH 原生纯黑体系（`#111113` / `#18181b` / `#1c1c1f`）与极光紫（`#7961f2`）微光，坚决杜绝科技蓝与非标控件。

## 2. 接口与数据流契约
### 2.1 后端直连生成接口 (HTTP Seam)
- 路由：`POST /omnimux/api/media/generate`
- 入参：
  ```json
  {
    "kind": "image" | "video",
    "prompt": "提示词文本",
    "model": "模型ID",
    "channel": "渠道ID或版本",
    "params": {
      "aspectRatio": "16:9",
      "resolution": "4k",
      "batch": 4,
      "duration": 5,
      "cfg": 7.5,
      "seed": -1
    },
    "references": []
  }
  ```
- 响应：
  - 成功直接启动任务并返回包含产物 URL 或 task_id 的标准响应：`{ ok: true, taskId: "...", status: "running" | "completed", url?: "..." }`

### 2.2 前端状态流与动画时序
1. 用户在 `MediaViewerComposer` 输入提示词，选择模型与参数；
2. 点击发送按钮或按 Enter；
3. `MediaViewerComposer` 立即触发 `onDirectSubmit`；
4. `mediaViewerStore` 立即登记生成中任务，`MediaViewerTab` 画布中央立即升起 `Organic Shimmer` 炫彩流光动画卡片；
5. 前端通过 `POST /omnimux/api/media/generate` 发送请求；
6. 接口返回生成结果后，图片通过 `store.addMedia` 自动入库，炫彩卡片淡出，产物大图高清呈现。

## 3. 验收标准
- [ ] 按钮排列严格为：生成方式 ｜ 模型 ｜ 参数展示，右侧为纯黑白 Ink CTA 发送按钮；
- [ ] 模型面板具备三级级联结构与价格标签，支持悬停联动与点击选定；
- [ ] 参数面板具备 4 列比例几何卡片与清晰度、数量分段控制；
- [ ] 敲击回车或点击提交后，不产生任何对话消息，画布中央立即出现炫彩执行卡片；
- [ ] 真实请求下能成功生成图片并落地展示；
- [ ] 所有单元测试与契约测试通过。
