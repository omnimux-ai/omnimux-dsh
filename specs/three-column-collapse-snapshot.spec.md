# 规格说明书：收起左侧栏时按「点击瞬间」的分栏比例快照保宽（工单 #2074 续 2）

## 1. 背景与问题定义

前两版修复（PR #2076、PR #2087）已消除「收起左栏导致会话栏全屏」与「单栏全宽读数污染基准」。开发版真机 CDP 实测仍暴露第三个缺口（1920 视口）：

```
展开：280px / 776px / 864px，--omnimux-conversation-width = 420px   ← 未学到真实分栏比例
收起：  0px / 420px / 1500px                                        ← 会话栏被压到回退值
```

根因：基准只在几何同步循环里取样，而同步循环**只由已观察到的 DOM 变更触发**。应用启动时右侧工作台尚未挂载（基准保持 420px 回退值），此后右栏挂载并不会触发同步循环，基准一直停留在回退值，直到用户下一次点击——而那次点击正是收起动作。

## 2. 验收标准（Acceptance Criteria）

- **AC-301（点击瞬间快照）**：用户点击「收起侧边栏」时，在触发官方折叠**之前**、帧仍处于三分栏形态的那一刻取样会话栏宽度，作为收起后的保宽基准。
- **AC-302（取样边界不放宽）**：取样仍然只接受「右侧工作台列 ≥ 200px 且会话栏 ≥ 420px」的读数；单栏形态一律不取样。
- **AC-303（收起结果自洽）**：收起后第一轨 0px、会话栏 = 快照值（像素级不变）、右栏 = 视口 − 会话栏 且 > 0。
- **AC-304（重复收起幂等）**：连续收起 / 展开多次，会话栏与右栏宽度稳定收敛，不产生漂移。

## 3. 测试与验证要求

1. 真实内核几何门禁（`scripts/three-column-collapse-qa.mjs`）：真实 Chromium、动态端口、临时 profile、自清理、PNG + JSON 留证，覆盖收起后列宽自洽与反向对照。
2. 单元测试：`rememberConversationWidth` 在三分栏形态返回 true 并写入变量；在单栏形态返回 false 且不改变基准；无右栏元素时返回 false。
3. 源码契约回归：点击处理器必须在 `triggerClick(official)` 之前调用快照函数。
4. 开发版真机 CDP 复测：1920 视口三分栏，收起左栏后会话栏宽度等于收起前宽度、右栏 = 视口 − 会话栏宽度且 > 0。
