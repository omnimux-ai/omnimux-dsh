# 三分栏收起布局防回归硬化（Issue #2140）

## 背景与问题

三分栏（左侧栏 / 中间会话栏 / 右侧工作台）的隐藏与收起行为经过连续六轮修复才稳定：
#2074（保宽 + 释放空间给右栏）→ #2076（首次落地）→ #2087（保宽基准只从真实三分栏取样）
→ #2091（点击瞬间快照）→ #2097（改为派生态、彻底移除记忆式基准）→ #2080（完全收起消除死带）
→ #2068（macOS 全屏顶栏重叠）。

当前防护以「源码文本正则断言」为主：`assert.match(PRODUCT_STAGE_CHROME, /grid-template-columns:…/)`
只验证某条规则**存在**，不验证它**是否生效**。真实生效取决于 CSS 层叠（重要性 → 特异性 → 顺序），
因此任何人新增一条靠后的 `grid-template-columns` 规则即可改变真实行为，而既有测试仍然全绿。
这就是「被随意改动后又乱掉」的真实路径。

## 用户操作旅程（必须保持稳定的四段）

1. 用户在三分栏展开态拖动右侧分割线 → 会话栏与工作台按原生轨道实时联动，松手后不回弹。
2. 用户点击顶栏左上角的「收起侧边栏」按钮 → 左栏完全消失（屏左无残留窄条），
   **会话栏像素宽度不变**，释放出来的宽度全部落到右侧工作台。
3. 用户在收起态再次拖动右侧分割线 → 会话栏宽度随分割线变化（不得被钉死）。
4. 用户再次点击同一按钮展开左栏 → 三分栏回到点击前的比例，无跳变、无黑缝。

附带必须保持的状态：
- 右栏确证收起时，会话栏占满整个视口宽度（绝不出现黑色死区）。
- 中间会话栏收起（进入右侧画布全屏）时，右侧面板占满右侧区域；但右栏已确证收起时严禁应用该折叠。
- macOS 全屏 + 左栏收起时，顶栏标签不得与左上角按钮重叠。

## 契约（分层断言依据）

### 状态标记（唯一真源）

| 标记 | 持有者 | 语义 |
| --- | --- | --- |
| `html[data-omnimux-left-collapsed]` | `sidebar-toggle-topbar.js` 镜像 | 左栏收起（用户意图，优先于壳层读数） |
| `[data-sidebar-collapsed]` | 官方 AppFrame | 外壳自身的左栏收起属性 |
| `[data-rightbar-collapsed="true"]` | 官方 AppFrame | 右栏确证收起 |
| `html[data-omnimux-conversation-collapsed]` | `conversation-collapse.js` | 中间会话栏收起 |
| `[data-details-collapsed="true"]` | 官方 AppFrame | 详情栏收起 |

### 网格规则状态真值表（PRODUCT_STAGE_CHROME 内，全部 `!important`）

| 编号 | 状态组合 | 期望列宽分配 |
| --- | --- | --- |
| R-A | 左栏收起 ∧ 右栏收起 | `0px minmax(0px,1fr) 0px` |
| R-B | 左栏收起 ∧ 右栏开 ∧ 详情栏未收起 | `0px var(--omnimux-conversation-width,420px) minmax(0px,1fr)` |
| R-C | 中间栏收起 ∧ 右栏开 | `var(--omnimux-sidebar-width,280px) 0px minmax(0px,1fr)` |
| R-D | 右栏收起 | `var(--omnimux-sidebar-width,280px) minmax(0px,1fr) 0px` |
| R-E | 左栏收起 ∧ 右栏收起（强覆盖） | `0px 100vw 0px` |

**INV-14（本任务新增的核心不变量）**：以上状态组合的胜出规则由「重要性 → 特异性 → 顺序」决定；
新增规则不得静默夺取任何既有状态组合。门禁必须在**胜出规则发生变化**时变红，
而不是仅在**规则文本被删除**时变红。

### 禁改清单

- 第三轨写 `auto`（右栏会与 `1fr` 竞争后被压成 0）；第三轨写死像素。
- 引入任何记忆式基准（`lastGoodConversationWidth` / `rememberConversationWidth` 之类）。
- 用测量宽度作为权威读数（`conversation-box.js` 用 `!important` 钉住轨道，
  测得的宽度是本函数即将写入值的函数 —— 自我确证的中毒读数）；权威读数只能是
  外壳 authored 的内联 `grid-template-columns`。
- 收起时把 `--omnimux-sidebar-width` 镜像成壳层读数（原生窄栏 90px 会留下屏左死带）。
- 对 `html`/`body` 做全树 `childList` 观测；在 ResizeObserver 回调里同步写布局（必须经 rAF 合并）。
- 保宽规则丢失 `:not([data-rightbar-collapsed="true"])` 排除（右栏收起时会话栏无法全宽）。

## 验收标准

| 编号 | 判定 | 层次 |
| --- | --- | --- |
| AC-1 | 每个状态组合的**胜出规则**与其列宽分配符合真值表 | 行为级门禁（真实 CSS 文本 + 真实选择器匹配 + 层叠模拟） |
| AC-2 | 人为新增一条靠后的覆盖规则 → 门禁变红并指出被夺取的状态组合 | 反向验证 |
| AC-3 | 人为打乱两条规则的顺序使其语义颠倒 → 门禁变红 | 反向验证 |
| AC-4 | 派生宽度：收起前后同宽、收起态跟随分割线、地板 320px、无 authored 栅格时回退 420px | 纯函数单测（既有 + 补充） |
| AC-5 | 真实内核：三分栏收起后会话栏宽度不变、右栏吸收释放宽度、拖动分割线跟随 | 真实浏览器几何（扩展既有 QA 脚本的状态矩阵） |
| AC-6 | 真实内核：右栏收起时会话栏占满视口、左栏完全收起无残留死带 | 真实浏览器几何 |
| AC-7 | 既有 `pnpm --filter omnimux test` 全绿且无新增跳过 | 命令证据 |

## 新用户基线

本次为纯防护性改动（新增契约文档、门禁测试、真实内核状态矩阵），不引入新的用户可见功能，
因此不新增对品牌新用户环境的能力依赖；被测对象（三分栏布局）在全新安装 + 登录后即可复现，
无需开发机私有状态、私有目录或私有端口。门禁与 QA 脚本使用动态空闲端口与临时 profile，
不读取开发机模型配置。

## 非目标

- 不修改任何现有界面行为、不重构三分栏实现。
- 不引入新的布局能力（例如新的面板、新的折叠态）。
- 不改造 `conversation-collapse.js` 的中间栏折叠语义。
