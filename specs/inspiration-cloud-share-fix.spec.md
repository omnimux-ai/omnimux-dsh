# 需求规格：云端作品分享创建链接静默失败修复（Issue #2075）

## 一、目标与业务背景

灵感社区中「云端作品」是社区公共库的内容。用户在云端作品预览弹窗点击「分享」→「创建链接」时，
当前表现为**浮层瞬间消失、无链接、无进度、无任何错误提示**，用户完全无法判断发生了什么。

实机 CDP 取证确认这由两个彼此独立的缺陷叠加造成，必须一并修复：

1. **素材地址读取字段不匹配**：客户端构造发布载荷时读取的是 `coverUrl/cover_url` 与
   `mediaUrls/media_urls`，而云端目录真源实际提供的是 `cover_key` 与 `media_keys`，
   导致提交给发布通道的素材地址全为空串，服务端必然拒绝。
2. **浮层身份判定过脆**：发布弹窗的复位副作用以 `item?.id` 为依赖，而云端目录行的 `id`
   是数字 `2789`、服务端发布任务行回写的是字符串 `"2789"`，类型翻转被误判为「换了一条记录」，
   于是点击创建的瞬间浮层被关闭、错误被清空，失败原因永远无法呈现给用户。

## 二、关键用户旅程

### CUJ-1：云端作品分享成功
1. 用户在灵感社区「全部 / 云端」列表点击任意云端作品卡片，预览弹窗打开；
2. 点击右上角「分享」，分享浮层打开，展示「创建链接」按钮；
3. 点击「创建链接」；
4. 浮层**保持打开**，进入真实发布进度（准备素材 → 生成Prompt → 发布中）；
5. 发布成功后浮层内展示云端返回的真实分享链接与有效期。

### CUJ-2：云端作品素材确实缺失时的可读失败
1. 用户对一条确实没有任何可用素材地址的云端作品点击「创建链接」；
2. 浮层**保持打开**；
3. 浮层内以中文展示明确原因（如「该云端灵感没有可用的云端素材地址（封面与视频均为空），无法生成分享链接」）；
4. 按钮变为「重新创建链接」，用户可重试。

### CUJ-3：本地作品分享链路不受影响
1. 用户对本地作品点击「创建链接」；
2. 仍走「准备素材 → 生成Prompt → 上传素材 → 发布中」四步；
3. 发布载荷中的地址为上传后由云端返回的地址。

## 三、验收标准（AC）

- [ ] **AC-1（字段真源对齐）**：`shareRequestPayload` 能正确读取云端目录行的 `cover_key` 与
      `media_keys`，并兼容既有的 `coverUrl/cover_url`、`mediaUrls/media_urls` 形态；
- [ ] **AC-2（地址形态规范化）**：本地媒体代理路径 `/omnimux/inspiration/media/<sub>` 在进入发布载荷时
      被规范化为云端可发布路径 `/api/inspiration/v1/public/media/<sub>`；已是云端前缀或绝对 https 地址的保持不变；
- [ ] **AC-3（浮层不误关闭）**：同一条记录即使 `id` 在数字与字符串形态间翻转，分享浮层也不得关闭、
      已展示的错误不得被清除；切换到最后打开的是另一条记录时才复位；
- [ ] **AC-4（失败可读）**：服务端拒绝发布时，用户在分享浮层内看到可读的中文原因，按钮变为「重新创建链接」；
- [ ] **AC-5（本地链路零回归）**：本地作品分享仍为四步进度，且载荷地址仍为上传后的云端地址；
- [ ] **AC-6（真实浏览器验证）**：在任务独立工作树内以真实 Chromium 验证浮层保持打开与错误可见，
      留存截图与结构化报告；全量单测与 E2E 全绿。
