# 4056 批量删除草稿提示已删除 0 条

Issue: #4056 · 分支 `agent/publish-batch-delete-fix-issue-4056` · 风险等级 **R2**（列表批处理）

## 背景

复现步骤：

1. 草稿箱勾选两条草稿；
2. 切换列表/刷新（列表数据重新加载）；
3. 再点「批量删除草稿」。

结果提示「已删除 0 条草稿」，草稿仍在。

根因有两层：

- `selectedIds` 只增不减：列表重新加载或切换 tab 后，旧的记录 id 仍留在选择集合里，批量栏还显示「已选 N 项」；
- `executeBatchDeleteDrafts` 对找不到的记录静默跳过，最后固定提示「已删除 0 条草稿」，用户不知道是失效还是失败。

## 方案

1. `useBatchOperations`：根据当前列表 id 集合裁剪 `selectedIds`，列表里不存在的选中项自动移除（不改变仍存在的选择）。
2. `executeBatchDeleteDrafts`：
   - 先筛出当前列表中存在且状态为 draft 的记录；
   - 一个都没有时提示「所选记录中没有可删除的草稿，请重新选择」，不发请求；
   - 逐条删除并统计成功/失败，失败时提示原因，不再静默。
3. `executeBatchRetry` 增加同样的「没有可重试项」提示，避免同样静默。

## 假设

- 列表刷新后仍在列表中的记录 id 不变，因此按 id 裁剪不会误删有效选择。
- 批量删除仍不做确认弹窗（与当前行为一致），本次只修正确性与反馈。

## 证伪方式

- 单测：选中集合包含已不在列表中的 id 时，批量删除只处理存在项并提示实际数量；空目标时明确提示且不调用 fetch。
- 浏览器/真机复现：勾选 → 切 tab → 切回 → 选择栏应只保留仍存在的项（或清空），再删能成功。
- 现有单测保持通过。

## 新用户基线

无新增配置；行为与其他列表一致：列表变化后失效选择自动清理。
