# 规范：技能市场「套件」分类、套件详情页与一键安装

> 任务真源：Issue #1668 · 分支 `agent/market-suite-marketplace-issue-1668`。
> 本文件是本任务人与 Agent 共享的验收真相源：写码前定死"建什么、怎样算完成"。

## 1. 业务目标与背景

### 1.1 现状问题

技能市场的条目只有**单个粒度**：一条等于一个技能，或一个专家。当一个"包"里含多个技能、附带规则、或附带预设角色时，入库后会被拆成 N 张互不关联的卡片——用户看不出它们同属一套，也无法整套浏览、整套安装、整套卸载。

### 1.2 目标：引入「套件」条目形态

- **判定标准**：非单个 skill 即套件。满足任一条件即为套件——① 包含多个技能；② 附带规则；③ 附带预设 Agent。
- **展示**：技能市场分类栏新增「套件」分类；套件卡一眼看出构成（技能 N · 规则 N · Agent N）；详情页按「技能 / 规则 / Agent」三块展示全部条目。
- **安装**：详情页一个「安装」按钮，把三样一次装到位——技能进技能库、规则写入 AGENTS.md、Agent 加入专家馆。

### 1.3 首批收录范围（6 个社媒运营 / 创作套件）

| 套件 | 技能 | 规则 | Agent |
| --- | --- | --- | --- |
| 社媒多模态内容创作工坊 | 0 | 5 | 7 |
| 全域内容分发专家团 | 6 | 0 | 5 |
| 社媒互动增长专家团 | 1 | 0 | 5 |
| AI 内容创作专家团 | 1 | 0 | 7 |
| 营销战役与内容 | 1 | 0 | 4 |
| 内容变现商业化专家团 | 1 | 0 | 5 |

数量以套件真实目录内容为准；真实清单由数据源生成，不在客户端硬编码。

### 1.4 用户已确认的决策（不得自行更改）

1. **专家馆现有 18 个专家团两边都保留**：不迁移、不删除、不改其入口；「套件」是技能市场内新增的入口。
2. **安装时规则默认写入当前项目**：安装弹窗可切换为「个人全局」，默认选中当前项目。

## 2. 核心交互契约

### 2.1 分类栏新增「套件」

- 技能市场分类栏在既有分类之外新增一项「套件」，位置紧跟「全部」之后。
- 选中「套件」时，列表只显示套件条目；选中其他分类时，不混入套件条目。
- 「套件」分类存在可见的数量角标，数值等于当前可用套件条目数。

### 2.2 套件卡

- 每张卡显示：套件名、一句描述、三项构成计数（技能 N · 规则 N · Agent N）。
- 计数为真实值：0 的项显示为 0，不做隐藏、不伪造。
- 点击整张卡进入该套件详情页。

### 2.3 套件详情页

自上而下：

1. **标题行**：套件名（左）+「安装」按钮（右）。
2. **来源行**：显示该套件来源。
3. **描述**：该套件的一句话说明。
4. **技能块**：标题「技能」+ 说明「技能会与对话相关时由智能体自动调用。」+ 网格卡片（每条：名称 + 一句话说明）。
5. **规则块**：标题「规则」+ 说明「规则定义了智能体的行为约束，安装后写入 AGENTS.md。」+ 卡片。
6. **Agent 块**：标题「Agent」+ 说明「Agent 是预设的专业角色，安装后可在专家馆召唤。」+ 卡片。
7. **空块不渲染**：某类内容为空时，该块及其标题整体不出现（不显示空态占位）。

### 2.4 一键安装

1. 点击「安装」弹出确认框，逐条列出将安装的内容与数量：技能 N 个、规则 N 条、Agent N 个。
2. 当套件含规则时，确认框内提供「规则写入位置」二选一：**当前项目（默认选中）** / 个人全局。
3. 确认后执行安装：技能落技能库、规则追加写入所选目标的规则文件、Agent 进入专家馆。
4. 安装完成：详情页按钮变为「已安装」且不可重复点击；详情页出现本次安装结果的回执（写明各类数量与规则落点）。
5. 幂等：重复安装不重复追加规则、不重复复制技能、不重复注册 Agent。

### 2.5 失败处理

- 任一环节失败必须明确回传失败项与原因，不得静默吞错、不得显示成功。
- 已成功的部分不回滚，回执中标注未完成的项。

## 5. 边界

- **总是**：只写入当前项目或用户在安装弹窗显式选择的目标规则文件；安装幂等；失败明确回传；改动限于 `plugins/omnimux-market` 与其目录数据。
- **先问**：需要越界写其他工作区/项目目录；需要改动既有技能包的内容；需要新增第三方依赖。
- **绝不**：写入生产目录（`~/.omnimux`）；静默吞错或伪造成功；改动或迁移专家馆既有专家团；改动官方 harness 源码。

## 6. 技术实现方案（调查已闭合）

依据：`.agent-reports/suite-marketplace/{suite-data, shelf-render, install-path}.md`。

### 6.1 数据层

- `src/expert/catalog.js`：`KINDS` 增 `'suite'`；`parseItem` 增 suite 分支——要求带 `skill`（包 slug）与结构化清单 `suite: { skills[], rules[], agents[] }`，每项 `{ name, title, desc }`；`source` 沿用既有两种（`bundled` → `catalog/experts/<pack>`，`git` → workbuddyskills 路径）。
- `catalog/index.json`：`categories` 增 `{ id: "sk-suite", title: "套件", tab: "skills" }`；`items` 增 6 条 `kind: "suite"` / `tab: "skills"` / `category: "sk-suite"` 条目，清单自 6 个真实包提取（合计技能 10 / 规则 5 / Agent 34）。**不标 `recommended`**，避开精选 69 条双语门禁链。
- 套件 3 复用既有 bundled 包 `catalog/experts/social-engagement-team`（合规改写版），不引入上游 git 副本，零新增真源。
- 分类错位（`social-engagement-team` 的 `exp-platform` vs `categoryId: 05-MarketingGrowth`）属既有张力，本任务不裁决，保持原状。

### 6.2 客户端

- 分类栏三处真源：`src/client/plaza/plazaUtils.js` 的 `WORKSHOP_DOMAIN_ORDER`、`src/client/skill-picker-logic.js` 的 `SKILL_SHELF_TAXONOMY`、`src/client/i18n.js` 的 ZH/EN `picker.tab.*`。
- 列表：`plazaDiscoverySections` 的本地卡片过滤由 `kind === 'skill'` 扩为 `skill | suite`；「套件」分类不发远端检索（套件是本地目录概念，远端无对应物）。
- 卡片：复用 `.regular-card` 骨架，套件卡追加一行三项计数（技能 · 规则 · Agent），零项显示 0。
- 详情：新增 `SuiteDetail` 模态，复用 `Overlay` + `.modal-dialog.ws-detail-dialog` 外壳；header 行右侧放「安装」，正文按「技能 / 规则 / Agent」三块网格渲染，空块整体省略。
- 安装交互：确认框列出三类数量；含规则时提供落点二选一（默认当前项目）；完成后按钮转「已安装」并显示回执。

### 6.3 服务端安装

新增 `suiteInstall` / `suiteUninstall`（进 `API_ROUTE_TABLE` 与 `MUTATING_METHODS`）：

1. **技能**：把包内 `skills/<name>/` 摊平装到 `$DSH_HOME/skills/<name>/`，复用既有摊平语义；已存在则跳过。
2. **规则**：把 `contracts/*.md` 转为文本段，用**套件自有标记对**（不复用连接器 MCP 段常量）幂等写入目标 `AGENTS.md`。
3. **Agent**：把 `agents/*.md` 写入 `$DSH_HOME/.agent-presets/<suite>-<agent>/`，正文作为 persona，使后续会话可发现。
4. **落点解析**：项目级 = 自会话工作区向上找 `.git` 定位项目 `AGENTS.md`；个人全局 = `$DSH_HOME/AGENTS.md`。
5. **幂等与部分失败**：重复安装不重复追加；失败项明确回传原因，已成功项不回滚，回执标注未完成项。
