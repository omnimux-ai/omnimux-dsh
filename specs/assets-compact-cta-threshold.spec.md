# 资产中心卡片按钮自适应收缩阈值校准规格

**文件：** `specs/assets-compact-cta-threshold.spec.md` ｜ **优先级：** P1 ｜ **Issue：** #2305 ｜ **模块：** `plugins/omnimux-assets`

## 1. 业务痛点与现状

### 1.1 现状与用户反馈
用户在资产中心浏览素材卡片时，悬浮层内部的两个主行动按钮（「查看详情」与「添加到会话」）在几乎所有常规电脑屏幕及全屏显示比例下均呈现为纯图标状态，文字标签被完全隐藏，无法体现预期的「图标+名称」与「纯图标」双态自适应效果。

### 1.2 根因分析
1. 前序提交通过 `@container asset-card (max-width: 296px)` 为卡片引入了紧凑退化。
2. 该 296px 阈值以最长外语文案（"Add to Conversation"）为临界值反解，定得过高。
3. 资产中心网格列数算法（`gridColumnsFor`）规定列宽达到 260px 即增加一列，导致在主流屏幕与常见窗口尺寸下，卡片实际单列宽度长期稳定分布在 260px~285px 之间。
4. 这导致正常宽屏下的卡片 100% 触发了 `<= 296px` 纯图标规则，使得自适应机制退化成了「全图标状态」。

## 2. 目标与验收标准 (Acceptance Criteria)

### AC-101：常规宽屏与正常页面比例下完整显示「图标 + 名称」
- **场景**：卡片宽度处于常规网格列宽区间（>= 220px，包括常见的 260px~360px）。
- **预期**：卡片悬浮层按钮展示完整的「图标 + 文字名称」（中文展示「查看详情」与「添加到会话」），按钮等宽平分空间，文字不截断、不折行。

### AC-102：极端紧凑宽度下优雅收缩为「纯图标」
- **场景**：窗口被极度压缩或卡片宽度进入紧凑区间（< 220px）。
- **预期**：文字标签退出布局，按钮自动收缩为 32px 方形纯图标按钮，居中排列，保留原有图标与无障碍标签（`aria-label`）。

### AC-103：多语言排版与截断防线
- **场景**：在英文或其他语言环境下。
- **预期**：文案与文字槽具备自适应收缩与省略（`text-overflow: ellipsis`）能力，不发生溢出破损。英文将 "Add to Conversation" 优化收敛为专业精炼的 "Add to Chat"，使 220px 以上空间完美适配。

### AC-104：回归测试与规范门禁 100% 绿灯
- **场景**：执行样式探针测试、单元测试与 UI 规范门禁。
- **预期**：相关测试用例全部通过，UI01~UI10 门禁零违规。

## 3. 技术方案
1. 修改 `plugins/omnimux-assets/src/client/styles.js`：
   将容器查询阈值 `@container asset-card (max-width: 296px)` 校准为 `@container asset-card (max-width: 220px)`。
2. 优化 `plugins/omnimux-assets/src/client/locales.js`：
   英文 `card.addToConversation` 文案优化为 `Add to Chat`，使 220px~260px 区间双语均可完整容纳。
3. 同步更新 `card-compact-cta.e2e.test.js` 与 `AssetGrid.test.js` 中的测试断言与实测宽度阶梯。

## 4. 新用户基线
改动仅涉及前端静态样式与文案声明，不依赖任何开发机私有状态或外部服务。全新安装环境下卡片按 220px 阈值正确执行双态自适应。
