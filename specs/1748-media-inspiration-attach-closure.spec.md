# 规格说明：悬浮工具栏与对话卡片灵感库直存及对话附件闭环

## 一、背景与问题
1. **悬浮胶囊栏「加入灵感库」（灯泡）假落地**：仅存入浏览器私有 `chrome.storage.local`，与主程序灵感库（`/omnimux/inspiration/local`）割裂，主界面灵感库完全看不见。
2. **对话卡片「保存到灵感库」脆弱易失败**：仅传页面 URL 依赖后端社媒解析器，在海外平台（推特/X等）遇到反爬或网络超时易静默失败。
3. **「加入对话」缺少拉起与聚焦闭环**：侧边栏未打开或刚打开时，暂存媒体拉取机制受限于通道状态，且无法在无活跃会话时自动创建挂载。

## 二、验收标准与核心行为
1. **悬浮栏「加入灵感库」真入库**：
   - 悬浮胶囊点击灯泡后，通过 background 优先探测并直通主程序 `/omnimux/inspiration/local/import-url` 或 `/omnimux/inspiration/local`（带 `title`、`cover_url`、`source_url`、`type: 'image'`/`'video'`）。
   - 主程序灵感库落盘后，气泡提示「已加入灵感库」，灯泡变实心打勾；桌面端灵感库即可见。
2. **对话卡片「保存到灵感库」直通与容错**：
   - 保存时不仅携带页面 URL，同时携带已探测到的媒体直链（`cover_url`/`video_url`）及标题、文案作为前台已解析数据。
   - 当服务端通用社媒解析不畅时，直接使用前台已提取的媒体信息落地为灵感条目，杜绝静默报错。
3. **「加入对话」自动拉起侧边栏并高亮装配**：
   - 侧边栏未打开时自动唤起侧边栏，后台稳妥暂存媒体。
   - 侧边栏初始化时取回暂存媒体，若当前尚无会话，自动初始化或直接将图片装配入输入框草稿附件中。
   - 附件挂载完成后，输入框自动获得焦点，对应缩略图高亮呈现，视觉反馈明确。

## 三、测试与验证计划
1. 单元测试：覆盖 background 真实灵感入库消息处理、前台媒体结构转换及草稿附件挂载逻辑。
2. 页面行为验证：模拟悬浮点击加入灵感库、保存到灵感库及加入对话链路，验证响应与状态流转。
