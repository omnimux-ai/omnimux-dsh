# 一键授权配对规格（Issue #2110）

## 1. 用户定稿
- **只保留授权按钮一条路**：6 位配对码的显示与输入全部删除（理由：同一条本机连接，授权不通则填码也不通）。
- 流程：插件面板点「连接本机 OmniMux」→ 自动打开应用授权页 → 点「确认授权」→ **授权页自动关闭** → 插件立即「已配对」，令牌自动保存。
- 文案：每个状态最多一行短句；授权页无解释性文字、无任何数字。

## 2. 核心改动规范

### AC-1 应用侧（Host，`plugins/omnimux-browser/src/pairing.ts` + 路由）
- `POST /ext/pair/request`（插件调用）：创建待授权请求 → `{ requestId, approveUrl }`；TTL 120 秒。
  - 准入：来源为回环且 `Origin` 不是 `http(s)://`（与既有扩展调用一致）。
- `GET /ext/pair?request=<id>`：渲染**极简授权页**（标题 + 一个「确认授权」按钮）；页面不含任何数字与密钥。
- `POST /ext/pair/approve` `{ requestId }`：标记已授权。
  - 准入：来源回环 **且 `Origin` 精确等于本机自身授权页来源**（`http://127.0.0.1:<port>` 或 `http://localhost:<port>`）；其它站点无法伪造该 Origin。
- `GET /ext/pair/status?request=<id>`（插件轮询）：`pending | approved | expired | unknown`；`approved` 时**一次性**下发 `{ token }` 并标记已消费，重复轮询不再返回令牌。
- 失败语义：未知/已消费请求 → 404/409；过期 → 410（或统一 409 + `expired`）；非回环/页面来源调用 → 403。
- 响应一律 `cache-control: no-store`，且**不设**通配 CORS。

### AC-2 插件侧（extension）
- 面板未连接时只有一个按钮「连接本机 OmniMux」+ 一行「等待授权…」；**删除配对码输入框与所有相关文案**。
- 点击后：请求授权 → `chrome.tabs.create(approveUrl)` → 每 1 秒轮询一次（上限 120 秒）→ 拿到令牌即保存、连接、**`chrome.tabs.remove(tabId)` 关闭授权页**，面板显示「✓ 已配对」。
- 授权页自身在授权成功后先尝试 `window.close()`；插件侧关闭为兜底，确保一定关闭。
- 失败只给一行短句（超时/无法打开授权页）。

### AC-3 安全边界不变
- 桥端令牌校验与既有安全断言零改动；令牌只交给插件的轮询查询，任何网页都拿不到。
- 请求一次性、2 分钟失效。

## 3. 验收证据
- 单测：创建/授权/轮询/一次性消费/过期；approve 只接受自身页面来源；页面来源轮询被拒。
- 真机端到端：点一次「确认授权」→ 插件变为已配对（连接成功）**且授权标签页确实被关闭**；页面与面板中不存在配对码相关 DOM/文案。证据落盘 `docs/evidence/`。
