**设计依据：** 用户反馈对比截图（图2：本地 Tab 选中删除交互范式）、统一模态弹窗规范、[design.md](../design.md)

## 1. 业务目标与交互对齐

### 1.1 核心诉求
用户在「产品库」选项卡中需要与「本地」选项卡保持一致的批量管理能力，包括：
1. 鼠标悬停卡片或选中卡片时，卡片左上角浮现圆形多选勾选框（`.omnimux-assets-check`）；
2. 勾选卡片后，在产品列表上方浮现操作条（`.omnimux-assets-selection`）：展示「已选 N 项」、右侧包含「取消选择」文本按钮和「移除 N 项」红色危险按钮；
3. 点击「移除 N 项」，弹出统一规范的 ConfirmModal 危险确认对话框，点击「确认移除」调用产品库删除接口，批量移除选中的产品引用并刷新列表；
4. 点击「取消选择」清空选中集合；
5. 点击卡片主体区域依然正常进入编辑/详情流程，勾选框的点击阻止事件冒泡。

### 1.2 详细设计方案
1. **卡片结构与角标布局**：
   - 卡片外层增加 `.omnimux-assets-focusable` 类名以获得一致的 hover 边框高亮与勾选框渐显效果；
   - 缩略图容器左上角挂载 `IconButton`，类名 `.omnimux-assets-check`，选中时 `data-selected="true"`，内嵌 `CheckIcon`；
   - 为避免与左上角勾选框重叠，卡片类型徽标 `.omnimux-products-badge` 调整为右上角定位（`top: 8px; right: 8px;`），与本地 Tab 中右上角标签（角色/道具/场景等）保持完全一致。
2. **选择栏与操作**：
   - 当 `selectedIds.size > 0` 时，在产品网格上方呈现 `.omnimux-assets-selection` 容器；
   - 包含计数文本 `t('select.count')`，按钮 `t('select.clear')` 及危险操作 `t('select.delete')`。
3. **确认弹窗与接口调用**：
   - 唤起 `ConfirmModal`，支持批量删除确认，单项和多项文案友好区分；
   - 点击确认后并发调用 `DELETE /omnimux/products/${encodeURIComponent(id)}`；
   - 删除成功后调用 `fetchProducts()` 重新拉取最新数据，并重置选中状态。

## 2. 验收标准（Acceptance Criteria）

### 2.1 卡片多选与勾选状态 (P0)
- **AC-101**：产品卡片左上角提供圆形勾选框，未选中时 hover 显现，选中时常驻高亮并展示对勾；
- **AC-102**：点击勾选框仅切换选中状态，不触发卡片本身的打开/编辑动作；
- **AC-103**：卡片角标定位在右上角，不与勾选框重叠。

### 2.2 批量选择操作栏 (P0)
- **AC-201**：未选中任何项时，选择栏隐藏；至少选中 1 项时，选择栏平滑展开；
- **AC-202**：点击「取消选择」，即刻清空所有已选项并隐藏选择栏；
- **AC-203**：选择栏展示准确的已选数量与移除数量。

### 2.3 确认弹窗与删除链路 (P0)
- **AC-301**：点击「移除 N 项」弹出规范的 `ConfirmModal`；
- **AC-302**：点击确认后调用后端 DELETE 接口批量删除，完成后列表即时刷新并关闭弹窗、清空已选项。
