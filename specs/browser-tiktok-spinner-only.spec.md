# TikTok 菜单进行中只保留转圈图标（Issue #3606）

## 1. 业务目标

菜单三项执行时，图标位换成旋转 spinner 已经足够表达“在进行”；右侧再补「解析下载中 / 提取音轨中 / 解析入库中」是重复解释。移除这三项右侧的状态文案，只保留 spinner 与原文案。

## 2. 范围

1. `plugins/omnimux-browser/extension/src/content/tiktok-scene/menu.ts`：删除 `.omx-item-state` 节点与 `stateLabels` 映射；`setRowState` 不再写文本；进行中只切 `is-busy` 并挂 `aria-busy="true"`。
2. `copy.ts`：删除 `busy` 字段与中英两套 busy 文案。
3. `styles.css`：删除 `.omx-item-state` 规则及错误态里对它的颜色选择器。
4. `tests/tiktok-menu.spec.ts`：把「执行中显示进度文案」改为「执行中出现 spinner、没有状态节点、文本仍是原文案、`aria-busy="true"`」，把 `.omx-item-state` 样式断言改为「样式表里不再存在该规则」。

## 3. 非目标

- 不改菜单项文案、顺序、锚点与动作语义。
- 不删除失败原因行（失败不是“进行中”，原因需要可读）。
- 不新增 toast/通知等提示渠道。

## 4. 成功标准

- **S1** 执行中：该行图标位是旋转 spinner，行文本仍是 `下载视频 / 下载音频 / 收藏到灵感库`，没有「解析中/下载中」等尾注。
- **S2** 成功回默认；失败仍显示宿主原因。
- **S3** 单测全绿、`node scripts/build.mjs` 通过、真实浏览器截图（进行中/完成）留存 `.agent-reports/`。

## 假设

- 假设用户能通过旋转图标识别“进行中”：三项都在同一图标位轮换，且执行中的行仍有禁用/变暗反馈；读屏用户通过 `aria-busy` 得到同一事实。
- 假设失败原因必须保留文案：它不是对进行中的重复解释，而是用户下一步行动的依据；移除会让失败变成静默。

## 证伪方式

- jsdom 单测：驱动一次挂起的执行，断言该行 `is-busy` 为真、图标位存在 `.omx-spinner`、文本里不出现任何 busy 文案；释放后回到默认。
- 真实浏览器（extension-e2e + 构建产物）渲染菜单并触发一次真实动作：截图中该行只应有 spinner、没有中文/英文状态尾注；若仍出现文案，则实现被证伪。
- 若失败路径不再显示原因行，也按证伪处理。
