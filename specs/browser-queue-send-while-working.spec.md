# 规格 · 排队态输入框有文字时右侧按钮由「停止」切回「发送」

任务：browser-queue-send-while-working（浏览器插件精灵助手）

## 1. 背景与问题

精灵助手在一次任务执行期间（消息排队态）会把右下角按钮显示为「停止」。此时用户在输入框里继续打字，本意是「再排一条消息」，但按钮仍然是「停止」：

- 视觉上无法提示「现在可以继续发送」；
- 用户按下按钮会停掉正在执行的任务，而不是把新消息排进队列。

## 2. 用户操作旅程

1. 用户发送一条消息，任务开始执行（排队态），右下角按钮显示「停止」。
2. 用户在输入框键入任意文字 → 右下角按钮立即切换为「发送」（可点击，高亮态）。
3. 用户点击「发送」或按回车 → 新消息进入排队队列，输入框清空，按钮回到「停止」。
4. 用户把输入框文字删空（或清空草稿图片）→ 按钮立即切回「停止」。

## 3. 验收标准

- **AC-1 有文字即发送**：排队态下，输入框含非空白文字或存在草稿图片时，右下角按钮渲染为「发送」按钮（向上箭头图标、发送无障碍标签），而非「停止」。
- **AC-2 清空即停止**：排队态下，输入框为空白且无草稿图片时，右下角按钮渲染为「停止」按钮（方块图标、停止无障碍标签）。
- **AC-3 排队发送可用**：该「发送」按钮处于可用态（未禁用），点击后调用既有排队发送路径（`session.prompt` 且 `mode: 'queue'`），输入框随之清空。
- **AC-4 非排队态不回归**：任务未执行时，有文字显示可点击的「发送」，无文字显示禁用态「发送」；不得出现「停止」。

## 4. 范围边界

- 仅调整输入区右下角按钮的渲染判定与可用态，不改排队坞（QueueDock）结构、样式与操作按钮。
- 不改精灵助手输入框自身的圆角、附件、模型胶囊等视觉。
- 不改停止逻辑本身（`stopTurn`）与排队 RPC 契约。

## 5. 关键实现点

- 判定入口：`plugins/omnimux-browser/extension/src/panel/App.tsx` 输入区尾部按钮分支。
- 排队发送窗口：`busy` 为假（提交在途为真）且会话未切换时，`send()` 走 `mode: 'queue'`。

## 6. 验证方式

- 单元/端到端：`plugins/omnimux-browser/extension/tests/e2e/queue-send-while-working.e2e.spec.ts`，用受控 RPC 桩驱动真实面板组件，断言 AC-1～AC-4。
- 构建：`node scripts/build.mjs`（浏览器加载 `extension/dist/`）。
- 回归：`pnpm test tests/queue-dock.spec.ts`。
