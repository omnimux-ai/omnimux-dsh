# 规格 · 系统默认生成方式不得锁死上游素材（#3214）

## 背景与现象

画布上新建的图片节点会先落到中枢目录的推荐生成方式「文生图」（`catalog.defaultOperations.image.operationId`）。此后连入一张已就绪的图片素材（JPG/PNG）时，节点仍停留在「文生图」，素材无法入槽，底栏以未使用素材条目报「当前生成方式不支持该素材」。用户读到的是「正常的 JPG 不被支持」，真实原因是生成方式被系统默认值锁死。

本地以真实网关函数复现（合成目录 + 真实 `recomputeCanvasSlots`）：

- 空节点：`operation=text_to_image`（系统写入）。
- 连入就绪图片后：`operation=text_to_image`、`slotBindings={}`，素材未入槽。

## 根因

`plugins/omnimux-workflow/src/shared/graph/canvasSlotRecompute.ts` 在节点尚无 `params.operation` 时把目录推荐模式写进 `params.operation`。此后该字段被当成「用户已保存的创作选择」：`resolveSlotOperation` 只在 `!params.operation` 时才按供给池自适应，于是连入素材再也改不动模式。

## 用户操作旅程

1. 用户在画布新建图片节点（空白，无上游素材）。
   - 期望：节点进入目录推荐模式（文生图），卡槽区呈现该模式的槽位与追加入口。
2. 用户把一张本地 JPG 导入为素材节点，并连到该生成节点。
   - 期望：节点自动改用能吸收这张图的已上架模式（图生图 / 多参考），素材入槽并显示为已装填卡；底栏不再出现「当前生成方式不支持该素材」；提交可用。
3. 用户在底栏显式选择过生成方式后再连入素材。
   - 期望：尊重用户选择，不再自动改写；若该模式确实无法消费素材，仍如实呈现未使用素材条目（不静默丢弃）。
4. 模型没有任何可吸收该素材的已上架模式。
   - 期望：行为不变，继续如实呈现未使用素材条目。

## 数据契约

节点数据新增 `autoOperationId`，只用于区分来源，不进入提交参数：

- `string`：系统上次自动写入的生成方式 id。
- `null`：用户显式拍板过生成方式。
- `undefined`：历史节点，来源未知；仅当被保存的模式等于该产出类型的目录推荐值时才按系统写入对待（历史节点自愈）。

## 验收标准

1. 空白图片节点获得目录推荐模式后连入就绪图片素材：模式自动切到可吸收该素材的已上架模式，素材入槽，未使用条目消失。
2. 用户显式选择过生成方式（`autoOperationId=null`）的节点不被自动改写。
3. 历史节点（无 `autoOperationId`、模式等于目录推荐值）同样被修复。
4. 模型无可吸收该素材的模式时行为不变（仍如实报未使用）。
5. 提交参数形状与后端契约不变；omnimux-workflow 包内的既有校验命令保持通过。

## 产品基线

不依赖开发机状态：判定只读中枢目录契约（`catalog.defaultOperations`、`model.operations`）与节点自身的上游素材可用性；目录不可用时保持既有 `catalog_unavailable` 行为。

## 文档影响

无独立文档改动：槽位与生成方式规则的事实归属仍是 `docs/contracts/node-input-submission.md` 与 `docs/contracts/hub.md`，本次只是让画布侧遵循既有「通用连线不锁槽位、不隐藏生成方式」约束，未新增或改变契约。
