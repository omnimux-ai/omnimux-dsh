# Spec: 语音合成（TTS）双模式架构：参考音频克隆 vs 内置音色库联动与防呆互斥

- 业务主题：创作画布音频节点（文本转语音 / 声音克隆）交互状态机与执行链路重构
- 风险级别：R2（核心节点交互状态机 + 跨插件提交网关）
- 准据：用户明确业务指令与网关真实支持契约

## 1. 业务目标与交互设计

**用户目标**：
在创作画布中，TTS 节点无缝支持两种模式，自动根据连线状态智能自适应：
1. **参考音频模式（音色克隆）**：只能通过上游连线输入；当连接了上游音频节点时，自动切换为此模式，复刻该参考音频的音色来朗读文案；
2. **内置音色模式（精选主播）**：在没有上游音频输入时，默认此模式，用户可从 509+ 款官方精品音色库中自由挑选；
3. **强互斥防呆**：
   - 当节点已连接上游音频时，音色库选择被锁定不可选，必须先移除上游输入连线才能切换自定义音色库，彻底杜绝两个输入的逻辑打架；
   - 在参考音频模式下，若上游输入未就绪或未连接，右下角「生成」提交按键强制禁用；
4. **底层提交流程**：
   - 参考音频模式向网关提交 `references: [{ audio_url }]`（若为本地物理文件，自动经 `hostLocalAssetsIfNeeded` 换取公网 URL）；
   - 内置音色模式提交 `voice`、`speed`、`format`。

## 2. 验收标准（AC）

- **AC-1 默认模式与智能自适应**：
  - 节点无上游音频输入时，默认为「内置音色模式」，展示音色库挑选入口；
  - 一旦连入上游音频素材节点，状态机立刻自动切换为「参考音频模式」。
- **AC-2 强互斥与防呆守卫**：
  - 存在上游音频连线时，音色库选择入口处于锁定/隐藏/提示状态，禁止用户选主播音色；
  - 提示文案明确引导“需先断开上游音频输入”；
  - 在参考音频模式下无有效音频输入时，生成提交按钮处于 disabled 状态。
- **AC-3 底层发包与参考音通道打通**：
  - 中枢 `mapOmnimuxInput` 与发包层对携带参考音频的请求，保留并透传 `references: [{ audio_url }]`；
  - 严禁将参考音频过滤删除。
- **AC-4 门禁全绿与真实验收**：
  - `pnpm verify:model-contracts` 严格模式通过；
  - 单元测试与端到端测试 100% 通过；
  - 基于真实网关验证参考音频克隆与内置音色生成均成功出片。
