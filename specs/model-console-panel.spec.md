# 中枢模型检索可视化面板规格 (Model Console Panel Spec)

- 任务工作树：`.worktrees/model-console-panel`（分支 `agent/model-console-panel`，基线 `origin/main` @ `cba279c8f`）
- 日期：2026-09-16
- 需求来源：用户「帮我做一个可视化面板 专门检索本地中枢接入的模型数据和状态 尽可能完善 UI 简洁」。

## 1. 背景与目标

当前中枢已接入 41 款模型，其中 17 款配置了渠道线路分组（共 40+ 条线路）。这些数据分散在三处真源：

| 数据真源 | 内容 |
|---|---|
| `plugins/omnimux/src/catalog/specs/*.yaml` | 模型契约：标识、品牌、模态、操作、输入卡槽、参数枚举 |
| `plugins/omnimux/src/catalog/serving/channel-groups.js` | 线路分组：定价、SLA、上游型号（wireModel）、上游分组（wireGroup）、分组契约约束 |
| `plugins/omnimux/src/catalog/contract/dispositions.json` | 上架准入与处置规则 |

目前查看这些数据只能靠读源码或运行零散命令，缺少**一屏总览**。目标是产出一个自包含的单文件可视化面板。

## 2. 目标

1. **单文件自包含**：零外部依赖、零网络请求，双击即可在任意浏览器打开。
2. **一屏总览模型状态**：总模型数、已就绪数、已配置线路数、线路分组总数。
3. **可检索**：按型号名 / 品牌 / 标识实时筛选；按模态（文本 / 图像 / 视频 / 音频 / 阅读器）与「是否已就绪」过滤。
4. **可下钻**：展开任一模型，查看其全部线路分组（名称、徽标、定价积分、SLA 稳定率、上游型号、上游分组、分组契约约束）与全部操作清单（标注已就绪 / 未就绪）。
5. **契约缺口可见**：显式标记未就绪操作、无线路分组配置的模型，便于发现遗漏。
6. **视觉极简**：严格遵循 `design.md` §3.6 黑白中性底体系（Structural Monochrome），无紫色滥用、无花哨装饰与动效。

## 3. 验收标准（可测试）

- **AC-1（数据完整性）**：面板渲染的模型总数与 `loadAll()` 返回的模型数一致；线路分组总数与 `MODEL_CHANNEL_GROUPS` 汇总值一致。
- **AC-2（自包含性）**：产出的 HTML 不引用任何外部资源（无 `http://` / `https://` 资源引用，无 CDN 脚本与样式），离线可用。
- **AC-3（检索与过滤）**：搜索框输入型号名或品牌时列表实时收敛；模态筛选与「仅看已就绪」开关可叠加生效；清空条件后恢复全量。
- **AC-4（下钻信息正确）**：展开模型后，其线路分组的上游型号、上游分组、定价积分与 SLA 与真源逐字一致；操作清单的已就绪状态与 `listed` 标记一致。
- **AC-5（缺口可见）**：未配置线路分组的模型显式标注；操作全部未就绪的模型显式标注。
- **AC-6（视觉规范）**：暗色主题下底色为深曜石黑系、卡片为半透暗石板、文字层级符合 §4.2 字阶；无紫色主按钮。

## 4. 交付形态

- 生成器脚本：`scripts/generate-model-console.mjs`（数据真源同源读取，页面不手工抄录任何清单）
- 产出页面：`docs/tools/model-console.html`
- npm 入口：`pnpm models:console`

## 5. 不做事项

- 不新增任何运行时依赖或前端框架。
- 不修改中枢模型契约与线路分组数据本身（本任务只读）。
- 不接入网络请求（不拉取上游网关实时数据，避免离线不可用）。
