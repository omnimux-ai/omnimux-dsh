# Spec: 输入框「优化提示词」按钮不可点修复

## 目标与边界

修复会话输入框右侧「优化提示词」图标按钮（`conversation.input.right`）表现为「点了没反应」。不新增可见 UI、不改文案白名单、不改 host 契约，不改任何既有评估断言文件。

根因两点：

1. **空草稿判定会失效**：`useInput` 槽位钩子缺位时，`readDraft()` 只是挂载瞬间的快照——之后打字不再触发组件重渲染，空草稿判定永久为真，按钮永远置灰不可点。
2. **原生置灰态吞掉一切反馈**：置灰态按钮不派发悬停，未配置态的「配置 API Key 后可用」提示永远不可见，用户无从得知原因。

## 决策

| 项 | 决策 |
|---|---|
| 草稿兜底 | 新增 `useDomDraft()`：无 useInput 时订阅捕获段 `input` 事件 + `omnimux:composer:set-draft` 回写事件，跟随真实输入框 |
| 置灰态提示 | 保持按钮原有置灰形态不变（`disabled` 形态契约不动），改用包裹元素承载悬停提示，未配置时用户能看到原因 |
| 文案 | 零新增，仅 `promptOptimize.tooltip` / `promptOptimize.noKey` / `promptOptimize.failed` 三个白名单键 |
| 状态机 | 不变：置灰 → 可点 → 运行中禁重入 → 回写聚焦 |

## 用户操作旅程

- 有草稿 + 已配置 → 可点，点击 spinner，完成回写并聚焦。
- 空草稿 → 置灰；未配置 → 置灰且悬停可见原因提示。
- 即使宿主没给 input.right 注入 useInput，键入文字后按钮也必须变为可点。

## 验收

1. 键入文字后按钮从置灰变为可点（useInput 缺位时同样成立）。
2. 未配置时悬停按钮区域能看到「配置 API Key 后可用」。
3. `pnpm --filter omnimux test` 全绿。
