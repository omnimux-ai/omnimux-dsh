# 推特助手与扩展交互：消除「抓整页第一个」的物理锚点隔离规格

## 1. 背景与根因

在当前推特助手与浏览器扩展中，存在 8 处在找不到局部容器时向后退化到全局查找（如 `composerContainer = ... || document`、`document.querySelector('main article[data-testid="tweet"]')` 或 `injector.ts` 中 `targetArea = document.querySelector(...)`）的脆弱逻辑。
在推特多输入框并存场景下（例如：页面顶部常驻发帖框、下方多条推文内嵌回复框同时展开）：
- **输入端**：可能读取到非当前点击图标所属输入框的草稿内容，导致模型收到错误的提示词；
- **输出端**：生成完成后，可能把内容注入到页面的第一个输入框（例如顶部的原创发帖框），覆盖用户原有的草稿；
- **上下文端**：回帖与引用分析时可能抓取到错误推文或将卡片内非作者链接解析为作者。

## 2. 目标与改动范围

### 2.1 注入层严格物理锚定（`injector.ts`）
- 移除 `|| document` 兜底容器，移除无锚点全局查找 `document.querySelector(...)`；
- 必须严格从传入的 `anchorButton` 向上寻找有效容器（标签包装层、对话框、表单、推文卡片）；
- 若局部容器内确实未找到对应的可编辑输入框，**坚决不执行全局查找**，直接安全降级为写入剪贴板并提示用户复制，杜绝填错框。

### 2.2 上下文提取严格物理锚定（`extractor.ts`）
- 提取草稿时，移除 `composerContainer` 的 `|| document` 兜底；若图标脱离容器，草稿留空，不误读全局第一个框；
- 提取回复目标推文时，移除 `Fallback: the first tweet in main`；若未能在弹窗、焦点推文或图标祖先推文中定位目标，则 `targetTweet` 保持 null，触发就绪闸门拦截，避免评错推文；
- 提取引用推文作者时，优先从 `[data-testid="User-Name"]` 内部解析博主主页链接，避免被推文内部包含的外部链接误导。

### 2.3 推速推文链接提取精准定位（`twitter-velocity/extractor.ts`）
- 优先从推文自身时间戳 `<time>` 的父级链接中提取真实 status ID 与 URL；
- 避免引用转推（Quote Tweet）卡片内部嵌套的 `/status/` 链接反客为主抢占主推文身份。

### 2.4 侧边栏/工作台推文感知焦点优先（`page-sensor.ts`）
- 优先抓取详情页焦点推文 `article[tabindex="-1"][data-testid="tweet"]`，其次才取页面推文，避免取错非焦点内容。

### 2.5 网页填充器支持传入首选目标（`dom-fill.ts`）
- `fillDom` 支持传入明确的 `preferredTarget`，优先填充调用方指定的物理元素，避免全局轮询选择器填错对象。

## 3. 验收标准

1. **单测覆盖**：
   - 构造多输入框页面（顶部发帖框 + 底部回复框 1 + 底部回复框 2）：
     - 点击回复框 2 的图标，仅提取回复框 2 内草稿；
     - 注入文本时，精准填入回复框 2，发帖框与回复框 1 的内容毫发无损；
     - 故意破坏容器时，注入层拒绝全局乱填，触发剪贴板复制兜底；
     - 回帖目标未定位时不抓取页面无关推文，触发就绪拦截；
     - 引用卡片提取作者精准命中用户名标签，不被正文链接干扰；
     - 推速链接提取在含有引用卡片的推文中准确命中主推文 status。
2. **全量回归测试**：
   - `twitter-copilot.spec.ts`、`no-purple-theme.spec.ts`、`velocity-flag.spec.ts` 全部 100% 通过。
3. **真实环境实机验证**：
   - 验证多输入框并存时的提取与注入隔离。
