# 规格说明：应用编辑与副本创建弹窗工作流 (Issue #2630)

## 1. 业务目标与价值
- **核心目标**：彻底修复应用详情页点击「编辑应用」时底层拦截的 `version-required` 报错；同时贯彻“官方预设应用数据只读不可变、用户编辑必走独立工程副本”的产品最佳实践。
- **用户价值**：
  1. 保证小白用户零门槛：弹窗默认预填名称与当前工作区，回车即可一键秒进画布开始编辑；
  2. 赋予进阶用户完全控制权：允许自由调整项目/创作页名称，自主选择加入当前项目或在任意工作区新建独立项目；
  3. 彻底防止软件升级冲毁用户配置：官方模板只读不可变，用户的所有改动安全保存在本地副本中。

## 2. 关键业务场景与验收标准

### 场景 1：官方预设应用点击「编辑应用」唤起轻量确认弹窗
- 当用户在应用详情页（`AppTab`）点击右上角「编辑应用」时，如果应用为官方预设应用（`app-creatify-*` 或 `OmniMux Official`），必须唤起模态弹窗 `ForkAppProjectDialog`；
- 弹窗标题为「创建应用编辑副本」，配有大白话副标题说明；
- 名称输入框（`input`）自动获得焦点，默认预填名称：
  - 当前会话已绑定项目：预填 `${应用名}_副本`；
  - 当前会话未绑定项目：预填 `${应用名} (副本)`；
- 存放模式分段选择（当前会话已有绑定项目时展示）：
  - 选项一：【加入当前项目】（作为新创作页追加，默认推荐）；
  - 选项二：【新建独立项目】（在指定工作区目录新建独立工程包）；
- 工作区路径挑选器（在新建独立项目模式下展示）：
  - 默认展示当前会话的工作区物理路径；
  - 支持展开单层目录树浏览本地其它文件夹并选择。

### 场景 2：弹窗确认与底层版本号保存（消除 version-required）
- 用户点击【确认并进入画布】（或在名称输入框按回车）：
  - 调用 `createProjectForkFromManifest`，根据用户选定的模式在当前项目创建新创作页，或在选定目录新建独立项目；
  - 无论哪种模式，首次保存画布工作流节点至新工作区（`PUT /omnimux-workflow/api/workspaces/:id`）时，请求体必须显式携带 `{ expectedVersion: 0, nodes, edges }`；
  - 后端乐观锁校验通过，返回 200 成功，杜绝 `version-required` 拦截报错；
  - 自动切换到创作画布并高亮聚焦（Focus）至该工作流打组容器。

### 场景 3：用户自建应用分诊
- 当用户点击「编辑应用」且该应用为当前用户自建已发布的本地应用（工程与画布仍在当前本地）：
  - 直接跳转至所属项目的源画布定位到对应工作流组，不强制增加冗余副本。

## 3. 自动化测试与质量门禁
1. `appOwnershipFork.test.mjs`：补充 `expectedVersion: 0` 必填契约断言，验证自定义 `projectRoot`、`projectTitle`、`pageTitle` 传参支持；
2. `appTab.test.mjs`：验证点击官方应用编辑按钮唤起弹窗而非静默执行；
3. `app-edit-and-fork-flow.e2e.test.mjs`：全链路端到端验证弹窗出现、确认创建、版本号校验放行与画布激活。
