# 规格说明：统一引用隐形导航（Agent 感知运行丝滑化 · 冲刺三）

## 一、背景与问题
1. **前两冲刺已闭环但仍有一步推理成本**：冲刺一让工具说明与中枢公理知道「统一引用是最终入参」，冲刺二让无界扫盘被毫秒级拦截；但 Agent 在首轮仍需自己推理「手上这个 `@inspiration/insp_xxx.mp4` 该交给哪个工具」。
2. **隐形上下文只有素材、没有动作**：灵感库「发送至对话」时，宿主通过原生 `agent/pre-step` 注入的伴随上下文只包含素材条目（如 `[视频] xxx (MP4): @inspiration/insp_xxx.mp4`），不含任何推荐动作，Agent 需要自行摸索。
3. **现状证据**：事故会话（session-63f46629）第 1–10 步全部消耗在「找文件」上，第 11 步才命中 `video_breakdown_analyze`。

## 二、验收标准与核心行为
1. **从伴随上下文中识别统一引用**：
   - 新增纯函数模块 `plugins/omnimux/src/workbench/reference-navigation.js`；
   - 能从注入文本中提取 `@inspiration/…`、`@asset/…`、`@product/…` 三类统一引用，去重并保序；
   - 文本中不含上述引用时返回空串，**不产生任何额外注入**。
2. **注入一段隐形导航（用户不可见）**：
   - 命中引用时，在**同一条**已存在的伴随上下文消息内追加导航区块，明确告知：这些引用可直接作为工具入参消费、推荐先调 `video_breakdown_analyze`、禁止用 `glob`/`find`/`bash` 到本地磁盘查找；
   - **不新增消息条数**（保持用户气泡与上下文注入条数不变），不修改用户输入框与气泡原文。
3. **零回退**：
   - 无引用的普通会话注入内容与条数与改动前完全一致；
   - `step !== 1` 不注入的既有行为保持不变。

## 三、测试与验证计划
1. 单元测试：
   - `reference-navigation.test.js`：多引用提取与去重、无引用返回空串、导航文案包含推荐工具名与禁用动作；
   - `context-injector.test.js`：含引用时消息条数不变且导航出现在同一条上下文消息内；无引用时注入文本与断言与既有测试一致。
2. 回归：`node --test plugins/omnimux/src/workbench/*.test.js` 全绿。
3. 静态检查：`git diff --check`。
