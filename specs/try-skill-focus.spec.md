# 规格：技能卡片点击「去对话中试试」后自动显露会话栏并聚焦输入框

- 状态：草稿
- 权威：产品契约
- 关联 Issue：#2201
- 关联 PR：TBD

## 1. 背景与用户痛点

用户在技能/专家卡片上点击「去对话中试试」后，底层技能临时挂载与输入框药丸数据虽然已就绪，但界面依然停留在全屏工作台视图（或会话栏被折叠收起），用户眼前的屏幕完全没有任何变化与反馈，误以为点击按钮无响应。

## 2. 验收准则（AC）

- **AC-1 显露会话**：在卡片悬停点击「去对话中试试」时，必须调用 `window.__omnimuxWorkbench?.ensureConversationVisible?.()` 及 `setFocus('split')`，确保中间的对话视口在视觉上被完全显露；
- **AC-2 聚焦输入框**：切回或显露会话后，自动定位并聚焦主输入框（`findComposer()?.focus?.()`），光标进入输入框，使用户一眼看到输入框底部高亮挂载的技能药丸；
- **AC-3 兼容会话创建**：如果当前没有活动会话而需要新创建会话，创建成功后依然保持 split 布局并显露对话栏；
- **AC-4 临时加载语义不变**：保持之前 Issue #2166 的契约，挂载方式为当前会话临时加载（`tryAttach`），绝不向技能目录安装，不影响「我的 Skill」；
- **AC-5 session-guide 引导不变**：Hypit 等特殊 `session-guide` 流程保持官方预填与引导行为不变。

## 3. 测试与验证策略

1. 单元测试 / 契约测试：覆盖 `trySkillInSession` 在点击后对 `ensureConversationVisible`、`setFocus('split')` 和 `findComposer` 的调用；
2. CDP 自动化验证：在真实浏览器环境中，打开全屏工作台，模拟点击卡片「去对话中试试」，验证会话栏在 500ms 内显露（`hasTextarea: true` 且 `textareaVisible: true`），光标聚焦，底部药丸正确反映所选技能。
