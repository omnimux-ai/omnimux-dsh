# 规格：通用智能填表协同助手 (Universal Form Copilot)

## 1. 业务痛点与重构目标

### 1.1 现状缺陷复盘
1. **动作与场景粗暴错配（截图问题）**：
   - 扩展在所有助手回复气泡底部无差别渲染「填入输入框」按钮。
   - 在用户打招呼、功能介绍、思路分析、日常答疑时均强行出现该按钮，存在极高的误触风险（用户极易将两百多字自我介绍一键填入公开推特发帖框），界面噪音严重。
2. **能力边界受限**：
   - 仅支持单个文本框的简单覆盖，无法处理账号注册、达人入驻、活动报名、企业认证等多字段复合表单场景。
3. **按钮文案混乱**：
   - 历史版本存在“填入输入框”、“填入发帖框”、“确认填入”等多头文案，心智不统一。

### 1.2 核心重构目标
- **界面净化**：日常沟通对话彻底移除填入按钮；
- **全场景自适应**：自适应单输入框（推特/社媒）与多字段复合表单（注册/申请/入驻）；
- **标准四步闭环**：建立「结构自动感知 → 智能生成推荐草稿 → 用户就地核对 → 一键填写回填」的标准流程；
- **文案强一致性**：所有场景统一主动作按钮为 **「一键填写」**。

## 2. 详细技术规范与实现准则

### 2.1 表单结构感知引擎 (`form-sniffer.ts`)
1. **单输入框场景探测（如 X / Twitter 发帖框）**：
   - 嗅探网页当前聚焦或主区域的 `[data-testid="tweetTextarea_0"]`、`textarea` 或带 `contenteditable="true"` 的单一富文本容器。
   - 状态标记：`MODE_SINGLE_INPUT`（单输入框模式）。
2. **多字段复合表单探测（如 入驻表、申请表、注册表）**：
   - 扫描当前激活视口内的 `form`、卡片容器中的全部输入项：`input[type="text|email|tel"]`、`textarea`、`select`。
   - 提取元数据：字段标签文本（Label）、输入框提示词（Placeholder）、字段名（Name/ID）、是否必填（Required）。
   - 状态标记：`MODE_COMPLEX_FORM`（复合表单模式，附带字段列表）。
3. **无输入框场景**：
   - 若当前页面无可写输入项，状态标记为 `MODE_NO_INPUT`。

### 2.2 文本清洗与结构化映射 (`form-sanitizer.ts`)
1. **思考过程剥离**：
   - 严禁将模型输出的“分析思路”、“选题建议”、“受众心理洞察”等前置文字混入待填内容。
   - 规则：以结构化分隔符或特定标记将沟通解释语留在上方气泡，仅将可执行正文放入草稿载体。
2. **复合表单键值对对齐**：
   - 将模型生成的推荐值按照感知到的表单字段一一映射（如 `姓名 → name`, `邮箱 → email`, `申请陈述 → reason`）。
   - 过滤非法字符与前后多余空行，确保数据格式符合输入框校验规则。

### 2.3 界面自适应渲染规范 (`FormDraftCard.tsx` / `DomFillButton.tsx`)
1. **沟通态（纯文本气泡）**：
   - 条件：开场白、功能菜单、异常报错、纯思路分析。
   - 呈现：标准气泡，底栏仅提供轻量复制，**100% 不渲染**「一键填写」按钮。
2. **单文本交付态（紧凑单条草稿盒）**：
   - 条件：用户要求生成单条推文、单次评论或单段短文本。
   - 呈现：无标签栏，显示场景微标（如 `🎯 精准定制推文`）与字符统计；
   - 动作区：右下角常驻高亮主按钮 **「一键填写」**（带 ⚡ 微标）及次按钮「复制」。
3. **多方案赛马交付态（标签切换草稿盒）**：
   - 条件：用户要求生成多套备选文案（方案 A / B / C）。
   - 呈现：顶部带横向选项卡，用户切换时正文与字数联动；各方案独立享有 **「一键填写」** 按钮。
4. **复合表单交付态（表单映射清单卡片）**：
   - 条件：探测到复合表单且用户要求准备填报数据。
   - 呈现：顶部显示“已映射网页表单 (N 项)”，中部按字段排列卡片行，支持点击直接修改内容；
   - 动作区：底部常驻主按钮 **「一键填写」**，点击后按序批量自动注入网页对应字段。

### 2.4 注入执行与状态流转 (`dom-injector.ts`)
1. **自然输入模拟**：
   - 支持向原生 `input/textarea` 注入值并派发 `input`、`change`、`blur` 事件。
   - 支持针对推特等复杂的 `contenteditable` 容器执行光标聚焦、选区替换并触发输入监听，确保前端状态绑定的同步更新。
2. **按钮状态确定性流转**：
   - **常态（待触发）**：蓝底白字 `⚡ 一键填写`；
   - **执行态（注入中）**：禁用点击，显示 `填写中…`，防止用户快速连击造成重复注入；
   - **完成态（成功）**：绿底白字 `✔ 已填写`，伴随网页输入框高亮闪烁，2.5 秒后平滑恢复；
   - **异常兜底**：若网页输入框失去焦点或被移除，弹出轻提示引导用户手动激活，同时静默复制文本至剪贴板作为兜底。

## 3. 验收标准与测试矩阵

| 场景用例 | 界面预期表现 | 按钮与动作预期 |
| :--- | :--- | :--- |
| **用例 1：日常寒暄问候** | 正常气泡文本，无多余装饰 | **绝对无「一键填写」按钮**，杜绝误触 |
| **用例 2：思路拆解分析** | 上方气泡展示分析与建议 | 绝不将分析内容挂载填入动作 |
| **用例 3：推特单条爆款文案** | 呈现单条草稿盒，无多余标签，字数实时显示 | 点击「一键填写」，仅将框内正文填入推特发帖框，按钮变绿标「已填写」 |
| **用例 4：三套备选方案赛马** | 呈现选项卡草稿盒，可自由切换 A/B/C | 点击选中的活动方案「一键填写」，仅填入当前方案 |
| **用例 5：多字段入驻/申请表** | 结构化呈现 4 项字段清单，支持字段内直接微调 | 点击「一键填写」，4 个字段依次高亮注入网页对应表单，状态变「已填写」 |
| **用例 6：网页无活动输入框** | 正常呈现草稿盒 | 点击弹出温和引导：“请先点击网页输入框”，绝不黑盒报错 |
