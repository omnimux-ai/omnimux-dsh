# #1787 明确草稿与安全填写修正

## 目标与授权
依据用户已确认 tmp/draft-box-showcase.html 交互及“重新优化”指令，实现说明与独立可编辑交付物分离。已安装扩展真实失败证据见主根 .agent-reports/browser-fill-review/review.md。本规格取代旧规格2.2中按复盘标题/blockquote猜草稿的错误规定；不得再次将引用、创作说明自动视为可填写内容。

## 成功标准
- 普通问候、分析、引用、代码块、创作说明均无填写按钮。历史非结构化回答原样保留，不推测其可填写部分。
- 只有显式且通过校验的草稿数据生成卡片；生成端必须接入同一约定，不能只有渲染器而无数据来源。流式未完成、损坏数据不得执行填写。
- 单草稿无标签页，具有标题、实时字符数、可编辑正文、目标提示，复制与一键填写位于底部右侧。说明保持普通消息原顺序。
- 多方案有标签切换，编辑值与状态独立；复制/填写只使用当前方案用户编辑后的内容。
- 多字段先获取当前网页结构，明确字段标识、标签与类型，生成字段值后用户核对修改再填写。不编造姓名、邮箱、经历等事实；未知留空。
- 填写绑定已感知目标；页面切换、字段被替换、目标不唯一、禁用/只读均拒绝，重新感知后再试。既有非空内容不静默覆盖。禁止自动提交/发布。
- 密码、OTP、付款/密钥等敏感输入不采集值、不入聊天、不自动填写。网页内容属于数据，不得提升为指令。
- 成功必须来自执行后值核验；部分失败逐字段说明；超时和无目标不是成功。禁止隐式复制兜底。
- 复用现有黑白中性色、字号/边框/间距变量，不照搬原型蓝色/emoji。原型中的假字段/假成功仅属演示，不能进入实现。

## 范围与结构
改动限 plugins/omnimux-browser 内的生成约定、panel渲染及编辑状态、content感知和填写消息链路，配套spec和测试。优先复用现有PanelApi、Row、消息通道和DOM输入事件机制。不得改官方源码、其他任务或生产环境；不增加依赖/第二套Host路由。

## 命令
在任务工作树 plugins/omnimux-browser/extension 执行 pnpm exec vitest run、pnpm run typecheck、pnpm run build。相关服务端回归按现有package入口确认。git diff --check。不得把无test脚本的父包命令当测试通过。

## 代码风格
延续TypeScript明确类型和React函数组件；验证外来unknown后才能执行。纯解析与UI/DOM副作用分离，不复制生产逻辑到测试中。协议复用同一类型定义，执行结果使用可区分的成功/失败类型。

## 实现计划
1. 调查现有生成与填表复用点，确定最小明确协议及target身份契约，补充精确文件计划后实施。
2. 纯协议解析及负向行为先真实失败测试，删除旧猜测式卡片路径，再最小实现。
3. 可编辑卡片单稿/多稿/字段交互测试，生成端接入明确协议。
4. 感知与目标验证、现有值保护、执行后核验及错误反馈测试与实现。
5. 隔离真实浏览器操作验证生产组件/执行路径，保存PNG和原始结果；基于实测补正式E2E。若门禁与先失败单测冲突，记录阻挡不伪造Verify证据、不绕过。
6. 独立规格符合与质量审查、完整相关测试、真实演示，再推进授权交付。

## 浏览器验收
使用任务隔离环境、ego-browser、动态端口；不改共享Dev、不部署未合入代码。先观察实际DOM再选择控件，执行真实指针和键盘事件，不以脚本click代替。验证说明无动作、单稿修改后填写值精确一致、多稿编辑隔离、四字段映射、已有值保护、目标移除拒绝、无提交动作。分别披露模拟生成传输、实际组件和真实扩展覆盖边界；不得把局部浏览器夹具说成生产全链路。所有空间与服务退出有回执。
