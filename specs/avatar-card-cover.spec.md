# 角色卡立绘优先渲染规格 (Issue #1966)

## 1. 现象
「资产中心 › 角色 › 动物拟人」等分类下，100 款免费数字人角色的卡片**全部是空的**：
只画出一块深色底 + 居中播放按钮，看不到角色立绘，也看不出角色长相。

## 2. 根因
这批角色的本地素材是**语音样本**（`.wav`），而角色门面是**立绘**（`.png`）。
卡片种类判定只看了媒体类型：

```js
if (asset?.mediaType === 'audio') return hasMedia ? 'audio' : 'text'
```

`mediaType === 'audio'` 直接判成「语音卡」，于是渲染分支只画纯色块 + 播放键，
`cover_url` 上的立绘根本没有进入渲染路径。

## 3. 目标
一行**既有立绘封面、又有语音**时，卡片画立绘，播放键浮在立绘上；
只有「没有立绘的纯语音行」才保持原来的纯色块样式。

## 4. 验收标准
- **AC-1** 有立绘封面 + 语音的行，卡片渲染出图片元素（`img`），且 `src` 指向该行封面。
- **AC-2** 同一张卡片仍带播放控件，点击只切换播放、不打开预览。
- **AC-3** 无立绘的纯语音行（配音样本）保持纯色块 + 播放键，不出现图片元素。
- **AC-4** 无媒体、无立绘的文本行仍渲染为文本卡。
- **AC-5** 有立绘 + 视频的行（实景数字人、场景、道具）行为不变。
- **AC-6** 既有单元测试与端到端测试全绿。
