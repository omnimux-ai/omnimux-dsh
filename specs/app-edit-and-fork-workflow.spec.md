# AI 应用编辑与副本跳转工作流规格 (Spec)

## 一、背景与业务诉求
响应用户明确交互需求：
1. **标题栏布局优化**：将应用描述从原本被推挤到最右侧的位置，调整为放置在标题与版本徽标的右侧，使标题与描述紧凑关联；
2. **右上角新增「编辑应用」入口**：在应用详情页顶栏右上角新增高质感极简按钮「编辑应用」；
3. **自适应所有权分诊与画布跳转**：
   - **同一个用户的应用**：若该应用源自当前用户本地项目且存在对应源工程与画布，点击后直接激活该项目画布，并精准定位至发布时的工作流组；
   - **不同用户的应用（官方内置/外部模板/无本地工程）**：自动为用户克隆该应用的工作流拓扑，创建独立的项目副本（例如：`手机与网页交互实机演示 (副本)`），将节点完整包裹为工作流组并保存至新画布，然后无缝跳转至该副本画布；
4. **重新打包发布与项目库闭环**：
   - 用户在副本画布中编辑修改后，可点击工作流组顶栏「🚀 发布应用」打包发布；
   - 发布的新应用立即存入本地应用注册表，并在「项目」页的「AI 应用」库中实时可见，支持一键打开与二次复用。

---

## 二、验收标准与核心场景 (Acceptance Criteria)

### 场景 1：标题栏布局重构
- 顶部 Header 左侧区域依次水平排布：`应用名称` + `分类标签` + `版本号` + `应用描述`；
- 描述文字紧随其后，带有轻量截断（溢出文本省略）与鼠标悬停完整提示（`title` 属性），不再孤立推挤到页面最右端；
- 顶部 Header 右侧独立挂载「编辑应用」按钮。

### 场景 2：右上角「编辑应用」按键交互与视觉风格
- 按钮展示大白话中文「编辑应用」，配备极简编辑/配置滑块图标；
- 遵循苹果/谷歌现代极简设计，边框细致、层次克制，具备平滑悬停效果与禁用/忙碌保护；
- 点击时触发自适应分诊流程，并伴随明确的业务状态反馈。

### 场景 3：同一个用户的应用（直接编辑）
- 识别规则：非官方预置应用（`author !== 'OmniMux Official'`），且应用 `workflowBinding.projectId` 或 `workspaceId` 存在于当前用户的本地项目库中；
- 行为：
  1. 激活该应用所属项目的画布工作区；
  2. 聚焦至发布时关联的工作流组（`focusGroupId: target.groupId`）；
  3. 弹出轻量提示：`已打开应用源项目画布，可直接编辑与调试`。

### 场景 4：不同用户的应用（创建副本）
- 识别规则：官方预置应用（如 `app-creatify-*`），或在本地项目库中找不到所属项目的应用；
- 行为：
  1. 自动提取该应用的工作流节点（`nodes`）与连线（`edges`），若清单快照缺失则从内置模板数据中解析；
  2. 自动生成工作流组容器（`GroupNode`），将子节点纳入其中，标题命名为 `${应用名} (副本)`；
  3. 调用工程 API 创建新项目，命名为 `${应用名} 副本`；
  4. 将包装后的工作流数据持久化保存至新项目分配的画布工作区；
  5. 自动激活并切换至新项目的创作画布，选中该工作流组；
  6. 弹出轻量提示：`已为你创建「${应用名}」的副本工程，编辑后可随时重新打包发布。`

### 场景 5：编辑后重新打包发布与项目库 AI 应用可见性
- 用户在画布中对组内节点完成编辑调整后，点击组顶栏「🚀 发布应用」；
- 调起发布向导完成打包，生成新的 `ApplicationManifest` 并落盘至 `omnimux_apps_manifests`；
- 触发全局事件通知，使得「项目」页的「AI 应用」分类下立即刷新并显示该应用卡片，卡片支持点击运行与再次编辑。

## 三、门禁与测试要求
1. `appTab.header.test.mjs`：验证标题描述位于左侧容器、右上角存在编辑应用按钮；
2. `appOwnershipFork.test.mjs`：验证同一个用户直接编辑、不同用户/预置应用创建副本并打包打组的逻辑闭环；
3. `e2e/app-edit-fork-publish.e2e.test.mjs`：端到端验证点击编辑应用、创建副本、发布新应用并在项目库可见的全链路。
