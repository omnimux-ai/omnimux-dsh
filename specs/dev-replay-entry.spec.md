# 规格 · 开发态失败请求一键重放（Issue #3237）

## 用户操作旅程（开发者视角）

1. 开发者在开发态以显式开关启动应用，复现一次失败请求。
2. 失败被记录到本机固定位置（`$DSH_HOME` 下的开发态目录），不写进仓库。
3. 开发者运行一条重放命令，选择最近一次失败（或按序号），脚本重发该请求并打印新旧响应对比。
4. **期望**：不必手工拼请求即可复现；记录文件不含密钥、不含超大体积内容。

## 验收标准

| # | 场景 | 期望 |
| --- | --- | --- |
| R1 | 开关未开（默认） | 记录器原样透传，零开销，不产生任何文件 |
| R2 | 开关开启且请求成功（2xx） | 不记录（只记失败） |
| R3 | 开关开启且请求失败（≥400）且响应为 JSON | 追加一行 JSONL，含方法/路径/请求体/响应体/状态/时间 |
| R4 | 失败响应为 SSE 或文件流 | 不记录，且不报错（明确边界） |
| R5 | 请求体或响应体含 `sk-*`、`Bearer <token>`、`access_token` | 落盘内容中这些值被替换为占位符 |
| R6 | 请求体超过 1MB | 只记 `{omitted:true,bytes:N}`，不落原始内容 |
| R7 | 记录文件超过条数或字节上限 | 自动裁剪最旧记录，不无限增长 |
| R8 | 生产环境（开关未显式打开） | 绝不写盘；开关是显式 opt-in，缺失即关闭 |
| R9 | 重放脚本 | 只面向开发态端口；对生产端口拒绝执行并给出明确提示 |

## 硬性约束

- 不得用 `NODE_ENV` 或端口号做开发态判定（构建期会把 `NODE_ENV` 硬替换为 production，开发/生产共用同一产物）；必须显式 opt-in 环境变量。
- 记录文件写入 `$DSH_HOME` 下的开发态目录，**不得**写进仓库（仓内 `.tmp/` 被明令禁止被源码依赖）。
- 重放入口为开发态脚本，不注册新路由、不参与应用物化。
- 必须明确与既有 `scripts/mock-sidecar.mjs` 的分工：mock-sidecar 管上游 AI/存储 HTTP 录制回放，本功能管本机路由失败记录；不得造第二套语义重叠的 replay 机制。

## 证据要求

- 单测：R1–R7（脱敏、超限省略、裁剪、开关默认关闭）全部覆盖。
- 脚本自检：R9 的拒绝路径有断言。
- 实跑：开启开关跑一次失败请求，展示记录文件内容（脱敏后）与重放输出。
