# 规格说明：创作画布手动执行解除单任务限制，支持多节点并发提交

Issue: #2255 · 模块: omnimux-workflow（创作画布岛） · 风险等级: R2

## 文档影响说明
创作画布的执行模型从「每画布单一活跃执行」改为「每画布多活跃执行」，需要把执行控制语义写清；本规格即该行为的真源，不新增独立契约文档。

## 新用户与产品基线
全新用户机器上，画布首次点击节点生成即走同一条提交路径：本地执行服务随插件启动，无需任何开发机私有配置、本地代理或额外端口。执行创建失败时（未绑定项目、模型未就绪、配额不足）节点上给出明确的错误文案，不静默吞掉点击。

---

## 一、背景与业务问题

1. **手动提交被静默丢弃**：画布岛只持有 1 个执行 id、1 条事件流、1 份节点状态。任一执行处于待执行/执行中/已暂停时，用户点击其它节点的生成按钮，`startExecution` 直接返回，界面无任何反馈——用户判定「点了没反应」。
2. **全局忙碌态误伤**：节点的生成按钮禁用条件取的是**全局**执行状态，只要画布上有任意一个任务在跑，其它节点全部不可点。
3. **重载只恢复一个执行**：画布重载时只挑第一个活跃执行恢复订阅，其余活跃执行的节点状态永久停留在「生成中」。
4. **后端本身无此限制**：执行引擎按执行 id 持有执行表，创建接口无「已有运行中执行」闸门——单任务限制纯属前端画布岛的状态模型，与工作流执行引擎无关。

---

## 二、验收标准与核心行为

### A. 手动提交不受其它执行影响
1. 用户在画布上依次点击 N 个节点的生成按钮（含同一节点已完成后再次提交）：
   - 每次点击都立即创建一条独立执行，节点立刻进入「待执行 → 生成中」可视状态；
   - 画布顶部状态条同时反映 N 条活跃执行的合计进度，不出现「第二个点击无反应」。
2. 单条执行的终态（完成/失败/取消）只收敛它自己涉及的节点，不改变其它执行涉及的节点状态。
3. 同一节点在一次执行进行中不可重复提交（按钮在该节点自身执行中时禁用），执行结束后立即可再次提交。

### B. 画布级执行控制
4. 暂停/恢复/取消是**画布级**动作：作用于该画布上所有处于对应状态的活跃执行（暂停→运行中的执行，恢复→已暂停的执行，取消→全部活跃执行），与单执行时代「作用于唯一那条执行」的语义一致，不出现「点了取消还有任务在跑」。
5. 画布上存在多条活跃执行时，顶部状态条显示活跃执行条数（「N 条同时执行」），进度为各执行的合计。
6. 节点卡片上的「生成中」标记来自该节点自身所属执行的状态，而非画布全局状态；一个节点在执行中时它自己的生成按钮为禁用态。

### C. 重载恢复
6. 画布重载（切换标签/刷新）后，该工作区**所有**仍活跃的执行都被恢复订阅，节点状态与进度不丢。
7. 无活跃执行时，画布文档里残留的「生成中」标记被收敛为终态，不出现永久转圈。

### D. 工作流自动级联语义不变
8. 单条执行内部仍由有向无环图拓扑分层驱动：有依赖的分支串行、无依赖的分支并行，工作区并行度设置仍生效。
9. 「全画布一键运行」仍由前端拒绝并给出提示（保持既有产品决策）。

## 三、用户旅程与状态转移

```text
[画布空闲]
   │ 用户点击节点 A 生成 ──> 执行 E1（A：待执行→生成中）
   │ 用户点击节点 B 生成 ──> 执行 E2（B：待执行→生成中）   ← 旧行为：静默丢弃
   │ 用户点击节点 C 生成 ──> 执行 E3（C：待执行→生成中）
   ▼
[画布顶部：3 条执行进行中]  A 完成 → 仅 A 收敛为已完成，B/C 继续
   ▼
[全部终态] → 画布回到空闲，所有节点可再次提交
```

```text
[单条执行内部：DAG 自动级联]
   A ──> B ──> D          依赖链：A→B→D 依次执行（串行）
   A ──> C ──> D          无依赖：B 与 C 同层并行（受并行度节流）
```

## 四、验收用例（可观察）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 空闲画布上连续点击 3 个不同节点的生成按钮 | 3 条执行同时活跃；3 个节点各自显示生成中；顶部显示 3 条进行中 |
| 2 | 在节点 A 生成中点节点 B 的生成 | B 立即进入生成中（不再无反应） |
| 3 | 等待 A 完成 | A 显示结果并收敛；B 的状态不受影响 |
| 4 | 节点 A 生成中再次点击 A 的生成 | A 的按钮为禁用态（该节点自身执行中） |
| 5 | 3 条执行进行中重载画布 | 3 条执行全部恢复订阅，节点状态与进度一致 |
| 6 | 无活跃执行时重载带有残留生成中标记的画布 | 残留标记收敛为终态，无永久转圈 |
| 7 | 提交一条含分叉的执行 | 同层无依赖节点并行、下游依赖节点等待上游完成 |

---

## 五、非目标

- 不修改后端执行引擎算法、事件协议与 `maxParallel` 节流语义。
- 不放开「全画布一键运行」。
- 不新增并发上限设置项（手动提交不受画布侧限制；真实容量由执行服务与模型通道决定）。
