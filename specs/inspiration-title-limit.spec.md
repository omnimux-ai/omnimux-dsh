# 需求规格：分享字段收敛到云端列宽，超长标题不再导致发布失败（Issue #2121）

## 一、目标与业务背景

用户分享作品时，云端返回并如实展示在浮层内的错误是：

```
发布灵感失败: Error 1406 (22001): Data too long for column 'title' at row 1
```

云端分享记录表对若干列有列宽上限。上游模型真源 `model/inspiration_share.go`：

```go
Category    string `gorm:"type:varchar(128);not null"`
Title       string `gorm:"type:varchar(255);not null"`
Description string `gorm:"type:text"`
Prompt      string `gorm:"type:text;not null"`
Model       string `gorm:"type:varchar(128)"`
```

即 `title` ≤ 255 字符，`category` / `model` ≤ 128 字符；`description` / `prompt` 是 text 列，无此限制。

而灵感库里的导入条目**标题常常就是整条帖文**。本机实测标题长度：1933 / 709 / 698 / 316 / 275 ……
凡超过 255 字符的条目，分享一律失败——而这条分享本只需把标题截短即可成功。

## 二、关键用户旅程

### CUJ-1：分享标题很长的作品
1. 用户对一个导入自社媒、标题即整条帖文的作品点「分享」→「创建链接」；
2. 中枢在发表前把标题收敛到云端列宽内；
3. 发布成功，浮层内展示云端返回的真实链接；
4. 分享页上标题是原值的前缀（截断），文案与提示词完整保留。

### CUJ-2：分享标题正常的作品（不得回归）
1. 短标题逐字不变，不追加省略号、不产生多余空白；
2. emoji 结尾的标题不得被切成半个代理对。

### CUJ-3：云端作品分享
1. 云端目录行的 `category` 可能来自上游任意分类串，同样受 128 字符保护。

## 三、验收标准

- [ ] **AC-1（标题上限）**：两条发布链路交给云端的 `title` 长度不超过 255 字符，且是原值前缀；
- [ ] **AC-2（分类与模型上限）**：`category` ≤ 128、`model` ≤ 128；
- [ ] **AC-3（不切代理对）**：截断处若正好落在代理对中间，必须回退一个码元，绝不产生半个代理对；
- [ ] **AC-4（短值零改动）**：未超限的值逐字返回，含 emoji 的短标题完全不变；
- [ ] **AC-5（两条链路都覆盖）**：本地发布与云端发布均走同一收敛；
- [ ] **AC-6（端到端）**：以列宽受限的云端桩（复刻真实 MySQL 行为）验证 1933 字符标题的条目能够发布成功，
      且发出的 `title` 恰为 255 字符前缀；自动化测试全绿。
