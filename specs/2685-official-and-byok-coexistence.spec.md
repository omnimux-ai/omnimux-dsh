# 规格：官方媒体专线与用户自备渠道正交共存与独立放行 (Issue #2685)

## 一、背景与问题定义
当前产品架构中，全局运行模式 \`runtimeMode\` 存在单维度垄断硬伤：
当用户将文字模型设置为本机 Agent 模式（\`runtimeMode: 'agent'\`）时，后端执行层在 \`mount.js\` 中要求 \`runtime.mode === 'official'\` 才能放行官方媒体专线，导致已登录官方账号的用户在选择官方视频/图片模型（如 \`minimax-h3\` 经济版、\`seedance-2-5\` 等）时，被硬编码拦截并报错：\`[omnimux:omnimux-request-failed] 尚未配置图片、视频和音频，当前运行方式不能使用这一项\`。

## 二、架构设计原则：正交共存与独立放行
1. **能力解耦**：用户的文字对话使用何种模式（官方 / 本地 Agent / 自定义 Key），与媒体生成（图片、视频、音频）节点使用何种渠道，在架构上完全正交独立，互不绑架。
2. **官方专线独立放行**：
   - 凡请求目标渠道属于官方专线（\`isOfficialRequest === true\`），只要宿主或当前会话具备合法有效的官方凭据（\`hasOfficialToken === true\`），**无条件直接放行作为官方请求执行**；
   - 彻底废除在官方媒体请求中对全局 \`runtime.mode === 'official'\` 的强制绑定。
3. **自备渠道直连**：
   - 凡请求目标渠道属于自备渠道（\`isByokChannel === true\`），检查该自备渠道的 Key 与配置，直接路由至第三方/自建端点，不消耗官方算力。
4. **两类渠道天然共存**：
   - 在模型选择器（\`ModelCascadeMenu\`）中，官方专线（旗舰版/官方版/经济版）与自备渠道（我的 fal.ai / 我的 OpenAI / 我的 自建端点）并列展示、互不排斥，用户可根据节点需要自由混合调度。

## 三、门禁与验证
- 单元测试覆盖：\`mountMedia\` 在 \`runtimeMode === 'agent'\` 下请求官方专线时，在拥有官方 Token 的前提下直接执行放行，不抛错。
- 保证已登录官方账号的用户在任何运行模式下均可正常使用官方媒体模型。
