# 浏览器插件精灵助手：空输入框回车依次插话发送排队消息

## 1. 背景与问题
任务运行中，输入框有文字按回车会排队；但队列只能逐条点按钮插话，缺少原生那种
「输入框空着连按回车，一条一条把排队消息插进当前任务」的手势。

## 2. 目标
与原生 steerQueue 手势一致：任务运行中、输入框为空时按回车，把**队首**排队消息插话发送；
继续按回车，继续发送下一条，直到队列清空。

## 3. 判定口径
- 成立条件：输入框无文字且无待发图片、任务运行中（working 且非 stopping）、队列非空。
- 命中后取队列第一条（FIFO）走 `session.updateQueue(itemId, { kind: 'steer' })`。
- 失败码 `session/steer-unavailable`、`session/queue-item-not-found` 静默（队列投影自行刷新）；
  其他失败提示「插话发送失败，请重试。」。
- 不成立时回车行为不变：有文字仍走排队提交。

## 4. 验收标准（可测）
- AC-1 任务运行中、输入框为空、队列有两条时，回车发出一次 steer，目标是队首条目。
- AC-2 再次回车发出第二次 steer，目标是新的队首（同一次连按可依次清空队列）。
- AC-3 输入框有文字时回车不发 steer（仍走排队提交）。
- AC-4 任务未运行或正在停止时不发 steer。
- AC-5 队列为空时不发 steer。
- AC-6 宿主回 steer-unavailable / queue-item-not-found 时不提示失败，其他失败提示失败。

## 5. 非目标
- 不改排队提交语义、不改插话按钮、不引入原生「忙碌回车偏好」设置项。
- 不实现原生 Cmd/Ctrl+Enter 的加速变体（本仓手势为纯回车）。

## 6. 用户关键旅程
任务运行中 → 连续输入两条消息回车（都进队列）→ 清空输入框 → 连按两次回车 →
两条消息依次插话进入当前任务执行，队列随之清空。
