# 规格说明：推特评论区右上角残留图标根治与回复卡片单实例守卫规范

## 一、背景与问题定义
用户反馈在推特评论页面回复框激活后，右上角分割线上依然残留一个孤立的幽灵图标（与底部回复按钮旁的图标同时存在，出现双图标）。
经深度排查，主要诱因有两点：
1. `findHorizontalToolbarAnchor` 向上遍历祖先节点时跨层级匹配到了位于卡片右上角或外部的 competitor 按钮（`.ai-assistant-button`），导致挂载点被错误定位于卡片右上角；
2. `isCollapsedInlineReply` 判定条件存在短路缺陷，在收起态占位栏中因检测到未激活的输入框而返回 false，导致未激活状态仍被挂载；
3. 缺少回复卡片级别的单实例铁律清理机制，未能强力清除处于卡片上半部分或非底部工具栏位置的任何残留图标。

## 二、验收标准（Acceptance Criteria）
1. **回复卡片级单实例铁律**：
   在同一个内联回复区块（包含 `tweetTextarea_0` 的卡片）内，**强制只允许保留唯一个 OmniMux 按钮**；
   该按钮必须且只能位于底部操作栏中的真实回复发送按钮旁边；任何位于卡片上半部分（例如右上角、分割线边缘等）或非底部操作栏的幽灵按钮，一律由全局清理函数在扫描时彻底销毁（`remove()`）。
2. **工具栏容器查找严格受限**：
   `findHorizontalToolbarAnchor` 仅在发送按钮的直接工具栏水平行（`rowContainer` 的直接子元素范围内）检测与对齐竞争对手按钮，严禁跨层级向外层整个卡片执行 `querySelector`。
3. **收起态六层立体精准判据**：
   内联回复栏未展开时（卡片高度 ≤ 68px、或卡片内无媒体/表情工具栏、或按钮处于卡片上半部分），严格判定为收起态，绝不挂载任何图标。
4. **单元测试与全量回归**：
   补充针对卡片内单实例强制清理、右上角残留清除、工具栏严格作用域界定的专项自动化测试。
