# 插件配置分栏解耦规格说明（Issue #2605）

## 背景与问题陈述
在之前的设置页呈现中，系统运行时（OmniMux Cloud 登录横幅、本机助手 CLI 与媒体生成提供商）被直接嵌套于「创作画布默认模型」标题与「仅影响新建节点」描述文本内部。
这种混排导致了用户认知与层级职责上的混淆——将系统级对话与多媒体算力生成链路误认为是创作画布节点的子配置项。

## 改造目标
在设置界面中彻底解耦并清晰分为两个结构完全独立的卡片栏目：

### 1. 栏目一：「对话与媒体生成模型」
- **专属卡片外框**：独立的 `.omnimux-models-card` 结构。
- **标题**：`t('runtime.cardTitle')`（中文：“对话与媒体生成模型”，英文：“Conversation & Media Generation Models”）。
- **说明**：`t('runtime.cardDesc')`（中文：“管理用于执行对话提示词的本地命令行助手，以及图片、视频、音频的媒体生成提供商”，英文：“Configure local CLI assistants for conversation prompts and media generation providers for images, videos, and audio”）。
- **主体内容**：
  - 顶置 OmniMux Cloud 协同横幅（独立于本地与第三方能力）；
  - 双分段选项卡（Tab 1: 本机 CLI ｜ Tab 2: 媒体生成提供商）；
  - 底栏常驻全局链路就绪指示器。

### 2. 栏目二：「创作画布模型」
- **专属卡片外框**：独立的 `.omnimux-models-card` 结构。
- **标题**：`t('models.title')`（“创作画布默认模型”）。
- **说明**：`t('models.description')`（“仅影响新建节点”）。
- **主体内容**：
  - 文本、图片、视频、音频四个维度的「默认模型」、「默认模式」与「思考等级」下拉选择行；
  - 输入框模型展示与隐藏勾选列表。

## 验收断言标准 (Spec Criteria)
- **S1 (双卡片独立性)**：设置组件必须渲染出两个并列独立的 `.omnimux-models-card` 根元素。
- **S2 (栏目标题准确性)**：第一个卡片标题严格为“对话与媒体生成模型”，第二个卡片标题严格为“创作画布默认模型”。
- **S3 (各栏目功能隔离)**：第一个卡片只包含运行时与媒体生成提供商配置；第二个卡片只包含画布新建节点默认模型选择。
- **S4 (UI 规范与无内联违规)**：双卡片间距使用标准的 `20px` 垂直间距，严禁使用违规内联样式，消费标准设计 Token。
- **S5 (全量自动化与 E2E 绿)**：现有单测与新增端到端测试 100% 通过。
