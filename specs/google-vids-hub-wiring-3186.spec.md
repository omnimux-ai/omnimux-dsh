# 规格 · Google Vids 面板接入中枢本机视频通道（Issue #3186）

## 背景与目标

中枢已上架本机 Google Vids 通道（模型 `google-vids-omni`，四种操作 `text_to_video` / `first_frame` / `video_edit` / `video_extend` 均已核实并上架）。`omnimux-video` 插件的四模式界面与请求契约已完成，但生成动作仍由插件自带的内部驱动执行。

本任务把面板的生成动作改走中枢的 `videoGenerate` 缝，使「创建 / 动画 / 修改 / 延续」四种模式真正产出视频，并让「修改 / 延续」能引用前序成片。目标状态：整条链路（面板 → 插件 HTTP → 中枢缝 → 本机 vids2api）测试可用。

## 术语

- **中枢缝**：中枢插件对外提供的 `videoGenerate` 能力，调用形态 `ctx.get('videoGenerate').execute(request)`。
- **上游任务号**：vids2api 自己的任务编号（16 位以上十六进制），取片地址为 `<服务地址>/videos/<任务号>/content`。
- **插件任务号**：插件自身任务记录里的编号，仅存在于插件内部。

## 现状缺陷（本任务必须修掉，否则动画与修改无法工作）

1. **中枢侧读不到图片**：守卫为 `first_frame` 产出 `image_with_roles`、为 `video_edit` / `video_extend` 产出 `image_urls`，而通道只读 `payload.image` / `payload.reference_images[].url`，于是经缝调用时报「需要一张输入图片 / 需要一张替换用的参考图片」。
2. **中枢侧丢弃分辨率与比例**：该模型四个操作只声明了 `duration`，守卫只转发已声明参数，`resolution` / `aspect_ratio` 被静默丢弃，面板的分辨率与比例控件经缝无效。
3. **插件侧两处入参中枢用不了**：客户端选图给的是浏览器内的临时地址（`blob:`），插件外无法抓取；`video_id` 传的是插件自己的任务号，而中枢只认本通道的取片地址。
4. **插件侧前置门禁错位**：opencli 与桥接的就绪检查挂在生成路径上，会让一条本来可用的中枢通道被判为不可用。
5. **插件侧吞错**：处理函数把任意异常压成通用 500，真实原因丢失。

## 用户操作旅程

| # | 旅程 | 期望界面反馈 |
| --- | --- | --- |
| J1 | 打开面板 → 「创建」→ 填提示词 → 提交 | 提交键短暂禁用并显示正在生成；进度只反映真实阶段（已提交 / 生成中 / 正在取回），不出现凭空的百分比跳动；完成后结果卡出现可播放视频与动作行 |
| J2 | 切到「动画」→ 选一张本地图片 → 填运动描述 → 提交 | 选图后附件行显示文件名；提交后同上；结果卡可播放；不因选图这一步失败 |
| J3 | 对已有结果点「设为源片段」→ 切到「延续」→ 填后续描述 → 提交 | 模式说明条显示已选源片段；提交后产出延续片段并可播放 |
| J4 | 对已有结果点「设为源片段」→ 切到「修改」→ 再选一张替换图 → 填改动描述 → 提交 | 附件行同时显示源片段与替换图；提交后产出改动片段并可播放 |
| J5 | 任一模式点「插入」 | 成片送入右侧剪辑器；剪辑器未就绪时给出可读原因，不静默失败 |
| J6 | 中枢通道未配置（新用户基线） | 提交后结果卡显示「本机 Google Vids 通道未配置…」这类可读原因，而不是空白或通用 500；不得静默回退到内部驱动冒充成功 |
| J7 | 中枢通道不可用但内部驱动可用 | 明确回退到内部驱动，并在任务消息中说明当前走的是哪条通道 |

## 验收标准（可测）

- **AC-1 中枢侧图片字段**：`first_frame` 经缝调用时，守卫产出的 `image_with_roles[0].url` 被通道读到并写进上游请求体的 `image_url`；`video_edit` 的 `image_urls[0]` 同理。验收方式为跑「守卫 → 通道」的组合路径，而不是只跑通道单点。
- **AC-2 中枢侧参数**：`resolution: '1080p'` 与 `aspectRatio: 'landscape'` 经缝调用后出现在上游请求体里；非法值（如 `resolution: '__bogus__'`）被通道按自身白名单拒绝，而不是被静默丢弃。
- **AC-3 插件侧入参映射**：四种模式各自的插件请求被映射成中枢请求：`seconds → duration`、`image_url → image`、`video_id → references[{type:'video', role:'source', pathOrUrl}]`、`mode → operation`；`text_to_video` 不发送多余字段。
- **AC-4 取片地址回填**：生成成功后插件任务记录带上游任务号与取片地址；随后「修改 / 延续」引用该任务时，传给中枢的是取片地址而非插件任务号。
- **AC-5 前置门禁只在回退路径**：中枢缝可用时，即使 opencli 未安装或桥接未连接，新建任务也返回 202 而不是 503；中枢缝不可用时才走原有 503 判定。
- **AC-6 错误可读**：中枢缝抛出的可读原因（未配置 / 上游失败）原样出现在任务记录的 `error` 字段与结果卡上，不被压成通用 500。
- **AC-7 对外契约不变**：`/omnimux-video/api/veo` 的路径、请求体、响应形状与轮询语义不变；该插件既有的接口契约验证继续通过。
- **AC-8 选图可被抓取**：动画与修改提交时，请求体里的图片来源是插件自身 HTTP 服务上的地址（可被本机服务抓取），而不是 `blob:` 地址；客户端仍保留本地缩略图预览。
- **AC-9 端到端**：以替身中枢缝跑通四种模式（含改片与延续引用前序任务），生成成功、任务记录终态为就绪、成片地址可播放、动作行可用。
- **AC-10 真机冒烟**：在本机 vids2api 已配置的前提下，「创建」模式经面板真实生成一次并产出可播放视频（视频生成的真机验证需任务级授权，本任务由用户指令覆盖）。

## 范围

**做**：中枢侧修图片字段读取与参数声明；插件侧新增中枢缝适配器、按可用性选择生成后端、前置门禁归位、入参透传、任务记录回填上游标识、选图改走插件自身 HTTP 服务；两侧的验证与端到端证据。

**不做**：不改 `/omnimux-video/api/veo` 对外契约与客户端轮询逻辑；不改四模式的参数域（4–12 秒 / 720p·1080p·4k / 横向·纵向）；不删除内部驱动（退役另开票）；不动中枢其他模型与画布配置；不发布生产。

## 关键约束

- **新用户基线**：不得为开发机写死地址、端口或默认值；中枢通道未配置时响亮失败，绝不静默回退。
- **边界**：领域插件不得 import 中枢内部模块，只走 `ctx.get` 缝；上游错误不得被空 `catch` 吞掉。
- **图片直链**：外部多模态接口传参要求可抓取的地址，不得使用本地路径、临时 blob 或内嵌 Data URL。
- **真机证据**：界面改动的交付必须附真实浏览器逐旅程截图与专属证据，不能用首页打卡式冒烟替代。

## 风险

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 中枢缝对图片地址的抓取方式未知 | 动画与修改可能仍失败 | 先以「插件自身 HTTP 服务地址」为默认路径；真机冒烟若失败则如实记录并降级为明确报错，不伪造成功 |
| 上游四模式的图片字段语义未在本仓留证 | 同上 | 以真机冒烟为准；失败时把上游原始报错透出 |
| 改片与延续依赖前序任务的上游标识 | 引用错对象会改到别的片子 | 只在同一次运行的任务记录内解析，找不到就响亮报错 |
