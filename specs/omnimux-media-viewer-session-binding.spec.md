# 图像生成页面会话绑定与隔离规格（Media Viewer Session Binding Spec）

## 1. 业务痛点与用户指正
用户实测图像生成页面并在多个会话切换时明确指出：
**「图像生成页面要绑定会话，只显示会话生成的图片/视频，而不是所有会话，研究下当前什么原因，我需要绑定会话」**

### 1.1 现状与根本原因
1. **素材收集无会话归属**：
   在助手消息媒体采集（`assistantMessageMediaEnhancer.ts`）与点击卡片进入图像生成页面（`openInSidebar`）时，向全局素材库（`getGlobalMediaViewerStore().addMedia`）添加媒体时，未记录当前会话的 `sessionId`。
2. **视图展示未按会话过滤**：
   右侧「图像生成」页面（`MediaViewerTab.jsx`）在渲染主视图大图（`activeItem`）、右侧候选缩略图纵向滚动切换栏（`.omx-mv-thumbnails-rail`）以及时间线列表（`getTimelineGroups`）时，直接使用了全局全量的 `mediaList`，导致之前所有会话生成的图片和视频全部混杂在同一个列表中。
3. **会话切换无状态同步**：
   用户在左侧切换不同会话时，右侧图像生成页面选中的 `activeId` 仍停留在前一个会话的素材上，或者回退到全局第一张素材，没有随当前会话上下文动态联动。

### 1.2 改造目标
1. **素材录入注入当前会话标识**：
   在提取或添加媒体时，获取并记录所在会话的 `sessionId`（优先取传入值，缺省自动解析当前活动会话 ID）。
2. **视图严格按当前会话过滤**：
   - 「图像生成」主视口中的大图浏览、右侧缩略图栏与时间线视图，一律只展示归属于当前活动会话（`sessionId`）的媒体列表；
   - 若某个历史素材无 `sessionId`（旧数据兼容），仅在初始兼容或降级场景下安全兜底，新采集与常规使用中严格隔离。
3. **切换会话自动自愈联动**：
   - 切换会话时，若当前选中的 `activeId` 不属于新会话的媒体列表，自动切换选中该新会话最近的一张媒体素材；
   - 若新会话尚无生成素材，展示干净的空状态，绝不串显其他会话的内容。

## 2. 验收标准（Acceptance Criteria）
- **AC-1（素材绑定会话标识）**：向素材存储添加图片/视频时，素材对象中必须明确包含对应的 `sessionId` 属性。
- **AC-2（单图/大图模式会话隔离）**：在单图大画布模式下，右侧纵向缩略图栏只展示当前会话的媒体，总数与当前会话生成素材数一致，不得出现其他会话的素材。
- **AC-3（时间线模式会话隔离）**：时间线瀑布流分组仅汇总当前会话的媒体项目。
- **AC-4（会话切换自动联动与自愈）**：当用户在左侧切换不同会话时，右侧图像生成页面的素材列表与选中项立即联动刷新为当前会话的内容；当当前会话无素材时不展示其他会话内容。
- **AC-5（打点批注与画布上下文绑定）**：打点批注上下文中的媒体标识与会话上下文严格对齐。
