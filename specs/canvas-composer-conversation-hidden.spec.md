# 规格：图像生成页底部输入框改为「会话栏收起即投射」

- 关联 Issue：#1998
- 分支：`fix/task-1998-issue-1998`
- 基线：`origin/main` @ `7c6176428`
- 变更面归属：**插件客户端（hub 侧投射规则集 + 契约断言）**，非壳层、非官方 DSH 源码。
  官方宿主 DOM 只作为只读接缝（`[data-composer-seat]` / `[data-composer-card]`）。
- 验证证据落盘路径：`.workbuddy/evidence/task-1998/`（截图与结构化报告）

## 1. 业务目标

图像生成页在看单张大图时，底部应当有原生 DSH 输入框，用户可以直接发指令继续生图 / 重绘。
现状是：只有「右侧栏全屏铺满」时才投射（#1821 / #1825），而从会话里的媒体卡进入图像生成页
会折叠中间会话栏、却不会让官方右侧面板全屏，于是输入框既不在会话列、也不在画布底部，**彻底不可见**。

本次把显示条件从「几何状态（右栏是否全屏）」修正为「业务事实（会话列是否真的不可见）」：

```
图像画布身份（data-omnimux-image-canvas + data-visible="true"）
  ∧ 会话列不可见
会话列不可见 = 右栏全屏 ∨（会话栏折叠 ∧ 非右栏收起）
```

## 2. 现状事实（真机只读实测，Dev App 视口 1728×994）

| 观测项 | 实测值 | 含义 |
| --- | --- | --- |
| `data-omnimux-image-canvas` | 存在，`data-visible="true"`，`subViewMode=single` | 画布身份成立 |
| `data-rightbar-fullscreen` | **不存在** | 全屏条件不成立 |
| `IMAGE_CANVAS_PROJECTION_SELECTOR` 命中数 | **0** | 输入框未投射 |
| 座席 `position` | `sticky`，`x=288` | 停留在会话列内 |

## 3. 核心场景与验收标准

| 编号 | 场景 | 期望 |
| --- | --- | --- |
| AC-1 | 图像生成页 + 会话栏收起（右栏未收起） | 画布底部居中投射原生输入框；`position:fixed`、`bottom:10px`；可聚焦 |
| AC-2 | 图像生成页 + 会话栏展开 | **不投射**；输入框留在会话列内（`position:sticky`） |
| AC-3 | 图像生成页 + 右侧栏全屏 | 保持现有行为：继续投射（不回归） |
| AC-4 | 图像生成页 + 会话栏折叠 **且** 右栏确证收起 | **不投射**（该组合下会话列被强制占满，投射会造成双输入框） |
| AC-5 | 其他插件页（创作画布、技能/专家、资产库等） | 一概不投射 |
| AC-6 | 时间线四宫格 / 当前会话无素材 / 标签在后台 | 不投射 |
| AC-7 | 左栏收起 + 会话栏收起 | 投射的座席左基准归零（`left:0`），卡片仍居中于画布 |

## 4. 实现约束（不得越界）

- **不得改动**会话列内输入框的原生宽度 / 边距 / 居中算法
  （`specs/restore-native-composer-spacing.spec.md` 的用户决策）。
- **不得新增**第二个自绘输入框（`docs/contracts/workbench-split.md:161`、`hub.md`）。
- 投射只允许新增显示路径，**不得删除**既有全屏路径：
  #1980 之后进入全屏会经 `fullscreen-collapse-sync` 置位折叠键，但该写入经 MutationObserver 异步到达，
  保留全屏支可避免过渡帧内输入框闪没。
- 会话列可见性的判据不得依赖焦点模式（`gui`/`split`）：`getWorkbenchFocus` 在折叠键为真时直接返回
  `gui`（`focus-state.js:139-141`），是派生值，构成循环依赖。

## 5. 既有断言的处理

`plugins/omnimux/tests/e2e/canvas-layout-alignment.spec.js` 现有三条断言是 #1821 时期「显示条件 = 右栏全屏」
的决策产物，被本次需求取代，须同步改写为对新判据的锁定：

1. 断言「投射必须含 `[data-rightbar-fullscreen="true"]`」→ 改为断言同时含全屏支与会话栏折叠支。
2. 断言「投射不得依赖 `conversation-collapsed`」→ 删除，替换为「折叠支必须带 `¬右栏收起` 门控」。
3. 断言「左栏收起变体」→ 扩展为同时覆盖两条分支。

## 6. 验证策略

- **单测**：投射选择器契约（两支齐备、门控存在、无 `html html` 拼接）、折叠布局 CSS 不回归。
- **契约**：`node --test plugins/omnimux/tests/e2e/canvas-layout-alignment.spec.js`
  （该目录 13 个 e2e 文件不在 `run-tests.mjs` 的 glob 内，必须直跑，否则断言空转）。
- **真实浏览器**：隔离工作树内起完整应用，逐条走 AC-1 ~ AC-7，留存截图与结构化报告。
- Dev 真机验收为人工职责，Agent 不等待、不阻塞、不代签。

## 7. 非目标
