# Spec: 确保模型 100% 收到文件路径与一次回车畅通发送闭环

## 1. 现象与问题定位
用户在输入框挂载了图片附件（Yuna）并输入“解释下这个图的内容”，敲回车发送后：
模型思考显示：`The user's request is to interpret an image, but the input lacks direct image data. Th...`，随后尝试调用 `assets_list` 和 `glob` 工具，并在调用 `glob` 时由于系统环境原因报红（`Error: glob could not start its search command`）。
这表明：
**模型在此次发送中，确实没有收到任何文件路径或图片信息，因此盲目搜索导致连锁异常。**

## 2. 根因分析
在上一轮修改中，我们为了避免把长篇上下文写回用户的输入框草稿并产生拦截警告，移除了草稿文本的组装，改寄希望于 Host 端的异步心跳。然而在即时发送场景下，用户添加附件后立即按回车，异步心跳往往来不及在当次请求前同步到 Host mailbox，导致模型收到的是一条纯文字消息，没有任何文件指针，模型因此产生“lacks direct image data”并盲目调用工具。

## 3. 终极解决方案
1. **即时装配文件指针**：
   在用户点击发送或按 Enter 的同一 tick，将用户文本与规范的文件指针（`@data/files/...`）装配完毕，作为实际提交的内容投递；
2. **零拦截畅通发送**：
   `check()` 永远返回 `true`，用户按一次回车，消息立即“啪”的一声发出，绝不调用 `stop(event)` 拦截，绝不展示“素材说明已加入草稿请再次发送”；
3. **输入框即时清空**：
   消息发出后，输入框随发送动作自然恢复为空白输入状态，绝不滞留大段上下文代码；
4. **气泡上方附件展示与正文清洁**：
   消息上屏后，`userMessageAttachmentsEnhancer` 在气泡左上角上方整齐展示附件缩略图卡片；
   `attachedContextCleaner` 实时将气泡内的结构化数据块从 DOM 中移除，气泡内部只保留“解释下这个图的内容”；
5. **模型视界**：
   模型在收到消息时，完整看得到 `@data/files/ast_fd4ca05a/yuna.jpg` 与场景说明，直接调用原生读取工具解读图片，彻底杜绝盲目调用 `glob` 报错。

## 4. 验收标准
1. 用户挂载附件并输入文字后敲回车，消息一次性顺畅发送成功；
2. 气泡左上角上方展示附件缩略图卡片，气泡正文 100% 纯净；
3. 模型收到的内容包含文件引用，不再报告“lacks direct image data”，不再去调 glob 搜图；
4. 单元测试与端到端测试 100% 通过。
