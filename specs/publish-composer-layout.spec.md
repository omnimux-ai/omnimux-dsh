# 3990 创建页布局参考 Postiz（编辑区 + 实时预览 + 底部操作栏）

Issue: #3990 · 分支 `agent/publish-composer-layout-issue-3990` · 风险等级 **R2**（发布页布局）

## 背景

本地部署并研究了 Postiz（`gitroomhq/postiz-app`）的创建页：左侧编辑、右侧实时预览、顶部可折叠 Settings、底部操作栏（标签/重复/时间/存草稿/加日历）。OmniMux 当前创建页是「左侧账号 + 右侧长表单」，没有预览，操作按钮在顶部，发布设置夹在表单中间，用户在填完之前看不到最终形态。

## 方案

1. 创建页改为「账号面板（保留）+ 工作区」两段；工作区内再分「编辑区 + 预览区」：
   - 编辑区：顶部返回/类型/锁定状态；下方依次是发布设置（可折叠）、标题、正文、话题、媒体、封面。
   - 预览区：TikTok 风格的帖子卡片（账号头像/昵称、图片网格、标题+正文+话题、隐私级别与互动状态），随输入实时更新。
2. 发布设置改为可折叠卡片：默认展开，头部一行标题+当前摘要，点击收起/展开；保留原有下拉与胶囊控件。
3. 底部固定操作栏：左侧显示「立即发布」与当前时间，右侧「保存草稿」「确认发布」。
4. 预览区在窄屏（<1100px）折叠到编辑区下方，避免挤压表单。

不改数据契约、校验逻辑与 Host 接口；仅重排 Composer 的 JSX 与样式。

## 假设

- 现有 `AccountPanel` 的宽度与交互可以保留，不需要改成 Postiz 的顶部头像行；左侧列表更适合多账号勾选。
- 预览只是只读回显，不参与提交；图片用 `mediaContentUrl` 缩略图，视频用占位。
- 折叠状态只存组件内 state，不写草稿。

## 证伪方式

- 浏览器实测（真实 Chrome + 真实 Composer）：输入标题/正文后右侧预览同步出现文字；添加媒体后预览出现图片；点击设置头部可收起/展开；底部操作栏存在「保存草稿」「确认发布」。
- 单测：现有 300+ 全部保持通过（数据契约未变）。
- 窄屏截图：预览折叠到下方，不出现横向滚动。

## 新用户基线

首屏即可看到「左边写、右边看」的结构；默认隐私仍是「仅自己可见」；无新增配置或密钥。

## 文档影响

无需改契约文档；仅 UI 布局。
