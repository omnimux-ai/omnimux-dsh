# TikTok 快捷菜单：只保留下载中状态，完成后恢复默认（Issue #3588）

## 1. 业务目标

用户点「下载视频 / 保存原声 / 收藏到灵感库」后，菜单只显示**进行中**的进度；成功后菜单项立即回到默认文案与图标，不再残留「已存到「下载」」和一段绿色文件名长文案。对照 CreatOK：它只显示「正在下载无水印视频…」，完成后不留成功态。

## 2. 现状（截图与代码）

- [copy.ts](../../plugins/omnimux-browser/extension/src/content/tiktok-scene/copy.ts) 提供 `done()` 与 `detail()` 两组成功文案；[menu.ts](../../plugins/omnimux-browser/extension/src/content/tiktok-scene/menu.ts) 的 `perform()` 成功后调用 `setRowState('done', …)` 与 `showDetail(copy.detail(...), 'ok')`。
- 结果是行内永久带 `✓ 下载视频 已存到「下载」`，下方展开长文件名段落，直到下一次交互或重新挂载。
- 失败路径（`.is-error` + caused-by detail）用户可操作，保留。

## 3. 范围

1. **删除成功文案**：`TiktokCopy` 去掉 `done`/`detail` 字段；成功路径把该行复位为 idle（原文案 + 原图标），并清空/隐藏 detail。
2. **保留失败提示**：失败仍进入 error 态并显示 `failed(outcome)` 的可执行原因。
3. **样式清理**：删除不再使用的 `.omx-item.is-done` 视觉规则。
4. **测试契约更新**：`tests/tiktok-menu.spec.ts` 中用于断言“成功文案/文件名详情”的 4 条用例改为断言“恢复默认且 detail 为空”；其余用例保持原语义。

## 4. 非目标

- 不改下载、入库、宿主消息协议与菜单布局/锚点。
- 不删除失败提示，也不把失败伪装成成功。
- 不加 toast/通知等新的成功反馈渠道。

## 5. 成功标准

- **S1**：执行中该行显示 `解析下载中`（video）/`提取音轨中`（audio）/`解析入库中`（save）。
- **S2**：成功后该行文本回到默认三项文案且无 `is-done` 视觉残留，detail 为空且不占位。
- **S3**：失败仍显示宿主给出的原因（如“未从该作品解析到可下载的视频直链”）。
- **S4**：`pnpm test`（extension）全绿、`node scripts/build.mjs` 通过、真实浏览器截图（下载中 → 完成恢复默认）留存在 `.agent-reports/`。

## 假设

- 假设菜单项是成功反馈的唯一有效载体：用户已经在菜单里点击，完成瞬间只需“回到默认”，不需要额外的确认文案；宿主随后会把文件落到系统「下载」目录，用户可在 Finder 看到。
- 假设失败提示不属于“非必要文案”：它携带用户下一步要采取的动作（启动主程序/稍后重试/换一条作品），删掉会让失败变成静默。
- 假设去掉 `done`/`detail` 不会影响 i18n 以外模块：这两个字段只在 tiktok-scene 内被引用。

## 证伪方式

- 在 worktree 的 jsdom 单测里驱动一次成功与一次失败：若成功行仍包含 `已存到`、detail 仍非空，或失败不再显示原因，则实现被证伪。
- 用真实浏览器（extension-e2e + Chrome for Testing）在真实 tiktok.com origin 的弹窗夹具上渲染构建产物：默认态不得出现任何成功文案；点执行后先出现进度态，宿主缺失时落到可执行失败原因。真实浏览器无法在没有宿主凭据时制造“成功”，因此成功复位由 jsdom 单测（同一事件循环内复位、detail 为空）证伪。
- 若把成功复位实现成延时撤销，而用户仍能看到成功文案，则“只展示下载中状态”被证伪（本实现要求同一次事件循环内复位）。
