# 节点模型严格类型边界 — Issue #1783

## Objective
用户于 2026-09-14 明确批准移除节点选模的兼容与兜底：每个节点只能显示符合该节点类型的模型。延续已确认方案，不新增模型、不将理解视频当作生成视频。

## Acceptance
- 文字、图片、视频、音频节点候选只来自该输出类型的权威已上架目录；不能以品牌静态列表、通用默认、其他类型目录或已保存型号补位。
- 目录未加载、加载失败、已加载为空：明确不可用，不制造可选模型或渠道；生成请求不得发出。
- 已保存越界/下架/未知型号：提示重新选择，不显示为有效已选项、不自动替换用户选择、不重新插入菜单、不提交。
- 品牌只有合法候选时才可见；点击品牌只选择本类型目录内真实型号。
- 正常合法型号仍可选择；合法多模态输入（文字节点理解图像/视频等）保持，判定依据输出类型及任务能力，不依据输入文件后缀。
- 空节点和旧节点/带连线节点分别验证；撤销重做/重载不得把越界型号带回有效候选。
- 未知节点类型不得当作视频或使用全目录；合法音频模式沿现有目录边界处理。

## Code Style
复用现有类型、目录选择和校验；移除逻辑而不是增加品牌黑名单或并行模型路由。精确 TypeScript 注解，命名沿现有约定；界面复用设计规范与状态文案。

## Testing Strategy
先写行为回归并运行确认失败，再最小实现及重构。浏览器现场观察定位之后固化正式端到端测试。负例证明无请求，正例证明选定合法型号和输入不变。独立代理审查规格符合与代码质量，关键问题阻塞合入。

## Boundaries
总是：只写本任务隔离工作树；保留用户输入、连线与数据；不覆盖其他任务；真实浏览器证据与离线请求捕获分开记录。
先问：新增能力、付费调用、生产发布或跨工作区写入。
绝不：静态补造型号、跨类型放行、凭名称猜能力、绕过门禁、假装验证完成。
不删除无关存储格式兼容、合法多模态适配或其他业务的兜底。

## Plan
1. 并行调查菜单/浏览器入口与提交边界；自审规格范围歧义。
2. 建立失败回归，移除静态备用候选、越界默认与旧型号再注入；共用严格类型校验。
3. 正负例单测、类型/构建/阶段检查，隔离浏览器验证并留图。
4. 独立评审、PR 必需检查与队列合入；仅清理任务资源。

## Design review
截图根因已核实。用户批准严格类型、不可用为空态、旧错误型号不能有效选择的方案。方案对比：只隐藏 Gemini 会留下 GPT 和旧数据漏洞；按品牌维护备用目录仍会漂移；选用权威目录严格类型边界。范围和边界自审无待定用户决策。
