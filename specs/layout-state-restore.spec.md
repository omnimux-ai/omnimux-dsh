# 布局状态还原

## 问题一：右侧栏进入全屏时，中间会话栏没有收起

实测（Dev App）：右侧面板已是 `data-sidebar-right-panel="fullscreen"`，但 `html` 上没有
`data-omnimux-conversation-collapsed`，会话列仍占 **670px**。

根因：`workbench/split-layout.js` 的 `syncConversationCollapsedForFocus(mode)` 只在焦点模式为
`gui`（工作台独占）时写入折叠标记。用户点面板右上角**原生全屏按钮**时走的是
`data-sidebar-right-panel="fullscreen"` 这条路径，不经过 `setFocus('gui')`，折叠标记therefore 始终没写。

**期望**：进入全屏即收起中间会话栏（宽度归零，画布铺满）；退出全屏自动还原原宽度。

## 问题二：输入框宽度丢失原生自适应

原生（`packages/client/ui-conversation`）定义：

| 原生常量 | 值 |
| --- | --- |
| `CONTENT_MIN` | 640px |
| `CONTENT_EDGE_BUDGET` | 176px |
| 自适应内容宽（无偏好时） | `max(680, min(列宽 × 0.64, 920))` |
| 输入框卡片上限 | 内容宽 `+ 32px` → 712 ~ 952px |
| 偏好存档键 | `dsh.conversation.contentWidth` |

实测存档里有 **920.68px** 的残留偏好，它绕过自适应规则把输入框钉在上限；宽列时直接顶到
952px，窄列时锁死 672px。

**期望**：清除残留偏好，让原生自适应公式重新生效；并在插件侧加防复发约束，
不让该偏好再被写歪。

## 验收标准

1. **全屏收起**：右侧面板进入全屏后，`html[data-omnimux-conversation-collapsed]` 存在，
   会话列实测宽度为 0，画布铺满剩余宽度。
2. **退出还原**：退出全屏后折叠标记移除，会话列回到进入前的宽度（±2px）。
3. **不误触发**：仅在分栏态拖拽分割线时，全屏收起逻辑不得介入（分栏拖拽仍走原生网格）。
4. **输入框复位**：清除残留偏好后，输入框卡片计算宽度等于 `max(680, min(列宽 × 0.64, 920)) + 32`。
5. **防复发**：插件侧存在对该偏好键的护栏，将其夹在原生合法区间内，越界值被纠正而不是采信。

## 交互步骤（真实浏览器复现）

1. 打开 Dev App，进入分栏布局（左栏展开、右侧打开画布）。
2. 点面板右上角全屏按钮：断言 `html` 折叠标记出现、会话列宽度为 0。
3. 再点一次退出全屏：断言折叠标记消失、会话列宽度恢复 ±2px。
4. 读取输入框卡片计算宽度，断言等于自适应公式结果。
5. 在分栏态拖动分割线，断言全屏收起逻辑未被触发。

## 非目标

- 不改动原生输入框宽度公式本身。
- 不改动分栏态的分割线拖拽实现（上一个任务已交付）。
- 不删除原生宽度拖拽手柄功能。
