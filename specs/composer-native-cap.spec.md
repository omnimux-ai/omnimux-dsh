# 输入框宽度回归原生上限

## 问题

会话栏输入框会随窗口一起变宽，宽窗口下几乎占满整列；官方 DSH 的输入框有明确上限并居中，这是预期效果。

## 实测（Dev App，CDP `CSS.getMatchedStylesForNode` 权威命中规则）

命中输入框卡片 `[data-composer-card]` 的宽度上限共有三条规则，优先级最高的是插件自己写的：

| 来源 | 声明 | 结果 |
| --- | --- | --- |
| 原生 `.Q7WfXG_card` | `max-width: var(--dsh-composer-card-max-width)` | 被覆盖 |
| 插件 `session-guide/styles.js`（starter-host + 分栏/紧凑态） | `max-width: 100% !important` | **胜出** |

宽会话列 A/B 对照（同一窗口，临时把会话列撑到 1446px）：

| 条件 | 卡片宽度 | 位置 |
| --- | --- | --- |
| 现状（插件强制 100%） | **1406px** | 左 300 / 右 1706，几乎占满整列 |
| 还原原生 `var(--dsh-composer-card-max-width)` + `margin-inline:auto` | **952px** | 左 527 / 右 1479，**居中** |

952px = 原生公式 `max(680, min(列宽 × 0.64, 920)) + 32` 在宽列下的封顶值（920 + 32）。

## 验收标准

1. **有上限**：宽窗口下输入框卡片宽度等于 `var(--dsh-composer-card-max-width)` 解析值（当前窗口为 952px），不超过该值。
2. **居中**：卡片左右留白相等（左右边距差 ≤ 2px）。
3. **工作区行对齐**：输入框上方的工作区行与卡片同宽同位置（左右边距差 ≤ 2px），保持既有对齐要求。
4. **窄列不回归**：会话列窄于上限时，卡片仍撑满可用宽度（不被强行缩小）。
5. **不影响其它区域**：右侧画布、侧边栏、弹窗的输入框与滚动条行为不变。

## 交互步骤（真实浏览器复现）

1. 打开 Dev App，进入会话列可见的布局。
2. 记录会话列宽度 W 与卡片宽度 C。
3. 把窗口/会话列拉宽到 W > 952：断言 C == 952 且左右留白相等。
4. 把会话列收窄到 W < 952：断言 C 撑满可用宽度（约 W 减去两侧 12px 留白）。
5. 断言工作区行与卡片左右边界一致。

## 非目标

- 不改动原生宽度公式本身，也不改原生宽度拖拽手柄。
- 不改动输入框内部布局、圆角、配色与按钮。
- 不改动右侧画布与侧边栏。
