# 页面操作卡片进展期零抖动（恒定几何）

## 目标与授权

用户报告：浏览器侧边栏对话面板在「页面操作」进行中，每次产生新进展，进度卡片都会抖动、不稳定；而正文流式输出时稳定。用户要求「有进展就正常流式更新，不要抖动」。

本规格只治理这张卡片的几何稳定性，不改变它的信息层级、配色与文案。

## 已知事实（真实 Chromium 内核实测，2026-09-14）

测量方式：复刻 `ToolActivity` 的真实 DOM 标记 + 直接引用生产 `styles.css`，在真实浏览器内逐条追加进展并读取 `getBoundingClientRect()`。原始数据见 `.agent-reports/tool-card-jitter/jitter-baseline.json`，截图见同目录 `jitter-baseline.png`。

抖动是**高度驱动**的，不是宽度：

1. `.tool-activity` 宽度全程恒定（容器 360px 时为 305px），宽度不是抖动来源。
2. 进展逐条追加时卡片高度阶梯式上跳：360px 容器下 46.32 → 65.02 → 83.71 → 102.41px，每约 2 步跳一次；320px 与 280px 容器下几乎每步都跳（46.32 → 65.02 → 83.71 → 102.41 → 121.1 → 139.8px）。机理：`.tool-summary` 在固定宽度下换行，第 2、3… 行落地即增高一行（16.675px）。
3. 状态由「进行中」切「完成」时，`.tool-state` 从 spinner（12px）变成完成徽标（44.5px），挤压 `.tool-copy` 可用宽度（360px 容器下 223 → 190.5px；320px 下 183 → 150.5px；**280px 下 143 → 110.5px**），触发额外换行：320px 容器下摘要从 5 行变 7 行，卡片瞬间 121.1 → 139.8px。
4. 单步摘要文本变长同样驱动高度：360px 容器下摘要长度 4 → 50 字符，卡片 46.32 → 62.99px。
5. 每次进展还会推动消息列表自动滚动（`App.tsx` 的 `scrollTo` effect），卡片自身尺寸跳变叠加滚动位移，放大了不稳定感。

## 与既有规格的关系

- 本规格**修订** `specs/browser-page-card-followup.spec.md` 的设计决策「步骤在空间不足时自然换行，允许卡片增高而非裁切」。该决策在实测中正是抖动来源：卡片高度随进展变化，用户可感知。改为「单行承载 + 早期步骤折叠」，不再允许因进展而增高。
- `specs/browser-page-card.spec.md` 的视觉要求（文字对比度、状态可见、卡材质、微步骤标签）继续有效，本规格不改动这些要求。

## 设计决策

1. **恒定卡片高度**：卡片总高在任一容器宽度下与步骤数、摘要文本长度无关，只由单行内容高度决定。
2. **两行窗口向上流动**（用户 2026-09-14 拍板，替代单行方案）：窗口固定露出两行（`height: calc(33.35px * var(--ui-scale))`、`overflow: hidden`），步骤链按每行两个步骤切行；行数增长时内容整体上移，最新一行从下方进入、旧的一行向上滑出。行内单格超宽时右侧遮罩淡出，并由组件在词边界截断。
3. **完整链条留在语义层**：窗口只呈现最新两行，但完整步骤链保留在 `aria-label`，屏幕阅读器仍可读全量进展。
4. **状态槽位恒定宽度**：`.tool-state` 固定为完成徽标所需的宽度，进行中态在槽位内居中显示 spinner。状态切换不再改变文本可用宽度，因此不再触发换行。
5. **移除布局过渡**：卡片只对颜色类属性做过渡（`border-color`、`background-color`、`color`），不再对可能引发布局的属性做过渡。

## 范围

只改 `plugins/omnimux-browser/extension/src/panel/` 下的 `App.tsx`（`ToolActivity` 组件）、`styles.css`（工具卡片相关规则）与其规格测试 `tests/tool-activity-card.spec.ts`；新增本任务的浏览器几何验收脚本与证据。

不改：`.ai-progress`（「正在整理结果」行）、`.spinner` 关键帧、工具文案映射表、消息列表滚动策略、其他卡片与全局主题。

## 验收标准

| 编号 | 标准 | 判定方式 |
| --- | --- | --- |
| AC-1 | 逐步追加进展（1→7 步）过程中，卡片高度在所有测量点完全一致 | 真实浏览器几何测量，高度集合大小为 1（实测 64.99px） |
| AC-2 | 状态由进行中切完成，卡片宽度与高度都不变 | 同容器宽度下两态几何逐一相等 |
| AC-3 | 摘要文本由 4 字符增至 56 字符，卡片几何不变 | 几何测量集合大小为 1 |
| AC-4 | 容器宽度 280 / 320 / 360 / 400px 四档分别满足 AC-1 与 AC-2 | 四档全通过 |
| AC-5 | 卡片不越界：卡片宽度不超过容器可用宽度 | 几何测量断言 `cardW <= available` |
| AC-6 | 可访问性不降级：`role="status"`、`aria-label` 保留；完整步骤链文本在 DOM 中可读 | jsdom 组件测试断言 |
| AC-7 | 每行两个步骤，窗口只露出最后两行，最新一步在窗口可见范围内 | jsdom 组件测试 + 真实浏览器逐帧断言（`latestVisibleEveryStep`） |
| AC-10 | 进展推进期间内容确实产生向上位移（流动感） | 真实浏览器记录内容上移量，要求出现负值位移 |
| AC-8 | 既有视觉契约保持：状态徽标可见且为正尺寸、文案映射不变、无写死浅蓝/亮紫 | 既有 `tool-activity-card.spec.ts` 全绿 |
| AC-9 | 修复前证据留存（基线几何数据 + 截图），修复后同方法复测 | 基线 JSON 与复测 JSON 同时存在 |

## 验证方法

1. 基线：真实浏览器复刻 DOM + `origin/main` 生产 CSS 的几何探针，记录 1→7 步与状态切换的几何（已产出：280/320/360/400px 下唯一高度 7/6/4/4 个）。
2. 修复后：同一探针在同一环境复测，断言 AC-1…AC-5 的几何恒定。
3. 组件层：`pnpm --filter <browser 包名> test` 覆盖 AC-6、AC-7、AC-8 与既有视觉契约。
4. 真实浏览器截图留证，供人工复核视觉效果。

## 文档影响与自审

- 文档影响：本规格修订 `specs/browser-page-card-followup.spec.md` 的一条设计决策，属于规格层更新；生产代码注释同步说明恒定高度原因。
- 自审：无占位符；验收标准全部可用几何测量或组件断言判定；范围限定在单组件与相关样式；歧义点「折叠计数是否损失可访问性」已通过保留完整 `aria-label` 消除。
- 已知边界：几何探针复刻 `ToolActivity` 的标记与生产样式，不经过扩展完整运行时的 WebSocket 通道；走查用合成事件序列，不代表真实模型调用。
