# 规格说明：旧版生成节点输入框打字即可提交

**Issue**: #2990
**状态**: Approved（用户 2026-10-03 对话确认「接着修 #2990：旧节点打字也能提交」，按只修旧逻辑处理）
**前置**: #2985（新输入绑定节点已统一为内核判断）

## 1. 目标

旧版生成节点（`inputBindingVersion` 缺省）的面板侧卡槽缺口检查，与执行端组装规则保持一致：可由本地文字满足的组合文本槽（`type=text`、带 `composition`、`valueSources` 含 `local_field`），只要最终提示词非空即视为已满足，不再提示「还差必需素材：prompt」。

依据：执行端 `assembleEffectiveInputsFromSlots` 已按「组合文本槽以最终提示词是否非空计数」判定必需槽；面板侧只数上游绑定，二者口径不一致，导致按钮被拦而实际可执行。

## 2. 用户旅程与期望反馈

| 旅程 | 期望 |
|---|---|
| 旧版图片/视频/文本/音频节点，不连上游，只在输入框打字 | 提交按钮可用，不出现「还差必需素材：prompt」 |
| 旧版节点，输入框为空、无上游文本 | 提交按钮直接禁用，原因沿用既有闭集（「请输入内容或连接上游文本」） |
| 旧版节点，媒体必需槽（如首帧）未绑定 | 行为不变，仍提示该卡槽缺失 |

不新增任何可见元素或文案。

## 3. 范围外

- 不迁移旧节点到新输入绑定版本。
- 不改执行端、内核判定与新节点门禁。

## 4. 新用户基线

仅依赖真实模型目录中 prompt 槽契约；目录不可用时沿用既有「模型目录不可用」原因。

## 5. 验收用例（seam：ConfigPanel 渲染出的提交按钮）

对图片、视频、文本、音频四类旧节点各跑：

1. 只输入提示词、无上游：按钮未禁用，输出不含「还差必需素材」。
2. 输入框为空、无上游文本：按钮 `aria-disabled="true"`。

另：旧节点媒体必需槽未绑定时仍禁用并保留卡槽缺口提示。真实浏览器截图复核旧版图片节点只打字后可提交。

## 6. 文档影响

仅新增本规格。
