# 规格：会话输入框「添加文件」前端自愈与免重启常驻

Issue: #2188
插件: omnimux
日期: 2026-09-17

## 1. 目标

在底座 Host 尚未重启或不同加载顺序下，前端 `commandUi` 包装层主动自愈补齐「添加文件」（`add-file`）条目，确保用户在不重启宿主进程的情况下，仅通过页面刷新即可立即在「+」号菜单中看到「添加文件」选项，并与「从资产库添加」、「计划模式」构成稳定的 3 项创作指令集合。

## 2. 成功标准

1. 当底座 Host 候选列表未包含 `add-file` 时（如热更新未重启），前端候选处理管线自动注入 `add-file` 描述与图标，确保「添加文件」常驻首位。
2. 菜单最终展示结果严格且仅包含 3 项：
   - 「添加文件」
   - 「从资产库添加」
   - 「计划模式」
3. 点击或键盘 Enter 选择「添加文件」时，通过 `wrappedDispatch` 与 `decorateFileCommand` 双重保障直接触发原生文件输入框点击，直达系统选择窗口。
4. 带 300ms 时间戳防抖，避免重复触发文件选择窗口。
5. 单元测试与端到端测试 100% 覆盖并全绿。

## 3. 边界

- 总是：保证热刷新下「添加文件」100% 可见可用；防抖保护；零外部依赖。
- 绝不：依赖用户必须重启 DSH 进程。

## 4. 验证

- 单测：输入不含 `add-file` 的候选列表时，自动自愈补全为包含「添加文件」的 3 项输出。
- 单测：输入已含 `add-file` 时，去重并保持 3 项输出。
- 单测：分派 `add-file` 时自动调用原生文件触发器。
- 端到端：模拟未重启宿主场景，验证菜单首位出现「添加文件」并可正常点击。
