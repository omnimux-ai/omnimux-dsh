# 卡片触发按钮选择器覆盖真实钩子（Issue #2158）

## 1. 背景

Issue #2144 交付的卡片触发按钮在真实 TikTok 页面实测：

| 页面 | 我们的选择器命中 | 结果 |
| --- | --- | --- |
| 个人主页 `/@user` | `user-post-item` × 19 | ✅ 19 个标记 |
| 搜索 `/search` | 0 | ❌ 无标记 |
| 探索 `/explore` | 0 | ❌ 无标记 |
| 推荐流 `/foryou` | —（按矩阵不该有） | ✅ 无标记 |

## 2. 根因

页面用的是另一套钩子名（真实页面实测抓取）：

- 搜索页：`search_top-item` / `search_top-item-list`
- 探索页：`explore-item` / `explore-item-list`

选择器只覆盖了个人主页与推荐流的命名，于是这两页静默失效——宿主元素建了，条目数为 0。

## 3. 范围

只改 `WORK_CARD_SELECTORS` 的选择器清单；不改显隐行为、不改消费矩阵、不改动作链路。

## 4. 验收标准

1. **AC-01** 选择器清单包含三个页面的真实钩子：`user-post-item`、`search_top-item`、`explore-item`。
2. **AC-02** 真实搜索页出现与作品数一致的标记。
3. **AC-03** 真实探索页同样。
4. **AC-04** 个人主页与推荐流行为不回退（主页仍挂满、推荐流仍为 0）。
5. **AC-05** 单元测试断言清单覆盖上述钩子名，避免下次静默失效。

## 5. 风险

选择器是站点钩子，站点改版会再次失效；本规格把「清单是否覆盖真实钩子」写成测试，使失效在测试层可见。

## 6. 新用户基线声明

只涉及页面内选择器常量，不依赖任何开发机私有状态。
