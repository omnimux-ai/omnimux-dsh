# 规格说明：生成节点提交门禁只认内核一套判断

**Issue**: #2985
**状态**: Approved（用户 2026-10-03 对话中确认方向）
**范围**: omnimux-workflow 画布生成节点（图片 / 视频 / 文本 / 音频）输入面板的提交按钮门禁

## 1. 目标

新输入绑定的生成节点（`inputBindingVersion = 1`）只保留一套「能否提交」判断：统一输入内核的整组校验结果。面板侧按卡槽绑定数计算的「还差必需素材」检查不再参与新节点的门禁，避免本地输入的提示词被判为缺失。

依据：docs/product/unified-upstream-input-2848.md 第 217 行写明，文本必需字段可由已使用的上游正文或本地输入满足。

## 2. 用户旅程与期望反馈

| 旅程 | 期望 |
|---|---|
| 新建图片/视频/文本/音频生成节点，不连上游，只在输入框打字 | 提交按钮可用，点击即提交，不出现「还差必需素材：prompt」 |
| 新建节点，不连上游，输入框为空 | 提交按钮直接呈禁用态（`aria-disabled="true"`），悬停原因来自内核闭集文案（缺正文时为「请补齐正文」）；不依赖点击后才弹提示 |
| 新建节点，连入上游文本且输入框为空 | 不在本次改动范围，行为保持现状 |

禁用态点击沿用既有画板通知行为，不新增 UI 元素与文案。

## 3. 旧节点

`inputBindingVersion` 缺省的旧节点不走内核整组校验，继续保留面板侧卡槽缺口检查，拦截行为不变。
文案裁定（PM 2026-10-03，PM_SIGN_OFF）：旧节点空输入的悬停原因随内核统一为「请输入内容或连接上游文本」（prompt 槽不是参考素材，原表述「此类参考素材至少需要 1 个」语义错误）——「行为不变」约束的是拦截与否而非文案措辞。
旧节点「已打字仍被拦」为独立历史缺陷，不在本次范围，另立 issue 处理。

## 4. 新用户基线

功能只依赖真实模型目录中各生成方式的 prompt 槽契约；目录不可用时沿用既有「模型目录不可用」原因并禁用提交，没有开发机专属依赖。

## 5. 验收用例

测试 seam：ConfigPanel 渲染出的提交按钮状态与原因。对图片、视频、文本、音频四类节点各跑：

1. 只输入提示词、无上游：按钮未禁用，输出不含「还差必需素材」。
2. 输入框为空、无上游文本：按钮 `aria-disabled="true"`，原因为「请补齐正文」，不含「还差必需素材」。

另需真机截图复核：图片节点只打字后按钮可用，空输入时按钮禁用。

## 6. 文档影响

仅新增本规格；产品口径已在 2848 规格中写明，无需修改。
