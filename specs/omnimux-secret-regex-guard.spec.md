# 规格：中枢防泄密规则边界收敛与模型清单正常加载 (Issue #2264)

## 1. 背景与业务痛点
用户在桌面端设置页打开「创作画布默认模型」时，文本、图片、视频、音频的「默认模型」下拉选择框持续处于「加载模型列表...」状态，无法展开选择具体模型，且页面左下角提示红色「HTTP 500」错误。

经过 CDP 连接运行中桌面端排查，实际根因为：
1. 页面加载时向后台请求中枢模型目录 `/omnimux/model-catalog`；
2. 中枢后台在 `plugins/omnimux/src/auth/http-routes.js` 中使用 `sendJson` 输出 JSON 响应；
3. `sendJson` 包含通用防泄密正则检查，规则定义为 `/access_token|sk-[A-Za-z0-9]/`；
4. 正则缺少前置单词边界隔离且匹配长度仅为 1 个字符，导致包含 `seedance-2-0-task-pro`、`seedance-2-5-task-pro` 等视频任务专线模型标识符中的 `task-pro`（含有拼写片段 `sk-p`）被严重误判为命中机密密钥；
5. 后台触发防泄密硬拦截，将状态码置为 500 并返回 `{"error":"refused to emit a secret"}`；
6. 前端捕获到 HTTP 500 异常，展示错误提示，模型下拉列表未能填充候选数据。

## 2. 目标与范围
- 修正 `plugins/omnimux/src/auth/http-routes.js` 以及同类模块中的防泄密正则，补充前置单词边界与真实密钥最小长度限制（8 位以上），杜绝合法普通词汇（如 `task-pro`、`mask-preview`）被误杀。
- 对齐同仓工作流模块与资产模块的成熟安全规则标准：
  `/(?:^|[^A-Za-z0-9])sk-(?:proj-)?[A-Za-z0-9]{8,}|access_token/`。
- 保证真实密钥（如带有 `sk-1234567890abcdef` 或 `sk-proj-abcdefghijk`）依然被严格拦截并返回 500。
- 确保 `/omnimux/model-catalog` 接口正常返回 200，设置页所有模型下拉列表正常渲染候选模型。

## 3. 产品基线与新用户体验
- 新用户机器环境刚安装与登录时，模型清单来自中枢已加载契约。
- 规则修复不引入任何外部依赖或开发机私有配置，纯离线正则匹配，完全符合产品基线。

## 4. 验收标准
1. **单元测试与防误判测试**：
   - 包含 `task-pro`、`seedance-2-0-task-pro` 等正常模型标识的 JSON 响应正常通过 `sendJson`，状态码 200，内容完整无截断。
   - 包含真实格式伪造密钥（如 `sk-12345678`、`sk-proj-12345678`、`access_token`）的响应依然被严格拦截，返回 HTTP 500 `{ error: 'refused to emit a secret' }`。
2. **端到端与接口验收**：
   - `/omnimux/model-catalog` 响应经 `sendJson` 序列化不再被拦截，HTTP 状态码为 200。
   - 前端设置页「创作画布默认模型」正常获取模型列表，消除卡死与「HTTP 500」错误。
3. **质量门禁 100% 通过**：
   - 单元测试与契约校验全绿。
