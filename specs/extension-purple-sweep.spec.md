# 扩展三处紫色残留清理规格（网页自动填写 / 推特小面板 / 设置页）

## 背景（源码全量扫描结果）

对 `plugins/omnimux-browser/extension/src` 全量扫描紫色字面量（hex 与 rgba 两种写法，含 hsl 复核），除已修复的推特助手填入层外，剩余紫色集中在三处：

### 1. 网页自动填写（`content/dom-fill.ts`）
- 第 84 行：填入后脉冲高亮 `outline = '2.5px solid #8b5cf6'`
- 第 85 行：光晕 `boxShadow = '0 0 16px rgba(139, 92, 246, 0.45)'`

### 2. 推特小面板（`content/twitter-velocity/`）
- `styles.css` 第 38~41 行：爆款徽标底色 `#250b44`（深紫）、描边 `#a855f7`、文字 `#f3e8ff`、光晕 `rgba(168, 85, 247, 0.35)`
- `styles.css` 第 151 行：曝光预测数值 `color: #a78bfa`
- `panel.ts` 第 43 行：爆款档位标签色 `#c084fc`（并以其 + `22` 生成半透明底）

### 3. 设置页（`panel/`）
- `styles.css` 第 14~18 行（Light 主题令牌，名字叫 blue 实为紫）：`--blue: #7961f2`、`--blue-hover: #6757e7`、`--blue-ink: #5644d6`、`--blue-soft: #ede9fe`、`--blue-wash: #f5f3ff`（共被引用 60+ 处）
- `styles.css` 第 1615 行：`.draft-image.lit > img` 描边 `#7c3aed` 与两处紫色光晕
- `styles.css` 第 4662 / 4664 行：`.brand-mini-badge` 底色 `rgba(139, 92, 246, 0.12)`、描边 `rgba(139, 92, 246, 0.25)`
- `styles.css` 第 4644 行：注释仍写「Black & White + Violet Accent」
- `main.tsx` 第 99 行：错误态「重新加载工作台」按钮底色 `#8b5cf6`

## 目标行为（验收标准）

1. 三处表面均无紫色；配色遵循 `design.md`：主色为黑白高对比、状态色仅用于语义（成功 `#4ade80`/`#16a34a`、错误 `#f87171`/`#dc2626`、警告 `#fbbf24`/`#d97706`）。
2. 网页自动填写的高亮与推特助手填入层统一口径：白色描边 + 深色外圈，浅色/深色页面均可见。
3. 设置页 Light 主题的强调色令牌改为黑白中性（令牌名保持不变，避免大范围改动）：主色近黑 `#111827`、悬停 `#374151`、软底 `rgba(17, 24, 39, 0.08)`、浅底 `rgba(17, 24, 39, 0.04)`；Dark 主题原本已是黑白，维持不变。
4. 推特小面板爆款徽标改用黑白高对比（黑底白边白字）以区别于「飙升」的橙色语义；曝光数值改白色。
5. 新增防复发硬门禁：单元测试全量扫描扩展源码，出现紫色字面量（`#a855f7`/`#8b5cf6`/`#7c3aed`/`#c084fc`/`#a78bfa`/`#6366f1` 及等价 `rgb(a)` 形式，阈值判定 R>150 且 G<120 且 B>220）即失败。

## 交互步骤（自动化验收）

1. 设置页：打开扩展设置页并切到 Light 主题 → 断言 `--blue*` 令牌解析为黑白中性值，页面主行动按钮为黑底白字；截图。
2. 推特小面板：在 x.com 时间线读取真实徽标计算样式 → 断言无紫色；构造爆款档位徽标与面板曝光数值 → 断言为黑白；截图。
3. 网页自动填写：在 x.com 触发一次填入（小面板的一键填入动作）→ 立刻读取输入框描边与光晕 → 断言白色描边 + 深色外圈、无紫色；截图。
4. 单元测试：`no-purple-theme` 扫描用例必须通过；既有推特助手用例保持全绿。

## 非目标

- 不改动设计规范本身，不新增设计令牌。
- 不改动「飙升」档位的橙色与「正常」档位的冷灰（属语义状态色，非紫色滥用）。
- 不改动设置页除配色外的任何交互与文案。
