# 分栏分割线拖拽回归原生网格

## 问题

会话列与右侧画布之间的分割线在拖拽时出现明显黑边，且跟手极差。用户诉求明确：
分割线拖拽必须使用外壳原生实现，不允许插件再单独实现一套。

## 实测证据（Dev App，CDP 真实鼠标事件，视口 1728×994）

| 指标 | 现状实测 | 期望 |
| --- | --- | --- |
| 拖拽中面板左缘与分割线的偏差 | 最大 71px（黑缝） | 恒定 ≤ 4px |
| 拖拽中面板计算 `transition-property` | `width, transform`（0.3s） | `none` |
| 拖拽中会话列右缘与面板左缘间隙 | -20 ~ +66px | 0px |
| 面板计算 `position` | `fixed` | `static`（分栏态） |

根因：`.dshDesktopFrame [data-sidebar-right-panel][data-sidebar-right-open]` 把右侧面板
改成视口右锚的 `position: fixed` 元素，面板因此脱离原生三列网格，不再跟随列宽；
同一条规则又给面板声明了 0.3s 宽度过渡，而外壳的 `[data-dragging]` 只中和帧与手柄的过渡，
面板过渡在拖拽中仍然生效，于是面板以 300ms 缓动追赶指针。

## 验收标准

1. **跟手**：分栏态拖拽分割线时，右侧面板左缘与手柄左缘的偏差在每一步保持恒定 ≤ 4px，左右两个方向均成立。
2. **无黑缝**：拖拽过程中与松手后，会话列右缘到面板左缘的间隙恒为 0px。
3. **无私有过渡**：分栏态面板的计算 `transition-property` 为 `none`；全屏态保留原有过渡。
4. **不溢出轨道**：会话列表面宽度不超过其网格轨道宽度（原生 `CENTER_MIN` = 400px）。
5. **全屏不回退**：右侧面板全屏态的定位、宽度与过渡行为与本改动前一致。
6. **收起态不回退**：左栏收起（`data-omnimux-left-collapsed`）与会话列收起
   （`data-omnimux-conversation-collapsed`）两个状态的既有布局不变。

## 交互步骤（真实浏览器复现）

1. 打开 Dev App，进入带右侧画布的分栏布局（左栏展开）。
2. 按住会话列与画布之间的分割线，向右拖动 300px，再向左拖回原处。
3. 每一步断言：手柄左缘、面板左缘、会话列右缘，以及面板的 `position` 与 `transition-property`。
4. 收起左栏后重复步骤 2–3，断言面板几何仍跟随手柄。

## 非目标

- 不改动全屏态面板的定位策略。
- 不改动会话列收起态的投影座席几何。
- 不新增插件侧的分割线拖拽实现。
