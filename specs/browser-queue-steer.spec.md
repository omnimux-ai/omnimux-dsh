# 浏览器插件精灵助手：排队消息「插话发送」规格

## 1. 背景与问题
任务执行中（消息排队态），排队坞里的消息只能编辑或删除，无法让它立刻插到当前任务里执行。
原生 DSH 侧栏的排队消息行提供一个「插话发送」按钮：点击后该条消息立刻并入正在运行的任务
（从队列移除并注入当前轮），当任务不在运行时按钮置灰并提示「仅运行中可插话发送」。

## 2. 目标
让浏览器插件精灵助手的排队消息与原生一致：每条排队消息都可一键插话发送，立刻执行而不必等当前任务结束。

## 3. 原生实现依据（只读核对）
- 宿主命令 `session.updateQueue(sessionId, itemId, { kind: 'steer' })`：宿主在 target 不是 next-turn
  或任务非运行中时抛 session/steer-unavailable，条目不存在时抛 session/queue-item-not-found；
  成功即从队列移除该条并把消息注入当前运行轮。
- 原生客户端：失败码为上述两者时静默（队列投影自行刷新），其他错误才提示失败。
- 原生文案（简体中文）：按钮「插话发送」；不可用提示「仅运行中可插话发送」。

## 4. 验收标准（可测）
- AC-1 排队坞每行都渲染「插话发送」按钮（不再依赖不存在的条目字段），任务运行中为可用态。
- AC-2 点击后发出 session.updateQueue，动作载荷为 { kind: 'steer' }，携带该条目 id 与会话 id。
- AC-3 任务未运行（空闲/正在停止）时按钮置灰，标题提示「仅运行中可插话发送」，点击不发请求。
- AC-4 宿主返回 session/steer-unavailable 或 session/queue-item-not-found 时不弹错误提示（队列投影自行刷新）；
  其他失败仍提示「立即发送失败…」。
- AC-5 编辑、删除、折叠、忙碌禁用等既有行为不回归。

## 5. 非目标
- 不改输入框提交语义（仍为排队），不引入原生「忙碌回车偏好」设置项。
- 不改排队坞视觉结构、间距与既有图标体系。

## 6. 用户关键旅程
任务运行中 → 输入框继续输入并回车（消息进入排队）→ 在排队坞该行点「插话发送」→
消息立刻并入当前任务执行、该行从队列消失；若任务已结束，按钮置灰并提示原因。
