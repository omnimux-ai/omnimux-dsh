# 规格：填入请求只交给可见的图像生成页（Issue #3009）

上游：`specs/chat-prompt-generate.spec.md`、`specs/prompt-prefill-shared-queue-2999.md`。

## 现象

#2999 合入后，点「使用提示词生成」按钮显示「已填入」，填入请求也进了队列，但右侧看得见的图像生成输入框仍为空。

## 原因

宿主同时挂着两个图像生成页：右侧标签页里一个（可见），底部面板里一个（隐藏）。两个都在等同一个填入请求，谁先处理谁取走。实测是隐藏的那个取走了，所以用户看到的输入框是空的。

## 目标

只有看得见的图像生成页才能取走填入请求。隐藏的页面不取、不改动请求。

- 刚打开时页面可能还没显示出来：在短时间内（约 1.5 秒内逐帧）重试，等页面可见后再取。
- 期间队列被别处取走或换成新请求，就停止重试。
- 环境里没法判断可见性时（如测试环境），按可见处理，不阻断原有行为。

## 用户旅程

1. 对话里点「视频提示词」块底部的「使用提示词生成」。
2. 右侧看得见的「图像生成」页模式切到「视频」，输入框是块内全文。
3. 隐藏的底部面板不发生变化。
4. 点击本身不发生成请求。

## 新用户基线

只依赖宿主已有的界面与两个插件；不依赖本地模型服务或开发机状态。

## 验收

1. 测试：一个隐藏、一个可见两个页面同时等待，同一请求只被可见页面取走，隐藏页面输入框不变。
2. 测试：页面起初不可见、稍后变为可见，变可见后取到请求。
3. 真机（开发版）：点击后右侧可见输入框字数等于块内全文，视频块切到视频。

## 边界

- 总是：只改「谁来取」的判断，不改按钮、文案、样式、布局。
- 绝不：在点击时发生成请求；改官方宿主源码。
