# 视频节点工具栏胶囊宽度溢出修复（Issue #3563）

## 背景

`#3547` 给视频节点加了第 4 个主区胶囊「深度视频」后，节点上方胶囊栏的圆角容器在「深度视频」处被截断，分割线与「⋯ 更多」溢出到容器外。用户提供的 Dev 截图可见该现象。

## 根因

- `pillMaxWidthForNode(350) = min(350 - 24, DEFAULT_PILL_MAX_WIDTH=280) = 280`。
- `partitionToolbarActions` 的设计是「主区全部保留，主区即使超宽也不折」，于是 4 个主胶囊（约 330px+）全部保留。
- `FloatingTopPill` 把 280 作为可见 `__group` 的 inline `maxWidth`，而 CSS 给 `__group` 设了 `width: max-content` 与子项 `flex-shrink: 0`：盒子被夹到 280，内容继续溢出 → 背景/边框在 280 处结束，后续项悬空。

## 修复范围

1. `FloatingTopPill`：把 `maxWidth` 只作为测量/分区预算，不再用它夹住可见容器；容器宽度始终由实际可见内容决定。
2. `partitionToolbarActions`：新增兜底——主区自身超过预算时，按从右到左的顺序把主区尾部胶囊折进「更多」，直到可见宽度可容纳或只剩 1 个主胶囊；这样窄节点（最小宽度 150）也不会撑破容器。
3. `pillMaxWidthForNode` / `DEFAULT_PILL_MAX_WIDTH`：放宽预算，使标准 350px 视频节点能完整展示 4 个主胶囊 + 更多；胶囊允许略宽于节点。

不改任何操作行为、节点默认宽度、其他节点类型的信息架构。

## 验收

- [ ] 350px 视频节点：内容拆解 / 分镜表 / 提取音频 / 深度视频 / 更多全部在圆角容器内，无边框截断或溢出（真实浏览器截图）。
- [ ] 窄视频节点（≈200px）：容器完整；尾部主胶囊折叠进「更多」，菜单可打开并触发对应操作。
- [ ] 文本 / 图片 / 音频节点工具栏不回归。
- [ ] 分区算法单测覆盖「主区超宽折叠」分支；`pnpm verify:stages`、anti-slop、workflow 包测通过。

## 新用户基线

纯前端布局修复，不引入任何本机私有状态、凭据或外部服务依赖；在全新安装的 Web/Dev 环境中行为一致。

## 假设

- 胶囊宽度由 `--dsw-alias-*` 主题下的 12px/500 字重中文文案与 13px 图标决定，标准 350px 视频节点上 4 个主胶囊 + 更多在放宽预算后可以完整排布（约 360–380px）。
- 取消可见容器上的 `maxWidth` 夹取不会影响节点拖动/选中命中区：胶囊自身有 `nodrag nowheel nopan` 与 `pointer-events: auto`，宽度由内容决定后只改变视觉包围盒。

## 证伪方式

- 在真实浏览器（画布 harness）中读取可见组的 `getBoundingClientRect` 与每个按钮的矩形：若任一按钮右边界超过组容器右边界（或左边界小于容器左边界），说明仍会溢出，假设被证伪，需要回到分区预算或按钮尺寸重新计算。
- 若窄节点（200px）下容器宽度仍被主胶囊撑破（容器宽度 > 可用宽度且菜单缺失），说明主区折叠分支未生效，用单测与浏览器矩形断言复核并修正。

## 非目标

- 重新设计工具栏信息架构（分组、二级菜单、两行布局）。
- 修改各胶囊操作本身的行为或文案。
- 调整节点默认宽度/尺寸体系。
