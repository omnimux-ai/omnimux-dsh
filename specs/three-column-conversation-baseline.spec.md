# 规格说明书：三分栏会话栏保宽基准必须来自真实分栏读数（工单 #2074 续）

## 1. 背景与问题定义

前一版修复（PR #2076）让「收起左侧栏」保持会话栏宽度并把释放空间交给右侧工作台。开发版实测（1920 视口）暴露了新缺陷：

```
展开：frameGrid 280px / 776px / 864px，--omnimux-conversation-width = 1640px  ← 错
收起：frameGrid   0px / 1640px / 280px                                        ← 会话栏反而吞掉右栏
```

根因：会话栏基准宽度的取样条件是「左栏未收起」，但没有要求**右侧工作台真的展开**。应用启动早期右栏尚未挂载时，会话栏本来就占满剩余宽度（1920 − 280 = 1640），这个单栏全宽读数被记成基准并一直复用，收起左栏后就把 1640px 钉死在第二轨，右栏只剩 280px。

## 2. 验收标准（Acceptance Criteria）

- **AC-201（基准只从真实分栏取样）**：仅当同一帧右侧工作台列宽度 ≥ 200px（确证三分栏）时才允许更新会话栏基准；单栏全宽读数一律忽略。
- **AC-202（无分栏读数时使用契约回退值）**：从未取到可信分栏读数时，基准等于 `CONVERSATION_WIDTH_FALLBACK_PX`（420px，与 `WORKBENCH_CONVERSATION_TARGET_PX` 同尺度），绝不使用大尺寸单栏读数。
- **AC-203（收起后列宽自洽）**：收起左栏后第一轨 0px、会话栏 = 基准、右栏 = 视口 − 基准，且右栏 > 0。
- **AC-204（单栏形态不受影响）**：右栏收起时仍为 `0px minmax(0px, 1fr) 0px`，会话栏占满全宽。

## 3. 测试与验证要求

1. 真实内核几何门禁（`scripts/three-column-collapse-qa.mjs`）：真实 Chromium、动态端口、临时 profile、自清理、PNG + JSON 留证，覆盖三分栏收起后的列宽自洽与反向对照（旧 `auto` 规则下右栏塌为 0px）。
2. 单元测试：单栏全宽读数（1640）不得写进 `--omnimux-conversation-width`；三分栏读数（485）必须写进变量；无任何读数时回退到 420px 契约值。
3. 源码契约回归：三分栏保宽规则的 CSS 变量回退值为 420px，右栏收起全宽分支仍存在，且保宽规则排除右栏已收起态。
4. 开发版真机 CDP 复测：1920 视口三分栏，收起左栏后会话栏宽度不变、右栏 = 视口 − 会话栏宽度且 > 0。
