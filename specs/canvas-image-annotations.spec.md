# 画布图片局部打点评论与大模型上下文理解实施规格 (Canvas Image Annotations & LLM Context Protocol Spec)

## 1. 业务背景与用户价值
在 AI 绘图与内容生成场景中，用户往往需要针对生成图片的特定局部位置（例如：某个特定人物的脸、衣服、背景物体等）提出针对性的修改意见。
以往的做法只能通过口头描述（如“把左边穿裙子的女生换成短发”），大模型很容易产生空间幻觉或者误解指示对象。
本功能完整实现：
1. **顶部操作入口**：添加「+ 添加评论」按钮，激活后鼠标光标自动切换为蓝色气泡标记指针（对标截图）。
2. **大图原地打点与录入**：在图片任意局部点击，原地落下一个蓝色圆角气泡标记（自动分配序号 1），并向右展开黑底胶囊输入框（输入修改文字，支持回车或点击白色圆形箭头 `↑` 快速提交）。
3. **连续打点与序号自增**：单条评论提交后，标记数字保留在图上，鼠标光标继续维持打点指针状态，方便用户连续点击标记序号 2、3 等多个局部。
4. **原生输入框挂件联动**：大图上有评论时，画布下方悬浮的原生官方 DSH 输入框自动浮现「`⊕ X 个评论`」交互挂件，顶部工具栏联动显示 `X 条评论 [发送] [✕]`。
5. **大模型上下文双通道打通**：
   - **视觉通道**：前端离屏生成一张绘制有 ❶ ❷ 标记圆标的视觉提示图（Visual Grounding Image）。
   - **语义通道**：组装结构化归一化坐标（0~100%）与批注指令清单，让视觉多模态大模型 100% 精确锁定局部进行重绘修改。

## 2. 交互细节与状态机

### 2.1 打点评论状态机 (`media-viewer-store.js`)
- `isAnnotating: boolean`：是否处于打点模式。
- `annotationsByMediaId: Record<string, AnnotationItem[]>`：
  ```ts
  interface AnnotationItem {
    id: string;
    index: number;         // 1, 2, 3...
    xPercent: number;      // 0 ~ 100
    yPercent: number;      // 0 ~ 100
    text: string;          // 评论文本
    status: 'draft' | 'saved';
    createdAt: number;
  }
  ```
- 点击顶部「+ 添加评论」：切换 `isAnnotating = !isAnnotating`。
- 在图片区域点击：创建草稿标记并计算 `(e.clientX - rect.left) / rect.width * 100`。
- 提交输入框：状态变更为 `saved`，清空草稿输入框，保留已保存数字图钉，保持 `isAnnotating = true` 继续打点。
- 点击顶部 `✕` 或底部挂件删除：支持移除单个标记或清空当前图片所有标记。

### 2.2 视觉规范 (对齐用户截图与 design.md)
- 图钉标记（Pin）：蓝色基准底色 `var(--dsw-alias-brand-primary)`，纯白序号文字，白色 1.5px 描边。
- 弹出输入框（Popover）：黑底磨砂圆角胶囊（高度 36px，圆角 9999px），提示文字 `添加评论...`。
- 提交按钮（Submit）：纯白圆形微型按钮配深黑箭头 `↑`。
- 底部挂件：原生输入框卡片浮现「`⊕ X 个评论`」徽标，点击高亮对应标记。

## 3. 验收用例 (Acceptance Criteria)
- **AC-1**：点击顶部「+ 添加评论」，大图区域光标变为气泡打点指针。
- **AC-2**：在大图上点击，生成序号 `1` 的打点与输入框；输入文本按回车提交，打点保留在画面对应百分比坐标处。
- **AC-3**：提交后鼠标继续维持打点状态，再次点击生成序号 `2`，实现序号连续自增。
- **AC-4**：当前大图有标注时，顶部工具栏居中显示评论计数，底部原生输入框展示「⊕ X 个评论」挂件。
- **AC-5**：模型上下文转译函数将标注数据转换为规范的结构化提示词协议。
