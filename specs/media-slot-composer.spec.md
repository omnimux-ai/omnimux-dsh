# 规格：图像生成输入框的通用素材卡槽

## 目标

在现有图像/视频生成输入框里，用同一套卡槽接收图片、视频、音频。数量、格式和时长上限来自当前所选模型在执行中枢登记的契约，不在界面里另写死数字。

用户是在图像生成页写提示词的人。成功的样子：

- 卡槽是竖屏虚线框，图片、视频、音频各用自己的图标。
- 图片生成：按当前模型的参考图上限放图片。不满 3 个并排；满 3 个收成一摞，右下角标数量；鼠标移到叠卡上摊开；移开收回。
- 还能继续加时，虚线框一直露在叠卡右侧，中间留空隙，不互相遮挡，点它就能加。
- 删掉一张时，它左边的不动，右边的往左补上，不整组重排。
- 视频生成沿用现有四种生成模式：文生视频不出现卡槽；首帧一个图槽；首尾帧两个图槽；全能参考按契约分别出现图片、视频、音频槽；视频编辑出现源视频槽和参考图槽。
- 格式不对，或时长超出该模型契约，在页面顶部给出一条提示，素材不进入卡槽。
- 新用户没有素材时只看到虚线框；目录暂时读不到时，不显示卡槽，也不用开发机上的数字顶上。

## 命令

```bash
pnpm --filter @omnimux/hub test -- src/client/media-viewer/media-slot.test.js src/client/media-viewer/media-viewer-composer.test.js
```

在任务工作区 `.worktrees/omnimux-media-slot` 内执行。浏览器验收用该工作区自己的页面，不写开发版、不写正式版。

## 结构

- `plugins/omnimux/src/client/media-viewer/media-slot.js`：从模型契约算出当前该显示哪些槽、上限和时长限制。
- `plugins/omnimux/src/client/media-viewer/MediaSlotGroup.jsx`：一套卡槽，图片/视频/音频共用。
- `plugins/omnimux/src/client/media-viewer/MediaViewerComposer.jsx`：接进现有输入框。
- `plugins/omnimux/src/client/media-viewer/styles.js`：沿用现有输入框的颜色和圆角。
- `plugins/omnimux/src/client/media-viewer/media-slot.test.js`：上限、模式切换、格式与时长拒绝。

## 代码风格

与现有输入框一致：函数组件、具名导出、中文界面文案、颜色只用页面已有的主题变量。

## 测试

- 纯逻辑：同一模型在「文生图」没有槽，「多图参考」按契约上限出图槽；视频四种模式分别出对应槽；时长按该槽自己的上限判断。
- 浏览器：打开图像生成页，放入 3 张后看叠放和数量，悬停看展开，删除中间一张看右侧左移，放一个不合格式的文件看顶部提示。

## 边界

总是做：复用现有输入框、现有模型选择和现有顶部提示样式；上限只读契约。

先问：把素材真正送进生成请求（本轮只把已选素材放进提交内容，不新开生成通道）。

绝不做：改模型契约文件；写开发版或正式版；在界面里写死某个模型的张数。

## 成功标准

1. 换一个参考图上限不同的模型，卡槽能放的张数跟着变。
2. 3 张及以上默认叠放且数量正确，悬停展开，未满上限时虚线框可见且不与叠卡重叠。
3. 删除任意一张，其右侧素材向左补位。
4. 视频四种模式的卡槽与契约槽位一一对应。
5. 不合格式或超时长的文件被拒绝，并在顶部出现一条说明。

## 假设

1. 只改图像生成页的输入框，不改画布节点。
2. 视频模式沿用输入框里已经有的「文生视频 / 首帧 / 首尾帧 / 全能参考」，并补上契约里已有的「视频编辑」。
3. 新用户读不到模型目录时，卡槽先不出现。
