# 规格：引用菜单跟着输入框翻转

## 目标

输入 @ 时，菜单贴着输入框展开：输入框靠近页面顶部时从下方展开，靠近底部时从上方展开。已加入素材的每一行开头显示缩略图。发出去的用户消息不再出现素材说明代码，改为缩略图卡片。智能体仍通过不显示的通道拿到素材；没有文件位置的素材也带上可识别地址。

新用户不依赖本机私有服务。没有素材时菜单不出现空分组，消息里也不出现空卡片。

## 用户怎么用

1. 在页面顶部的输入框里输入 @：菜单出现在输入框下方。
2. 对话开始后输入框吸到底部，再输入 @：菜单出现在输入框上方。
3. 菜单里「已加入素材」每一行开头是这张素材的小图，后面是名称和类型。
4. 选中素材并发送：用户消息里只看到缩略图和名称，看不到代码。
5. 智能体仍能识别被引用的素材，包括原先没有文件位置的那一张。

## 期望界面

- 菜单不超出页面可视范围。顶部输入框向下展开，底部输入框向上展开。
- 素材行缩略图为小方图，放在文字前面。没有图的素材用类型色块代替，不留破图。
- 用户消息气泡正文不含素材说明代码。缩略图卡片出现在气泡上方。

## 验收用例

- 用例一：输入框上沿距页面顶部不足菜单高度时，菜单从输入框下沿展开；否则从输入框上沿展开。
- 用例二：素材候选带缩略图地址，菜单行用它画在名称前面。
- 用例三：发送时写入用户消息的引用只保留名称，不包含文件说明代码。
- 用例四：没有文件位置的素材，在不显示的通道里仍带可识别地址。
- 用例五：没有素材时不出现空分组，也不出现空卡片。

## 边界

- 总是做：保留官方文件与对话记录引用，素材分组仍排在它们前面。
- 先问：改动官方安装包，或改动正式版。
- 绝不做：把素材说明代码继续写进用户能看见的消息正文。
