# Spec: 吸底后切 Tab 被强制跳顶（#3812 后续）

- 风险级别: R2（单插件客户端交互修复，可逆，不改官方源码）
- 宿主: OmniMux Dev / dsh `0.2.1-rc.3`
- base: `origin/main` @ `529c16243`

## 1. 目标与用户故事

用户在探索模板里点了一张素材卡，输入框吸到底部、素材挂好、指令写好。此时点 Tab 栏切到另一个库（或换二级分类），页面被整块推回顶部：素材区消失、Tab 栏跑出视口、输入框跟着弹回顶部。用户丢失了刚选的素材位置，得重新往下滚。

期望：切 Tab 只换下面的内容，Tab 栏原地不动，输入框继续吸底，已挂的素材与写好的指令都不丢。

## 2. 根因

两件事叠在一起：

1. **换库先清空列表**。`ExploreTemplatesSection` 的加载 effect 把 `cards: []` 写死，只剩一行「加载中…」。素材区容器从约 989px 塌到 160px，页面总高度骤降。
2. **浏览器夹回滚动位置**。页面变矮后当前 `scrollTop` 超出新的最大值，浏览器只能把它夹回去。这段位移被 `useComposerDocking` 的滚动判定读成「用户滑回顶部」，于是把吸底输入框弹回原位。

素材区本来没有视口最小高度兜底（精选 shelves 有、素材库 grid 没有），所以塌陷在素材库这一路必然发生。

## 3. 实测证据（真实 Chrome，`scripts/tab-switch-scroll-anchor-qa.mjs`）

滚到底部 → 点资产库卡片吸底 → 切灵感库，取换库瞬间的几何：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 素材区高度 | **160px**（塌陷） | 989px |
| 在屏卡片数 | **0**（只剩「加载中…」） | 24（旧卡片保留） |
| Tab 栏距视口顶 | **-116px**（被推出视口） | 0px |
| 吸底标记 | 保持 | 保持 |

## 4. 修复方案

- **换库不清空旧卡片**：`cards` 保留，改用新增的 `refreshing` 标记（旧卡片淡化到 45%），新数据到达后原子替换。首屏无卡片时才走 `loading`。
- **素材区至少一屏高**：`.omnimux-explore-grid-view-wrap.omnimux-explore-grid-view-flow` 补 `min-height`，与精选 shelves 同一套算法（含吸底态扣减），卡片少时下方自然留白。
- **被动位移静默窗口**：`useComposerDocking` 新增 `holdScroll(ms)`；切 Tab / 换二级分类前声明一次，窗口内滚动判定不读这段被浏览器夹出来的位移，也不清 `leftTop`。窗口结束后照常按真实滚动判定——用户自己滚回顶部仍然正常归位。

## 假设

跳顶的直接前因是「换库瞬间素材区高度塌陷 → 浏览器夹回 scrollTop → 被误读为用户滚动意图」，不是 Tab 切换代码里主动调用了 `scrollTo(0)`（已确认切换路径无任何滚动指令）。若该假设成立，那么只要同时做到「高度不塌」与「被动位移不计入滚动判定」，跳顶即消失，且用户手动滚回顶部的归位行为不变。

## 证伪方式

若补齐最小高度与静默窗口后，切 Tab 仍出现 Tab 栏离开视口顶部或素材区跌破半屏，则假设错误，需转去查宿主的滚动容器是否在换库时被重新挂载（`data-conversation-scroll` 换节点会让 scrollTop 归零，与高度无关）。

可执行验证：
- `node scripts/tab-switch-scroll-anchor-qa.mjs`：修复侧 8 条断言全过；反向对照（退回「清空卡片 + 撤掉最小高度 + 关掉静默窗口」）必须复现塌陷与跳顶。
- `node --test src/explore/*.test.js`（omnimux-inspiration 包内）保持全绿。

## 5. 新用户基线

不依赖开发机私有状态：素材来自 `/omnimux/assets/library`、`/omnimux/inspiration/local`、`/omnimux/products` 三个产品内公开地址。空库或未登录时列表为空、容器仍保留一屏高度，不引入新的失败面。

## 6. 文档影响

无新增契约。行为对齐既有 `specs/tab-sticky-top-min-height.spec.md`（Tab 栏置顶 + 少卡留白 + 输入框恒定吸底），本次把该规格的兜底从精选分支补齐到素材库分支。
