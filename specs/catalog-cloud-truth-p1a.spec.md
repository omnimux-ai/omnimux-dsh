# 云端目录接入运行时（P1a：接入不改行为）

- Issue: #3719（父任务：让云端成为模型清单唯一真源）
- 阶段: P1a / P1a·P1b·P1c 三步中的第一步
- 基线: `origin/main`
- 上游计划: `/Users/x/Desktop/Project/dsh-plugin/deliverables/omnimux-catalog-refactor/PLAN.md`（用户已批准）

## 这一步要什么

把 P0 已经交付的「拉取 / 归一 / 缓存 / 比对」模块接进运行时，**但不改变任何用户可见结果**：目录输出、默认值、成员资格、线路、价格全部与今天逐字节一致。这样可以在真实进程里先跑起来、先出诊断，再谈切换真源。

具体四件事：

1. **打包快照**：仓库内随包发布一份归一化后的网关目录快照（新机器、断网、首启用）。
2. **运行时解析**：打包快照 → 磁盘缓存 → 进程内，按生成时间与最低版本挑最新可用的一份（照抄 Apps 目录 `resolve.js` 的规则）。
3. **刷新调度**：启动时 + 每 6 小时 + 登录/切号时拉 `<siteBaseUrl>/api/pricing`；失败保留上一份并标过期，空响应不覆盖，内容未变不发事件。
4. **只读诊断**：既有目录路由新增一个 `?view=diagnostics` 视图，输出「当前快照来源 / 摘要 / 是否过期 / 与本地目录的差异计数」。不新增路由、不改目录响应体。设置页与画布在 P1b 才消费它。

## 用户旅程与期望反馈

- **新机器断网首启**：目录完整可用（来自打包快照），设置页模型卡片正常显示；诊断显示来源为「随包快照」。
- **联网启动**：后台刷新一次；若网关内容与上次不同，发出既有的 `omnimux/model-catalog-updated` 事件（客户端与 composer 已监听）。
- **刷新失败（断网/网关 5xx/响应为空）**：本次不改动目录，诊断显示「过期」与失败原因，不阻塞启动、不清空缓存。
- **用户什么都没看到变化**：本步不改目录内容，前端展示与今天完全一致。

## 方案

新增（都在 `plugins/omnimux/src/catalog/cloud/`）：

- `config.js`：`Config.catalog` 默认值与校验（开关、地址、刷新间隔、超时、打包快照目录）。地址必须是 https 且与 `siteBaseUrl` 同源（照 `apps/config.js` 的校验方式）。**默认开启远端**——成员资格必须来自网关，这与 Apps 默认关闭不同；断网时用打包快照。
- `bundled.js`：读随包快照并校验 schema 版本与 `models` 数组；缺失或损坏时返回「没有」，不抛错。
- `live.js`：进程内当前快照 + 解析（bundled / 磁盘 / 内存按生成时间取最新，磁盘比打包旧则丢弃）。
- `refresh.js`：刷新一次（拉取 → 归一 → 写入），带三条保护：空快照不覆盖、单次消失超过一半不覆盖、失败只标过期。内容摘要不变时不产生「变化」事件。
- `bundled/pricing.json`：打包快照（归一化结果，只保留 id/展示名/线路/端点类型/计费/网关 contract + 顶层分组倍率与可用分组；不保留描述、厂商、owner 等无关字段）。
- `plugins/omnimux/scripts/catalog-snapshot.mjs` + 根 `package.json` 的 `catalog:snapshot`：从网关生成打包快照（只读公开定价接口，不调用任何模型）。

宿主接入（`src/host/apply.js`）：启动时创建解析器与刷新器，按 TTL 触发；刷新产生变化时发既有事件。**`buildModelCatalog` 不改**，诊断走新接口。

## 验收

- [ ] `buildModelCatalog()` 输出与改动前逐字节一致（含 fingerprint）；用同进程对比测试固定这一点。
- [ ] 打包快照存在且能解析：模型数 > 0，schema 版本正确。
- [ ] 解析优先级：内存 > 磁盘 > 打包（按生成时间）；磁盘比打包旧时被丢弃。
- [ ] 刷新：内容未变不发事件；空响应不覆盖；消失超过一半不覆盖并标过期；网络失败只标过期。
- [ ] 诊断接口输出来源/摘要/过期/差异计数，且不改变目录输出。
- [ ] 配置校验：非 https 或与站点不同源时拒绝；TTL/超时必须为正整数。
- [ ] `pnpm --filter omnimux test` 通过；`pnpm check:boundaries` 通过。
- [ ] 不调用任何真实模型（只用公开定价接口生成打包快照 + 夹具测试）。

## 假设

- 公开定价接口匿名可读，且返回 `data[]` 且每行都有 `enable_groups`：本步已实测一次（11 行、全部带线路与 contract），但运行时仍按「缺线路」视为不可用，不假设永远如此。
- 网关没有可用的版本号（`pricing_version` 是常量），因此变化检测只能靠内容摘要；摘要算法已由 P0 固定。
- 打包快照是公开数据（匿名可读的定价与线路），可以进仓库；归一化后不含中转站名称、URL、账号或密钥。
- 本步不动 `buildModelCatalog`，因此不会影响 composer、画布、提交守卫的任何现有行为。

## 证伪方式

- 若「输出逐字节一致」的对比测试失败（指纹或列表有任何差异），说明本步意外改变了行为，必须回退到只做缓存不接入。
- 若打包快照解析出的模型数为 0，或诊断显示来源为「无」，说明兜底路径没接上，产品基线（新机器首启可用）不成立。
- 若在断网夹具下刷新失败导致目录被清空或启动被阻塞，说明 keep-last-good 没生效。
- 若诊断接口的差异计数与 P0 的 `catalog-diff` 在同一份输入上不一致，说明两条路径读的不是同一份快照，必须统一后再进 P1b。

## 旧标准变更

本步不修改任何既有测试用例或断言（只新增文件与新增测试）。

诊断最初计划挂在一条新路径上，但那会让既有的路由表枚举用例失败，而那个文件当前被门禁文件级规则挡住（见 `#3718`：含执行类导入的测试文件任何编辑都被拒）。为避免为了新路由去削弱既有断言，诊断改为复用既有目录路由的 `?view=diagnostics` 视图：路由表不变，目录响应体逐字节不变，既有断言一项未动。
