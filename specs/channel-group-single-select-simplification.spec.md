# 模型级联菜单渠道分组单选与契约锁定规格 — Issue #2049

## 一、需求背景与目标
在工作流画布中，模型级联选择浮层（ModelCascadeMenu）原先提供了渠道分组多选机制以及「稳定性优先 / 低价优先」调度策略。
但由于 Seedance 等多模态模型的各渠道分组（如特惠版、进阶版、官方版）在输入模态（纯图 vs 音视频参考）、计费方式（按条 vs 按秒）与参数约束（时长、分辨率）上严重异构：
- 多选导致节点无法确定开放哪些输入卡槽（取交集则高级专线被阉割，取并集则低配线路运行时报 400）；
- 计费呈现出现区间浮动，增加用户认知负担与客诉风险。

遵循「奥卡姆剃刀」设计哲学，进行彻底的减法重构：
1. 取消「稳定性优先」与「低价优先」调度策略；
2. 渠道列表由多选（Checkbox）全面收敛为互斥单选（Radio）；
3. 移除底部的「已选 X/X 个、清空、全选」操作区；
4. 单选分组直接唯一锁定输入契约与价格，彻底消除多选冲突。

## 二、关键用户旅程（Critical User Journeys）
- **J1：打开级联菜单查看渠道**
  - 用户点击模型胶囊打开级联菜单，展开第三列「选择版本」；
  - 顶部直接平铺渠道列表，不再有策略切换胶囊；
  - 底部直落到底，不再有多选计数与清空全选按钮。
- **J2：单选切换渠道分组**
  - 渠道行呈现互斥单选体验，点击任一渠道即成为唯一激活分组；
  - 激活项展示高亮描边与绿色对勾，其他项自动取消；
  - 预览态（鼠标扫过其他型号）保持只读。
- **J3：锁定契约与节点联动**
  - 选定某一渠道后，节点数据写回 `allowedGroups: [selectedGroupId]`；
  - 节点严格采用该渠道的独占契约（LineConstraints），卡槽与参数所选即所得。

## 三、验收标准（Acceptance Criteria）
- [ ] **AC1（移除策略按钮）**：第三列顶部移除「稳定性优先」与「低价优先」按钮，策略选择逻辑彻底剥离。
- [ ] **AC2（单选互斥）**：渠道列表采用互斥单选（Radio）交互，点击某一渠道立即切换且仅有当前项被勾选。
- [ ] **AC3（移除底部批量操作）**：移除「已选 X/X 个」、「清空」、「全选」操作条，列表无多余操作区。
- [ ] **AC4（胶囊精简）**：外部触发胶囊移除策略图标（盾牌/百分比）与多选计数，展示纯粹克制。
- [ ] **AC5（契约锁定）**：选中分组的约束（LineConstraints）单一生效，无多选交集冲突。
