# 3372 账号监控恢复与真实采集验收

## 目标与授权

用户要求恢复自动更新，修正成功判定、账号错误提示与重试，并用现有账号真实采集验收。范围仅限参考博主监控，不改推荐、复刻动作、发布矩阵、生产配置、凭据引导或官方 Harness。普通 PR、合并、Dev 物化和任务清理沿当前授权连续完成。子任务 #3373 负责结果判定，#3374 负责客户端提示与重试。

## 新用户基线与复用

沿用中枢正式社媒数据能力与用户自己的现有凭据，不使用开发机代理、私有默认模型、硬编码账号或渠道；缺少凭据、登录、额度时给出明确失败。不创建第二套采集器或账号存储。账号监控现有资料/作品映射、刷新队列、额度账本和界面组件为唯一实现来源。

## 接受条件

1. 插件加载时启动唯一刷新定时任务，并在卸载时清理；已到期账号能更新，终态不被自动无限重试，原有日额度与退避上限保留。
2. 账号资料必须有可识别的有效字段；作品必须有已知列表形状。明确空列表可成功；未知形状、业务失败、非空却全部无效的作品不得记成功、清失败或覆盖旧缓存。
3. 首采错误归属于当前账号/平台筛选；显示具体账号与经过白名单翻译的可行动原因，不直接回显可能含秘密的任意错误。
4. 刷新和重试只处理明确范围内的账号；停止账号能经显式重试恢复；受理、额度拒绝、冷却、采集失败有可见回执，不把受理等同完成。重复点击不产生并发重复任务。
5. 隔离 worktree 中真实浏览器覆盖失败提示、筛选隔离、重试与成功内容出现，保留截图和结构化证据。局部夹具与真实云采集分别记录，不冒充完整新用户安装或 Dev 人工验收。
6. 用户授权现有账号真实采集。每账号先单次受控采集、核对结果再决定后续；沿正式中枢调用，不探测模型能力，不记录秘密。真实失败应保留明确原因；拿到作品才算作品采集通过。

## 检查与交付

先以回归用例证明问题，再修复。运行相关包测、产品基线、插件装载、Stage 与反模式门禁；以影响矩阵补齐真实触及面。界面 E2E 在同任务真实验证证据之后编写。独立评审后经 required CI 与 Merge Queue 合入，按仓库 ship 流程同步与物化 Dev；保留报告后清理任务工作区。文档影响限本规格与任务证据。
