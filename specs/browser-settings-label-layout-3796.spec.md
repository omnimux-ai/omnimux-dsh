# 规格 · 设置面板行标签与说明句的窄宽度布局（Issue #3796）

## 背景

侧栏设置面板每行是 `<label>` 里的一对「标签 + 说明句」，下面挂控件。`src/panel/styles.css` 的
`.settings label` 用 `grid-template-columns: 1fr auto`：标签在 `1fr` 列，说明句在 `auto` 列。
说明句是长中文且没有换行约束，`auto` 列按内容撑到接近整行宽，`1fr` 列被压到不足一个汉字宽。
中文在极窄容器里逐字断行：420px 面板实测「文本生成模型」标签列只剩 12px 宽、竖着叠成 6 行，
「鉴权 Token」叠成 2 行；两行说明句长短不同，行高也不齐。

## 目标

- 标签永远单行完整显示，不逐字竖排。
- 宽面板下标签列带 45% 上限：异常长标签换行而不是撑出容器被 `.settings-panel` 的
  `overflow:hidden` 静默裁掉（窄面板走单列，上限不参与）。
- 说明句让出列宽：宽面板下与标签同排右对齐并允许换行；窄面板下落到标签下方、左对齐。
- 控件（模型选择器）整行满宽，与说明句之间不留异常空白。
- 只改 `.settings label` 行的排版规则，不动任何设置键、持久化、文案与控件实现。

## 假设

- 竖排的直接成因是网格 `1fr` 列被 `auto` 列挤到不足一字宽，而不是字体、`word-break` 或缩放变量；
  因此把标签列改为按内容取宽、说明句列改为可收缩可换行，就能在不改文案的前提下恢复单行。
- 设置面板所有 `label` 行共用同一套网格，修好模型两行不会连带破坏其它行，因为其它行控件本就
  `grid-column: 1 / -1` 满宽跨两列，列宽变化只影响标签与说明句的相对位置。

## 证伪方式

- 若真实浏览器（未打包扩展，280/340/420px 面板宽，深浅两套主题）里标签仍出现竖排、或说明句仍占满整行，
  则本改动未生效。判据是逐行几何：`labelLines === 1` 且标签 `scrollWidth` 未超自身宽。
- 若共用这套网格的**开关行**（`.setting-toggle`，窄面板规则用 `:not()` 排除它）或**中继配置行**
  （`.relay-profile label`，自带 flex 列）出现标签被裁切、行 `scrollWidth` 超自身宽、或开关被挤到
  文案下方，则说明改法误伤了共用行，判为证伪。这两类行是媒体查询特判的对象，必须实测而不是只靠声明。
- 若回退 `grid-template-columns` 后同一套断言仍然全通过，说明断言恒真、没有判别力，判为证伪。

## 验收用例

1. 真实浏览器、面板宽 280/340/420px（窄）与 1280px（宽）：两行标签各占一行、完整可读；控件满宽。
2. 窄面板下说明句落到标签下方；宽面板下同排右对齐且未压窄标签；任何宽度下说明句都不覆盖控件。
3. 22 行全部无逐行横向溢出；开关行保持两列（开关在文案右侧）；中继配置行标签单行未裁切。
4. 宽面板下人为构造的 90 汉字标签被 45% 卡住（轨道宽 = 内容宽 × 0.45）、换行且不溢出；
   实际字数记录在证据 JSON 的 `longLabel.probeChars`，不靠叙述。
5. 深浅两套主题都成立。
6. `panel-settings-label-layout` / `panel-styles` / `panel-text-model-isolation` 定向单测通过。

## 旧标准变更

无。本任务不改写任何既有具名用例的断言；`panel-styles.spec.ts` 对 `.settings` 与 `.settings > *`
的断言保持原样（本改动不触及这两条规则）。
