# Spec · 技能列表菜单显示在输入框上方并提升图层层级防遮挡

## 1. 业务意图与背景
用户在会话输入框中键入斜杠或技能名称（例如 `/tiktok-shop-product-video-maker`）时，系统应当清晰弹出匹配的技能候选项菜单供用户快速点选。
然而，在会话首页居中态下，由于先前的居中态自适应判定逻辑，弹出的技能列表菜单被强行定位在输入框下方（`top: calc(100% + 4px)`），直接落入输入框正下方的核心快捷技能栏（4个核心胶囊按钮：`⚡ 技能`、`▷ 视频广告`、`🖼 图片广告`、`🔍 竞争对手研究`）所在的坐标区域。
更严重的是，菜单的 `z-index` 被设置为了较低的 `80`，而下方胶囊栏容器的 `z-index` 为 `120`。这导致技能列表菜单被直接压在下层，胶囊按钮浮在上面将技能菜单的名字与描述截断遮挡，用户无法正常查看与点选技能。

## 2. 核心问题与根因分析
1. **位置判断错误覆盖**：先前的自适应菜单逻辑原旨在处理全屏居中态下点击「+」号弹出的指令卡片，但其 DOM 选择器包含了 `[data-trigger-menu]` 与 `[class*="iRJKyq_menu"]`，导致键入 `/` 或 `@` 触发的联想菜单也被当成下拉菜单强制放置到下方。
2. **图层层级倒挂**：菜单样式的 `z-index` 被强制赋予了 `80 !important`，明显低于输入框下方胶囊按钮栏的 `120` 和 popover 的 `130`，形成致命的视觉层级倒挂（Layer Inversion）。
3. **用户明确指示**：“把技能列表菜单 显示到上一层”。需要同时在空间方位（输入框上方“上一层”）和图层层级（Z 轴最顶层）彻底解决。

## 3. 详细方案与设计规格
1. **技能触发菜单始终在输入框上方展示**：
   - 技能列表联想菜单（`[data-trigger-menu]`、`[class*="iRJKyq_menu"]`）专用于输入框内键入 `/` 或 `@` 时的即时联想补全；
   - 无论处于居中态（hero）、沉底态还是全屏模式，技能列表菜单统一固定在输入框上方升起（`bottom: calc(100% + 4px) !important; top: auto !important;`）；
   - 输入框下方原有的胶囊栏（`CreatifyPillsBar`）和探索卡片流保留完整展示，空间上完全解耦，零重叠冲突。
2. **图层层级彻底置顶**：
   - 技能列表菜单及其所有相关浮动菜单的 `z-index` 提升为 `1000 !important`；
   - 无论是菜单在上方还是特定弹窗在下方，均绝对高于页面内任何普通组件（胶囊栏 120、弹窗 130 等），彻底杜绝任何被遮挡的可能。
3. **自适应判定函数解耦**：
   - 在 `shouldPlaceMenuBelow` 函数中增加对技能列表菜单（`data-trigger-menu` / `iRJKyq_menu`）的排他性过滤，直接返回 `false`；
   - 在 `syncMenuPlacement` 中，对技能列表菜单始终恢复上方布局，并赋予高优先级置顶层级；
   - 在静态注入样式 `ensurePlacementStyles` 中，明确写入高优先级置顶规则，避免首帧闪烁。

## 4. 验收标准与测试矩阵
- **场景 1：居中态输入技能触发联想**
  - 在居中态（新对话）输入框键入 `/` 或技能名称；
  - 验证弹出的技能列表菜单完整显示在输入框上方（`bottom` 定位生效，`top: auto`）；
  - 验证输入框正下方的 4 个核心胶囊按钮保持可见，不受遮挡。
- **场景 2：图层层级严格高于所有组件**
  - 验证技能列表菜单的 `z-index` 计算值为 `1000`；
  - 验证即使下方或周围存在 `z-index: 120` 的胶囊栏，菜单也绝不会被任何图层压在底下。
- **场景 3：沉底态对话流程**
  - 随着消息发送输入框沉底，验证技能菜单继续在输入框上方正常展示。
- **场景 4：回归自动化测试**
  - 现有及新增单元测试与 E2E 测试 100% 通过。

## 5. 用户交付与演示门禁
- 遵循“必须先演示、后合入”原则；
- 提供单文件演示页面，直观呈现优化前后对比与最新交互效果；
- 采用大白话三段式汇报向用户说明当前结果、界面变化与后续计划，等待用户确认后再合入主干。
