# 浏览器插件配对方案 B 规格（Issue #2095）

## 1. 业务问题
浏览器插件连接本机 OmniMux 必须带 `ext-bridge-token`（64 位十六进制）。该令牌是安全扫描 BROWSER-01 后的唯一准入凭据，但用户只能手工从隐藏文件复制——对非技术用户不可行，UI 文案也曾误导为「本机无需填写」。

## 2. 目标
安装插件后：应用点一下 → 应用显示 6 位配对码 → 插件输一次 → 永久自动连接，不再需要任何密钥复制。

## 3. 核心改动规范

### AC-1 兑换通道（Host，`plugins/omnimux-browser/src/pairing.ts` + 路由）
- 新增内存态配对会话：6 位数字码、`PAIRING_TTL_MS = 120_000`、`PAIRING_MAX_ATTEMPTS = 5`；重新生成即覆盖旧码。
- `GET /ext/pair`：仅回环可取；生成（或复用未过期）会话并以 HTML 页面显示 6 位码与剩余秒数；页面不写任何密钥。
- `POST /ext/pair`：请求体 `{"code":"123456"}`（≤ 1 KiB），成功返回 `{"token":"..."}`。
- 兑换前置条件（全部满足才放行）：
  1. 来源为回环地址（`isLoopbackAddress`）；
  2. 请求头 `Origin` 不是 `http://` / `https://` 开头（网页无法伪造扩展来源；无 Origin 的本机客户端可放行）；
  3. 会话存在、未过期、尝试次数未耗尽、码匹配（常量时间比较）。
- 失败语义：非回环 → 403；网页 Origin → 403；无会话/过期 → 409；码错 → 401（消耗一次尝试）；超次数 → 429。
- 响应头：`cache-control: no-store`；**不得**设置 `access-control-allow-origin: *`（否则网页可读取令牌）。

### AC-2 现有安全边界不得放宽
- `BridgeServer.attach` 的令牌校验零改动；回环免密捷径不得回归。
- `/ext/bridge-config` 继续不包含任何密钥。

### AC-3 插件侧（后续阶段在本任务内完成）
- background：新增配对消息，用配对码向 Host 兑换令牌 → 写入 `settings.token` → 立即重连；错误分级（码错/过期/超次数/实例不可达）。
- 面板：连接被拒时就地出现配对卡片（输入 6 位码 + 一键打开配对页面）；成功后卡片消失，之后启动即自动连接。
- 高级设置保留手动令牌字段（远程/企业场景）。

### AC-4 撤销与多实例
- 配对码由某实例生成、只对该实例有效，天然不会配错实例。
- 本阶段不做令牌轮换（避免其它已配对浏览器掉线）；「重置配对」后续单独排期。

## 4. 验收证据
- 单测（`plugins/omnimux-browser/tests/`）：码错/过期/超次数/非回环 403/网页 Origin 403/成功返回令牌且不带通配 CORS；既有 `tests/server.spec.ts` 安全断言保持绿色。
- 真实浏览器端到端：应用侧取码 → 插件输码 → `hello.ok` 连接成功，截图与结构化报告落盘 `docs/evidence/`。
