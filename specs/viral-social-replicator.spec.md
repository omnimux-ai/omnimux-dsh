## 1. 产品背景与痛点深度解构（Background & Problem Statement）

### 1.1 业务背景与行业核心矛盾
当前 OmniMux 定位为全流程社交媒体 Agent 运营助手，核心使命是协助用户在 TikTok、Instagram、YouTube Shorts、X (Twitter)、Threads、小红书等主流社交平台上，高效完成内容生产与矩阵分发。

在这一过程中，最核心也最具商业价值的挑战是：**“如何基于用户自身的产品、服务或内容意图（如 UGC 种草、品牌出海、个人 IP 起号），帮助用户以最简单、最快速的方式，稳定产出高质量的病毒式（Viral）内容？”**

然而，直接依赖大语言模型（LLM）“无中生有”地自由创作，已被全行业证实是一条死胡同：
1. **预训练数据钝化与脱节**：通用大模型的预训练数据具有滞后性，无法感知当下社交平台瞬息万变的爆款趋势、即时梗（Memes）与平台算法推流偏好；
2. **缺乏网感与通病“AI 味”**：没有约束的 Agent 生成内容充满陈词滥调（如“在这快节奏的时代…”、“不可否认的是…”）、说教腔、毫无起伏的书面语，无法在社交媒体信息流中建立前 3 秒的用户留存；
3. **缺乏底层病毒性逻辑**：爆款内容背后有一套精密的情绪张力曲线、认知反差机制、视觉/文字留白节奏与行动号召（CTA），纯 Prompt 驱动的随机生成无法稳定命中这些爆款要素。

### 1.2 核心破局点：“爆款即公式，内容即变量”
最理想且已被验证有效的破局路径是：**逆向工程（Reverse Engineering）**。
- **让 Agent 寻找“已经爆火验证过的爆款模板或成功作品”作为结构模具**；
- **提取其最核心的底层骨架（黄金 Hook、情绪曲线、分镜节奏、埋梗诱饵）**；
- **将用户自身的产品特性、业务卖点与价值主张作为“变量”注入到骨架中，实现高质量二次重构**。

### 1.3 必须攻克的两大核心门槛
基于上述逻辑，整个系统的生死线取决于攻克以下两个核心技术与产品门槛：

```
┌────────────────────────────────────────────────────────────────────────┐
│                          两大核心门槛与产品卡点                         │
├──────────────────────────────────┬─────────────────────────────────────┤
│ 门槛 1：海量数据下的高精准模板适配 │ 门槛 2：爆款内核解构与二次高质量重构  │
├──────────────────────────────────┼─────────────────────────────────────┤
│ • 外部海量 UGC 库与内部灵感库     │ • 严禁 1:1 像素级抄袭（查重、侵权）  │
│   数据量庞大（数万~数十万级）      │ • 严禁脱离内核自由发挥（丢掉爆款灵魂） │
│ • 必须精准命中用户业务领域与痛点  │ • 必须提取黄金 Hook、情绪张力与节奏  │
│ • 杜绝南辕北辙的模板推荐           │ • 注入平台地道网感，消除 AI 工业味   │
└──────────────────────────────────┴─────────────────────────────────────┘
```

## 2. 产品愿景与三阶段目标体系（Vision & Milestone OKRs）

### 2.1 整体定位
打造一套向导式（Wizard-driven）、交互卡片化（Card-based Interactive UI）、全流程工具化的**社媒病毒式内容复刻与生成流水线（Viral Replicator Pipeline）**，让任何小白用户在 3 分钟内，基于自身产品产出具有百万爆款潜力的社交媒体内容。

### 2.2 三阶段演进计划（Roadmap）

#### Phase 1：MVP 跑通与标准化交互流程定型（当前重点）
- **核心目标**：构建闭环流水线，跑通“产品画像解析 ➡️ 模板卡片推荐 ➡️ 骨架提取与填空 ➡️ 病毒性打分 ➡️ 草稿预览”的端到端体验。
- **覆盖形态**：短视频分镜脚本（TikTok/Reels）与图文轮播/推文串（X/Threads/小红书）。
- **关键指标（KR）**：
  - 单次创作全流程耗时 $\le 3$ 分钟；
  - 爆款黄金 Hook 的用户直接采纳率 $\ge 80\%$；
  - 初次生成内容的去 AI 味合格率 $\ge 90\%$。

#### Phase 2：海量数据融合与多领域扩圈（扩展期）
- **核心目标**：接入外部海量 UGC 数据库，搭建自动化 ETL 清洗与特征向量索引系统；扩展电商带货、B2B 获客、本地生活、个人 IP 等垂直领域。
- **关键突破**：支持同一模板衍生 3~5 组不同情绪维度的 A/B 变体；支持与 OmniMux 画布及 Clip 剪辑工作台联动直接出片。
- **关键指标（KR）**：
  - 模板推荐准确度（Top 3 点选率） $\ge 85\%$；
  - 外部 UGC 库沉淀优质模板 $\ge 50,000$ 篇，覆盖 20+ 细分垂直赛道。

#### Phase 3：闭环数据飞轮与全自动矩阵进化（飞轮期）
- **核心目标**：打通多平台（TikTok/X/YouTube 等）API 自动发布后的效果回流，沉淀用户私域高转化模板库，构建“抓取-解构-生成-发布-反馈-自学习”飞轮。
- **关键指标（KR）**：
  - 用户发布内容的平均赞播比/互动率达行业同赛道大盘均值的 2.5 倍；
  - 形成用户专属的个性化爆款风格档案（Voice Profile）。

```

          ▼
```

### 5.2 标准化人机协作 5 步流程（5-Step SOP Pipeline）

拒绝无序长文本对话，全流程通过**交互式卡片（Interactive Cards）**引导推进：

```
[01. 产品意图输入] ──► [02. 爆款模板召回] ──► [03. 基因解构透视] ──► [04. 爆款二次重构] ──► [05. 质检与分发]
  向导式输入/URL解析      Top 3 异构推荐卡片      透视骨架与槽位对齐      多版本变体与去AI化      Post-Grader打分+发帖
```

#### Step 01：产品画像与意图输入（Profile Ingestion）
- **界面交互**：向导式表单卡片，支持用户输入文本或直接粘贴网页链接。
- **核心输入项**：
  - `product_name`（产品或服务名称）
  - `target_audience`（目标受众，如“海外大学生”、“跨境卖家”）
  - `core_benefit`（最核心解决的一个痛点 / 一句话卖点）
  - `platform`（首发目标平台：TikTok / X / 小红书 / Instagram）
  - `goal`（核心诉求：涨粉破圈 / 信任带货 / 互动引流）
- **交付卡片**：《产品画像提炼卡》（包含提取的痛点标签与业务关键词）。

#### Step 02：爆款模板智能召回（Template Scouting）
- **界面交互**：水平滑动或网格状呈现 **Top 3 爆款候选卡片**。
- **卡片展示内容**：
  - 爆款原型标题与原片播放/互动量（如：🔥 2.4M 播放 · 85k 点赞）；
  - 核心套路类型标签（如：`痛点吐槽`、`反直觉颠覆`、`保姆级实操`）；
  - Agent 推荐理由（为什么这个模板极其适合你的产品）；
  - 交互动作：`[选用该模板]` · `[换一批]` · `[查看原片解构]`。

#### Step 03：基因解构与槽位透视（DNA Extraction）
- **界面交互**：折叠面板式呈现原片解构与业务变量映射关系。
- **展示内容**：
  - 左侧：原片分段骨架（黄金 Hook、冲突展开、价值点、CTA）；
  - 右侧：针对用户产品的注入映射方案；
  - 允许用户在这一步微调槽位内容（如修改痛点场景描述或更改行动口号）。

#### Step 04：爆款二次重构生成（Viral Synthesis）
- **界面交互**：并排或切换展示 **2~3 组不同风格的成稿草稿**：
  - *变体 A（激进痛点版）*：情绪张力拉满，语言犀利；
  - *变体 B（专业权威版）*：逻辑严密，强调数据与真实体验；
  - *变体 C（幽默生活版）*：口语化吐槽，去防备心。
- **展示规格**：
  - 短视频：分镜剧本表（含台词、视觉动作提示）；
  - 图文：标题建议（3个高CTR选项）+ 卡片文字排版 + 正文描述 + 推荐 Hashtags。

#### Step 05：前置质检与矩阵分发（Grading & Publishing）
- **界面交互**：质检体检卡与发布控制台。
- **体检维度**：
  - Hook 留存预测分（$\ge 8.5$）
  - 情绪共振指数
  - 去 AI 化纯净度（严禁存在套话）
- **发布动作**：
  - `[立即发布]`（对接平台官方 API）
  - `[加入排期]`（设置定时发布时间）
  - `[保存至我的模板库]`（沉淀私域资产）

## 6. 数据资产飞轮机制（Data Asset Flywheel）

为支撑海量数据源的不断扩展与多领域覆盖，系统建立三级数据资产协同体系：

```
                    ┌────────────────────────┐
                    │ 外部付费 UGC 海量数据池  │ (全网持续爬取/采购)
                    └───────────┬────────────┘
                                │ ETL 过滤提纯 (淘汰后90%平庸内容)
                                ▼
                    ┌────────────────────────┐
                    │  OmniMux 云端公共灵感库 │ (高潜爆款骨架，多领域覆盖)
                    └───────────┬────────────┘
                                │ 用户创作消费
                                ▼
[用户发布到真实社媒] ◄─── [二次重构内容生成]
        │
        ▼ 真实数据回流 (播放量/转赞比/评论)
┌────────────────────────────────────────────┐
│         用户私域资产库 (Local & Private)    │
│  • 经过真实市场验证的高转化专属模板        │
│  • 用户个人语气风格档案 (Voice Profile)    │
└────────────────────────────────────────────┘
```

1. **外部采集数据的自动化清洗（ETL Engine）**：
   - 外部爬取或批量采购的原始 UGC 数据，需通过清洗脚本过滤掉互动率低于大盘基准线的平庸内容；
   - 针对通过门槛的内容，调用后端解构模型，自动打标抽取其黄金 Hook、情绪曲线与抽象骨架，存入公共灵感库。
2. **私域沉淀与自学习进化（Self-Evolution）**：
   - 用户发布后，根据平台反馈的实际互动数据（完播率、互动率），系统自动对该次重构策略做成败归因；
   - 表现优异的内容自动归档为用户的“镇店模板”，后续生成同类型产品内容时权重置顶。
