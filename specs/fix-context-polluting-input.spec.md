# Spec: 彻底根除上下文污染输入框与发送拦截问题

## 1. 现状与根因分析
在现有代码 `plugins/omnimux/src/client/composer-add/AttachmentSubmitBridge.jsx` 中，老逻辑通过 `actions.setDraft(result.draft)` 强行在用户按回车或点击发送时将 `\n\n---\n### 会话关联上下文 (Attached Context): ...` 覆写回用户的输入框（草稿）。
更恶劣的是，由于检测到附件文本变更，它执行了 `return false` 并弹出通知 `'attachments.submit.synced': '素材说明已加入草稿，请检查后再次发送。'`，直接中断了用户的发送！
导致用户按回车发送时：
1. 消息发送被强行拦截，无法发出；
2. 输入框内被长篇上下文代码填满；
3. 用户界面呈现被污染、极具侵入性的体验。

## 2. 改造目标
1. **输入框草稿零污染**：用户输入什么，草稿就是什么，严禁向输入框注入任何系统拼接的上下文。
2. **零拦截顺畅发送**：用户敲回车或点击发送时，直接放行（返回 true），不再强行阻断并弹出“素材说明已加入草稿，请检查后再次发送”。
3. **原生上下文注入 (DSH Native Pre-Step Context)**：
   利用 DSH 的 `agent/pre-step` 机制，在模型推理前伴随注入标准的 context 快照消息（`role: 'user', source: { kind: 'plugin', plugin: 'omnimux-reference', form: 'snapshot' }`）。
   - 用户输入框 100% 纯净；
   - 用户消息气泡 100% 纯净；
   - 模型在后台准确获得完整的本地文件指针（@path）与场景上下文（卖点/参数）。

## 3. 验收标准
1. 用户挂载附件后，输入文字按回车，消息直接一次性顺畅发出，绝不被拦截；
2. 输入框草稿绝对不出现 `### 会话关联上下文` 文本；
3. 提示栏绝对不再弹出“素材说明已加入草稿，请检查后再次发送”；
4. 跑通单元测试与端到端回归。
