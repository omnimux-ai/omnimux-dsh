# 中枢模型检索面板 · 打开即实时规格 (Model Console Live Spec)

- 任务工作树：`.worktrees/model-console-live`（分支 `agent/model-console-live`，基线 `origin/main` @ `035d3e920`）
- 日期：2026-09-16
- 需求来源：用户「做成打开的时候实时更新」。

## 1. 背景与问题

PR #2054 已交付静态面板 `docs/tools/model-console.html`：数据由生成器从真实配置现算，但产物是**生成那一刻的冻结快照**；配置变更后页面不会自己更新，必须重跑生成器。

用户要求「打开的时候实时更新」。技术约束：
- 浏览器对 `file://` 协议的静态页面禁止用脚本读取本地文件（同源与安全限制），因此纯静态文件无法在打开时读取仓库配置。
- 要实现「打开即实时」，必须由一个本地进程在每次请求时重新读取真实配置并渲染页面。

## 2. 目标

1. 新增本地只读 HTTP 服务：每次请求 `/` 时**实时**从三处真源重新读取并渲染页面，响应头禁用缓存，确保刷新即最新。
2. 复用既有渲染逻辑（不复制第二份页面模板），把生成器重构为「可导入的渲染函数 + 可执行的 CLI」。
3. 页面顶部显示**实时状态条**：标明数据为实时读取、并显示本次渲染时刻与数据指纹，用户一眼可辨页面是否最新。
4. 服务只读本地回环地址（`127.0.0.1`），不监听外网，不写任何文件。

## 3. 验收标准（可测试）

- **AC-1（实时性）**：连续两次请求 `/`，若配置未变，两次的数据指纹一致；若在两次请求之间修改任一真源（模型契约 / 线路分组 / 上处置规则），第二次请求返回的数据指纹与统计值随之变化。
- **AC-2（渲染复用）**：服务与 CLI 使用同一渲染函数；`docs/tools/model-console.html` 与服务的响应正文在相同配置下内容一致（除实时状态条差异）。
- **AC-3（无缓存）**：响应包含 `Cache-Control: no-store`，浏览器刷新不会命中缓存。
- **AC-4（只读本机）**：服务绑定 `127.0.0.1`，不写任何文件，不向外网发起请求。
- **AC-5（页面标识）**：页面顶部明确标注「实时读取」，并显示本次渲染时刻；静态产物则标注生成时刻。
- **AC-6（URL 稳定）**：默认端口固定，URL 形如 `http://127.0.0.1:<port>/`，重复打开均为最新数据。

## 4. 交付形态

- 重构：`scripts/generate-model-console.mjs` 导出 `renderConsoleHtml()` 与 `collectConsoleData()`，原 CLI 行为保持不变。
- 新增：`scripts/serve-model-console.mjs`（零依赖，Node 内置 `node:http`）。
- npm 入口：`pnpm models:console`（生成静态产物）、`pnpm models:console:serve`（启动实时服务）。

## 5. 不做事项

- 不引入任何第三方依赖（Express / ws / 打包器均不引入）。
- 不监听 `0.0.0.0`，不做端口转发，不暴露到局域网。
- 不改动模型契约与线路分组数据本身。
