# BeefTV 三维导演台迁移需求与真实验收规格

## 1. 目标与本轮边界

把 BeefTV 已实现的三维导演功能迁入 OmniMux 现有画布，走通“导演节点 → 摆放人物道具 → 姿态与机位 → 动画/运镜预演 → 保存重开 → 构图图与可播放白膜参考视频 → 现有生成/剪辑消费”的完整旅程。白膜为无纹理人偶镜头参考，不承诺最终人物外观或精确视频复刻。

研究阶段已完成。用户于2026-10-14明确要求“立即实施”，任务 #3289 进入隔离实施、相关检查、真实验收和普通PR/MQ/开发交付阶段，沿用自主决策授权；生产、跨仓、付费视频及资金边界不变。研究文档定义验收，不代表验收已通过。执行目标见[目标文档](../docs/specs/2026-10-14-beeftv-director-goal.md)。实施工作树保持原研究路径，分支为 agent/workflow-beeftv-director-issue-3289，当前已刷新基线 f3876a31bc126e41d3033ea7a11846afc214088d；所有变更/证据绑定实施实际身份。必要新任务测试按精确路径人工例外新增，既有保护测试不放宽。

本功能为角色视频创作的专用镜头预演，不另建通用三维平台，不改[MVP范围](../docs/contracts/mvp-scope.md)或[产品定位](../docs/contracts/product-positioning.md)。迁移功能等效，UI适配本产品，不逐像素复制品牌。以下必选功能完整覆盖，首个小闭环不等于整套完成。

## 2. 研究基线、来源与明确排除

源提交 `5e2ad6022addd387001d08a478e3316ee2266524`，来源 glanderness/BeefTV。目标研究基线 `911cb74a60b7dd7d63fd56328b75ae47c0c5e5fb`；实施前刷新远端并核对漂移。开发机源仓只为只读研究，不得成为产品默认路径。

证据：[源功能核对](../.agent-reports/beeftv-director/source-features.md)、[目标承接核对](../.agent-reports/beeftv-director/target-integration.md)、[父级补证与验收准备](../.agent-reports/beeftv-director/verification-readiness.md)。证据为静态研究，不是功能运行通过。

- 保留 Three.js、React Three Fiber、Drei 和 three-stdlib 上的场景数学、姿态、轨迹、视口和捕获实现；替换原账户/配置/上传/任务/状态及外层UI，不搬整仓后台和桌面壳。
- 源代码 MIT，实质复制随包保留版权与许可。父级已读男女 Quaternius 随仓许可：免费 Standard 包声明 CC0，未含付费 Source 包。逐项审查实际采用依赖与资产，不用根MIT代替素材许可；独立许可文件不能依赖打包保留注释。
- 源文字自动搭场入口禁用，不列已开放迁移能力。识图只生成标准人偶/方盒站位，不是三维重建；提示12与解析前16候选有差异。目标统一为最多16候选，提示/校验一致，无可靠主体显示无结果，不冒充成功。
- 识图替换只替对象并解除已删除目标的机位绑定、清分组，不重置所有机位/全景，文案必须准确。
- 深度/法线有视口实现，但源画布仅上传构图图/白膜视频；必选迁移为查看，不默认新增独立深度/法线文件出口。
- 源关闭flush只排本机持久化队列，不单独等待后端项目保存；目标要求主机写盘回执及恢复验证。
- 源详细高级时间轴分支被 compact/preview 布尔关系排除，不能宣传隐藏骨骼子轨UI已迁入。保留实际可达时间轴与骨骼数据/播放内核，差异明确记录。

排除：一句话自动完整建场、照片真实三维重建、任意上传模型自动绑骨、付费三维资产、LibTV私有服务/账户、源全部后台、通用建模雕刻/物理景深、无证据的帧序列导出、自动发布。光学字段不代表物理效果；本地白膜录制不等于付费视频模型生成。

## 3. 用户故事与完整范围

新用户安装登录后，无源仓和模型密钥仍能本地建场、编辑、保存、截图/录制。编辑描述不自动生成；关闭只更新原节点封面；显式导出创建/更新受管输出媒体。智能辅助缺能力不禁用本地导演功能。

| 编号 | 必选功能组 | 要求 |

| F02 | 场景管理 | 搜索、多选、分组/解组、复制删除、显隐锁定、聚焦、撤销重做；输入快捷键不误删 |

| F04 | 人物道具 | 内置免费男女、源体型/几何人偶、群众阵列、几何物体；体型变形不冒充新精细资产 |
| F05 | 姿态骨骼 | 姿势预设、身体四肢头手指调节、骨骼选择、重置与历史；不可靠模型不给假人体编辑 |

## 4. 承接方案与项目结构

采用 `omnimux-workflow` 专用导演节点 + 按需编辑器。遵循[Workbench](../docs/contracts/workbench-split.md)、[输入合同](../docs/contracts/node-input-submission.md)、[项目资产](../docs/contracts/project-assets-contract.md)、[中枢](../docs/contracts/hub.md)。

| 归属 | 责任 |
|---|---|
| workflow `src/shared/` | 独立导演类型/schema/版本、NodeSpec与输出引用 |
| workflow `src/canvas/director/`（拟） | 编辑器、数学/姿态/轨迹、WebGL捕获与生命周期；不在普通画布首屏加载重包 |
| workflow `src/workflow/` | 主机保存/权限/三维文件导入/导出登记/Agent动作 |
| 既有bridge和素材供给 | 优先投影为既有image/video素材节点，明确outputId/来源修订；不扩大全局媒体类别 |
| `plugins/omnimux/` | 仅确有缺口的视觉理解/生图/任务接缝；账户密钥与提供方调用只属中枢 |
| assets/clip公开服务 | 交接受管媒体，不跨导入私有three/store/vendor，不替换OpenReel |
| 任务测试与证据 | 最小修复私有装配、包身份与WebGL前检；功能旅程、实际媒体、截图与结果 |

目标通用快照宽校验data/type不是导演schema；必须主机独立校验。普通导入不支持三维文件，新增受限三维资源接入，不能关闭全局白名单或把模型伪装图片。现有单材料类型投影不能自动支持多出口，优先通过明确图像/视频输出节点复用，若直连多端口须完整实现输出选择和消费绑定。

已有画布React19隔离树，宿主React18仅传DOM/普通数据/回调。导演处于画布树，不跨树交换组件/refs/context；依赖受管锁定并验证兼容，不搬源Ant Design/Tailwind全套。外层遵循[design](../design.md)、[UI指南](../docs/contracts/ui-design-guidelines.md)、[文案](../docs/contracts/ui-copywriting-and-naming-standards.md)。

### 数据与安全

只设一个主机权威场景；P0以代表场景体积及既有锁/合并实验，选节点内嵌或项目相对文档一个布局，不同时双权威。明确项目/节点/场景修订/画布版本，保存写盘回读；409保留未确认编辑，失败不显示已保存或覆盖旧封面。

模型贴图、全景、截图视频受管复制与相对引用，不持久化blob URL或开发绝对路径；GLTF配套拒绝穿越/符号链接越界/私网/任意远端URL，限制大小和解析资源。导出暂存→实际解码持久化→提交引用，失败保留旧成果，迟到回写复核身份和修订。

全图执行不隐式触发录制/AI消费；显式操作才输出/生成。只清任务自有无引用临时文件，不删原素材。Agent至少读、建/编辑、保存、导出/状态查询，同UI权限/schema/版本，不提供任意脚本和路径写。

WebGL/录制缺能力明确失败，不黑屏假绿；视觉能力按消费场景经中枢路由，聊天模型不支持图片不禁其他渠道。输入图/模型均为不可信数据。

## 5. 测试策略与真实验收

### 前置安全与环境

现有完整应用装配读取Dev配置/profile且软链共享media/projects/exports，与[QA合同](../docs/contracts/plugin-qa.md)不一致。先修任务私有配置、项目、媒体、凭据与可写路径，正式打包安装任务插件，不依赖已有Dev业务数据。未修之前不执行导演写入测试；这是本任务必要前置，不做全仓无关整治。

正式验证为完整应用正常登录/项目入口，不是独立演示页、Stage夹具或仅核心应用。真实浏览器优先ego，现场记WebGL/context/renderer与实际像素；运行器含disable-gpu参数不能代替实测判定。软件渲染只证功能，不证硬件性能。不要替代当前GUI或操作共享45120实例。

本地白膜录制不调用视频模型。真实识图/全景生图仅用已授权渠道凭据并保存脱敏实际任务/文件证据；缺前提记待实测，模拟不冒充。付费视频模型另须任务级批准和预算。普通插件无需桌面验收，原生行为引入则追加真实Electron证据；人工Dev检查独立记录。

### 全部子功能的可追溯覆盖

实施P0建立F01–F12每个子功能的逐项覆盖账本：实际入口、源代码/源运行证据、目标操作、预期外部结果、runId/截图/文件证据、状态。A01–A12是旅程组，不替代子项；每个姿势/体型/机位/路径预设、导入形式、控件和画幅至少有代表操作与恢复证明，缺项不按组绿灯掩盖。

A10“四模式”专指摆场/姿态/动画/摄影机，另逐项验证美化/白膜/姿态/深度/法线五种渲染视图的实际像素与模式准入。A07/A08还需验证截图历史选取/删除与重开恢复、多个镜头切换和各自输出、重复导出保留正确来源修订。A12逐项验证Agent读取、创建、编辑、保存、导出、状态查询及无权限/版本冲突，不能只做一次工具调用。

智能辅助真实验收须另列任务私有渠道装配方案。现行完整应用live装配只规定单个DeepSeek凭据，不假设它自动提供视觉理解和生图；需要在中枢公开配置/凭据注入边界内单独装配已获准的视觉和图像消费场景。禁止复制整个Dev profile/凭据文件或读Prod。配置无合规可行路径则A11真实子项明确未验收，继续其他独立工作，不用模拟补绿、不扩大视频权限。

视频独立播放器与解码验证，不用成功文字或非零文件当通过；webm/mp4实际格式如实，不改扩展名伪转码。30fps是录制请求，不把实时录制当确定性逐帧离屏输出。性能测同设备场景基线，未测不承诺秒开/固定帧率。

证据包括runId、源目标版本/实际包身份、脏状态、动态URL/端口/进程、任务空间、隔离证明、逐项结果与失败/skip原因、可解码PNG/媒体指纹、时间/清理回执；不落密钥/完整登录URL。所有必选功能与必要证据齐全才算“完整迁移验收”，源码/单测/HTTP200/CI/源项目测试不替代目标运行。
