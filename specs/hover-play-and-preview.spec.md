# 资产中心所有可播放资产悬停直接播放与点击保持放大预览规格 (Issue #2019)

## 1. 业务背景
用户在资产中心浏览实景数字人（视频）及其他带试听媒体的资产时反馈：
1. **实景数字人视频鼠标悬停无法直接播放**：鼠标移上去视频不动，体验呆板；
2. **所有支持播放的资产（视频画面、拟人角色声音等）需要统一交互规范**：
   - **鼠标悬停（Hover）**：直接触发播放预览（视频循环静音播放画面，语音卡直接播放声音试听），鼠标移走立即停止；
   - **鼠标点击（Click）**：整张卡片点击（包括缩略图在内）统一保持打开放大预览弹窗（`AssetPreviewModal`），绝不能被播放拦截导致无法查看大图大视频。

## 2. 根因分析
1. **视频无法悬停播放根因**：
   - `<video>` 声明了 `preload="none"`，并且未在挂载或准备播放时调用 `load()`。浏览器在冷启动状态下直接调用 `element.play()`，媒体引擎没有就绪元数据与缓冲数据，无法实现瞬时播放；
   - 快速划过鼠标时 `element.pause()` 打断了尚未 resolve 的 `play()` Promise，导致抛出 `AbortError` 中断；
   - 视频样式在未完全解码就绪时直接覆盖导致闪烁。
2. **点击放大预览被拦截根因**：
   - 在带播放控制的缩略图容器上（`PLAYABLE_THUMB_CLASS`），绑定了 `onClick={handlePlayClick}`，并在内部执行了 `event.stopPropagation()`；
   - 这导致用户点击缩略图时，事件被拦截并执行播放/暂停，无法冒泡到外层卡片触发 `openPreview`，破坏了直觉上的“点击卡片看大图/大视频”体验。

## 3. 改造目标
1. **视频预加载与顺畅悬停播放**：
   - 将 `<video preload="metadata">` 改为元数据预备，并在卡片挂载时准备好首帧；
   - 鼠标悬停（`hovering === true`）时调用 `element.play()`，优雅捕获并忽略中断错误；鼠标移走（`hovering === false`）时暂停并重置 `currentTime = 0`；
   - 视频真实处于播放状态时平滑淡入覆盖封面图，零黑屏零卡顿。
2. **拟人角色/音频悬停试听**：
   - 鼠标移入（`onMouseEnter`）：带音频的卡片自动触发试听播放；
   - 鼠标移出（`onMouseLeave`）：自动停止试听播放。
3. **整卡点击统一放大预览**：
   - 移除缩略图容器上的 `onClick` 冒泡拦截，点击缩略图直接触发 `openPreview` 打开放大预览；
   - 仅居中浮现的小播放按钮本身独立保留 `onClick={(e) => { e.stopPropagation(); togglePlay(); }}`，允许精准点击切换。

## 4. 验收标准（AC）
- **AC-1（视频悬停即播）**：所有视频资产（`mediaType === 'video'`）鼠标悬停在卡片上时直接开始自动循环播放，移出卡片后暂停并回到首帧。
- **AC-2（音频悬停试听）**：所有带语音/音频的卡片（`canPlay === true`），鼠标悬停时自动启动试听，移出卡片时自动停止。
- **AC-3（点击保持放大预览）**：点击卡片缩略图或标题主体任何区域，均直接打开放大预览弹窗（`AssetPreviewModal`），不被播放拦截。
- **AC-4（独立播放按钮）**：悬停时浮现的播放按钮本身点击时仅切换当前卡片的播放/暂停状态，不误触放大预览。
- **AC-5（质量门禁）**：端到端契约测试与全量单测 100% 通过。
