# 规格：合并成功后自动把改动装进开发版

- 工单：#2539
- 分支：`agent/common-auto-materialize-issue-2539`
- 涉及：`scripts/worktree.sh`、`scripts/worktree-delivery.test.mjs`、收尾规则与收尾手册

## 目标

插件改动一旦确认合并进正式版本，开发版必须自动跟上。昨天四入口面板漏装，是因为自动安装只挂在一条收尾命令上，另一条在正式版本已经拉齐时直接跳过；规则又把安装写成可做可不做。

## 成功标准

1. 合并后的收尾，只要这次改了插件，就会调用安装，目标只有开发版。
2. 删除临时工作区时，即使正式版本已经拉齐，也会补装这一次合并带进来的插件。
3. 开发版里这一处已经和正式版本一致时，不重复安装。
4. 只有文档、流程、脚本、不影响已安装运行时的测试时，不安装。
5. 正式版不写。正在开着的开发版不因此被重启；界面类改动刷新页面，其余改动等下次打开再生效。
6. 规则和收尾手册不再把开发版安装写成可做可不做。开发版打开后由人查看，这一步仍然不是交付前提。

## 边界

- 总是做：只装开发版；安装失败时留下明确提示，不把「已合并」写成「开发版已更新」。
- 先问：写正式版、重启正在使用的开发版。
- 绝不做：未合并的改动装进开发版；为了装开发版去改写或覆盖别人的未提交改动。

## 验证

`node --test scripts/worktree-delivery.test.mjs` 覆盖成功标准 1 到 4。规则改动用 `git diff --check`。
