# 媒体资产归一化与特征排重规格（Media Asset Normalization & Fingerprint Dedup）

## 1. 背景与业务痛点
用户在发送生图指令时，系统助手可能会在单轮对话内连续执行多个操作：
1. 调用生成工具（如 `image_generate`）完成绘图，生成组件在折叠框内渲染临时数据流图片（`data:image/...;base64,...`）；
2. 随后助手为向用户展示图片，又调用了文件展示工具（如 `display_file`），指向本地已落盘的图片文件，生成组件渲染出基于文件路径的静态访问链接（`/plugins/omnimux-viewer/serve?path=...`）；
3. **原补丁逻辑缺陷**：先前的消息尾部提取器仅做简单的 `<img>` 标签扫描与表面 `src` 字符串完全相等去重。由于临时 Base64 数据与文件服务链接在字符级别完全不同，导致算法误判为“生成了两张不同的图片”，最终在消息气泡底部并排展示了两个一模一样的大图卡片，严重破坏了用户体验与界面整洁度。

## 2. 核心设计原则
1. **真实资产唯一性（Single Asset Identity）**：单次生成任务产出的物理资产是唯一的，界面的不同呈现只是该资产在不同生命周期阶段（内存流、临时预览、落盘实体）的投影。
2. **规范化指纹比对（Multi-dimensional Fingerprinting）**：通过提取资产核心特征（底层文件名、几何尺寸比例、所属轮次时序上下文）进行语义级等价归一，彻底替代死板的 URL 字符比对。
3. **最优持久源选拔（Canonical Source Promotion）**：当同一资产同时存在临时 Base64 数据与本地持久化文件引用时，自动合并收敛，并优先保留可溯源、可缩放、可全屏联动的持久化文件源。

## 3. 规范化与排重算法流程
```
[Turn 节点深度扫描]
       │
       ▼
[提取所有媒体候选节点] ──> 获取 src、alt、title、所属工具上下文（Tool Call Block）
       │
       ▼
[资产指纹归一化 (Fingerprint Normalizer)]
 ├── 提取底层文件标识：从 URL 参数、alt 标签、周围文本路径中解析标准文件名（如 image-2026-09-14T...jpg）
 ├── 区分形态级别：Base64 临时数据流 vs 持久化静态/本地路由
 └── 几何与时序聚合：同轮次生成产物与展示产物自动映射
       │
       ▼
[指纹聚类排重 (Deduplicator)]
 ├── 相同文件标识 -> 视为同一资产，合并为单项
 ├── 相同 Base64 内容或同一步骤派生 -> 合并为单项
 └── 保留优先级：Persistent URL > Base64 Data URL
       │
       ▼
[最终消息尾部交付物 (Normalized Tail Card)]
 ├── 若仅有 1 个归一化资产 -> 渲染精致单图大卡片（带复制、右侧联动操作栏）
 └── 若有 N 个互不相同的资产 -> 渲染多图横向网格（Grid）
```

## 4. 自动化验收标准（Acceptance Criteria）
- **AC-1（同源多形态自动合并）**：同一轮对话中，若同时存在 `image_generate` 产出的 Base64 预览与 `display_file` 产出的本地文件预览，尾部卡片必须精准收敛为 **1 张**，严禁出现双胞胎重复。
- **AC-2（最优源保留与右侧联动）**：收敛后的单卡片必须携带持久化的文件访问路径，点击后能正确唤起右侧侧边栏媒体库并定位。
- **AC-3（真实多图不受影响）**：当一轮对话真正生成了多张不同文件名的图片时（如批量出图），排重算法必须准确识别并完整保留所有不同资产，呈现多列网格。
- **AC-4（侧边栏防抖自动展开）**：同轮次内相同资产只触发一次右侧侧边栏展开，避免重复调用或状态闪烁。
