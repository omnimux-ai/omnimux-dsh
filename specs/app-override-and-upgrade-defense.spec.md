# 规格说明：AI 应用同名覆盖发布与安装包升级防冲毁 (Issue #2802)

## 一、业务目标与价值 (Objective & Value)
- **核心目标**：实现 AI 应用在发布时的同名排他性检查与覆盖发布机制，并构建「只读底座 + 用户数据层」的分层遮蔽架构，确保客户端版本更新或安装包替换时用户的自定义应用配置 100% 安全免疫，绝不被官方出厂数据冲毁。
- **用户价值**：
  1. **零权限门槛自由定制**：所有用户均可通过「官方内置应用克隆副本 → 画布自由修改调试 → 改回原名发布」实现对内置模板的个性化定制，无需特殊管理员权限；
  2. **同名排他与安全拦截**：发布应用时系统自动检测同名冲突，通过现代 SaaS 极简对话框提示覆盖影响，防止误操作；
  3. **软件升级无损保留**：用户覆盖发布的修改写入独立持久化层，切断首页卡片点击时的盲目冲刷，彻底杜绝安装包升级导致的配置重置；
  4. **出厂设置一键还原**：对已覆盖的官方应用，在详情页顶栏提供轻量可信的「恢复默认」通道，随时可安全回退到底座原生配置。

---

## 二、用户操作旅程 (User Journey)
1. **定制起点**：用户在官方内置应用（如《手机与网页交互实机演示》）详情页点击右上角「编辑应用」，确认后创建副本工程并进入画布；
2. **画布微调**：用户自由修改提示词、模型版本或槽位参数；
3. **同名发布**：在工作流组顶栏点击「🚀 发布应用」，在基本信息中将名称保留（或改为）原名《手机与网页交互实机演示》；
4. **覆盖拦截**：点击发布时，向导检测到系统存在同名内置应用，弹出「覆盖已有应用确认」对话框；
5. **确认覆盖**：用户点击「确认覆盖」，系统复用原生应用 ID（`appId`），注入 `isUserOverridden: true` 标记并安全保存；
6. **升级免疫体验**：
   - 用户访问首页「探索模板」点击该应用卡片，系统优先呈现用户覆盖后的最新定制版本，绝不用安装包里的静态数据抹除用户修改；
   - 即使客户端升级新版本，用户的自定义版本依然完整保留；
7. **出厂还原**：若用户需要重新使用官方最初配置，在详情页点击「恢复默认」，一键清空用户层覆盖并切回官方原生出厂状态。

## 三、现代 SaaS 极简 UI 文案字典 (PM Copywriting Whitelist)

严格对标 Linear、Vercel、Apple HIG 现代科技 SaaS 标准，**零同义废话、零冗余图标、零感性营销副标题**。

### 1. 覆盖确认对话框 (Override Confirmation Dialog)
- **对话框标题**：`覆盖已有应用`
- **说明文案**：`已存在同名应用「{name}」。继续发布将覆盖原应用的所有配置与工作流，后续将优先使用当前版本。`
- **次要操作按钮**：`返回修改`
- **主要操作按钮**：`确认覆盖`

### 2. 应用详情页顶栏操作区 (AppTab Header Actions)
- **常规官方应用**：`编辑应用`（主按钮）
- **已被用户覆盖的官方应用**：
  - `编辑应用`（直接跳转所属工程画布，文案：`编辑应用`）
  - `恢复默认`（次级幽灵按钮，文案：`恢复默认`，提示：`恢复为官方初始配置`）
- **恢复默认确认对话框**：
  - **标题**：`恢复官方默认配置`
  - **说明**：`确定还原为官方出厂配置？您的本地工程与画布仍会保留，但该应用将恢复为初始参数。`
  - **取消按钮**：`取消`
  - **确认按钮**：`确认恢复`

## 四、核心架构与技术实现策略 (Architecture & Implementation)

### 1. 存储分层遮蔽模型 (Layered Shadowing)
- **只读底座层（Base Layer）**：
  - 源码/安装包内置的 `PRESET_WORKFLOW_MAP` 与 `FEATURED_APPS_CARDS`，仅作初始兜底；
- **用户覆盖层（User Override Layer）**：
  - 保存在持久化存储（`omnimux_apps_manifests` 及后端 `$HOME/.omnimux/apps/`）；
  - 标记 `isUserOverridden: true`、`baseAppId: string`；
- **运行时加载优先级**：
  - `User Override Layer > Base Layer`。

### 2. 首页卡片盲目覆写切断 (ExploreTemplatesSection.jsx)
- 打开卡片时，检查目标 `appId` 是否已存在且包含 `isUserOverridden: true`；
- 若已存在用户覆盖版本，**跳过** `manifestsMap[appId] = item.manifest` 的覆写操作，彻底杜绝安装包升级带来的状态冲毁。

### 3. 同名排他性与冲突判定 (appLibrary.js)
- `checkAppNameConflict(rawName, currentAppId, storage, builtinApps)`：
  - 严格不区分大小写与空格裁剪对比；
  - 覆盖官方预设与本地已发布两类清单；
  - 正确排除当前编辑的应用自身 `appId`。

### 4. 所有权自愈识别 (appLibrary.js)
- `isAppOwnedByUser` 识别 `isUserOverridden === true`：
  - 若已覆盖且本地存在绑定的有效项目工程，判定为用户所有（返回 `true`），直接激活源画布，不再强制弹窗二次 Fork。

## 五、验收标准 (Acceptance Criteria)

- [ ] **AC-1 同名排他性校验**：在发布向导中输入与官方应用或已有自建应用同名时，系统准确检测并阻断静默提交；
- [ ] **AC-2 极简覆盖确认弹窗**：同名时唤起覆盖确认弹窗，文案 100% 符合产品文案白名单；
- [ ] **AC-3 覆盖态发布装配**：确认覆盖后，复用原 `appId`，继承工作流与表单配置，并注入 `isUserOverridden: true`；
- [ ] **AC-4 升级防覆盖保障**：在用户覆盖官方应用后，模拟首页卡片点击，断言本地用户的自定义配置未被官方代码抹除；
- [ ] **AC-5 出厂设置一键还原**：覆盖后的应用在详情页顶栏提供「恢复默认」入口，确认后清空覆盖记录，应用恢复官方初始状态；
- [ ] **AC-6 覆盖应用直接编辑**：已被用户覆盖且本地源工程存在的应用，点击「编辑应用」直接定位到源画布工作流组，不产生冗余副本。
