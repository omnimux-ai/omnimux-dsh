# 规格 · 画布节点失败提示显示上游归因（Issue #3235）

## 用户操作旅程

1. 用户打开项目会话的「创作画布」页，画布上有一个视频素材节点。
2. 用户点该节点的「分镜表」（或「内容拆解」）操作，等待生成。
3. 该次请求被上游拒绝（例如所选渠道的模型不接受视频输入）。
4. **期望**：节点卡片进入失败态，除既有「生成失败」标签与中文摘要外，还多出一行**上游归因**：先给一句中文结论（该渠道不支持此素材类型），再给一条弱化的技术原文（上游返回的英文摘要，截断显示）。用户据此直接知道该换渠道或换素材，不必翻服务端日志。

## 期望界面反馈

- 失败卡片结构（自上而下）：状态标签「生成失败」→ 中文摘要（沿用既有文案）→ **新增：上游归因行** → 任务号 → 重试按钮。
- 归因行 = 中文结论 + 技术原文，同一行内用分隔符区分；技术原文用弱化色、单行省略号截断，不撑高卡片。
- 没有上游归因的失败（如空素材、渠道不可用）**不渲染**该行，卡片高度与现状一致。
- 归因行不参与既有错误文案的二次翻译逻辑，必须走独立字段与独立属性传递。

## 验收标准

| # | 场景 | 期望 |
| --- | --- | --- |
| A1 | 502 响应体含 `upstream.code='omnimux-invalid-request'`、`detail='tool model only accepts text and image input'` | 卡片出现归因行：中文结论「该渠道不支持此素材类型」+ 技术原文原样 |
| A2 | 502 响应体含 `upstream.code='unknown-model'` | 中文结论为「该模型未启用」，技术原文照常显示 |
| A3 | 502 响应体**不含** `upstream` | 不渲染归因行；卡片与改动前一致 |
| A4 | `upstream.code` 是未知码 | 中文结论回退为通用句，技术原文照常显示 |
| A5 | `detail` 为 200 字符长文 | 单行省略号截断，卡片高度不变 |
| A6 | 归因行渲染 | 不出现英文机器码本身；技术原文为唯一允许的非中文内容 |
| A7 | 中英双语字典 | 新增键在 zh/en 两份字典同时存在，键集合相等，英文侧无中日韩字符 |

## 硬性约束

- 归因不得与既有 `executionError` 拼串——同文件内的错误文案二次翻译会吞掉拼串内容。
- 文案风格对齐仓内既有先例（`[现象]：[技术约束]，[处置动作]。`），全中文、句末句号。
- 新增样式复用既有设计令牌与既有失败行样式，不新造视觉语言。

## 证据要求

- 单测：码→中文结论映射（含未知码回退、空输入）。
- 静态门禁：i18n 键同步测试、类型检查。
- 真机浏览器：注入带 `upstream` 的 502 夹具，导航到画布节点触发失败，截图留存归因行；同时截一张无 `upstream` 的对照图。
