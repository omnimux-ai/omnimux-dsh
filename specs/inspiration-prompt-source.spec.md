# 需求规格：云端作品分享携带内容拆解，同款提示词不再退化为原文案（Issue #2088）

## 一、目标与业务背景

灵感分享的核心价值是「分享一套能生成同款内容的提示词」。用户实机反馈：
分享链接存盘的 `prompt` 与 `description` **完全相同**，即原推文文案被原样发出，
根本没有生成任何同款提示词；分类也归到了来源平台而不是目标模型。

排查确认有**两个独立原因**，本任务修复其中的真实产品缺口，并把另一个（部署）如实报告：

- **原因一（部署，不在本任务代码范围内）**：那次分享由**尚未重启**的旧宿主进程发出
  （分享时间 22:03:34，服务该页面的主进程启动于 19:25:56，早于相关改动的物化时间）。
  宿主侧逻辑在进程启动时载入，重启后即按新行为工作。
- **原因二（本任务要修的缺口）**：**云端社区作品的拆解从未被送到发布端**。
  云端目录行自带完整拆解（`analysis.visual_breakdown` 画面描述、`analysis.hook_highlight` 开场钩子等），
  但页面交给发布端的载荷只带 `caption`，于是合成器拿不到任何拆解，
  只能退回用原文案充当「画面描述」，产出「原文案 + 一句通用后缀」。

## 二、关键用户旅程

### CUJ-1：分享云端社区作品
1. 用户在灵感社区打开任意云端作品，点「分享」→「创建链接」；
2. 页面把该作品的内容拆解（画面描述、开场钩子）一并交给发布端；
3. 发布端据画面拆解合成一套可直接驱动模型出同款内容的提示词；
4. 分享链接上展示的是**提示词**，而不是原帖文案。

### CUJ-2：分享本机作品（不得回归）
1. 用户对本机作品点「创建链接」；
2. 发布端仍以该作品自己的拆解摘要为首选画面描述，合成结果与既有行为一致。

### CUJ-3：完全没有拆解时（不得阻断）
1. 条目既无拆解也无可用文案时，仍按既有契约给出可读中文提示，不产生空提示词发布。

## 三、验收标准

- [ ] **AC-1（云端拆解上送）**：云端行存在 `analysis` 时，`shareRequestPayload` 把
      `visual_breakdown` 与 `hook_highlight` 作为拆解一并交给发布端；
- [ ] **AC-2（画面描述优先序）**：缺少 `summary` 时，合成器以 `visual_breakdown` 作为画面描述来源；
      同一段文本不得因被用于两个位置而在提示词中重复出现；
- [ ] **AC-3（本机零回归）**：本机条目仍以 `deconstruction.summary` 为首选，既有断言不变；
- [ ] **AC-4（不阻断）**：完全无拆解且无文案时仍返回空串，由调用方给出可读失败，不发布空提示词；
- [ ] **AC-5（端到端）**：云端形态的行经页面载荷 → 发布路由 → 中枢能力后，
      实际发出的提示词以画面拆解为主、不再等同原文案；本机四步进度链路不变；
- [ ] **AC-6（真实浏览器）**：任务独立工作树内以真实 Chromium 验证提示词内容与浮层行为，
      留存截图与结构化报告；全量单测与 E2E 全绿。
