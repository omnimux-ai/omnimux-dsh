# 规范：推特就地助手真实大模型实时推理与加载闭环 (Twitter Copilot Live LLM Generation)

## 1. 业务痛点与用户诉求
用户明确指出：
“不对哦 还是之前的问题 点击菜单选项立即就填写到表单了 根本就没经过流程处理 你自行去 ego 验证下 修复后 自行测试验收 能正常生成才交付给我”

原实现缺陷：
当后台 Bridge 暂未建立会话时，代码直接退回了本地字符串正则拼接模板，导致点击瞬间（0.01s）秒填入表单，没有经过大模型真实思考与调用流程。

---

## 2. 验收标准与真实处理流程

### 2.1 真实大模型推理调用 (Live LLM Engine)
- 在 Background 与 Content 之间建立完整的异步大模型调用链路：
  - 优先调用系统已配置且验证可用的大模型服务通道（兼容 OpenAI 规范的实时补全协议，如 `https://api.apikey.fun/v1` 上的 `kimi-k2.6`，或 DeepSeek 官方通道）；
  - 真正向模型发送 `systemPrompt` 与 `userMessage`；
  - 真实耗时 1~3 秒等待模型推理完毕返回结果。

### 2.2 视觉状态与等待交互 (Loading & Feedback)
- 用户点击菜单项后：
  1. 菜单立即平滑收起；
  2. 助手小幽灵图标进入**旋转加载动画**（`animation: omnimux-spin`）；
  3. 弹出轻提示：“AI 正在根据原推深度思考生成中...”；
  4. 绝不在点击瞬间瞬间完成，杜绝虚假秒填。

### 2.3 确定性输出与异常保障
- **成功生成**：
  模型返回真实文案后，模拟系统剪贴板粘贴安全注入推特富文本输入框，点亮推特官方“回复”按钮；
- **真实异常阻断**：
  若网络断开或服务端不可达，助手结束旋转，弹出明确的错误提示（“模型调用未返回有效文案，请检查网络状态”），**坚决不再使用假模板偷偷秒填覆盖**！
