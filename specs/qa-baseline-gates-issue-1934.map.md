# #1934 能力与交付地图

关联事项：#1934（父事项 #1930；解除 #1931 的主分支既有验收阻塞）

## 目标

恢复主分支现有的模块边界检查与页面打开检查，同时保留已经合入的分栏、会话优先和单一激活规则。此次只调整测试归属、受控检查模型和相应合同文字，不改账户业务行为或产品运行路径。

## 独立能力

| 能力 | 输入 | 输出 | 独立验收 |
| --- | --- | --- | --- |
| 模块边界测试归属 | 当前跨插件私有导入、浏览器源码目录中的测试专用 Node 辅助文件 | 测试辅助文件位于 Hub 测试目录；跨插件断言回到各自插件测试 | 模块边界检查无违规；各归属插件测试保持覆盖并通过 |
| 当前页面检查模型 | 官方右栏当前页签、会话可见状态、分栏焦点与会话隔离 | 受控 Host 能表达当前真实状态；断言与现行行为一致 | 页面检查、相关门禁和隔离真实浏览器旅程通过 |

两项能力可以并行实现，最终在同一 #1934 分支合并后执行完整门禁、真实浏览器验收和独立复核。

## 交付顺序

1. 先提交本地图及两份规格。
2. 两个独立工作树分别完成“模块边界测试归属”和“当前页面检查模型”。
3. 集成后执行定向检查、完整仓库门禁和真实浏览器验收。
4. 由未参与实施的 Agent 复核实际差异和证据。
5. 通过必需检查后提交 PR、进入合入队列，并在合并后清理任务工作树。

## 总边界

- 不修改账户业务代码、生产设置、凭据、发布路径或正式环境。
- 不新增模块边界豁免，不削弱或跳过检查。
- 不为测试方便新增产品运行时公开入口。
- 不回退分栏默认、会话记录优先或左栏单一激活规则。
- 开发版真机验收由人工决定；Agent 交付依据为任务工作树内的真实浏览器证据。
