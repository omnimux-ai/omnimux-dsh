# 规格说明：电商视频批量生产执行层——正交配方引擎与 DSH workflow 分镜流水线

## 一、背景与问题

1. 商家需要批量化产出差异化的电商视频素材。此前只有单次人工撰写的路径，既无法保量，也无法证明「这一条配方」对应「这一段画面」，无法做归因与回流。
2. 官方 DSH 已具备 `dsh-workflow`（`agent` / `parallel` / `pipeline` / `phase` / `log` / `args` 编排）与 `dsh-subagent` 能力，并已在 OmniMux 预设中装配，但项目内没有可复现的配方引擎与分镜脚本产出工作流。
3. 执行侧（OmniMux app）读不到开发机项目仓（macOS 按目录授权限制）。让执行侧直接读仓库脚本会让模型绕行探测，实测首跑花掉 57 步 / 6 分 25 秒 / 4.8M token 才产出配方。

## 二、验收标准与核心行为

1. **确定性配方引擎**
   - 四层正交变量：手法 / 人设 / Hook / 画面形态。
   - 同一 seed 与同一入参必须产出逐位一致的配方批（指纹含在比对范围内）。
   - 指纹唯一 + 同角色内不重样；违反时 fail loud，不静默降级。
2. **扇出工作流**
   - 每个配方启动一个隔离子代理，互不共享上下文。
   - `agent()` 只使用受支持选项（`label` / `phase` / `schema` / `provider` / `model`），传入越界选项必须立即报错。
   - 配方缺失或指纹重复时 fail loud；每次调用都带 `label`，便于进度面板辨识。
3. **离线校验器**
   - 覆盖编排逻辑 41 项，含静态与运行时双 `agent()` 选项白名单、label 齐全性、dry-run 不启动子代理、fail-loud 行为。
   - 校验器必须在没有真实运行的前提下拦住已知误用（本 Issue 前身曾漏掉 `agent()` 选项误写）。
4. **物化前置**
   - 把工作流脚本与配方物化到 `$DSH_HOME/omnimux/recipes`，执行侧一律从 DSH home 读取，不再尝试读取项目仓。
   - 物化产物带 sha256 清单，可核对版本。
5. **文档与规格**
   - 可直接复制的执行指令、排障背景手册、钩子契约说明。
   - PRD 含递进式验收里程碑（先验收分镜脚本，再验收分镜图，最后成片），不追求一步到位。

## 三、测试与验证计划

1. 离线校验器：`node scripts/workflows/verify-batch-shoot.mjs` → 41/41 通过。
2. 配方可复现：`node scripts/workflows/prepare-args.mjs` 同 seed 复现同一批指纹，与本仓既有产物逐位一致。
3. 隔离 worktree 内静态检查：`git diff --check` 与变更面相关门禁。
4. 真实运行证据（OmniMux Dev，属人工复核范畴，不由 Agent 卡点）：
   - dry-run：子代理数 0；
   - full：完成 12 个子代理、`failed=0`，12 条指纹与本地配方逐位一致。

## 四、非目标

- 前台页面与三步向导（S4）。
- 分镜图与成片生成（S2/S3）。
- 灵感库真实种子视频接入。
- 任何插件源码、manifest、模型边界或运行时契约改动。
