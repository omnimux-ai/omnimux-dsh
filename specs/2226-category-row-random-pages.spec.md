# 公共资产库分类流全库跨页随机推荐机制规格

**文件：** `specs/2226-category-row-random-pages.spec.md` ｜ **Issue：** #2226 ｜ **优先级：** P0

## 1. 业务痛点与目标
用户反馈在公共资产库“全部”视图下的单行分类流中，展示的卡片“看起来还是按时间顺序排列的”。
经排查根因：原实现固定只请求第 0 页（前 24 个素材）并在该小池子内洗牌，导致每次进入或刷新看到的面孔高度同质化（局限于早期录入的一小撮素材），无法体现全库海量素材的多样性。

本特性目标：
1. 建立全库跨页随机采样机制：根据分类元数据的总页数（`totalPages`），在全部分页范围内智能随机抽取页码；
2. 多样化混编洗牌：跨页合并素材池并执行 Fisher-Yates 算法全局打乱，呈现多元风格；
3. 保留会话防跳动缓存：单次会话内保持卡片位置稳定，仅在主动刷新或重入时重新随机；
4. 优雅降级与网络容错：当全量分页请求失败或单页数据不足时，优雅回退至第 0 页兜底。

## 2. 核心算法与接口规范
1. `fetchCategoryRandomItems(catId, options)`：
   - 探测总页数：通过第 0 页或分类元数据获取 `totalPages`；
   - 单页分类（`totalPages <= 1`）：直接使用第 0 页数据打乱；
   - 多页分类（`totalPages > 1`）：在 `[0, totalPages - 1]` 范围随机采样目标页码；
   - 风格混编：当总页数充足时，支持跨不同时间段/风格的页码抽取与去重合并。
2. 会话缓存协同：
   - 依然由 `globalShuffleCache` 保证单会话一致性；
   - 刷新信号 `refreshKey` 触发时清除缓存，重新全库随机抽样。

## 3. 验收用例表

| # | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| 1 | 多页分类随机抽样 | 多次刷新多页分类（如角色 18 页、场景 142 页） | 抽取的卡片集合覆盖不同分页，不再固定局限于第 0 页老面孔 |
| 2 | 单页分类兼容 | 分类仅有 1 页数据 | 正常展示并原地打乱，不产生非法页码请求 |
| 3 | 会话防跳动保持 | 切换标签页或浏览详情后返回 | 保持当前会话卡片顺序不变，无闪烁跳动 |
| 4 | 主动刷新重采样 | 触发刷新动作（refreshKey 变化） | 缓存重置，跨页重新随机抽取全新卡片组合 |
