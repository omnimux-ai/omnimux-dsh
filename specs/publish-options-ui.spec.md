# 3973 TikTok 发布选项布局优化

Issue: #3973 · 分支 `agent/publish-options-ui-issue-3973` · 风险等级 **R2**（发布页样式与结构）

## 背景

#3970 落地了 TikTok 发布选项，但界面直接暴露成「原生 select + 四个竖排 checkbox」，有两个问题：

1. 违反 [design.md](../../design.md) §2.4：严禁裸用原生 `<select>`（macOS/Electron 会弹系统蓝白菜单，破坏暗色主题）。
2. 视觉上是一列散装控件，与表单其他区块（标题/正文/话题/媒体）的节奏不一致，用户看不出「谁可以看」「互动设置」「商业披露」是三个层次。

## 方案

1. 隐私级别改用 `dsh-ui-kit` 的 `DropdownSelect`（32px 高、8px 圆角、毛玻璃浮层）。
2. 三个互动项由竖排 checkbox 改为一行胶囊按钮（`Button size="xs"`，开/关用 secondary/ghost + 勾选图标区分），账号侧禁用的项置灰并给出说明。
3. 商业内容保留单 checkbox；勾选后在同组内展开「你的品牌 / 付费推广」两个胶囊选项与音乐确认，不再与互动项混排。
4. 整个区块收成一张分组卡片（`bg-layer-1` 背景、`border-l1` 边框、10px 圆角、12px 内边距），标题行右侧显示一行摘要（`公开 · 可评论 · 可合拍 · 可拼接`）。
5. 位置从「媒体素材」之前挪到之后，表单顺序变成：标题 → 正文 → 话题 → 媒体 → 发布设置 → 封面。
6. 校验提示合并成一行，不再每个问题各占一行。

## 假设

- `DropdownSelect` 的浮层由官方 Menu 提供，行为与设计契约一致；不需要额外键盘处理。
- 胶囊按钮在 13px 字号、32px 高度下可容纳「允许评论 / 允许合拍 / 允许拼接」三项，窄屏自动换行。
- 摘要行只是当前状态的只读回显，不替代控件本身（TikTok UX 指引要求的隐私/互动/商业披露仍然全部可见可选择）。

## 证伪方式

- 浏览器实测：隐私下拉可展开并选中「公开」；互动胶囊点击后状态与草稿一致；商业内容展开后出现两个胶囊与音乐确认；截图确认无原生 select 样式与竖排 checkbox。
- 单测保持 300/300（控件替换不改数据契约）。
- `git grep "<select" plugins/omnimux-publish/src/client` 为空。

## 新用户基线

- 首次打开发布页即看到分组卡片与默认「仅自己可见」，无额外配置或密钥依赖。
- 未审计账号的隐私下拉仍只有「仅自己可见」（creator-info 决定）。

## 旧标准变更

- `tests/e2e/publish-tiktok-options.harness.jsx` :: `*`

该文件是浏览器验收脚本而非 node:test 用例，无法按用例名枚举。原断言围绕原生 `<select>`（`.omnimux-publish-select`）与 checkbox；控件改为 DropdownSelect 与胶囊按钮后选择器与交互步骤必须改写。新证据：同一份脚本改为打开下拉菜单点选「公开」、点击胶囊开关、断言禁用项与商业分组，9 条断言仍覆盖同样的数据契约。
