# 规范：设置面板两行模型标签简化

## 背景
侧边栏设置面板里两行模型配置的长标签「对话模型与推理等级」「文本生成模型与推理等级」在窄面板里换行、占位过多，与 UI 文案「布局自己解释、不堆副标题」的规范冲突。

## 目标
- 两行标签分别简化为「对话模型」「文本生成模型」（英文 `Chat Model` / `Text Generation Model`）。
- 推理等级仍由行内选择器自身承载，标签不再重复说明；描述行文案保持原样。
- 不改变任何设置键、持久化、空值选项（文本行仍保留「跟随对话模型」）。

## 假设
- 用户能从「对话模型 / 文本生成模型」两个标签区分两行的作用范围；推理等级控件在行内仍可见，标签删去「与推理等级」后用户不会误解该行不含推理配置。这两个断言是本改动成立的前提。
- 现有 panel 隔离测试按行标签定位选择器，标签更新后断言同步即可，不需要新增功能行为测试。

## 证伪方式
- 若改后在真实侧边栏中两行仍显示旧长文案、或选择器按新标签定位失败导致测试找不到行，则本改动未生效，判为证伪。
- 若移除「与推理等级」后行内不再出现档位选择控件或推理等级无法切换，则说明标签简化误伤了功能，判为证伪。

## 旧标准变更

- `plugins/omnimux-browser/extension/tests/panel-text-model-isolation.spec.ts` :: `两行同时存在、文案已更新，文本行带「跟随对话模型」空值选项`
  - 原断言：两行标签为「对话模型与推理等级」「文本生成模型与推理等级」，且不存在「默认模型与推理等级」。
  - 必须改的理由：本任务的核心就是缩短这两行标签，旧文案断言与新需求直接冲突。
  - 新期望证据：设置面板截图显示「对话模型」「文本生成模型」；隔离测试改用新标签定位选择器并断言旧长文案不再出现。

## 验收用例
1. 打开侧边栏设置面板 → 两行标签分别为「对话模型」「文本生成模型」；
2. 文本生成行仍含「跟随对话模型」空值选项，对话行不含空值；
3. `panel-text-model-isolation` 测试以新标签定位两行选择器并全部通过。
