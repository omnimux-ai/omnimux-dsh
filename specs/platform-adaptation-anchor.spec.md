## 1. 业务目标与改造方案

### 1.1 背景与最终形态

用户明确指正并锁定最终形态：

1. **消除双实现**：在 TikTok 页面内完全禁用 `media-hover` 的视频悬停胶囊（出现在视频左下角带幽灵标志的黑色悬浮框），避免同屏双入口混乱。
2. **按钮锚定位置**：在所有 TikTok 视频播放及推荐流页面中，**按钮位于作品右侧互动列（包含点赞、评论列）中作者头像的正上方 8px**，严禁挂在左侧导航栏。
3. **按钮形态**：**48px 圆形**，品牌淡紫底 `#b8b7ff` + 深色幽灵图案，无文字标签，且不带浏览器原生 `title` 属性（防止悬停时弹出系统黑色气泡遮挡操作菜单）。
4. **交互与菜单**：**鼠标悬停展开菜单、移开收起**；菜单项采用**左图标、右文字**的左右排布格式（`flex-direction: row`，单行无折行）；菜单方向自适应（默认靠右，右侧空间不足自动翻至左侧）。

### 1.2 根因：头像识别失败，退回了硬编码兜底

线上现象是图标出现在兜底坐标，而不是任一布局的正确位置。真机实测（`evidence/live-probe.md`）给出了两条布局下的选择器命中真相：

| 选择器 | 桌面布局 | 竖向布局 | 结论 |
| --- | --- | --- | --- |
| `[data-e2e="nav-user-avatar"]` | **0** | **0** | 具名 hook 实际上是空的 |
| `[data-e2e="nav-profile"] img` | **1**：32×32 @ left=20, top=472 | **0** | 桌面左栏头像唯一可用信号 |
| `[data-e2e="nav-bar"]` / `nav[role="navigation"]` / `nav` | 0 | `nav` **1**：168×28 @ left=131（顶部标签栏） | 横向标签栏不是侧栏 |
| `aside` | 1 但 **0×929 @ left=1920**（视口外，不可用） | 0 | 0 宽容器不是侧栏 |

即：**两种布局下都不能指望具名 hook 单独解决问题**——桌面只有 `nav-profile img` 可用，竖向布局则全部落空，必须靠**受几何谓词约束的结构扫描**找到右侧操作栏里的头像。

### 1.3 技术方案要点

- **TikTok 推荐流作品操作栏识别（关键增强）**：
  在 TikTok 推荐流（For You、Explore 等）中，作者头像并不在传统全局导航栏，而是随每个视频垂直卡片右侧的动作条（`section[class*="SectionActionBarContainer"]` 或含 `[data-e2e="like-icon"]` 的操作栏）一起呈现。
  `findActiveFeedAvatar` 优先拾取当前视口内可见、距离视口中心最近的卡片操作栏内第一项（`[data-e2e="video-author-avatar"]`、`[class*="ActionItemPlaceHolder"]` 或头像图片），使 OmniMux 触发器精准坐落在作品右侧操作栏作者头像上方 8px，彻底消除掉落左下角兜底位置的缺陷。
- `src/platform/registry.ts`：平台配置承载点保持不变（纯数据 + 纯函数，可被 background 导入）。TikTok 场景链改为**头像优先**，兜底按「是否认出了侧栏」分派。
- `src/platform/anchor.ts`：删除沉浸式分支与视频基准；`AnchorLayout` 收敛为 `'side-rail' | 'unknown'`；新增侧栏几何谓词（**贴左缘或贴右缘**）+ 头像结构扫描。
- `src/platform/video.ts`：**删除**（只服务于已删除的沉浸式分支）。
- `src/content/tiktok-scene/menu-side.ts`：菜单方向判定（纯函数，可单测）。
- `src/content/tiktok-scene/{menu.ts,styles.css,copy.ts}`：横向菜单、垂直居中、方向落地，文案收敛为短标签。

## 2. 验收标准（Acceptance Criteria）

### 2.1 头像锚点 (P0)

- **AC-101**：找到头像时，图标的左边缘等于头像左边缘（容差 ±1px）；图标下边缘等于「视口高度 − 头像上边缘 + 8px」（容差 ±1px）。
- **AC-102**：桌面布局下由具名 hook `[data-e2e="nav-profile"] img`（实测 32×32 @ left=20, top=472）命中的左栏头像，图标贴其正上方（`left=20`，`bottom=视口高−472+8`）。
- **AC-103**：竖向布局下右侧操作栏内的头像被识别，图标贴该头像正上方，**不落到任何硬编码兜底坐标**。
- **AC-104**：找不到头像时的兜底与改造前逐值一致——认出侧栏 → `{left: 16, bottom: 96}`；什么都没认出 → `{left: 12, bottom: 88}`。
- **AC-105**：代码中**不存在**「以视频包围盒左下角为基准」的分支，也不存在按视口左下角对齐的沉浸式分支；`src/platform/video.ts` 及其用例被删除。

### 2.2 头像识别 (P0)

- **AC-201**：具名 hook 优先（`[data-e2e="nav-user-avatar"]` → `[data-e2e="nav-profile"] img` → `a[href^="/@"] [data-e2e="nav-user-avatar"]`），命中即可用，不做尺寸二次筛选。
- **AC-202**：hook 全落空时做结构扫描，扫描**限定在通过几何谓词的侧栏容器内**：`width > 0 && height > 0`、`height > width`、宽度不超过视口宽度的 50%、**贴左缘或贴右缘**（与视口左/右边缘的距离不超过视口宽度的 8%）。
- **AC-203**：`nav` 为 168×28 的顶部横向标签栏时，**不得**被当作侧栏；其中的图片不得被当作头像。
- **AC-204**：`aside` 宽度为 0（实测 0×929 @ left=1920）时不可用，不得作为头像扫描的容器。
- **AC-205**：结构扫描内的近似方形图片判定沿用现状：最短边 `≥ 24px`，长宽差不大于较长边的 20%。
- **AC-206**：视频封面等大图**不得**被误判为头像——结构扫描内的候选图片另有上界（`≤ 128px`），超出即排除；hook 命中的图片不受此上界限制。
- **AC-207**：页面上同时存在视频与侧栏时，判定结果与视频选取逻辑无关（锚点不再读取 `<video>`）。

### 2.3 形态与悬停交互 (P0)

- **AC-301**：图标为圆形——`border-radius: 50%`，直径 `48px`（宽高均为 48，容差 ±1px）。
- **AC-302**：图标**不含文字标签**。
- **AC-303**：默认态菜单不可见（`visibility: hidden` 或 `opacity: 0`）且不可被点击命中；鼠标进入图标或其容器后 `200ms` 内变为可见；移开后恢复不可见。
- **AC-304**：菜单三项，顺序为 下载视频 / 保存原声 / 收藏到灵感库；每项**图标在上、文字在下**，三项横向排成一行。
- **AC-305**：菜单与按钮**垂直居中**：`top: 50%` + `transform: translateY(-50%)`，`-50%` 在展开态仍然保留。
- **AC-306**：`prefers-reduced-motion: reduce` 时关闭过渡动画，功能不受影响。
- **AC-307**：触屏点按（无悬停）仍可展开/收起；键盘聚焦可展开，移走焦点收起。

### 2.4 菜单方向自适应 (P0)

- **AC-401**：默认在按钮**右侧**展开：菜单左边缘 = 按钮右边缘（视口坐标）。
- **AC-402**：按钮右侧空间不足时**自动翻到左侧**展开：菜单左边缘 = 按钮左边缘 − 菜单宽度。
- **AC-403**：判定依据是**菜单渲染后的实际宽度**（`getBoundingClientRect().width`）+ **按钮中心到视口右缘的距离**；不得使用「固定阈值/魔数」代替几何测量。
- **AC-404**：必须做**双向几何校验**——右侧候选位与左侧候选位都按实际几何核对（右：`菜单左 + 菜单宽 ≤ 视口宽`；左：`菜单左 ≥ 0`），按首选方向落位；首选方向放不下时切换到另一侧。
- **AC-405**：无论选哪一侧，菜单**不得超出视口**（左边缘 `≥ 0`，右边缘 `≤ 视口宽度`）。

### 2.5 既有行为保持 (P0)

- **AC-501**：X（推特）上浮标坐标逐像素不变——`tests/fab-twitter-style.spec.ts` 锁定的 `1845px` / `728px` 断言保持通过。
- **AC-502**：`tests/platform-marks.spec.ts` 与 `tests/page-sensor.spec.ts` 保持全绿。
- **AC-503**：`src/platform/registry.ts` 的平台配置承载点（条目字段、`platformForHost` / `platformById` / `detectPageType` / `anchorChainFor`）与其用例保留，不删不改语义。
- **AC-504**：TikTok 快捷动作的**执行链路与结果**不变（三个动作仍走既有 transport 与 background 导出路径）；仅入口形态与展开方式改变。

### 2.6 可扩展性 (P1)

- **AC-601**：新增一个平台的锚点配置，只需在 `registry.ts` 追加一条数据，不修改锚点解析实现。

### 2.7 回归基线 (P0)

- **AC-701**：`pnpm --filter dsh-browser-extension test` 全量套件失败数 ≤ 1，且唯一失败仍为既有 `tests/tool-activity-card.spec.ts:223`（缺历史证据文件，与本改动无关）。
- **AC-702**：断言「沉浸式 → 视频左下角」的用例全部改写为「紧贴头像上方」。
- **AC-703**：新增用例覆盖：①桌面 hook 命中 `nav-profile img`；②`nav` 为 168×28 顶部标签栏时不得当作侧栏；③`aside` 为 0 宽时不可用；④hook 全落空但侧栏内存在 96×96 方形头像时贴其上方；⑤竖向布局右侧操作栏头像被正确识别；⑥菜单默认靠右；⑦右侧空间不足时翻左且不超出视口。

## 3. 关键用户旅程与验证步骤

### 3.1 旅程 A：竖向布局 TikTok 推荐页

1. 以竖屏视口打开 TikTok 推荐页（无左侧导航栏，右侧为竖排操作栏）。
2. 等待内容脚本注入，图标挂载完成。
3. **预期视觉结果**：右侧操作栏内**用户头像的正上方 `8px`**出现 48px 圆形图标（淡紫底 + 深色幽灵，无文字），菜单不可见。
4. 将鼠标移到圆形图标上。
5. **预期视觉结果**：菜单在按钮**右侧**横向展开，三项图标在上、文字在下；菜单与按钮垂直居中对齐；展开过程有轻微位移与淡入。
6. **预期视觉结果**（按钮贴右缘时）：右侧放不下时菜单**自动翻到按钮左侧**展开，且整块菜单不超出视口。
7. 将鼠标移开；菜单收起。
8. 向下滚动切换视频：图标跟随当前头像重新锚定，不出现停留在上一位置或跑到屏幕外。

### 3.2 旅程 B：桌面 TikTok 首页（左侧导航栏）

1. 在桌面视口打开 TikTok 首页，页面保留左侧导航栏。
2. **预期视觉结果**：图标仍贴左栏底部头像正上方，间距 `8px`（挂钩子命中 `[data-e2e="nav-profile"] img`）。
3. 页面认不出头像时：图标停在左栏底部停车位 `{left: 16, bottom: 96}`，不会消失；完全认不出布局时停在 `{left: 12, bottom: 88}`。

### 3.3 旅程 C：X（推特）浮标位置（零回归）

1. 在 X 打开任意时间线页面。
2. **预期视觉结果**：浮标位置与改造前完全一致（与 Grok / Chat 抽屉浮标纵向成列，间距 12px）。

## 4. 非目标

- 不合并 FAB 与场景触发器的交互模型（仅共享锚点层、分槽位）。
- 不新增第三方依赖。
- 不改造 TikTok 三个快捷动作的执行链路与后端导出能力。
- 不为「视频左下角」保留任何形态（该方向已被用户明确撤销）。
- 不触碰已登录态以外的 TikTok 页面形态（视频详情页、剧场模式按既有行为保持，不作为验收前置）。

## 5. 已知待确认项

- `LEFT_EDGE_FRACTION = 0.08`、`MAX_RAIL_WIDTH_FRACTION = 0.5` 为推断常量（真机未直接测到侧栏容器本身），已隔离在两个具名常量内，替换成本为改两行。
- 结构扫描的深度与元素数上限（`STRUCTURAL_SCAN_DEPTH` / `STRUCTURAL_SCAN_LIMIT`）是性能界，不是几何判据：只在具名容器全部落空时才启用。
- 竖向布局右侧操作栏的容器在真机实测中未被任何选择器命中（`aside` 0 命中），本次以几何谓词覆盖；已登录态下的容器语义仍需后续真机复核。
- 菜单方向的真机观感（翻左时的位移方向）未在真实浏览器复核，本次以单测锁定几何。
