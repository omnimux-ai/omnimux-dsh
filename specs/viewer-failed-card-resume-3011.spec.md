# 媒体查看器：失败任务原位提示 + 重试，生成中任务刷新续传（Issue #3011）

## 背景
用户 2026-10-03 拍板，推翻旧口径「查看器内不放失败提示/恢复入口，异常只走主会话」。
现状：失败只标 failed 不存原因；缩略图栏过滤掉失败项；失败后自动切走；只弹一次原始英文 toast；生成中任务不持久化，刷新即丢。

## 新用户基线
依赖已配置的 OmniMux 官方 API 密钥；缺失时卡片原样透传服务端中文凭证提示，不新增其它依赖。

## 用户旅程
1. 在媒体查看器提交图像生成 → 主画布原位出现生成中卡片，缩略图栏出现生成中方块。
2. 生成服务异常 → 该卡片原位变为失败卡：一行原因 +「重试」；缩略图栏该项变为静态失败方块（title「生成失败」）；不切走、不弹 toast。
3. 点「重试」→ 按钮置灰，提交成功后原位置恢复生成中卡片，完成后原位出图。
4. 生成中刷新页面 → 卡片显示「正在恢复任务」，按服务端任务记录续传：完成出图、失败显示原因、仍在生成继续等待。

## 文案白名单（PM 核定，逐字）
- 失败卡仅含：原因（≤2 行，溢出省略，title 全文）+ 按钮「重试」。禁止标题、图标、错误码、原始英文、HTML、时间戳、其它按钮。
- 原因映射：
  - 网关/网络（5xx、522、超时、连接失败、HTML 响应）→「生成服务暂时不可用，请稍后重试」
  - 服务端中文原因（含中文且无 HTML 标签）→ 原样透传
  - 其它未知 →「生成失败，请稍后重试」
  - 刷新后无法续上 →「任务已中断，请重新提交」（隐藏重试）
- 重试：提交返回前置灰不改字；不可重试时隐藏。
- 缩略图失败项：静态弱化错误色纯色块，无文字无图标，title「生成失败」。
- 续传状态行：「正在恢复任务」。
- 失败不再弹 toast。

## 验收
- A1 失败原因映射四类全部命中白名单原文。
- A2 失败任务保留在缩略图栏，activeId 不被切走。
- A3 失败卡含原因 + 重试；点重试以同参数重新提交并原位恢复生成中。
- A4 生成中任务（含 requestKey/taskRef/提交参数）随存储持久化；刷新后续传：完成→出图，失败→原因，记录缺失→「任务已中断，请重新提交」。
- A5 直连提交走异步（wait:false），服务端提交前落账本并返回 taskRef；取回接口按 taskRef 轮询直至完成或失败。
- A6 真实界面：网关异常失败卡截图 + 刷新续传出图截图。

## 不在范围
删除/关闭失败任务、批量重试、错误详情面板。
