# 规格：创作画布「默认生成模式」与新建节点素材卡槽

- Issue: #2003
- 类型：界面 + 行为
- 状态：待实现

## 1. 背景与问题

创作画布的视频 / 图片生成节点新建后，默认停在「不消费素材」的生成模式（文生视频 / 文生图）。按现行判定规则，这类模式在模型契约中没有可绑定的媒体输入槽，素材卡槽区整块不渲染（无 DOM、无占位、无提示）。

后果：用户从上游连入图片后，节点面板看不到任何装填入口，也没有任何说明；素材虽按合同保留在供给池，却既不入卡槽也不随请求发送。用户只能自行发现「要把模式切成首帧 / 垫图参考」才会出现卡槽。

文本节点此前通过一条专属自适应通路（#1899 / #1903 / #1913 / #1915）绕开了该问题，视频 / 图片 / 音频三类节点从未覆盖，因此问题反复复发。

根因调查报告：`.agent-reports/slot-missing/A-root-cause.md`（含离线内核复现脚本与逐模式实测输出）。

## 2. 目标

在设置页「创作画布默认模型」中新增「默认生成模式」配置，使新建节点默认即处于带素材卡槽的模式；用户无需先理解模式与卡槽的关系。

## 3. 用户操作旅程

| # | 旅程 | 期望界面反馈 |
| --- | --- | --- |
| J1 | 打开 设置 → 插件 → 创作画布默认模型 | 视频、图片两项下方各出现一个「默认生成模式」下拉，默认值分别为「全能参考」「垫图参考」 |
| J2 | 展开视频默认生成模式下拉 | 选项来自当前所选视频模型的可用模式（MiniMax H3 下为：全能参考 / 首帧 / 尾帧 / 首尾帧 / 文生视频） |
| J3 | 切换视频默认模型为 Seedance 2.5 | 模式下拉选项随之刷新为 Seedance 2.5 的可用模式；已配置的模式若在新模型下不存在，回退到该模型第一个模式并如实显示 |
| J4 | 点击「恢复默认」 | 该行回到回退链算出的默认值（视频：全能参考；图片：垫图参考） |
| J5 | 回到画布新建一个视频节点 | 节点默认选中「全能参考」，提示词框上方渲染出参考图 / 参考视频 / 参考音频卡槽，可直接装填 |
| J6 | 新建一个图片节点 | 节点默认选中「垫图参考」，渲染出参考图卡槽 |
| J7 | 新建一个文本节点 | 行为不变：自动落到图文对话，渲染出多模态卡槽 |
| J8 | 打开一个此前保存的旧工程 | 已保存节点的模型与模式不被改写，界面与保存时一致 |

## 4. 验收标准

- AC-1：设置页视频、图片两项各新增一个「默认生成模式」下拉；未显式配置时显示回退链算出的值，并可通过「恢复默认」回到该值。
- AC-2：模式下拉的选项集合来自所选模型在该输出类型下的已上架模式，不含未上架模式；切换模型后选项即时刷新。
- AC-3：新建视频节点默认选中「全能参考」，卡槽区渲染（`[data-testid="wf-slot-wells"]` 存在且 `data-preset` 非 none），槽位含参考图 / 参考视频 / 参考音频。
- AC-4：图片侧配置项与回退链就绪：一旦该输出类型存在已上架的媒体消费模式，默认模式必须选中它；在此之前不得选中任何未上架模式（见 §8 已知限制）。
- AC-5：回退链生效：首选模型缺少目标模式时，降级到次选模型的目标模式；次选也没有时，降级到该模型第一个模式。任何情况下不得出现空模式或未上架模式。
- AC-6：既有工程图不被改写：加载旧工作区后节点保存的模型 / 模式保持原值，设置项不产生隐式覆盖。
- AC-7：未配置默认模式时，行为等价于「回退链默认值」，不因缺少配置而报错或空模式。

## 5. 非目标

- 音频节点：本次不新增配置项、不改行为（当前音频模型仅「文字转语音」一个模式，且该模式被定义为不接收参考音频）。
- 不新增「思考档位」设置项（宿主层已有该能力，画布本次不暴露）。
- 不改写模型契约数据与画布模型白名单。
- 不引入新的自动切换模式行为（不因连线自动改写用户已保存的模式）。

## 6. 测试计划

- 单元 / 契约测试：回退链解析（首选有目标模式 / 首选无目标模式 / 均无目标模式 / 模型不存在 / 模式未上架），配置读写与「恢复默认」。
- 端到端：新建视频节点与图片节点后卡槽区渲染断言；设置页新增下拉的存在性与联动。
- 真实浏览器预演：隔离工作树内跑，产出 PNG 证据。

## 7. 风险

- 默认模式影响新建节点，属于行为变更；对既有工程图必须只读不改（AC-6 覆盖）。
- 模式下拉依赖模型目录的模式列表；目录不可用时需退化为不可编辑并显示原因，而不是静默空列表。

## 8. 已知限制（实现期间实测发现）

**图片侧当前无法显示卡槽，原因是模型契约而非本功能。**

`plugins/omnimux/src/catalog/specs/image-models.yaml` 中 `gpt-image-2.5` 的 `multi_reference`（垫图参考）为：

- `research.status: "draft"`（未通过官方文档核验）
- `implementation.status: "ready"`
- `execution.status: "stub"`

按 `computeOperationListed`（`plugins/omnimux/src/catalog/contract/status.js:276`）的五谓词，`research.status !== 'verified'` 使其 `listed = false`，即**该模式未上架**。实测目录投影证实：`gpt-image-2.5` 的已上架模式只有 `text_to_image`，无任何消费媒体的模式。

因此图片节点在补上该模式的官方文档核验前，不可能出现素材卡槽；本功能已把配置项与回退链就绪，模式一旦上架即自动生效（AC-4 覆盖，`default-operations.test.js` 的第二个用例会在上架后自动切换到「必须选中媒体消费模式」的断言分支）。

同类结论适用于音频：`seed-audio-1.0` 仅 `text_to_speech` 一个模式，且该模式被 `deriveSlotLayout` 定义为不接收参考媒体。

补充该模式的核验证据属于模型接入工作，需按 [模型 API 准据](../docs/contracts/model-api-authority.md) 核对所选渠道官方文档，不在本规格范围内。
