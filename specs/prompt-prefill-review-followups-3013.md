# 规格：补审 #3003 / #3010 的修复项（Issue #3013）

上游：`specs/prompt-prefill-shared-queue-2999.md`、`specs/prompt-prefill-visible-target-3009.md`。

## 背景

对两次修复补跑了独立审查（规范轴、规格轴、本机 ocr）。本规格只处理审查确认的问题，不改按钮、文案、样式和布局。

## 要修的问题

1. **页面迟到可见时请求滞留。** 图像生成页约 1.5 秒内还没显示出来就放弃取请求，请求一直留在队列里；之后页面显示出来也不会再去取，输入框一直是空的。
2. **新的端到端测试没有被执行。** 主插件的测试脚本只找 `.test.js` 和 `.test.ts` 文件，`promptFenceCrossBundle.e2e.test.mjs` 从没被执行过。
3. **「一个订阅者出错不影响其他订阅者」没有测试。**
4. **端到端测试断言失败时不清理。** 订阅和观察器会残留到后面的测试。

## 目标行为

- 页面不可见时不取请求，也不放弃：页面无论多久后变为可见，都会取走仍在队列里的这条请求。
- 请求被别处取走、被新请求替换，或页面卸载时，停止等待。
- 页面一直不可见时不应持续占用资源：等待改为在页面可见性可能变化时再检查，不做无上限的逐帧轮询。

## 用户旅程

1. 用户点「使用提示词生成」，右侧图像生成页正在打开，但因为布局切换要稍等一会儿才显示出来。
2. 页面显示出来后，输入框里出现块内全文，模式切到「视频」。

## 新用户基线

只依赖宿主已有界面与两个插件；环境无法判断可见性时按可见处理，不阻断原有行为。

## 验收

1. 测试：页面超过 1.5 秒后才变为可见，仍能取走请求。
2. 测试：等待期间请求被替换或取走、或调用取消，均停止等待且不再取请求。
3. 测试：订阅者抛错时，其余订阅者仍收到通知。
4. 主插件测试脚本执行新的跨打包端到端测试（文件改为 `.e2e.test.js`）。
5. 端到端测试失败时仍会清理订阅与观察器。
