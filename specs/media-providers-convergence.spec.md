# 插件配置收敛：本机 CLI 与媒体生成提供商分层共存架构规格（Issue #2597）

## 背景与问题陈述

在此前的实现中，将“官方云端”、“本机助手 (CLI)”、“自备密钥 (BYOK)”做成了单一互斥的“三选一”单选模式。该模式存在根本性架构冲突：
1. **能力割裂与互斥冲突**：对话模型与媒体生成是独立能力，本地助手与外部媒体 API 完全应当协同共存。用户无需登录云端，也可以同时使用本地 CLI 进行对话以及通过第三方服务生成媒体。登录云端仅是为了获得团队空间、共享项目与协同大盘。
2. **与 DSH 原生模型入口重叠**：DSH 原生已有“模型”设置入口用于对话模型。在插件设置中单独设置通用的 API 提供商造成概念混乱和职责重叠。

## 目标与收敛架构

彻底废除单选互斥模式，按 OpenDesign 标准对齐收敛：
1. **DSH 原生「模型」菜单**：纯粹保留 DSH 原生对话模型配置，保持原生语义不变。
2. **DSH「插件 (OmniMux)」内部收敛**：
   - **顶置横幅：OmniMux Cloud**：
     - 未登录状态：展示“使用 OmniMux Cloud，登录云端版本后可启用团队空间、共享项目、云端资产与协同能力”，提供 [登录 / 注册] 按钮。绝不阻塞本地对话与媒体生成。
     - 已登录状态：展示绑定账号信息与协同状态，提供退出登录。
   - **双分段选项卡（Segmented Tabs）**：
     - **Tab 1: 本机 CLI**：扫描本地已安装的 Agent/CLI（Claude Code, Codex CLI, Kimi, Qwen, Grok 等），选中的卡片高亮并可展开实时模型与推理等级配置，支持单项 [测试]。
     - **Tab 2: 媒体生成提供商**：专门承接图片、视频、音频生成的模型供应商。优先支持官方三大协议：
       - `fal.ai`：图片 (Flux/SD3.5)、视频 (Kling/Minimax/Luma)、音频 (F5-TTS)
       - `OpenAI`：图片 (DALL·E 3)、音频 (TTS-1/Whisper)、视频 (Sora API)
       - `OpenRouter`：全聚合模型路由
       - 每个供应商提供 API Key（安全存储于本地凭据库，绝不持久化明文于设置文件）、Base URL、多模态模型选择器与 [测试连接]。
   - **底部全局状态栏**：常驻呈现当前对话链路（如 Codex CLI）与媒体链路（如 fal.ai），清晰体现能力共存、绝非互斥。

## 用户操作旅程

1. **进入设置面板**：用户点击 设置 → 插件 → OmniMux，看到清晰的顶置 OmniMux Cloud 横幅与两大 Tab（`本机 CLI` | `媒体生成提供商`）。
2. **配置对话链路**：在 `本机 CLI` Tab 中，系统自动检测出本地已安装的 CLI，用户点击选择并测试任一 CLI（例如 Codex CLI），底部状态立即显示“当前对话链路：Codex CLI”。
3. **配置媒体生成**：用户切换至 `媒体生成提供商` Tab，选择 `fal.ai`（或 OpenAI / OpenRouter），填入 API Key 并测试通过，保存后底部状态立即更新“媒体链路：fal.ai”。
4. **协同云端（可选）**：用户可在顶置横幅随时点击 [登录 / 注册] 接入云端协同，也可随时登出，完全不影响正在工作的 CLI 对话和媒体生成。

## 验收断言标准 (Spec Criteria)

- **S1 (平级分层与 Tab 切换)**：OmniMux 配置卡片必须呈现 `本机 CLI` 与 `媒体生成提供商` 双分段选项卡，可平滑切换对应配置面板。
- **S2 (顶置云端横幅独立性)**：顶置 OmniMux Cloud 横幅独立于底层 Tab，未登录不锁定任何本地或第三方能力，提供登录/注册入口。
- **S3 (本机 CLI 对话能力就绪)**：支持展示检测到的本地 CLI 列表，支持选中生效与单独参数展开配置，选中的 CLI 写入对话路由。
- **S4 (三大媒体提供商标准)**：媒体生成提供商支持 `fal.ai`、`OpenAI`、`OpenRouter`，支持图片、视频、音频的细分模型映射。
- **S5 (密钥隔离与安全性)**：所有媒体提供商 API Key 严格保存至本地安全凭据库，设置存储仅保存端点、启用标志与模型名，杜绝凭据泄漏。
- **S6 (免登录与守卫隔离)**：生成动作不弹官方登录窗；仅触发账号、发布、额度等云端动作才提示登录。
- **S7 (自动化回归测试 100% 绿)**：所有单元测试、E2E 界面测试通过，无语法与样式违规。
