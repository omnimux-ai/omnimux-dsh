# 规格：提示词填入队列跨插件共用（Issue #2999）

上游规格：`specs/chat-prompt-generate.spec.md`（Issue #2540）。本规格只补一处：填入请求必须真正送到图像生成页。

## 现象

对话里点提示词块底部「使用提示词生成」：右侧「图像生成」页打开了，但输入框为空、模式不切到视频、按钮不显示「已填入」。

## 原因

待填队列是模块里的单例。按钮在 OmniMux 主插件里写队列，图像生成页在查看器插件里读队列。两个插件各自打包，各得一份队列，写和读不在同一处。

## 目标

写入方与读取方共用宿主窗口上的同一份待填队列，不依赖两个插件打成同一个模块。对外函数与行为不变：

- 空内容不入队；
- 只能用对应 token 取走一次；
- 取走或清空后订阅者收到空值；
- 订阅者出错不影响其他订阅者。

## 用户旅程

1. 对话里出现「视频提示词」块，用户点底部「使用提示词生成」。
2. 右侧打开「图像生成」页，模式切到「视频」，输入框里是块内全文。
3. 按钮短暂显示「已填入」，再回到「使用提示词生成」。
4. 用户自己点发送才生成；点击本身不发生成请求。

## 新用户基线

只依赖宿主窗口与已安装的两个插件，不依赖本地模型服务或开发机状态。窗口上还没有队列时自动建立空队列；没有窗口（如服务端或测试环境）时退回全局对象，不报错。

## 验收

1. 单测：两份独立模块实例，一份写入，另一份能读到、能收到通知，取走后两边都为空。
2. 既有单测全部保持通过。
3. 真机（开发版）：点「使用提示词生成」后右侧输入框等于块内全文，视频块切到视频；网络里无生成请求。

## 边界

- 总是：只改队列存放位置，不改按钮、文案、样式和图像生成页布局。
- 绝不：在点击时调用生成接口；改官方宿主源码。
