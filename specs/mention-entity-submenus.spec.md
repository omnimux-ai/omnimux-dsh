# 规格：输入框 @ 引用角色与产品二级菜单业务衔接规范

## 一、目标与背景

当用户在对话输入框输入 `@` 时：
1. 在原有文件与对话记录引用前，提供常驻的「角色」与「产品」一级分类入口；
2. 鼠标悬停在「角色」或「产品」选项上时，右侧（或自适应居左）展开二级菜单；
3. 二级菜单采用极简设计：**彻底无分组标题、无副标题描述**，每个选项仅为单行「小方图缩略图 + 实体名称」的组合；
4. 点击二级选项后触发**双向联动**：
   - 自动将对应实体添加到顶部素材卡槽（Attachment Tray），商品带 JSON 规格，角色带 ASSET/立绘标识；
   - 在输入框光标处插入对应的标准胶囊节点（Mention Chip），并自动清除原触发字符 `@`；
5. 严格复用现有商品库接口（`GET /omnimux/products`）、资产库角色接口（`GET /omnimux/assets/library?type=character`）、附件响应式 Store（`AttachmentStore`）与输入框节点机制，不新增孤立冗余逻辑。

---

## 二、关键用户旅程 (Critical User Journeys)

### Journey 1: 输入 @ 唤起一级菜单
- 用户在会话输入框聚焦并键入 `@`；
- 菜单展示，前两项为「角色」与「产品」，带右向指示箭头 `›`。

### Journey 2: 鼠标悬停展开极简二级菜单
- 鼠标移入「产品」：右侧（视口充足时）平滑滑出二级菜单，直接展示商品库中的商品列表，格式为 `[商品主图] 商品名称`，无标题无描述；
- 鼠标移入「角色」：展示资产库中的角色列表，格式为 `[角色立绘] 角色名称`，无标题无描述；
- 鼠标在选项与二级浮层间移动时具有 180ms 延时保护，避免偶发失焦闪烁。

### Journey 3: 点击选项执行双向联动
- 用户点击某个商品（如“中老年纯棉前扣无钢圈薄款文胸”）：
  - 顶部附件导轨（Attachment Tray）即时生成一张附件卡片，标明 `JSON`，可随时点击 `×` 删除；
  - 输入框内已输入的 `@` 字符被替换为实体胶囊 `[图标] 中老年纯棉前扣无钢圈薄款文胸`；
  - 二级菜单与一级菜单自动关闭，输入框恢复焦点，光标位于胶囊后。

## 三、验收标准与门禁规范

1. **结构与视觉契约**：
   - 二级菜单 DOM 结构内禁止包含任何分组标题节点（如 `groupTitle`）与描述文本节点（如 `itemDescription`）；
   - 缩略图为 28×28 圆角矩形，图片加载失败时以带背景色块的默认 SVG 图标平滑降级，绝无破图。
2. **状态与存储契约**：
   - 加入素材必须通过全局 `getGlobalAttachmentStore().addAttachment(sessionId, payload)`；
   - 商品卡片 payload 包含 `sourcePlugin: 'omnimux-products', kind: 'product', extension: 'JSON'`；
   - 角色卡片 payload 包含 `sourcePlugin: 'omnimux-assets', kind: 'image' | 'asset', extension: 'ASSET'`。
3. **兼容性要求**：
   - 不影响现有的已加入素材与官方文件/会话引用逻辑；
   - 输入框上下翻转特性（`[data-omnimux-mention-up]`）对二级浮层定位同步生效。
