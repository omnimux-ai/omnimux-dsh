# 推特助手 · 填入高亮与提示条配色/双语修复规格

## 背景（代码与设计规范核实）

`plugins/omnimux-browser/extension/src/content/twitter-copilot/injector.ts` 是文案写入推特输入框的落点，残留两处与既有约定不符：

1. **配色**：文案填入后的脉冲高亮描边写死 `2px solid #a855f7`、投影 `rgba(168, 85, 247, 0.45)`；提示条默认（info）底色写死 `#8b5cf6`——均为紫色。`design.md` 规定主行动色为黑白高对比、**坚决禁用紫色**，且状态色语义为 `--dsw-alias-status-success`（Dark `#4ade80` / Light `#16a34a`）、`--dsw-alias-state-error-primary`（Dark `#f87171` / Light `#dc2626`），规范要求「文字使用状态色，背景使用同色 12%~15% 半透明色」。同套件的下拉菜单（`styles.css`）已统一为深中性底 `#18181b` + 白字。
2. **双语**：`injector.ts` 内三条提示语（剪贴板兜底成功、输入框与剪贴板均不可用、已填入输入框）为纯中文硬编码；菜单层（`menu.ts`）已按 `detectCopilotLocale()` 全量双语，填入层未适配，英文环境用户看到中文提示。

## 目标行为（验收标准）

1. 填入文案后输入框的脉冲高亮为**黑白中性**：白色描边 + 深色外圈投影，不含任何紫色（`#a855f7` / `#8b5cf6` 及等价 `rgb(168,85,247)` / `rgb(139,92,246)`）；在浅色与深色推特主题下均可见。
2. 提示条底色统一为深中性 `#18181b`（与下拉菜单一致），文字按语义着色：成功 `#4ade80`、错误 `#f87171`、信息 `#ffffff`；不再出现紫色底色。
3. 三条填入层提示语均按当前语言输出：中文环境中文、英文环境英文（复用 `injectTweetText(text, anchor, locale)` 已有的 `locale` 参数）。
4. 不改动菜单文案、提示词内容与场景判定；不改变提示条的显示时长与动画节奏。

## 交互步骤（自动化验收）

1. jsdom 单元：以 `locale='zh'` 调用 `injectTweetText` → 提示条文案为中文；以 `locale='en'` 调用 → 提示条文案为英文；两者均写入成功。
2. jsdom 单元：断言输入框被写入后其内联 `outline` 与 `boxShadow` 不含紫色色值；断言提示条底色为 `#18181b`。
3. 真机：在 x.com 首页发帖框点图标并选用一项功能，文案填入后抓取输入框描边与提示条配色截图，确认黑白中性且提示语与界面语言一致。

## 非目标

- 不处理套件内其它子功能的紫色残留（`content/dom-fill.ts`、`content/twitter-velocity/*`、`panel/*`），另案报告。
- 不调整设计规范本身，不引入新的设计令牌。
