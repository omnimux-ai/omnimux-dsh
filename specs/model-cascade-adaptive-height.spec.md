# 模型级联面板默认高度与最高高度自适应规格 — Issue #2191

## 一、需求背景与目标
在工作流画布中，模型级联选择浮层（ModelCascadeMenu）原先硬编码了 `480px` 固定高度（`POPOVER_HEIGHT = 480`，CSS `.wf-loomi-col--* { height: 480px; }`）。
当候选品牌、型号或渠道分组选项极少（例如仅 1 个品牌、1 个型号、2 个版本）时，内容实际仅需约 `140px~170px`，产生高达 70% 以上的无效黑色空白区域，视觉空旷突兀，且在笔记本等较小视口下存在遮挡画布与溢出视口的风险。

按照 UI 交互设计师的全新设计规格，进行自适应高度优化：
1. **最小默认高度（Min Height）**：标定为 `160px`，少选项时紧凑包裹内容（Hug Content），彻底消除无效暗色留白；
2. **最高封顶高度（Max Height）**：标定为 `400px`，超出时平滑滚动，并受视口剩余可用高度自适应约束（不超过可用空间的 70% 或 `calc(100vh - 120px)`）；
3. **多列联动等高（Unified Harmonized Height）**：展开的多列之间保持顶部与底部等高，高度由当前激活展开的各列中最高列动态决定，保持方正规整的几何美感；
4. **定位防抖机制**：浮层绝对定位根据动态计算出的实际高度自适应钳制，展开第三列或切换品牌时平滑无纵向与横向跳变。

## 二、关键用户旅程（Critical User Journeys）
- **J1：少选项极简场景**
  - 用户点击模型触发胶囊，展开仅有少数选项（如 1~2 项）的模型浮层；
  - 面板三列自适应收缩至约 160px~180px 高度，紧密贴合选项，底部无多余空黑区域。
- **J2：适中选项场景**
  - 用户切换至包含 3~5 个型号的品牌，浮层自然平滑舒展至对应高度（约 220px~300px），多列底部始终对齐。
- **J3：超量选项场景**
  - 用户查看包含大量选项（6 项以上）的列表，面板高度展开至 400px 后封顶，内部细滚动条从容滚动，绝不顶破视口边缘。

## 三、新用户与基线说明（Baseline）
- 新用户首次打开画布添加节点并选择模型时，所有模态（图片、视频、文本、音频）的模型级联浮层均直接消费自适应高度样式与计算，无任何外部依赖或开发机私有配置。

## 四、验收标准（Acceptance Criteria）
- [ ] **AC1（消除固定死高）**：移除固定 480px 硬编码，引入 `min-height: 160px` 与 `max-height: 400px` 弹性自适应。
- [ ] **AC2（多列动态联动等高）**：三列展开时外轮廓底部齐平，高度由当前展开各列的最大内容高度共同决定，不出现锯齿下边缘。
- [ ] **AC3（视口与滚动安全）**：多选项时受 400px / 视口约束安全封顶，并提供平滑细滚动条；少选项时紧凑无冗余大黑底。
- [ ] **AC4（定位无跳动）**：展开与收起第三列、切换品牌悬停时无纵向错位与跳跃。
