# 规格文档：产品库插件作为一级 Tab 迁移整合至资产库界面

**文件：** `specs/integrate-products-into-assets.spec.md` ｜ **优先级：** P0 ｜ **模块：** `plugins/omnimux-assets` + `plugins/omnimux-products`
**变更面：** Client / Stage / 页面导航 / 操作行联动
**设计依据：** 用户明确指令（保留产品库独立性，UI 上整合至资产库作为一级 Tab，进入后一级按钮切换为新建产品）、[design.md](../design.md)、[first-level-page-layout.md](../docs/contracts/first-level-page-layout.md)

---

## 1. 业务目标与架构原则

### 1.1 背景与目标
- 用户在创作与选品链路中，频繁在左侧侧边栏切换「资产库」与「产品库」两个独立页面，认知割裂。
- 用户希望将「产品库」作为一级选项卡（Tab）整合进「资产库」页面，使资产库涵盖「本地素材」、「云端素材」与「产品库」。
- 进入「产品库」Tab 后，一级主按钮智能切换为「+ 新建产品」，并支持实物与数字产品悬停分流。
- 切回「本地」或「云端」后，一级主按钮恢复为「+ 添加资产」，次按钮恢复为「导入资产包」。

### 1.2 架构隔离与最小侵入原则
- **保留独立性**：`plugins/omnimux-products` 插件的数据结构、持久化存储（`$DSH_HOME/omnimux/products/data/`）、Host 后端接口（`/omnimux/products/*`）及下游引用（`@产品/名称`）100% 保持原生独立，不做破坏性合并。
- **UI 层聚合**：在 `plugins/omnimux-assets` 视图层接入「产品库」选项卡，根据 Tab 状态派发操作栏与内容区渲染，代码改动轻量可控、零副作用。

---

## 2. 详细验收标准（Acceptance Criteria）

### 2.1 一级选项卡与操作按钮联动 (P0)
- **AC-101**：资产库顶层选项卡由「本地、云端」扩充为「本地、云端、产品库」。
- **AC-102**：选中「本地」或「云端」Tab 时：
  - 一级主按钮展示为 `+ 添加资产`（点击打开添加资产弹窗）；
  - 一级次按钮展示为 `导入资产包`。
- **AC-103**：选中「产品库」Tab 时：
  - 一级主按钮动态切换为 `+ 新建产品`（包含实物产品/数字产品悬停分流菜单与直接触发）；
  - 一级次按钮动态切换为 `对话中添加`（支持通过 Agent 智能解析添加）。

### 2.2 二级分类与内容视图切换 (P0)
- **AC-201**：在「产品库」Tab 下，二级分类筛选胶囊展示产品类型（`全部`、`实物产品`、`数字产品`），并展示各自总数。
- **AC-202**：内容区展示产品列表卡片，支持展示产品主图、名称、卖点/战略、价格、以及复制 `@产品/名称` 引用标识。
- **AC-203**：点击产品卡片或「新建产品」可进入产品二级详情/表单，支持返回并保持原视图状态。

### 2.3 规范与兼容性 (P0)
- **AC-301**：所有按钮、选项卡、卡片严格遵循 `dsh-ui-kit` 与 `--dsw-*` 设计规范。
- **AC-302**：单元测试与契约检查 100% 通过。

## 3. 任务分解与执行路径
- **T01**：在 `plugins/omnimux-assets` 中增加产品库多语言文案与选项卡支持。
- **T02**：重构 `AssetsActionRow`，实现基于选定选项卡动态切换 `+ 添加资产` / `+ 新建产品`。
- **T03**：在 `omnimux-assets` 客户端实现产品库整合视图（`ProductsView`），对接产品库 Host 状态与操作。
- **T04**：编写自动化单元测试，验证选项卡切换、按钮切换及渲染行为。
- **T05**：执行测试门禁，全绿后交付。
