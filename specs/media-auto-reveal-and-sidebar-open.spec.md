# 规范：生图/生视频结果强制末尾外露与侧边栏自动展开机制

## 1. 业务目标与背景
用户在对话中发起生图或生视频任务时：
- 宿主默认行为会将多步中间过程（包括 `image_generate`、`display_file` 等工具调用）收起在可折叠的进度指示器（如“3 次工具调用 · 1 条消息 >”）内；
- 导致生成的图片结果被锁在折叠框里，用户无法直观在消息最后看到结果，且右侧侧边栏未自动打开；
- 本规范确立前端业务逻辑自动判定与强制外露准则：**结果展示绝不能靠 Agent 提示词主动触发，必须由前端业务逻辑在检测到媒体生成后强制在消息尾部外露，并自动展开右侧侧边栏**。

## 2. 核心交互契约

### 2.1 强制在消息最后外露展示（No Fold for Results）
- 即使上方的工具调用面板处于折叠状态，生图/生视频生成的高清图片/视频卡片必须**强制渲染在助手回复正文的最下方、操作栏正上方**；
- 卡片完全对齐截图 1 样式：包含高清预览大图、悬浮操作栏（复制图片、点赞评价、在右侧侧边栏打开大图按钮）；
- 支持多图生成横排并列。

### 2.2 右侧侧边栏自动展开（Auto-Open Right Sidebar）
- 一旦业务逻辑检测到本轮生成了图片或视频产物：
  1. 自动将新生成的媒体文件（URL、本地路径、时间戳）存入全局媒体存储库 `media-viewer-store`；
  2. 自动将其标记为当前激活项 `activeId`；
  3. 自动调用 `window.__omnimuxWorkbench.openWorkbench({ tabId: 'omnimux:media-viewer' })` 展开右侧侧边栏，呈现时间线或大图浏览窗口；
- 整个过程 100% 由客户端业务逻辑触发，零人工点击成本，无需 Agent 发出任何指令。

## 3. 技术实现方案
1. **渲染槽位链注入**：
   - 接入 `conversation.chat.turnTail` 槽位，此槽位属于轮次结算末尾，天然不受 `turn-process` 折叠影响；
   - 在该槽位中注册媒体呈现组件，当检测到轮次中有生成媒体时立即挂载；
2. **事件与 DOM 级双保险提升**：
   - `ViewerCard` 与生成工具在解析到图片文件路径时触发全局事件广播；
   - `assistantMessageMediaEnhancer` 监听全局广播并在 DOM 树中双向校准：确保即使槽位链未覆盖，也能第一时间在助手气泡尾部插入卡片，并自动拉开右侧栏。
