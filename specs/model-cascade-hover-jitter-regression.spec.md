# 模型级联菜单悬停抖动回归修复规格 — Issue #2250

## 一、现象与根因

画布节点底栏的模型级联浮层（`ModelCascadeMenu`）展开后，鼠标从一个品牌悬停到另一个品牌时，整块浮层频闪抖动：选项在光标下方反复位移，用户无法稳定点选。

根因是一条**悬停反馈回路**，由 #2195 的高度自适应改动引入：

1. 浮层是 `position: fixed` + `bottom` 锚定（从触发器向上弹出），底边固定、顶边由内容高度决定；
2. #2195 把三列从固定 `height: 480px` 改为内容自适应（`.wf-loomi-col { min-height:160px; max-height:min(400px,calc(100vh-120px)); height:auto }` + 容器 `align-items: stretch`），浮层高度改为「当前可见各列中最高列」决定；
3. 悬停切换品牌会换掉二级列内容，悬停型号会换掉三级列内容，且悬停其它品牌时三级列整体隐藏 —— 三种情况都会改变浮层高度；
4. 高度变化 → 顶边位移 → 品牌行从光标下方移走 → 浏览器重算 `mouseenter` → 悬停态翻转 → 内容与高度再次变化 → 抖动自我维持。

历史修复 #1803 用固定高度切断了这条回路，但代价是少选项时大面积死黑空白；#2195 为消除空白改回内容驱动，回路重新出现。

## 二、修复原则

**浮层外框几何必须在一次展开期间与悬停状态无关。**

做法：在展开时一次性量出「当前候选集内所有品牌二级列 + 所有型号三级列 + 品牌列」的自然内容高度，取最大值锁定为浮层高度（仍受 `160px ~ 400px` 与视口约束）。锁定的高度覆盖了所有可能悬停到的形态，因此：

- 保留 #2195 的「贴合内容、无死黑空白」：锁定值来自真实内容上限，而不是 480px 机械写死；
- 彻底消除抖动：悬停不再改变浮层尺寸，顶边不动，悬停态不再翻转。

## 三、关键用户旅程

- **J1：悬停切换品牌**。展开浮层 → 依次悬停每个品牌 → 浮层顶边、底边、高度在容差内恒定；品牌行屏幕位置不随悬停变化。
- **J2：悬停预览型号与三级列显隐**。悬停型号使三级列出现/消失 → 浮层尺寸不变。
- **J3：少选项**。候选集只有少量品牌与型号时，锁定高度贴合真实内容上限，不回到 480px 死空白。
- **J4：多选项**。内容超过 400px 时锁定在 400px 封顶，列内细滚动条正常滚动，不顶破视口。

## 四、新用户与基线说明（Baseline）

新用户在全新安装环境下打开画布、添加节点并点击底栏模型胶囊时，浮层高度由本规格的探测与锁定逻辑即时计算，不依赖任何开发机私有配置、本地模型服务或凭据；探测节点仅存在于浮层内部且不可见、不可交互，缺任何数据源时退化为 `160px~400px` 的既有约束。

## 五、验收标准

- [ ] **AC1（几何恒定）**：浮层展开后，悬停任意品牌、任意型号，`getBoundingClientRect()` 的 `top` / `bottom` / `height` 变化 ≤ 1px。
- [ ] **AC2（悬停目标不位移）**：悬停切换品牌时，各品牌行与型号行的屏幕 `top` 不发生变化。
- [ ] **AC3（保留贴合内容）**：少选项候选集的锁定高度等于真实内容上限（≤ 400px），不出现 #2195 之前 480px 的死黑空白。
- [ ] **AC4（封顶与滚动）**：内容超过 400px 时锁定 400px，列内细滚动条生效。
- [ ] **AC5（无探测副作用）**：量尺节点不可见、不可交互、不可聚焦，不进入无障碍树，不改变浮层可见内容与交互。
- [ ] **AC6（门禁全绿）**：相关单测与端到端静态门禁全部通过，隔离工作树真实浏览器证据留存。

## 六、影响面

仅 `plugins/omnimux-workflow` 画布模型级联浮层的几何计算；不改模型契约、渠道分组数据、提交参数与任何后端行为。
