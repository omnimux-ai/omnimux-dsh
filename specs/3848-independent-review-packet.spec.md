# 规格 · 净室评审输入包（review packet）

- Issue: #3848（PR B）
- 风险级别: R1（新增仓内脚本与流程文档，不改插件运行行为）
- 来源: MiniMax mcode-stack independent-review（MIT）：评审者在全新上下文中只拿三样输入——diff、需求原文、真实测试证据，不看实施者的对话、计划与自评。

## 目标

现有合同要求「合并前独立评审（可由另一 Agent 完成）」，但没有规定评审者拿什么输入，实际常把实施会话整段 fork 给评审者，评审被实施者的叙述带偏。本任务提供一个可复现的评审输入包生成器，并在 Git/PR 合同里写明净室评审协议。

## 范围

- 新增 `scripts/review-packet.mjs`：从当前 HEAD 相对 base 的已提交改动、指定规格文件、指定测试证据文件生成一份 Markdown 评审包，写到仓库外的临时目录并打印绝对路径。
- 新增 `scripts/review-packet.test.mjs`，并加入 `test:gates` 首个 `node --test` 列表；`package.json` 新增 `review:packet`。
- `docs/contracts/plugin-git-pr.md` 在既有「独立评审」条目上扩展净室评审协议；`.agents/skills/omnimux-repo-workflow/SKILL.md` 补两处指针。
- 不在范围：自动派发评审 Agent、解析评审结论、改 CI。

## 新用户基线

只依赖仓库内的 git 与 Node（内置模块），不读开发机私有状态、会话日志或环境密钥，不联网。缺规格、缺/空证据、diff 为空、工作区有未提交改动时直接以非零退出并打印可读原因，不生成残缺评审包。

## 文档影响

更新 `docs/contracts/plugin-git-pr.md` 的独立评审规则（净室评审协议为唯一归属）与仓库工作流 skill 的两处指针；其他文档只引用，不重复。

## 验收标准

| # | 场景 | 期望 |
| --- | --- | --- |
| A1 | 干净工作区、有提交改动、给定规格与证据 | 生成包含头信息（base / merge-base / head SHA / 分支 / 日期 / 文件列表）、`## 需求（规格原文）`、`## 改动（diff）`、`## 测试证据（原文）`、`## 评审要求` 的 Markdown，且无其他二级标题；路径打印到 stdout |
| A2 | 规格缺失 | 非零退出，原因含规格路径 |
| A3 | 未给 `--evidence` / 证据文件不存在 / 为空 | 非零退出，原因可读 |
| A4 | HEAD 与 base 无差异 | 非零退出，提示 diff 为空 |
| A5 | 有未提交的已跟踪改动或未忽略的未跟踪文件 | 非零退出，提示评审包必须绑定提交 |
| A6 | 输出位置 | 写在仓库外；生成后夹具仓库 `git status --porcelain` 仍为空 |

## 假设

评审偏差主要来自评审者继承了实施者的上下文（计划、自评、对话），而不是评审者能力不足；只要输入被限制为 diff + 需求原文 + 真实测试证据，评审者就会独立地发现未验证假设与遗漏的需求条目。同时假设已提交改动（merge-base...HEAD）足以代表待评审内容，未提交改动一律拒绝。

## 证伪方式

运行 `node --test scripts/review-packet.test.mjs`：若生成的包缺少任一三段输入、混入额外二级标题、写进了仓库、或在脏工作区/空 diff/缺证据时仍成功退出，则实现假设被证伪。流程层面：若净室评审者在拿到评审包后仍需要回问实施者的对话才能判断，说明三样输入不足以支撑评审，需要补充输入项。
