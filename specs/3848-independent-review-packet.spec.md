# 规格 · 净室评审输入包（review packet）

- Issue: #3848（PR B）
- 风险级别: R1（新增仓内脚本与流程文档，不改插件运行行为）
- 来源: MiniMax mcode-stack independent-review（MIT）：评审者在全新上下文中只拿三样输入——diff、需求原文、真实测试证据，不看实施者的对话、计划与自评。

## 目标

现有合同要求「合并前独立评审（可由另一 Agent 完成）」，但没有规定评审者拿什么输入，实际常把实施会话整段 fork 给评审者，评审被实施者的叙述带偏。本任务提供一个可复现的评审输入包生成器，并在 Git/PR 合同里写明净室评审协议。

## 范围

- 新增 `scripts/review-packet.mjs`：从当前 HEAD 相对 base 的已提交改动、指定规格文件、指定测试证据文件生成一份 Markdown 评审包，写到仓库外的临时目录并打印绝对路径。规格必须先提交再生成评审包（工作区不干净时按设计拒绝）。
- 输入校验：规格与证据按字节读取，含 NUL 或不是严格 UTF-8 即拒绝（截图等二进制按协议以路径交给评审者）；每份证据必须含当前 head SHA 前 7 位；写出前扫描高置信密钥模式，命中即失败，只报 文件:行，不回显匹配值。
- 输出：头信息含 base 提交时间（`git show -s --format=%cI`）供判断新鲜度；仓库外文件只显示文件名；新建目录 0700（默认目录已存在时也收紧到 0700，用户自带 `--out-dir` 不改权限）、文件 0600；文件名 `<branch>-<head12>-<hash8>.md`（hash8 为规格与证据文本 sha256 前 8 位），同输入同文件，换证据得新文件，不覆盖旧包。
- 新增 `scripts/review-packet.test.mjs`，并加入 `test:gates` 首个 `node --test` 列表与 CI；`package.json` 新增 `review:packet`；在治理注册表登记。
- `docs/contracts/plugin-git-pr.md` 在既有「独立评审」条目上扩展净室评审协议（只管输入怎么交付）。
- `.agents/skills/omnimux-repo-workflow/SKILL.md`：明确在范围内的两处改动——（1）委派规则：只委派中间产出后续不需要、只要结论的工作（如独立调研、黑盒验证、净室评审），不按角色拆分（该规则经用户确认）；（2）合并前独立评审指向 `pnpm review:packet` 与净室评审协议。
- 不在范围：自动派发评审 Agent、解析评审结论、改评审核对项（归 `docs/contracts/plugin-qa.md`「评审与验收结论」）。

## 新用户基线

只依赖仓库内的 git 与 Node（内置模块），不读开发机私有状态、会话日志或环境密钥，不联网。缺规格、缺/空/二进制证据、证据未绑定 head、疑似含密钥、diff 为空、工作区有未提交改动时直接以非零退出并打印可读原因，不生成残缺评审包。

## 文档影响

`docs/contracts/plugin-qa.md`「评审与验收结论」继续归属评审核对项（实际 diff、测试证据、授权、未解决风险）；`docs/contracts/plugin-git-pr.md` 的净室评审协议只归属输入如何交付（全新上下文、评审包、附加材料），重点关注项是对 plugin-qa 的补充而非替代。仓库工作流 skill 改两处（见范围）；其他文档只引用，不重复。

## 验收标准

| # | 场景 | 期望 |
| --- | --- | --- |
| A1 | 干净工作区、有提交改动、给定规格与证据 | 生成包含头信息（base / merge-base / head SHA / 分支 / 日期 / 文件列表）、`## 需求（规格原文）`、`## 改动（diff）`、`## 测试证据（原文）`、`## 评审要求` 的 Markdown，且无其他二级标题；路径打印到 stdout |
| A2 | 规格缺失 | 非零退出，原因含规格路径 |
| A3 | 未给 `--evidence` / 证据文件不存在 / 为空 | 非零退出，原因可读 |
| A4 | HEAD 与 base 无差异 | 非零退出，提示 diff 为空 |
| A5 | 有未提交的已跟踪改动或未忽略的未跟踪文件 | 非零退出，提示评审包必须绑定提交 |
| A6 | 输出位置 | 写在仓库外，目录 0700、文件 0600；仓库外证据只显示文件名；生成后夹具仓库 `git status --porcelain` 仍为空 |
| A7 | 证据含 NUL 或非法 UTF-8 | 非零退出，提示截图按协议以路径交付 |
| A8 | 证据不含 head SHA 前 7 位 | 非零退出：「证据未绑定当前 head（请在证据中记录 git rev-parse HEAD 的输出）」 |
| A9 | 证据含高置信密钥模式 | 非零退出，报 文件:行，不回显匹配值，不写文件 |
| A10 | 同输入重复生成 / 换证据 | 同文件名；换证据得新文件，旧包不变 |
| A11 | 头信息 | 含 base 提交时间（ISO 8601） |

## 假设

评审偏差主要来自评审者继承了实施者的上下文（计划、自评、对话），而不是评审者能力不足；只要输入被限制为 diff + 需求原文 + 真实测试证据，评审者就会独立地发现未验证假设与遗漏的需求条目。同时假设已提交改动（merge-base...HEAD）足以代表待评审内容，未提交改动一律拒绝。

## 证伪方式

运行 `node --test scripts/review-packet.test.mjs`：若生成的包缺少任一三段输入、混入额外二级标题、写进了仓库、泄露仓库外绝对路径、或在脏工作区/空 diff/缺证据/二进制证据/未绑定 head/含密钥时仍成功退出，则实现假设被证伪。流程层面：若净室评审者在拿到评审包后仍需要回问实施者的对话才能判断，说明三样输入不足以支撑评审，需要补充输入项。

## 第二轮净室评审退修（head cede3dcfb，REQUEST_CHANGES）

- F1 密钥漏报：主体字符集放宽到 `[A-Za-z0-9_-]`，新增 `gh[opsur]_`、Google `AIza`、AWS `ASIA`；逐规则正例测试。
- F2 误报：前缀前要求非单词字符（`(?<![A-Za-z0-9_-])`），AWS 加尾部边界；反例覆盖 `task-<sha>`、`risk-…`、`XAKIA…`、`ask-…`。
- F3 覆盖：文件名指纹纳入 base SHA、规格/证据显示名，每个字段带长度前缀。
- F4 证据截断：第三轮证据保存完整原始输出。
- F5 授权输入：协议与评审要求改为任何风险等级都附 Issue/PR 中的授权范围与风险等级，R0 须为明确授权记录。
- F6 规格须已提交：规格必须是仓库内、被 git 跟踪的文件，否则拒绝。
- F7 diff 不扫描密钥、F8 head 前缀子串匹配：保留现状。规格只要求扫描规格与证据；已提交密钥由仓库既有的全库密钥扫描负责；7 位前缀符合 A8。
