# 4058 批量操作按所选记录类型显示，提示改为浮层气泡

Issue: #4058 · 分支 `agent/publish-batch-actions-issue-4058` · 风险等级 **R2**（列表交互）

## 背景

用户选中「发布中」和「失败」两条记录时，批量栏仍显示「批量删除草稿」；点击后提示「所选记录中没有可删除的草稿，请重新选择」。两个问题：

1. 不该出现的操作出现了：删除草稿只对草稿有意义，选中里没有草稿时应隐藏（或禁用并说明）。
2. 提示是页面顶部的普通文本块，不像系统消息；应改为顶部浮层气泡，自动消失。

## 方案

1. `PublishViewport` 计算选中记录的类型统计（`draftCount`、`failedCount`），传给 `PublishBatchBar`。
2. `PublishBatchBar` 按可用操作渲染：
   - `draftCount > 0` 才显示「批量删除草稿」；
   - `failedCount > 0` 才显示「批量重试失败」；
   - 两者都没有时显示「所选记录暂无可批量操作」。
3. 批量栏提示从 `PublishViewport` 内联 `<div className="omnimux-publish-alert">` 改为 `omnimux-publish-toast` 浮层（顶部居中、深色卡片、阴影、自动消失，沿用现有 3 秒定时）。
4. 文案保持简洁，不再出现「请重新选择」这类责备式措辞（无操作时只陈述状态）。

## 假设

- 「失败」记录一定包含 failed 子任务，按子任务状态统计即可；没有子任务的记录不计入 failedCount。
- 批量删除仍只针对 draft；已提交记录按账本保留，不提供删除。
- 浮层气泡只影响展示，不改变 toast 生命周期。

## 证伪方式

- 单测：选中发布中+失败时，批量栏不出现「批量删除草稿」，出现「批量重试失败」；选中草稿时相反；什么都不选时（批量模式）提示暂无可操作。
- 浏览器实测：两种选择状态截图对比，删除按钮按类型出现/消失；提示为浮层气泡。
- 现有 312 单测保持通过。

## 新用户基线

无需配置；操作与记录类型一致，不会看到无关按钮。

## 文档影响

无。
