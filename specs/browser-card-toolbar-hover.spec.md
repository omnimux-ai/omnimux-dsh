# 卡片触发按钮：工具栏悬停连续性修复规格

## 1. 背景与缺陷

作品卡片右上角的小幽灵图标（媒体触发按钮）悬停后会展开三个动作的工具栏。实测（真实 TikTok 搜索页）：鼠标从小图标移向工具栏时，工具栏立即淡出，三个按钮一个都点不到。

### 根因

小图标与工具栏是两个视觉上相邻、盒子上却不相邻的部件：

- `.omt-entry` 的盒子只有小图标那么大（工具栏是绝对定位子节点，不参与父盒子尺寸）；
- 工具栏用 `left/right: calc(100% + 6px)` 与小图标之间留了 6px 视觉间隙。

这 6px 既不属于小图标也不属于工具栏，指针跨过它时 entry 收到 `pointerleave`，于是：

1. `.is-open` 被摘掉 → 工具栏 `pointer-events: none` **立即**生效（该属性不参与过渡）→ 工具栏不再可命中，点击落空；
2. `.is-revealed` 同时被摘掉 → 小图标也一并消失，指针下方只剩页面。

即：进入工具栏的唯一路径是一段「谁都不属于」的死区。

### 附带缺陷

从工具栏退回卡片时同样无条件摘掉 `.is-revealed`。此时指针仍在卡片上，但 `pointerenter` 不会再次触发，小图标会一直不出现，直到指针离开卡片再回来。

## 2. 需求与范围

### 范围包含

- 小图标与工具栏之间的间隙改为**可命中**（透明桥接层），指针在两者之间移动不产生离开语义。
- 展开状态由「指针在卡片上」与「指针在按钮区域内」两个独立事实推导，任一条成立即显示小图标。
- 离开按钮区域后延迟收起（缓冲期），缓冲期内重新进入即取消收起；防抖、防快速斜向移动误关。
- 桥接方向随工具栏所在侧翻转，四个角落方向均成立。

### 范围不包含

- 不改动既有视觉：小图标尺寸、圆角、配色、工具栏 6px 视觉间隙、三个动作与文案全部保持原样。
- 不改动卡片匹配规则、门禁矩阵、动作协议与后端调用。
- 不改动媒体悬浮胶囊（`media-hover`）的既有逻辑。

## 3. 验收标准

- **AC-1**：指针从小图标移动到工具栏后，工具栏保持展开，且工具栏内按钮仍可命中（`pointer-events` 未失效）。
- **AC-2**：指针在两者之间快速移动（一次移动跨越整段间隙）后，工具栏仍保持展开。
- **AC-3**：工具栏内三个动作可被点击并触发对应动作（灵感库 / 复制 / 加入对话）。
- **AC-4**：指针从工具栏退回卡片时，工具栏收起，但小图标保持显示（指针仍在卡片上）。
- **AC-5**：指针离开卡片与按钮区域后，工具栏与小图标都收起。
- **AC-6**：工具栏位于小图标左侧与右侧两种方向，桥接层都覆盖间隙（四角落方向均满足 AC-1）。
- **AC-7**：既有行为不回归：门禁不允许的页面不挂载、每张卡片一个标记、卡片移除后标记跟随、释放后宿主消失。

## 4. 验证方式

- 真实浏览器内驱动真实指针序列：卡片 → 小图标 → 工具栏 → 点击动作，逐步留存截图与结构化报告（含每一步的 `pointer-events` 与命中元素）。
- 单元测试覆盖 AC-1..AC-7，其中 AC-1/AC-2 以「离开后缓冲期内进入即取消收起」与「桥接层存在且方向正确」两条断言落地。
