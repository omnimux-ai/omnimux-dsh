# 规格说明：修复三栏布局竞争与全屏状态失衡缺陷，收敛伪全屏并保护会话物理宽度

## 一、背景与问题定义

在 OmniMux 桌面端三栏（左侧导航/工作区列表、中间会话流、右侧工作台/画布）协同场景中，存在严重的状态竞争与几何失衡缺陷：
1. **伪全屏状态倒挂（图 1 -> 图 2）**：点击左侧“项目”（`omnimux-workflow:library`）等业务功能时，`resolveDefaultFocus` 默认将其设为 `gui` 伪全屏模式。插件将右侧工作台强拉至 `1448px` 并强制将中间会话栏收缩至 `0px`（`data-omnimux-conversation-collapsed`），但宿主系统（DSH AppFrame）依然处于普通 `push` 侧栏模式。结果右上角按钮显示为“全屏”（未全屏态），与视觉排版彻底脱节，且左下角穿透残留中间会话文字。
2. **全屏响应失效（图 2 -> 图 3）**：在图 2 状态下点击全屏按钮，右上角虽变为“退出全屏”，但由于左侧导航栏未联动收起（依然占 `280px`），右侧面板尺寸毫无变化，视觉上未实现真正的全视口全屏。
3. **退出全屏布局断裂与黑洞死区（图 3 -> 图 4）**：点击退出全屏后，宿主分配中间 `670px`、右侧 `778px`，但中间会话流容器与右侧面板之间断裂，产生大面积纯黑空白死区。

## 二、验收标准（Acceptance Criteria）

1. **废除插件级 `gui` 伪全屏，默认以清晰分屏（Split）呈现**：
   - 用户在左侧导航点击“项目”（`omnimux-workflow:library`）、“资产库”等功能时，默认以标准的 `split`（分屏）模式打开，右侧工作台与中间会话栏并存，杜绝未经全屏操作私自将会话栏压瘪为 0px。
   - 右上角全屏按钮在分屏状态下统一清晰显示为“全屏”，视觉状态与系统控制钮 100% 吻合一致。
2. **真全屏联动与左侧边栏自适应**：
   - 当用户主动点击右上角“全屏”时，右侧工作台进入宿主真全屏（`mode === 'fullscreen'`）；
   - 在真全屏状态下，右侧面板独占视口，中间会话栏完全安全隐藏且所有子元素（包括欢迎文案与输入框座席）彻底裁剪（`overflow: hidden` / `display: none`），左下角绝对无任何文字穿透残影。
3. **退出全屏平滑自愈，消除黑洞死区**：
   - 从全屏退出回分屏时，中间会话栏容器与右侧工作台宽度保持协调，会话流主体自适应撑满中间区域，消除任何断层黑洞或空白死区。
4. **会话栏物理防挤压防护**：
   - 非全屏状态下，中间会话栏拥有最小物理保护宽度（`min-width: 420px`），防止因任何几何计算失误被压缩变形。
5. **单测与全量回归保持 Green**：
   - 包含 focus-state、split-layout、conversation-box、rail-activation 在内的单元测试与回归测试全量通过。

## 三、关键交互旅程（User Journey）

1. 刷新进入主界面，三栏初始正常（左 280px，中 1448px，右 0px）。
2. 点击左侧“项目”：右侧打开项目库，以优雅分屏呈现（会话与项目并列，中间无挤压、无文字穿透残影，右上角为“全屏”图标）。
3. 点击右上角“全屏”：右侧项目库沉浸全屏铺满，右上角变为“退出全屏”，会话内容完全隐藏且无任何文字泄露。
4. 点击右上角“退出全屏”：平滑恢复到分屏状态，会话流与项目库并排自适应展示，中间无任何黑色空洞。
