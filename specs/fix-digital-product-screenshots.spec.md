# 数字产品首屏截图抗黑屏与动态渲染就绪优化规格

**文件：** `specs/fix-digital-product-screenshots.spec.md` ｜ **优先级：** P0 ｜ **模块：** `plugins/omnimux-products`

## 1. 问题与用户旅程

### 1.1 现状与痛点
用户在资产中心「添加数字产品」表单中粘贴目标官网链接（如 `www.omnimux.ai`）并点击「智能解析」。
文本信息（产品名、受众、品牌等）解析正常，但右侧「首屏截图」区域的电脑端首屏（1440×900）与手机端首屏（390×844）卡片内呈现为全黑画面，导致用户误判为截图失败。

### 1.2 根因定性
1. **无协议输入 URL 归一化未生效**：`captureSiteScreenshots` 虽调用 `normalizeImportUrl` 校验，但未将补齐 `https://` 的结果重新赋给导航 URL，导致直接传域名时 CDP 导航异常。
2. **现代单页应用首屏渲染就绪时间不足**：`loadEventFired` 仅代表静态文档与基础脚本下载完成。现代单页应用（SPA / SSR 混合架构）需执行 React/Vue 渲染与资源装载，原有的固定 600ms 等待过短，快门截到了尚未挂载内容的初始深黑背景层（生成体积仅 5.8KB 的纯黑 PNG）。
3. **缺乏黑屏/空帧检测与智能重试防线**：单次抓拍缺少有效内容校验，即使截到纯黑色空帧也直接落盘并挂为主封面。

## 2. 目标与验收标准 (Acceptance Criteria)

### AC-101：URL 协议自动补全与归一化
- **场景**：传入无协议头的链接（如 `www.omnimux.ai` 或 `omnimux.ai`）。
- **预期**：`captureSiteScreenshots` 自动归一化为标准的 `https://www.omnimux.ai/`，CDP 导航稳定无阻。

### AC-102：动态渲染感知与稳定等待提升
- **场景**：目标页面为具有深色主题或需要客户端脚本挂载的现代网站。
- **预期**：在 `loadEventFired` 之后，将基础稳定沉淀时间从 600ms 提升至 1500ms（或动态检测 document.readyState 与主内容绘制），确保主体文字、图文、导航排版完全呈现。

### AC-103：黑屏/单色空帧智能检测与补拍重试防线
- **场景**：首拍因网络波动或首屏渐入动效截取到纯黑/极小体积（< 15KB）的未就绪帧。
- **预期**：自动触发抗黑屏补偿机制，在预算允许范围内等待 1000ms 后进行二次补拍；若二次补拍呈现有效内容（体积显著增大且包含非纯黑内容），以补拍结果为准。

### AC-104：向后兼容与优雅降级
- **场景**：网络超时、无浏览器或网站彻底无法访问。
- **预期**：保持既有契约（`outcomeOf`, `SCREENSHOT_REASON` 等），不抛出未捕获异常，平滑降级，文本信息与表单依然可用。

### AC-105：全量自动化测试与回归保障
- **场景**：运行全量单元测试、集成测试与规范门禁。
- **预期**：既有 1005+ 项测试 100% 绿灯，UI 规范门禁 0 违规。
