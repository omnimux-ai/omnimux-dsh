# 规格：浏览器插件会话栏「自动/手动」模型选择按钮 (Issue #2966)

## 一、背景与问题定义

浏览器插件（omnimux-browser extension；侧栏面板与网页悬浮工作站共用同一套输入栏 UI）的会话输入栏目前只有「附件」与「发送」两个操作，模型选择只能到设置页进行。产品要求在输入栏附件按钮右侧新增模型控制按钮：

- 默认「自动模式」开启：每条消息发出前由 Jev（TypeSafe System-1 决策引擎，宿主侧 `decisions` seam）为**该条消息**自动选择对话模型；
- 关闭自动模式：展开旗舰模型列表，用户手动点选模型，选择即时应用于当前会话并持久化为默认偏好。

用户已确认：自动路由粒度为**每轮发送前**；模型行**不带锁图标**。

## 二、名词与范围

| 名词 | 定义 |
|---|---|
| 会话栏（composer） | 输入框底部操作条：左侧附件按钮区 + 右侧发送按钮区 |
| 模型按钮 | 新增的胶囊按钮，触发态文案为「自动」或已选模型名，带下拉箭头 |
| 模型面板 | 按钮点击后向上展开的浮层：标题、自动模式开关、说明文案、（开关关闭时）模型列表 |
| 自动路由 | 宿主侧在 `session.prompt` 进入 agent 之前，用 Jev 决策模型并写入 `session.selectModel` 的链路 |
| 手动模型 | 用户在列表中点选的模型；同时写入本地偏好与全局默认模型设置 |

范围内：输入栏按钮与浮层、模式持久化与下发、宿主自动路由、模型列表数据源。
范围外：桌面宿主输入框、推理强度（effort）选择器（沿用既有默认值）、媒体/画布模型选择、回合级模型角标回显。

## 三、用户关键操作旅程

1. **默认态**：首次使用即见「自动 ⌄」按钮；点击弹出模型面板，「自动模式」开关处于 ON，面板显示说明文案；列表不展开或仅展示自动态视图。
2. **切换手动**：关闭开关 → 面板展开模型列表（品牌图标 + 名称 + 副标题）；点击某模型行 → 面板收起、按钮文案变为模型名；该选择立即作用于当前会话并写入默认模型偏好。
3. **回到自动**：开启开关 → 列表收起、按钮恢复「自动」；下一条消息起恢复 Jev 路由。
4. **发送路径**：自动 ON 时用户无感知发送；宿主在消息进入会话 agent 前完成 Jev 选型并应用；Jev 失败时消息照常按当前模型发出（fail-open）。
5. **跨入口一致**：侧栏面板与网页悬浮窗呈现同一按钮与面板，行为一致。
6. **跨会话/重启**：模式与手动选择持久化，重开面板后恢复；新会话沿用模式。

## 四、功能与交互规格

### 4.1 触发按钮
- 位于附件（回形针）按钮右侧、发送按钮左侧的同排操作区。
- 自动态显示「自动」+ 下拉箭头；手动态显示已选模型显示名 + 下拉箭头。
- 展开态按钮保持高亮/激活样式；`aria-haspopup="dialog"`、`aria-expanded` 如实同步。

### 4.2 模型面板（浮层）
- 结构（自上而下）：面板标题「模型」→「自动模式」行（左文案右开关）→ 说明文案 → （开关 OFF 时）模型列表区。
- 开关为 `role="switch"`，`aria-checked` 如实同步。
- 模型列表每行：品牌图标 + 模型名 + 一行副标题；当前生效项有选中态。
- 关闭：点击面板外、Esc、或选择模型后自动收起；关闭后焦点回到触发按钮；Tab/Shift+Tab 焦点不出面板。
- 空态：列表不可用时显示空态文案，不渲染残缺行。

### 4.3 模式持久化与下发
- 模式 `auto | manual` 与手动模型 id 持久化于浏览器本地存储（按实例端口分键），重启后恢复。
- 模式变更与桥连接建立时，面板把当前模式经 bridge 本地方法下发宿主；宿主进程内持有当前模式（同 `session-model` 先例：进程级、不落盘、默认 auto）。
- 手动模型写入沿用现有三通道：本地存储、`agent-default-model` 设置、会话级 `session.selectModel`（会话存在时）。

### 4.4 自动路由（宿主侧）
- 拦截 `session.prompt`：auto 开 → 取候选模型集合 → Jev 决策 → `session.selectModel` 应用于该会话 → 转发原 prompt；auto 关 → 直透。
- 候选集：宿主已知的对话模型目录（订阅模型组为主，含 provider 映射）；Jev 返回不在候选集的结果视为失败。
- 失败容忍：Jev seam 缺失、超时（上限 8 秒）或返回非法 → 使用会话当前模型继续发送，绝不阻断 prompt。
- 包装顺序：自动路由在会话延迟创建（deferral）包装器**内侧**，保证 selectModel 时 agent 已存在；sessionId 对不上即跳过路由（按无 auto 处理）。

### 4.5 模型列表数据源
- 首选宿主会话模型目录（`session.modelCatalog`，需在 bridge 方法白名单登记）；失败时回落 `/ext/bridge-config` 的 `modelGroups`（订阅列表）。
- 品牌图标与副标题由面板侧显示字典提供（数据行只给 id/name/provider），文案字典以 PM 四件套为准。

## 五、非功能要求

- 双语：全部可见文案走既有 i18n 通道，zh/en 齐全，禁止硬编码单语。
- 无障碍：开关、选项的 role/aria 完整；键盘可操作（Tab/Shift+Tab 焦点圈、Esc 关闭）。
- 视觉：沿用面板既有暗色 `clean-*` 体系；不引入新色板、不新增装饰徽章。
- 新用户基线：未登录宿主时按钮照常可用、选择仅写本地存储；连接恢复后随下发同步；列表空时给空态而非按钮消失。
- 性能：Jev 调用只在发送路径发生且设 8s 上限；面板打开不做网络请求以外的工作。

## 六、测试接缝（seams）

以下接缝为本规格的测试边界，实现前与主理人确认：

- 面板侧纯函数：模式归一化（输入合法/非法/缺省 → auto|manual）；候选模型 → 显示行（分组拍平、brand 映射、副标题字典查找）。
- 宿主侧纯函数：`withAutoModelRouting` 包装器——auto 关直透、auto 开且 Jev 返回合法 id 时先 selectModel 后 prompt、Jev 非法/超时/缺失时直透、sessionId 缺失时直透；deferral 包装顺序（selectModel 发生在 prompt 之前且 agent 已实体化）。
- bridge 协议：新本地方法的 set/get 语义与非法载荷拒绝；`session.modelCatalog` 白名单映射。
- DOM/e2e：按钮渲染位置、面板开合、开关切换驱动列表显隐、点选模型行后按钮文案与持久化写入。

## 七、可测验收标准

1. 附件按钮右侧出现「自动 ⌄」胶囊按钮；点击展开模型面板，自动模式开关默认 ON。
2. 开关关闭 → 面板出现模型列表；点选任一模型 → 面板收起、按钮显示该模型名、本地偏好与 `agent-default-model` 写入、会话存在时 `session.selectModel` 被调用。
3. 开关打开 → 恢复自动；模式与手动模型在面板重开后保持。
4. auto 态发送消息：宿主侧先完成 `session.selectModel`（Jev 选出的候选集内模型）再放行 prompt；Jev 抛错/超时/返回集外 id 时 prompt 仍发出。
5. manual 态发送消息：宿主不做 Jev 调用，prompt 直接透传。
6. 面板满足：外点/Esc 关闭、焦点回收、Tab 焦点圈、开关 aria 状态如实；zh/en 文案与 PM 字典逐字一致。
7. 列表源两级兜底：`session.modelCatalog` 失败时回落 `modelGroups`；两者均空时显示空态文案。

## 八、风险与开放项

- 设置页「默认模型」与新按钮共用同一持久化键（`omnimux_default_model`）：两处编辑同一真源，语义统一为「手动偏好」；PM 在文案中界定「自动模式下的兜底」含义。
- Jev 每轮一次调用带来可测延迟与积分消耗；8s 上限 + fail-open 保证不堵发送；后续可评估按会话缓存决策。
- `session.selectModel` 对不存在的 sessionId 会失败：路由内按 session 有效性判定，deferral 内测保证 agent 已创建。
