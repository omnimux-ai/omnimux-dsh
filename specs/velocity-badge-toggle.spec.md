# X 爆速角标：设置面板开关规格

## 背景

X 爆速角标（`content/twitter-velocity/`）目前在 x.com 上一律挂载，用户无法关闭。设置面板已有两个「页面级开关」（浮动球、图片工具栏），由 `feature-flags.ts` 统一承载：`chrome.storage.local` 为权威通道 + localStorage 镜像供首屏同步读取，默认全开，内容脚本用 `subscribeFlag` 同时监听存储变更与面板发来的运行时消息。

本次按同一模式新增第三个开关：**是否显示 X 爆速角标**。

## 目标行为（验收标准）

1. **设置面板**新增一张卡片（与浮动球、图片工具栏同款样式），标题「X 爆速角标」、开关文案「显示 X 爆速角标」、说明「在 X 推文上展示爆速指标与评论机会提示。」；英文环境对应英文文案。
2. 开关状态持久化到 `chrome.storage.local`（键 `omnimux_velocity_badge_enabled`），并同步镜像供首屏同步读取；默认**开**（保持现有行为，用户可主动关闭）。
3. **关闭时**：x.com 上已有的角标与其宿主节点立即移除，且不再随信息流滚动新增；页面**已有**角标不残留。
4. **打开时**：立即重新扫描当前页面并挂载角标，后续随信息流继续挂载。
5. 开关切换在已打开的标签页即时生效（存储变更 + 运行时消息双通道，与既有两个开关一致）。
6. 既有开关行为不回归；角标自身的配色、判定与交互不改。

## 交互验收步骤

1. 打开扩展设置面板 → 可见第三张卡片，开关默认打开；
2. 关闭开关 → 切到 x.com 标签页刷新生效后角标消失（同一标签页无需刷新即消失）；
3. 重新打开开关 → 角标立即回来；
4. 关掉扩展面板重开 → 开关状态保持（持久化）；
5. 单元测试覆盖：新键被 `isFeatureFlagKey` 识别、默认值、面板卡片渲染与写入调用、角标按开关挂载/卸载。

## 非目标

- 不改角标样式、定位、指标算法与一键抢评链路；
- 不改动既有两个开关的语义与默认值。
