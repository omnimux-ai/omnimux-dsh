# 表单作者工作流与页面约定

## 交付边界

本期交付离线配置、校验、Prompt/素材引用草稿和官方样例。尚无表单运行时、可视化设计器、工坊安装或自动发送能力。此文件规定未来渲染与接入时必须验证的行为，不是这些能力已上线的证明。

统一业务流程：设计配置 → 检查 → 统一页面渲染 → 用户填写 → 校验并生成草稿 → 携带素材进入新会话草稿 → 用户编辑确认并发送。

## 单一真源

- `packages/form-contract/src/schema.ts` 定义结构，`src/index.ts` 定义跨字段语义、填写检查及草稿生成；消费者通过 `@omnimux/form-contract` 公开接口使用。
- [生成参考](../../../../packages/form-contract/generated/reference.md)列出字段、命令、结构示例与错误码；不要手改生成物。
- `protocolVersion` 表达协议兼容性，`templateVersion` 表达模板内容版本。破坏性协议升级必须附显式迁移、旧版本样例及迁移测试；没有迁移不能假装兼容。
- JSON Schema 只检查可表达的结构规则；默认值与选项、字段映射、步长等语义仍必须调用公开接口。

## 统一页面约定（后续实施）

采用一个页面框架：宽屏左侧案例、右侧表单、固定操作区；窄屏案例在上、表单在下，操作区不遮挡字段或错误。案例使用固定槽位，图像和视频保持原始宽高比。

Chakra UI 3 是后续组件实现基线。配置只描述业务字段，不包含库私有 props、任意 CSS/HTML、表达式、请求或事件处理器。标签、说明、Prompt 和用户输入都作为纯文本渲染，不作为 HTML 执行。比例选择与媒体容器的宽高比是不同职责。

字段顺序就是展示顺序；label、description、required 与错误展示由框架统一处理。示例用于解释输入或结果，不新增模板专属页面框架。

## 创建与语义核对

从[三个官方模板](../../../../packages/form-contract/templates/)选择起点，按[命令参考](../../../../packages/form-contract/generated/reference.md#命令)创建到不存在的目录；父目录须存在。`init` 的产物是起步样例，必须替换业务标题、说明、案例、字段和填写数据；不要保留与用户任务无关的示例。

每个官方模板目录包含 `definition.json`、`values.json`、`expected-draft.json`、`invalid-values.json`。最后一个文件包含 `values` 与 `expectedErrors`（错误码和字段路径）；它必须确实触发预期错误。新增模板的目录名必须与配置 id 一致。

Prompt 使用固定文字与字段占位符，仅替换一次；选项输出 value，而 label 仅用于界面显示。可选字段缺省时占位符为空字符串；需要在固定文案中让空值仍可读。默认值只对缺省字段生效，显式传入非法值不会回退默认值。

检查以下问题：用户要求是否保留、是否加入未授权目标、文字与素材是否对应、数量/时长/比例是否清楚。样例中的范围是此表单的输入政策，不代表任何模型支持承诺。涉及生成能力的执行仍须核对实际可用能力。

正式样例的预期草稿是经语义审阅的验收依据。实现行为改变时先确认是否符合用户意图，再决定修改实现或更新预期，不能无条件重生成快照。

## 素材与接入边界

文件值包含不透明引用与文件元数据；草稿将引用独立输出，不把文件名当作 Agent 可访问的附件。离线检查只能确认元数据与配置相容，不能证明文件存在、MIME 声明真实、视频可解析或上传已完成。

未来由现有素材与会话接入层解析引用、完成上传和附加，并保护已有草稿。只有所有必要引用可用才能宣称草稿准备成功；失败应保留填写内容并说明原因。表单不得直接调用模型或另建对话路由，不能自动发送用户未确认的 Prompt。

## 验收与后续开放

运行 `check` 和 `preview` 留存实际结果，再运行 `verify:forms`。本期自动检查覆盖结构、语义、输出样例及生成物漂移；视觉质量和业务准确性不能由 Schema 完全证明。

后续开放前另外验证：L2 与 Dev 页面、窄屏布局、键盘焦点与字段错误、真实素材上传、引用解析失败、已有草稿保护、重复点击和最终发送。统一运行时通过这些检查后，再从同一真源分发用户 Skill；生成参考和工具随兼容契约一起分发，不维护另一套参数说明。
