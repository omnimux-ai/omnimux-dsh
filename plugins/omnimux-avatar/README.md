# omnimux-avatar

OmniMux 角色创作工作台。产品方向见[角色生成与视频复刻](../../docs/contracts/product-positioning.md)，逐项变化、适配与未完成项见[迁移映射](../../docs/implementation/influencer-avatar-sync-3283.md)。源码和模拟验收不代表真实收费渠道、正式部署或生成质量已经验证。

## 创作能力

- 角色设计提供自然、夸张、极限、猫、狗五类，21分类208项，新增发色和肤色；首开随机，手选类别在后续随机中保持，会话草稿按可见性与冲突规则恢复。
- 新角色图采用16:9胸像与全身双视图；动物保持双足、动物头与毛发、尾巴和爪。多视角从选定成功父图及完整父快照派生，不借最新角色参数替代。
- 风格参考图片通过受管文件上传，显式图片参考操作和真实组提交。图像上限5MiB，支持PNG/JPEG/WebP，上传失败与不可用渠道明确报错。
- 视频创作提供动作复刻、角色替换与爆款复刻三种模式；图片与视频为独立素材角色，通过中枢videoGenerate执行。分辨率和输出画幅由当前完整候选提供，替换保持原片画幅。素材及模型声明不保证视频会精确复现参考作品。三个模式各自保存已选素材与说明，切换不互相覆盖，上传库与历史库共享。
- 爆款复刻只有「生成视频」一个动作：点下去先拆解参考片，再立即提交编译好的提示词。参考视频**只作拆解材料**——抽帧后交给文本模型读镜头与节奏，视频本身不会进入视频生成请求；成片请求只有你的参考图与编译后的提示词。拆解进度按有界计时如实推进，不伪造服务端百分比；拆解失败与提交失败分开呈现，提交失败保留已完成的拆解，重试不再二次拆解。时长跟随参考片（4–30 秒），画幅固定竖屏。
- 参考视频与参考图可多选上传，上传中卡片按发起顺序原位显示真实状态；失败可单独重试，切换模式后仍落在发起它的模式。任务失败卡显示中文原因与可展开的原文，重试语义收敛为预览窗里的「重新生成」。预览里的分镜拆解只读，不触发重新分析。
- 图像、视频、派生任务共用角色账本，保存每次输入；后续生成使用任务独立文件。历史完整预览、视频播放、同源下载及有限媒体恢复不触发新生成；明确“重新生成”才创建新意图。
- 角色预设沿用随包快照；动作与趋势视频复用现有中枢公共灵感目录，不复制或分发官网第三方视频素材。目录不可用时显示真实原因。

## 操作与布局

角色设计与视频创作保持各自草稿。视频参考与图片参考分槽选择，选择面板只展示对应类型，可筛选上传或生成来源并独立预览；选择和预览不触发生成。生成视频按钮固定在左栏底部，窄屏同样可见。风格文字按模式保存，自定义说明关闭时保留草稿但不发送。类型和色块使用独立名称行；照片特征加载完成后在悬停或键盘聚焦时显示名称，加载或失败时保持名称可读。类型和分类可折叠，折叠不清除选择。角色灵感按原画幅采用连续列式瀑布流，预览与套用是独立操作。重置特征不清除参考图或补充说明。

## 执行与数据边界

中枢独占提供方请求、凭据、模型路由、托管、接受账本和续取。领域仅经公开的imageGenerate、videoGenerate、mediaInspect、modelCatalog、assetLibrary、textComplete与videoProcess能力执行，不能读取密钥或导入中枢内部代码。爆款复刻的拆解就建在这两个公开能力上：videoProcess 按真实时长等距抽帧（512 长边、约 1.2 秒一帧、6–12 帧），textComplete 先读帧与参考图出结构化分镜，再编译成一条生成提示词。不用场景检测抽帧——它按画面切换选帧，长镜头会一帧都取不到。缺任一能力时明确报「视频分析能力未就绪」或「文本能力未就绪」，不空转、不静默降级；抽帧产物是临时文件，用完即删。

默认数据位于 `$DSH_HOME/omnimux/avatar/`，缺省为 `~/.dsh`。角色账本包含input快照、父任务及中枢taskRef；受管上传文件保留摘要、真实大小与媒体信息，使用时检查归属与摘要。第一份主图/多视角保留main.png/多视角/turnaround.png兼容布局，后续为任务独立文件；视频为独立任务mp4文件。真实MIME由中枢字节检查提供，不因目标扩展名推断。

无需开发端口、本机模型或手工安装视频工具。图片以正式随包的纯解码依赖处理并限制40百万像素；目前只接受非交错静态PNG、JPEG和静态WebP，交错PNG请先另存为普通PNG；参考视频检查单视频轨道、真实时长尺寸、常用编码、12–60帧及AAC音轨，限制4–30秒及240–4096像素。这是容器与采样包检查，不是逐帧视频解码或生成质量保证。缺中枢、模型、完整候选、素材或权限时明确报错，不返回演示模板或伪进度。使用照片、视频、声音和商品素材前须确认肖像与版权授权，执行中枢可能将参考素材托管到外部服务，不能承诺全部本地保留。

## HTTP 与工具

HTTP前缀 `/api/omnimux/avatar`。保留taxonomy、presets、角色CRUD、sheet、multiview、tasks、task与sync；新增materials列表/文件/二进制import、motion、motion/options与recreate/analyze。JSON写入上限64KiB（拆解与motion路由放宽到256KiB，因为拆解结果要带分镜与编译提示词），二进制图片5MiB、视频100MiB。先宿主鉴权，再同源检查；文件请求只收角色及素材/任务标识，不接客户端任意磁盘路径。历史refresh为显式收取原任务，有副作用，不应当作纯只读查询。

Agent工具保留avatar_create/list/get/update/delete/generate/multiview/tasks/library_sync，与界面共用账本。删除角色需confirm；视频界面能力不等于已新增视频Agent工具。

## 构建与验证

`npm run build` 构建本包host公共能力副本与客户端。公共计算源来自MIT共享包 `@omnimux/generation-capabilities`，通过构建捆入本包lib，不引入中枢私有bundle或安装后工作区路径。

插件自动化使用package中的test；界面验收在任务隔离完整应用ui模式下进行，须保留专属截图和断言。真实视频生成需要任务级授权。合并后按仓库交付流程更新开发版，正式发布另需授权。
